# 一、基础题（稳住基本盘）

## 1. 什么是 IoC？

**标准答案：**
IoC（控制反转）是一种设计思想，把对象的创建和依赖管理从程序内部转移到容器中统一管理。

**面试话术：**
“以前对象是我自己 new，现在交给 Spring 容器帮我创建和维护依赖关系，这就叫控制反转，本质是**解耦**。”

------

## 2. IoC 和 DI 的区别

**标准答案：**

- IoC 是思想
- DI（依赖注入）是实现方式

**面试话术：**
“IoC 是目标，DI 是手段。Spring 通过依赖注入实现 IoC。”

------

## 3. 依赖注入方式

**标准答案：**

- 构造器注入
- setter 注入
- 字段注入（@Autowired）

**面试话术：**
“推荐构造器注入，因为依赖是强制的，而且更利于单元测试；字段注入写起来方便，但不太规范。”

------

## 4. BeanFactory vs ApplicationContext

**标准答案：**

| 特性     | BeanFactory | ApplicationContext      |
| -------- | ----------- | ----------------------- |
| 加载方式 | 懒加载      | 默认提前加载            |
| 功能     | 基础 IoC    | 功能更全（AOP、事件等） |

**面试话术：**
“BeanFactory 是基础容器，ApplicationContext 是增强版，实际开发基本都用 ApplicationContext。”

------

## 5. Spring 容器启动流程

**标准答案：**

1. 读取配置
2. 解析 BeanDefinition
3. 注册到容器
4. 实例化单例 Bean
5. 完成依赖注入

**面试话术：**
“可以理解为：先把‘图纸’加载进来（BeanDefinition），再按图纸造对象。”

------

# 二、常考细节

## 6. Bean 作用域

**标准答案：**

- singleton（默认）
- prototype
- request / session / application（Web）

**面试话术：**
“默认单例，大多数场景够用，prototype 用在需要多实例的场景。”

------

## 7. 单例 Bean 线程安全吗？

**标准答案：**
不一定，取决于是否有共享可变状态。

**面试话术：**
“Spring 只保证单例，不保证线程安全，如果有成员变量，就要自己保证。”

------

## 8. @Component 等区别

**标准答案：**
本质一样，都是组件扫描，只是语义不同。

**面试话术：**
“主要是语义区分，比如 @Service 表示业务层，更清晰。”

------

## 9. @Autowired vs @Resource

**标准答案：**

- @Autowired：按类型（byType）
- @Resource：默认按名称（byName）

**面试话术：**
“@Autowired 是 Spring 的，@Resource 是 JDK 标准。”

------

## 10. 循环依赖

**标准答案：**
Spring 通过三级缓存解决**单例 + setter 注入**的循环依赖。

**面试话术（重点）：**
“核心是提前暴露一个‘半成品 Bean’来打破循环。”

------

# 三、进阶（重点拉开差距）

## 11. Bean 创建流程（高频）

**标准答案：**

1. 实例化（构造方法）
2. 属性填充（依赖注入）
3. 初始化（init）
4. 放入缓存

**面试话术：**
“核心就是：先 new，再填依赖，再初始化。”

------

## 12. Bean 生命周期（必考）

**标准答案：**

1. 实例化
2. 属性注入
3. Aware 回调
4. BeanPostProcessor 前置
5. 初始化
6. BeanPostProcessor 后置
7. 使用
8. 销毁

**面试话术：**
“中间最关键的是两个扩展点：BeanPostProcessor。”

------

## 13. BeanPostProcessor

**标准答案：**
用于在 Bean 初始化前后做扩展处理。

**面试话术：**
“AOP、代理对象就是在这里做的。”

------

## 14. 三级缓存（核心）

**标准答案：**

- 一级缓存：singletonObjects（成品）
- 二级缓存：earlySingletonObjects（半成品）
- 三级缓存：singletonFactories（代理工厂）

**面试话术（关键）：**
“三级缓存主要是为了解决 AOP 代理问题，避免返回原始对象。”

------

## 15. 早期暴露

**标准答案：**
在 Bean 还没完全初始化时，把引用提前放入缓存。

**面试话术：**
“就是先把‘还没完全做好’的 Bean 拿出去用。”

------

# 四、源码级问题

## 16. 如何判断需要代理？

**标准答案：**
根据是否匹配切面（AOP）。

**面试话术：**
“看有没有切面增强，比如 @Transactional。”

------

## 17. AOP 在哪生成？

**标准答案：**
BeanPostProcessor 后置阶段。

**面试话术：**
“初始化之后、返回之前做增强。”

------

## 18. 为什么构造器注入不能解决循环依赖？

**标准答案：**
因为构造器执行时对象还没创建，无法提前暴露。

**面试话术：**
“对象还没出来，就没法‘借用半成品’。”

------

## 19. getBean() 做了什么？

**标准答案：**

- 从缓存取
- 没有就创建
- 处理依赖
- 返回 Bean

**面试话术：**
“核心就是：先查缓存，没有就创建。”

------

## 20. DefaultSingletonBeanRegistry 三缓存

**标准答案：**

- singletonObjects
- earlySingletonObjects
- singletonFactories

（同上）

------

# 五、拉开差距题

## 21. 手写 IoC 容器

**面试话术：**
“我会这样设计：

1. 扫描类
2. 保存 BeanDefinition
3. 反射创建对象
4. 维护一个 Map 作为容器
5. 做依赖注入”

------

## 22. 为什么默认单例？

**面试话术：**
“减少对象创建，提高性能，也是大多数业务需求。”

------

## 23. IoC vs 工厂模式

**标准答案：**

- 工厂模式：你主动拿
- IoC：容器主动给

**面试话术：**
“IoC 是更高级的工厂模式。”

------

## 24. Spring vs Google Guice

**标准答案：**

- Spring 功能更全面（AOP、事务）
- Guice 更轻量

**面试话术：**
“Guice 更像纯 DI 框架，Spring 是全家桶。”

------

## 25. 没有 IoC 会怎样？

**面试话术：**
“代码高度耦合、难维护、难测试。”
