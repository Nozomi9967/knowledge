# 为什么 >=、<=、BETWEEN、like 前缀匹配不会停止最左匹配？

> [!info] 联合索引最左匹配 — Composite Index Leftmost Prefix Matching
> MySQL 联合索引（复合索引）按字段顺序排序，仅当查询条件从最左字段开始、且**不出现"无法定位起点的范围"**时，后续字段才能继续利用索引的有序性。

---

## 一句话结论

**`>`、`<` 是"开区间式"范围查询——无法在索引上确定一个明确的起点**（只知道"从某个值往后/往前的所有"，不知道第一个确定的点），所以联合索引在第一个范围字段处停止匹配。

**`>=`、`<=`、`BETWEEN` 是"闭区间式"范围查询——能在索引上精确定位到起点**（如 `>= 18` 就是"从 18 开始"），所以起点之后仍能利用索引有序性继续匹配下一个字段。

`LIKE 'xxx%'` 类似 `>=`：能在索引上定位到所有以 `xxx` 开头的第一条记录，起点明确。

---

## 原理：联合索引的排序结构

以联合索引 `(a, b, c)` 为例，B+Tree 叶子节点按 `a` 升序、`a` 相同时 `b` 升序、`b` 相同时 `c` 升序排列。可以把索引看成**先按 `a` 排序，`a` 相同的小集合内再按 `b` 排序，`b` 相同的小集合内再按 `c` 排序**。

利用后续字段索引的前提是：**前面字段的值已经相等（被精确定位为同一值或一个极小的集合）**。此时"局部有序"才能起作用。

---

## 场景对比

### 场景 1：`a > 1 AND b = 2`（> 会停止）

- 索引能定位到 `a > 1` 的所有记录，**但这些记录里 `a` 可能是 2、3、4、5……，各不相同**。
- 在 `a` 各不相同的前提下，`b` **全局无序**（B+Tree 只在 `a` 相同的局部小集合内保证 `b` 有序）。
- 所以 `b = 2` 这个条件**无法用索引定位**，只能全部回表后过滤。

**结论：遇到 `>` / `<`，联合索引在 `a` 处停止匹配，`b` 失效。**

### 场景 2：`a >= 1 AND b = 2`（>= 不会停止）

- 索引能定位到 `a = 1` 的那条记录（起点明确），然后向右扫描。
- 关键：MySQL 优化器知道"起点是 `a = 1`"，所以从 `a = 1` 开始向后扫的这段区间内，`a` 都是 **1**（连续一段相等的 `a`），在这个小区间内 `b` 是有序的。
- 因此 `b = 2` 仍能用索引。

**结论：`>=` 给出明确起点，相当于先做一次 `=` 定位再向右扫，`b` 仍能利用索引有序性。**

### 场景 3：`a BETWEEN 1 AND 10 AND b = 2`（BETWEEN 不会停止）

- 等价于 `a >= 1 AND a <= 10`，起点 `a = 1` 明确。
- 在 `a ∈ [1, 10]` 这个闭区间内，MySQL 可以按 `a` 升序逐段扫描，每一段相等的 `a` 内 `b` 有序。
- `b = 2` 仍可用索引。

### 场景 4：`a LIKE 'xxx%' AND b = 2`（前缀匹配不会停止）

- 前缀匹配本质上是**字典序上的闭区间**：`['xxx', 'xxy')`。
- 起点是 `a = 'xxx'`，明确。
- 与 `>=` 同理，`b` 仍可用索引。

### 场景 5：`a LIKE '%xxx%' AND b = 2`（中缀/后缀会停止）

- 起点不明确（不知道 `a` 从哪里开始），无法定位。
- 只能全表扫，`a` 这一列都用不上索引，更别说 `b`。

## 用图来理解

```
联合索引 (a, b) 叶子节点内容（a 升序，a 相同则 b 升序）：

a=1, b=1
a=1, b=3
a=1, b=5
a=2, b=2
a=2, b=4
a=2, b=7
a=3, b=1
a=3, b=6
a=4, b=3
...
```

| 查询条件 | 能否定位到起点 | 起点之后 a 的特征 | b 能否用索引 |
|---|---|---|---|
| `a = 1 AND b = 3` | 是（a=1） | 全是 a=1 | ✅ |
| `a >= 1 AND b = 3` | 是（a=1） | 从 a=1 开始，a 值连续 | ✅ |
| `a > 1 AND b = 3` | 否（不知道从哪开始） | a=2,3,4…各不相同 | ❌ |
| `a BETWEEN 1 AND 3 AND b = 3` | 是（a=1） | a ∈ [1,3] | ✅ |
| `a LIKE '1%' AND b = 3` | 是（a='1'） | 全是 a='1'开头 | ✅ |
| `a LIKE '%1%' AND b = 3` | 否 | — | ❌ |

---

## 一句话原理总结

> **`>` 和 `<` 是"开区间"，起点模糊，所以 `a` 在范围扫描中会取到一系列不同的值，导致后续 `b` 失去"局部有序"的前提**。
> **`>=`、`<=`、`BETWEEN`、`LIKE 'xxx%'` 是"闭区间"，起点明确，等价于"先 `=` 定位 + 向右扫"，起点之后一段 `a` 都是同一个值，`b` 在这段小集合内仍有序**。

---

## 面试话术

> 面试官：为什么 `>=` 不会让最左匹配停止，而 `>` 会？
>
> 答：核心看"能否定位到起点"。
> 联合索引 `(a, b)` 是先按 `a` 排序，`a` 相同再按 `b` 排序，所以 `b` 能用索引的前提是"扫描区间内 `a` 全部相等"。
> - `a > 1`：起点模糊，扫到的是 `a = 2, 3, 4, 5...`，`a` 各不相同，`b` 全局无序，索引失效。
> - `a >= 1`：起点明确（`a = 1`），从 `a = 1` 向右扫时有一段连续相等的 `a`，这段内 `b` 有序，所以 `b` 仍能用索引。
> - `BETWEEN` 相当于 `>= AND <=`，`LIKE 'xxx%'` 相当于字典序的闭区间，本质都和 `>=` 一样。
> 所以判断"会不会停止"的诀窍就是：**这个范围条件能不能在索引树上精确停到第一条记录**。
