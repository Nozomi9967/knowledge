# 小红的满减购物清单（子集枚举 / 位运算）

> [!abstract] 题目
> 每件商品最多买一件。购物原价每满 200 减 20；若所选商品包含至少 3 个不同类别，则改为每满 200 减 30，两种优惠不叠加。给定预算，求折后价不超过预算时的最大满意度总和。

| 参数 | 范围 |
|-----|------|
| 预算 B | [10, 1000] |
| 商品数 n | 1 ~ 20 |
| 类别 | [1, 10] |
| 价格 | [1, 200] |
| 满意度 | [1, 240] |

**输入描述：** 第一行输入预算，第二行输入商品数 n，随后 n 行输入唯一编号、类别、价格、满意度。

**输出描述：** 输出最大满意度总和。

**示例 1：**
```
输入：
100
3
10001 1 100 90
10002 2 100 100
10003 3 100 110
输出：
110
说明：预算只能购买其中一件。
```

**示例 2：**
```
输入：
200
4
10001 1 200 200
10002 2 10 10
10003 3 10 10
10004 3 10 10
输出：
230
说明：四件原价 230，三个类别触发减 30，折后正好 200。
```

---

## 核心思路：子集枚举（位运算）

n ≤ 20，所以 2²⁰ ≈ 100 万种子集全部枚举一遍是可行的——这是本题能暴力枚举的根本依据。

对每个子集 i（0 ~ 2ⁿ-1）：

```
sp = 所选商品原价总和
ss = 所选商品满意度总和
count = 所选商品的不同类别数
折后价 = sp - ⌊sp/200⌋ × (count >= 3 ? 30 : 20)
若 折后价 ≤ 预算，更新 ans = max(ans, ss)
```

### 关键细节

- **每件最多买一件** → 每个商品选/不选，天然是 0-1 子集问题。
- **满 200 减 20/30** → `⌊sp/200⌋` 是能触发的优惠次数，每满 200 减一次。
- **优惠不叠加** → 只有一个满减档位，类别数是否 ≥3 决定用哪档。
- **类别去重** → 用位标记记录出现的类别，`Integer.bitCount` 统计不同类别数。

## 完整 Java 代码

```java
import java.util.Scanner;

// 注意类名必须为 Main, 不要有任何 package xxx 信息
public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int b = in.nextInt();
        int n = in.nextInt();
        int[] c = new int[n];
        int[] p = new int[n];
        int[] s = new int[n];
        int ans = 0;
        for (int i = 0; i < n; i++) {
            in.nextInt();
            c[i] = in.nextInt();
            p[i] = in.nextInt();
            s[i] = in.nextInt();
        }
        for (int i = 0; i < (1 << n); i++) {
            int sp = 0, ss = 0, sc = 0;
            for (int j = 0; j < n; j++) {
                if ((i >> j & 1) != 0) {
                    sp += p[j];
                    ss += s[j];
                    sc |= (1 << j);
                }
            }
            int count = Integer.bitCount(sc);
            sp -= (int) Math.floor(sp / 200) * (count >= 3 ? 30 : 20);
            if (sp > b) continue;
            else ans = Math.max(ans, ss);
        }
        System.out.print(ans);
    }
}
```

> [!warning] 原代码的类别去重 Bug
> 第 18 行 `sc |= (1 << j)` 用的是**商品下标 j**，而统计"不同类别数"应该用**类别编号**：`sc |= (1 << c[j])`。
> 当两件商品类别相同（如示例 2 中 10003 和 10004 都是类别 3），`1 << j` 会把它们算成两个不同类别，导致 count 偏大、错误触发减 30 档。
> 正确写法：`sc |= (1 << c[j]);`（类别范围 [1,10]，位标记不越界）。示例 2 恰好需要 count=3 才能得到 230，若按原代码 count=4 仍是 ≥3，所以该样例通过；但若商品类别重复较多，会误判。

## 复杂度

- 时间：O(2ⁿ × n)，n ≤ 20 → 约 2×10⁷ 次操作，可过
- 空间：O(n)

## 面试话术

1. **为什么能直接暴力枚举？** → n ≤ 20，2²⁰ ≈ 1M 种子集，每种子集 O(n) 计算，总约 2×10⁷，在时限内。
2. **为什么用位运算枚举子集？** → `(1 << n)` 的每个二进制位代表一个商品的选/不选，`i >> j & 1` 判断第 j 件是否选中，天然 0-1 建模。
3. **优惠次数为什么是 ⌊sp/200⌋？** → "每满 200"按原价向下取整，是标准满减计算；只有一档优惠，不是阶梯满减。
4. **不同类别数怎么统计？** → 位标记集合：`sc |= (1 << c[j])` 后 `bitCount(sc)` 即不同类别数。⚠️ 千万别用商品下标 j 代替类别 c[j]。
5. **这个题和背包 DP 的区别？** → 背包 O(nB) 也能做，但满减规则让"价值"依赖原价和类别数两个全局量，子集枚举反而更直接；n 小是前提。
