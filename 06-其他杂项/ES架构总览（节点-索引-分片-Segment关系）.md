# ES 架构总览：节点、索引、文档、分片、Segment 的关系

> 本文件是 [[06-其他杂项/ES详解]] 的架构总览延伸，从物理存储单元到运行实例完整串联 ES 的层级关系。

---

## 一句话概括

> **节点是运行实例，索引是逻辑数据集合，文档是基本数据单元，分片是分布式单元，Segment 是物理存储单元——它们通过分片连接在一起。**

---

## 概念定义

| 概念 | 定义 | 层级 | 作用 |
|------|------|------|------|
| **节点（Node）** | 一个运行中的 ES 实例，属于某个集群 | 运行时实例 | 承载分片，处理读写请求，存储数据 |
| **索引（Index）** | 文档的逻辑集合，是用户交互的基本单元 | 逻辑数据集合 | 组织文档，提供搜索、分析接口 |
| **文档（Document）** | JSON 格式的数据记录 | 数据单元 | 存储实际业务数据 |
| **分片（Shard）** | 索引的子集，是一个完整的 Lucene 索引 | 数据分区 | 水平扩展、并行处理、高可用 |
| **段（Segment）** | Lucene 索引内部不可变的存储单元 | 物理存储单元 | 真正存储数据，实现近实时搜索 |

---

## 层级关系

```
集群 Cluster
 └─ 节点 Node（运行实例）
     └─ 索引 Index（逻辑数据集合）
         └─ 分片 Shard（数据子集，每个分片 = 一个 Lucene 索引）
             └─ Segment（不可变存储单元，倒排索引的物理载体）
                 └─ 文档 Document（JSON 数据，存储在 Segment 中）
```

---

## 关系详解

### 文档 → 索引

一个文档属于且仅属于一个索引。索引是文档的逻辑容器，通过索引名称操作文档（增删改查）。

### 索引 → 分片

一个索引被划分为 1 个或多个主分片，每个主分片可以有 0 个或多个副本分片。每个分片都是独立的 Lucene 索引——这是 ES 分布式特性的基础。

### 分片 → 节点

分片被分配到集群的不同节点上。一个节点可承载多个分片，但同一个分片的主副本不会在同一节点（保证高可用）。

### 分片 → Segment

每个分片内部由多个 Segment 组成。Segment 不可变，写入新文档生成新 Segment，删除只在 `.del` 中标记。查询时遍历分片内所有 Segment。

---

## 写入链路中的关系体现

```
用户写入文档
  → 指定索引（Index）
    → 路由到对应主分片（Shard）
      → 写入内存 Buffer + translog
        → refresh（1s）→ 生成新 Segment
          → Segment 可被搜索
            → 异步段合并（Merge）→ 清理删除文档
```

## 查询链路中的关系体现

```
用户查询索引
  → 协调节点（Coordinating Node）
    → 分发到所有相关分片
      → 每个分片遍历内部所有 Segment
        → 合并结果、计算得分
          → 返回结果
```

---

## 面试话术

> "ES 的架构从外到内五层：集群里有多个节点，每个节点上跑着多个索引，每个索引被拆成多个分片分布在不同节点上，每个分片内部由多个 Segment 构成。Segment 是真正的物理存储单元，不可变，所以更新和删除都是标记操作，真正的清理要等段合并。用户只需要关心索引和文档，分片和 Segment 是 ES 底层自动管理的。"
