### **魔理沙的魔导书收纳 — 选/不选背包 DP 易错点**

核心思路是**"挑战数量"为维度的背包型 DP**：`d[i][j]` 表示处理完前 i 本书、已挑战 j 本时的最大剩余魔力，转移分"跳过（无条件继承）"和"挑战（严格大于消耗值）"两条独立路径。本题最大的坑在于把无条件继承塞进有条件 if 块导致状态被丢弃。时间复杂度 $O(n^2)$，空间 $O(n^2)$。

---

### **一、题目描述**

雾雨魔理沙正在帕秋莉的图书馆中"借"阅魔导书。魔理沙初始拥有 E 点魔力值，她面前依次排列着 n 本被魔法结界保护的魔导书。

对于第 i 本魔导书，魔理沙可以选择**挑战结界**或**直接跳过**。

1. **挑战结界**：只有当魔理沙当前的魔力值**严格大于**该结界消耗值 $a_i$ 时，才能挑战成功。挑战成功后，她的魔力值会减少 $a_i$，但随后会从魔导书中吸收 $b_i$ 点魔力反馈。即魔力值变为 $\text{current} - a_i + b_i$。
2. **跳过**：魔理沙不挑战该结界，直接前往下一本书，魔力值保持不变。

魔理沙希望在保证**挑战过程中魔力值始终不为负数**的情况下，尽可能多地收纳魔导书。求她最多能成功挑战多少个结界。

- 时间限制：C/C++ 1 秒，其他语言 2 秒
- 空间限制：C/C++ 256M，其他语言 512M
- 第一行：整数 E，初始魔力值
- 第二行：空格分隔的整数 $a_1, a_2, \dots, a_n$，结界消耗值
- 第三行：空格分隔的整数 $b_1, b_2, \dots, b_n$，魔力反馈值

**示例：**

```
输入：
18
15 17 4 18
1 15 4 17

输出：
2
```

**说明：**
- 初始魔力 18
- 跳过第 1 本书（消耗 15，反馈 1），魔力仍为 18
- 挑战第 2 本书：18 > 17，成功，魔力变为 18 - 17 + 15 = 16
- 挑战第 3 本书：16 > 4，成功，魔力变为 16 - 4 + 4 = 16
- 第 4 本书消耗 18，当前魔力 16，不满足 16 > 18，无法挑战，只能跳过
- 最终成功挑战数量为 2，其他方案无法超过 2

### **二、思路分析**

#### **为什么用 DP**

这是一道典型的**序列上"选 / 不选"决策**问题，且每个决策有**前置条件**（魔力要够）和**后效性**（改变剩余魔力）。贪心不可行（因为"消耗少"和"反馈多"可能冲突），所以用动态规划。

#### **状态定义**

$$d[i][j] = \text{处理完前 } i \text{ 本书、已挑战其中 } j \text{ 本时，剩余魔力的最大值}$$

- $-1$ 表示该状态**不可达**
- 存最大值是因为：同样的"挑战了 j 本"，剩余魔力越多，后续越容易继续挑战

#### **状态转移**

对第 i 本书（对应 $a[i-1], b[i-1]$），每个状态有两种决策：

| 决策 | 条件 | 转移 |
|------|------|------|
| **跳过**第 i 本 | 无条件 | $d[i][j] = \max(d[i][j],\ d[i-1][j])$ |
| **挑战**第 i 本 | $d[i-1][j] > a[i-1]$（严格大于） | $d[i][j+1] = \max(d[i][j+1],\ d[i-1][j] - a[i-1] + b[i-1])$ |

#### **初始化**

- $d[0][0] = E$（0 本书、挑战 0 本，魔力为初始值）
- 其余全部填 $-1$（不可达）

#### **答案**

从 $j = n$ 向 $j = 0$ 倒序，找第一个 $d[n][j] \geq 0$ 的 j，即为最多挑战数。

### **三、AC 代码**

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        long e = in.nextLong();
        in.nextLine();
        String[] tem = in.nextLine().trim().split(" ");
        int n = tem.length;
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = Long.parseLong(tem[i]);
        tem = in.nextLine().trim().split(" ");
        long[] b = new long[n];
        for (int i = 0; i < n; i++) b[i] = Long.parseLong(tem[i]);

        // d[i][j] = 前 i 本已挑战 j 本时的最大剩余魔力；-1 表示不可达
        long[][] d = new long[n + 1][n + 1];
        for (int i = 0; i <= n; i++) Arrays.fill(d[i], -1);
        d[0][0] = e;

        for (int i = 1; i <= n; i++) {
            // 1) 跳过：无条件继承上一阶段
            for (int j = 0; j <= i; j++) {
                d[i][j] = Math.max(d[i][j], d[i - 1][j]);
            }
            // 2) 挑战：必须严格大于消耗值
            for (int j = 0; j < i; j++) {
                if (d[i - 1][j] > a[i - 1]) {
                    d[i][j + 1] = Math.max(d[i][j + 1], d[i - 1][j] - a[i - 1] + b[i - 1]);
                }
            }
        }

        for (int i = n; i >= 0; i--) {
            if (d[n][i] >= 0) {
                System.out.print(i);
                break;
            }
        }
    }
}
```

运行结果：**通过全部用例**，41ms / 11404KB。

### **四、踩过的坑**

#### **Bug 1：挑战条件写成 `>=` 而非 `>`**

```java
// ❌ 错误：等于时也放行
if (d[i-1][j] >= a[i-1]) ...
// ✅ 正确：严格大于
if (d[i-1][j] > a[i-1]) ...
```

**根因**：题目明确说"严格大于"，一眼扫过去没注意"严格"二字。当魔力恰好等于消耗值时（如魔力 16、$a_i=16$），按题意不能挑战，但 `>=` 会放行并多算一本。

**教训**：读题时遇到"大于 / 严格大于 / 不小于"这类比较条件，必须逐字确认边界，最好在草稿上标红。

#### **Bug 2：把"跳过"的无条件继承塞进了挑战的 `if` 块（最致命）**

最初的写法：

```java
for (int j = 0; j < i; j++) {
    d[i][j] = Math.max(d[i-1][j], d[i][j]);            // 跳过
    if (d[i-1][j] > a[i-1]) {
        d[i][j+1] = Math.max(d[i-1][j] - a[i-1] + b[i-1],
                             d[i-1][j+1]);             // ← 挑战 + 继承混在一起
    }
}
```

问题在于 `d[i][j+1]` 有两种来源：

- **挑战第 i 本**：`d[i-1][j] - a[i-1] + b[i-1]`，**需要条件**（魔力够）
- **继承上一阶段**：`d[i-1][j+1]`，**无需任何条件**（之前挑战过 j+1 本，现在跳过第 i 本即可）

两者被一起放进了 `if` 里。一旦 `d[i-1][j]` 不够挑战，整条赋值都不执行，`d[i][j+1]` 保持 $-1$，于是上一阶段本来可达的 `d[i-1][j+1]` 被直接丢弃，后续连锁错误。

**反例复现**：`E=10`，`a=[9, 200]`，`b=[100, 1]`

```text
正确过程：挑战第1本（10>9 ✓）→魔力101，跳过第2本（101>200 不成立）→答案1
错误输出：d[2][1] 因条件不满足未赋值，把 d[1][1]=101 丢掉，输出0
```

**修正**：把跳过和挑战拆成两个独立循环，跳过无条件执行。

### **五、其他细节备忘**

| 细节 | 说明 |
|------|------|
| `e` 的类型 | 初始魔力、$a_i$、$b_i$ 都可能很大，全程用 `long`，避免 `int` 溢出 |
| `Long.valueOf` vs `Long.parseLong` | 功能等价，`parseLong` 更直接，无装箱开销，语义更贴合 |
| `import java.util.*` | `Scanner` 和 `Arrays` 都在 `java.util` 下，别漏 |
| 样例能过但隐藏挂 | 这类 bug 的典型特征：样例恰好不触发"条件不满足但状态可达"的场景，**务必自己造反例自测** |
| 空行处理 | `in.nextLine()` 先吃掉第一行 `int` 后的换行符，否则第二行 `split` 会拿到空串 |

### **六、思维升级总结**

#### **核心原则**

> **DP 转移中，每一种决策（选 / 不选、挑战 / 跳过）的状态更新必须完全独立。**
> 把"无条件继承"混进"有条件更新"的分支里，是这类背包 DP 最隐蔽的错误来源。

#### **判断方法**

写完转移后，自问两个问题：

1. 这个状态的更新有几条来源路径？
2. 每条路径的前置条件分别是什么？

如果某条路径**无条件**却被写进了**有条件的 if 块**里，就是 bug。

#### **通用模板**

凡是"在序列上选/不选、且选择有前置条件"的题，都可以套这个结构：

```text
for i = 1 to n:
    for j = 0 to i:          # 跳过：无条件
        d[i][j] = max(d[i][j], d[i-1][j])
    for j = 0 to i-1:        # 选择：有条件
        if 满足条件(i, j):
            d[i][j+1] = max(d[i][j+1], 转移(i, j))
```

把"无条件继承"放最前面单独处理，能从根上杜绝这类错误。

---

### **七、复杂度分析**

- **时间复杂度**：$O(n^2)$。两重循环，每本书遍历所有挑战数 j。
- **空间复杂度**：$O(n^2)$。d 表 $(n+1) \times (n+1)$。

### **八、面试话术**

1. **为什么存"最大剩余魔力"而不是"是否可达"？** — 挑战数 j 相同时，剩余魔力多的状态在后续转移中严格占优（同样条件更容易满足），所以每格只保留最大值，天然剪掉被支配的状态。
2. **为什么答案要倒序找第一个可达 j？** — 状态定义保证了 d[n][j] 是"前 n 本挑战 j 本"的最优剩余魔力，从大到小找第一个 $\geq 0$ 的 j 就是能挑战的最大数量。
3. **为什么不贪心？** — "消耗少"和"反馈多"两个属性可能冲突（消耗大的书反馈可能更多），按单一维度排序无法保证全局最优。
4. **这类题和 01 背包的关系？** — 01 背包按"容量"维度压缩，这题按"已选数量"维度记录，都是"前 i 个物品选 j 个"的经典结构；区别是本题"容量"（魔力）是动态变化的，不能直接用背包容量维度。
