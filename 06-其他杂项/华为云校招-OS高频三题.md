## T1 · 进程 / 线程 / 协程（概念对比）

**①** 进程和线程的区别是什么？各自是"什么的最小单位"？

**②** 为什么线程切换比进程切换便宜？关键差别具体在哪一步？请解释「共用页表 → 不切 CR3 / 不刷 TLB / 缓存命中部分保留」三个动作分别指什么。

**③** 有了线程为什么还要协程？进程 / 线程 / 协程三种切换成本从贵到便宜怎么排，根因分别是什么？

**④ 追问**：JDK 21 的虚拟线程是协程的工程化落地吗？它挂在什么载体上、遇到阻塞 IO 时发生什么？pinning 是什么、JDK 24 修的是哪一种 pinning？

**⑤ 追问**：同进程内一个线程崩溃为什么整个进程都完？进程之间为什么不会互相影响？

> [!success]- 参考答案（口述版）— 先裸答，再展开对照
> **① 定位**："进程是操作系统**资源分配的最小单位**——它有一份独立地址空间、自己的页表、自己的文件描述符表，进程之间物理隔绝，一个崩了不影响别的；线程是**CPU 调度的最小单位**——它是进程里的一条执行流，同一进程的线程共享代码段、堆、全局数据整一套地址空间，各自私有的只有栈、程序计数器、寄存器组。因为共享地址空间，切线程不用换页表——这就是线程比进程轻的根本原因。"
>
> **② 切换差在哪**："关键只有一条：**同进程的线程共用一张页表，切换不换页表**。进程切换要把 CR3 换成新进程的页表基址，而 TLB 里存的『虚拟→物理』映射全是按旧页表翻译出来的，页表一换全部作废——x86 上写 CR3 本身就触发 TLB 整条刷空；同时 L1/L2/L3 缓存里全是上个进程的代码和数据，新进程的工作集不在里面，命中率断崖式下跌。线程切换 CR3 不动、TLB 一条不清，跑的还是同一份代码同一份数据，上个线程留的热缓存下个线程接着用，只有私有栈和 ThreadLocal 是冷的。所以贵不贵不在那几条指令，贵在**切换之后缓存和 TLB 的重建**。"
>
> **③ 还要协程**："线程是内核对象：创建要走 `clone()` 系统调用、默认栈 8MB、数量受内核调度能力限制，十万并发就是十万个内核线程，扛不住。协程把这件事从内核搬到用户态——阻塞时让出、就绪时恢复，挂起的只是栈上几个字节的状态，切换不陷入内核。成本从贵到便宜：**进程**换地址空间→TLB 全刷+缓存全丢；**线程**换栈和寄存器、不换页表、缓存大部分还热；**协程**纯用户态保存少量上下文。一句话：进程换空间、线程只换上文、协程连内核都不进。"
>
> **④ 追问·虚拟线程/pinning**："虚拟线程就是 JVM 实现的协程。它挂在**载体线程**（ForkJoinPool 里的平台线程）上，遇到阻塞 IO 时把栈帧卸载成堆上的 continuation 对象，载体线程立刻去跑别的虚拟线程——所以百万虚拟线程背后，内核看到的还是那几十个平台线程。它解决的不是并发不够，而是**阻塞 IO 浪费内核线程**。代价也要说清：JDK 21 里 `synchronized` 块中阻塞会 pinning、退化占死载体线程，JDK 24 起经 JEP 491 已消除；现在只剩 Native 方法调用还会卡住载体线程。"
>
> **⑤ 追问·崩溃影响**："线程崩溃为什么带崩整个进程：同进程线程共用一张页表，一个线程的野指针崩掉的是整张页表的主人。进程为什么互不影响：各有独立页表，A 怎么算地址都翻译不到 B 的物理帧——路径根本不存在；访问未映射页触发缺页异常，内核发 SIGSEGV 只杀掉 A 自己。"

## T2 · 为什么要有虚拟内存（因果推演）

**①** 虚拟内存解决哪三个问题？「隔离与安全」具体靠什么机制保证——为什么 A 进程访问 `0x1000`，物理上就碰不到 B 进程的数据？

**②** 一次「访存」的地址翻译链路是什么？TLB 是什么、命中与 miss 的成本差多少？为什么进程切换会连带 TLB 失效、线程切换不会？

**③** 内存不够时把哪个页换出去？**精确 LRU** 用什么数据结构实现、复杂度是多少？为什么操作系统实际用 Clock 近似而不用精确 LRU？

**④ 追问**：`malloc` 小块和大块分别走 `brk` 还是 `mmap`？阈值是多少？程序 `free` 了很多内存为什么 `top` 里 RES 不降？

**⑤ 追问**：缺页异常有哪三种？哪种要读盘、哪种只是在内存里补建映射？

> [!success]- 参考答案（口述版）— 先裸答，再展开对照
> **① 三个动机**："虚拟内存解决三件事。**隔离与安全**——每个进程一套独立地址空间，A 访问 `0x1000` 经过自己页表翻译落到 A 自己的物理帧，B 的页表里根本没有通往 A 或内核物理页的路径，不是拦着不让碰，是路径压根不存在；访问未映射的地址触发缺页异常，内核发 SIGSEGV，进程段错误只死自己。**连续内存假象**——物理内存是碎的、多进程交错分配，虚拟地址让程序以为有一大块连续空间，链接和加载才简化。**按需分配 + 可换出**——虚拟页可以不对应任何物理帧而"存在"，访问时触发缺页异常，内核再分配物理帧或从 swap 换入；不用的页可以换出到 swap、腾出物理帧给别人。这两点加在一起才撑起了两件事：
> - **超配**：物理内存 8G 可以给所有进程承诺总计 16G 的虚拟空间，反正不会同时都用到
> - **写时复制**：fork 时父子进程共享同一批物理帧，页表标记只读，谁要写谁才触发缺页、复制出自己的帧，没写过的页永远不复制"
>
> **② 翻译链路+TLB**："一次访存：CPU 出虚拟地址，页内偏移不变、只翻页号；先查 TLB——它是页表项的缓存，存『虚拟→物理』映射，就在 MMU 硬件里，命中大概 1 个周期；miss 才走四级页表 walk，几十上百个周期。Linux 默认页大小 4KB。进程切换 TLB 失效，是因为 TLB 条目都是『在当前 CR3 指向的页表下翻译出来的』，换页表映射全作废；线程共用一张页表、映射没变，条目直接能用。现代 CPU 有 PCID/ASID 给表项打进程标签，能避免全刷。"
>
> **③ 置换算法**："精确 LRU 是**哈希表+双向链表**：哈希 O(1) 定位节点，链表维护访问顺序、头插、淘汰尾节点。但每次访问都要移动节点，硬件开销太大，所以实际系统用 Clock/二次机会：环形链表+引用位，指针指到引用位 1 的就清 0 跳过、指到 0 的淘汰，O(1) 摊还。Redis 的 allkeys-lru 采样近似、Caffeine 的 W-TinyLFU，都是同一条工程取舍：精确 LRU 太贵。"
>
> **④ 追问·brk/mmap**："小块走 brk 移动堆顶，大块超过 **128KB** 走 mmap 单独映射、munmap 立刻归还。free 很多但 RES 不降，是因为小块走 brk，glibc 把释放的块留在自己的空闲链表复用，堆顶不轻易下移、中间有内存空洞挡着，真归还要 `malloc_trim()`；mmap 来的那是立刻还的。"
>
> **⑤ 追问·缺页三种**："三种：**非法访问**，段错误；**硬缺页**——页合法但不在物理内存，要读盘，比如换页进来、mmap 首次访问读文件；**软缺页**——页其实已经在内存，只是没建映射，fork 写时复制就是典型，不读盘。"

## T3 · Load 很高但 CPU 不高（线上排查）

**①** Linux 的 Load 统计的到底是什么（提示：不只是"正在跑"的任务）？怎么判断机器压力大不大？为什么单核 Load 接近 0.7 就该告警、但 4 核机 Load=4 不是问题？

**②** 面试高频硬题：*"Load 很高但 CPU 使用率不高，说明什么？"* 这时候加 CPU / 加线程有用吗？该去看哪几个指标？

**③** 给一条完整排查命令链：`top` → `vmstat 1` → `iostat -x 1`，每一条看哪几个字段、各自对应什么结论？

**④ 追问**：`free` 显示内存只剩 200MB，要不要慌？`available` 和 `free` 的区别是什么？

**⑤ 追问**：`kill -9` 杀不掉一个进程，最可能是哪两种状态？D 状态和 Z 状态各该怎么处理？

> [!success]- 参考答案（口述版）— 先裸答，再展开对照
> **① Load 是什么**："先说清一件事：Load 不是命令，是内核自己统计的**指标**，看它用 `uptime` 或 `top` 顶部那一行 `load average: 1.87, 1.56, 1.40`。它统计的是 **R 状态（运行+可运行）加上 D 状态（不可中断睡眠、在等 IO）的任务数**，是 1/5/15 分钟的指数衰减移动平均。所以它是一个**个数、不是一个百分比**——CPU 使用率告诉你这颗 CPU 有多忙，Load 告诉你有多少个任务在跑、在排队、在等 IO，两者是两回事。判断压力先除以核数：4 核机 Load=4 是满载，超过 4 就开始排队，单核接近 0.7 就该告警。所以我把它当**任务堆积指标**用。"
>
> 通俗理解：Load 像超市收银台前排队的人数——CPU 使用率看收银员忙不忙，Load 看站着几个人（在结算 + 排队 + 卡在扫码等网络/磁盘）。Load 高但 CPU 不高，就是排满了人但收银员在发呆，因为大家都在等门禁刷卡机（磁盘 IO）——加收银员没用，得修刷卡机。
>
> 看趋势口诀：三个数是不同时间常数的指数衰减移动平均（1 分钟灵敏、15 分钟平滑），**1 分钟 > 15 分钟 = 负载在往上走，1 分钟 < 15 分钟 = 在回落，接近 = 稳态**——只报单个数没有意义，要报"R1 明显大于 R15、说明最近压上来了"。
>
> **② Load 高 CPU 不高**："说明大量进程卡在 **D 状态等 IO**——磁盘慢、NFS 挂、大量缺页换页。CPU 空转不是因为闲，是没人 runnable、全在等。这时候加 CPU、加线程完全没用，该去看 `iostat`、`vmstat` 的 `wa` 和 `bi/bo`。"
>
> **③ 命令链**："`top` 看全局：`%wa` 高是 IO 瓶颈、`%sy` 高是内核态开销大（上下文切换/系统调用/软中断多），按 `H` 看单线程；`vmstat 1` 看 `r`（等 CPU 的数）、`cs`（每秒上下文切换次数）、`si/so`（在换页说明内存紧）、`wa`；`iostat -x 1` 看 `%util` 逼近 100% 是盘打满、`await` 是平均等待时长。判断方向：`r` 大是真缺 CPU，`wa` 大是存储瓶颈，两种处理方向完全相反。"
>
> **④ 追问·available/free**："不慌。`free` 是彻底没用过的内存，`available` = free + **可回收的 cache**；cache 可回收、不是真占用，所以看内存先看 `available`。"
>
> **⑤ 追问·D/Z 杀不掉**："杀不掉就两个可能：**D 状态**在等磁盘/NFS IO，信号在内核态暂时没法响应，`kill -9` 也没用，只能查存储或重启；**Z 状态**是进程已退出、父进程没 `wait()` 收尸，kill 一个僵尸没意义，该修的是父进程代码。top 里一堆 D 查磁盘，一堆 Z 查父进程。"
