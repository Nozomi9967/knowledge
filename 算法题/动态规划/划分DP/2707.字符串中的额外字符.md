### **LeetCode 2707「字符串中的额外字符」动态规划解法**

核心思路是**一维划分 DP**：`d[i]` 表示前缀 `s[0..i-1]` 中最少需要"额外保留"的字符数（即不参与任何字典词匹配的字符），通过枚举"最后一段匹配"的起点完成状态转移，时间复杂度 $O(n^2)$。

---

### **一、问题本身**

给定字符串 `s` 和一个单词字典 `dictionary`，可以从 `s` 中选出**一些子串**，这些子串必须是字典中的单词。选中的子串之间不能重叠，且可以**跳过**任意字符（被跳过的字符就是"额外字符"）。求最少需要跳过多少个字符。

> 例如 `s = "leetscode"`，`dictionary = ["leet","code","leetcode"]`
> 可以选 `"leet"`（下标 0-3）和 `"code"`（下标 5-8），跳过下标 4 的 `'s'`，额外字符数为 1。

关键观察：这是一个**字符串切分 + 字典匹配**问题。每一步决策是——前缀 `s[0..i-1]` 的最优方案中，最后一段是什么？如果最后一段是字典中的某个单词，那么这段不贡献额外字符；否则最后一段可能就是一个单独的"额外字符"。

### **二、DP 解法**

```java
class Solution {
    public int minExtraChar(String s, String[] dictionary) {
        int n = s.length();
        int[] d = new int[n + 1];
        var dic = new HashSet<String>(
            Arrays.stream(dictionary).collect(Collectors.toList())
        );
        for (int i = 1; i <= n; i++) {
            d[i] = d[i - 1] + 1;           // 默认：s[i-1] 是额外字符
            for (int j = 0; j < i; j++) {  // 枚举最后一段 s[j..i-1] 的起点
                if (dic.contains(s.substring(j, i))) {
                    d[i] = Math.min(d[i], d[j]);  // 匹配成功，不增加额外字符
                }
            }
        }
        return d[n];
    }
}
```

#### **状态定义**

`d[i]`：前缀 `s[0..i-1]` 中**最少额外字符数**。

`d[0] = 0`（空串没有额外字符）。数组大小为 `n+1` 而非 `n`，是为了方便处理"前缀长度为 0"的边界。

#### **状态转移**

对于每个位置 `i`（1 到 n），有两种选择：

1. **把 `s[i-1]` 当作额外字符**：不参与任何字典词匹配，额外字符数 +1
   $$
   d[i] = d[i-1] + 1
   $$

2. **枚举最后一段字典词**：对每个 `j`（0 ≤ j < i），如果 `s[j..i-1]` 是字典中的词，那么这段完全匹配不浪费字符，额外字符数就是前缀 `s[0..j-1]` 的最优值：
   $$
   d[i] = \min_{0 \le j < i,\ s[j..i-1] \in \text{dic}} d[j]
   $$

综合两者，取最小值：

$$
d[i] = \min\Bigl(d[i-1] + 1,\ \min_{\substack{0 \le j < i \\ s[j..i-1] \in \text{dic}}} d[j]\Bigr)
$$

#### **初始化**

`d[0] = 0`，其余默认 0（但会被循环覆盖）。

#### **答案**

`d[n]`，即整个字符串 `s[0..n-1]` 的最少额外字符数。

### **三、与 132「分割回文串 II」的对比**

这两道题本质是**同一类 DP 模板**——都是枚举"最后一段"做划分：

| 维度 | [[132.分割回文串 II]] | 2707. 字符串中的额外字符 |
|------|----------------------|----------------------|
| 状态含义 | 前缀最少**切割次数** | 前缀最少**额外字符数** |
| 最后一段条件 | 必须是**回文串** | 必须是**字典中的词** |
| "不匹配"时 | 必须切一刀（+1） | 丢弃一个字符（+1） |
| 匹配时 | 继承 `f[l-1]` | 继承 `d[j]` |
| 预处理 | 需要 `isPalindrome` 表 | 只需 `HashSet` 查词 |

**核心模板一致**：`dp[i] = min(dp[i-1] + 1, min(dp[j] if s[j..i-1] is valid))`。区别只在于"valid"的判断条件——回文 vs 字典词。

---

### **四、复杂度分析**

- **时间复杂度**：外层 `i` 走 `n` 次，内层 `j` 最多走 `n` 次，循环体 `substring + HashSet.contains` 各为 $O(1)$（Java `substring` 在 Java 7+ 会复制字符数组为 $O(i-j)$，但在算法分析中通常视为常数或计入循环）。总计 $O(n^2)$。
- **空间复杂度**：`d` 数组 $O(n)$，HashSet 存字典 $O(M)$（M 为字典总长度）。合计 $O(n + M)$。

**优化思路**：如果字典总长度很大，可以用 [[Trie]]（字典树）替代 HashSet，在枚举 `j` 时从 `i-1` 往前 Trie 匹配，把内层循环从 $O(n)$ 降为 $O(\text{字典最大词长})$，总复杂度 $O(n \cdot L)$（L 为最长词长度）。

### **五、一个具体例子走一遍**

以 `s = "leetscode"`，`dictionary = ["leet","code","leetcode"]`（`n = 9`）为例：

| i | 前缀 | d[i-1]+1 | 枚举 j（匹配的 s[j..i-1]） | d[i] |
|---|------|----------|---------------------------|------|
| 0 | ""   | —        | —                         | 0    |
| 1 | "l"  | d[0]+1=1 | 无匹配                    | 1    |
| 2 | "le" | d[1]+1=2 | 无匹配                    | 2    |
| 3 | "lee"| d[2]+1=3 | 无匹配                    | 3    |
| 4 | "leet"| d[3]+1=4 | j=0: "leet"∈dic → d[0]=0 | **0** |
| 5 | "leets"| d[4]+1=1 | 无匹配                    | 1    |
| 6 | "leetsc"| d[5]+1=2 | 无匹配                    | 2    |
| 7 | "leetsco"| d[6]+1=3 | 无匹配                    | 3    |
| 8 | "leetscod"| d[7]+1=4 | 无匹配                    | 4    |
| 9 | "leetscode"| d[8]+1=5 | j=5: "code"∈dic → d[5]=1 | **1** |

返回 `d[9] = 1`，即只需跳过 1 个字符（`'s'`），与预期一致。

### **六、面试话术**

这道题的面试要点：

1. **为什么是 DP 而不是贪心？** — 贪心（每次选最长的匹配词）可能不是最优。例如 `s = "abcde"`，`dic = ["ab","abc","cde"]`，贪心选 `"abc"` 后剩 `"de"` 需要 2 个额外字符；但选 `"ab"` + `"cde"` 只需要 0 个额外字符。
2. **状态转移的核心思想** — "最后一段"视角：前缀最优 + 最后一段是否匹配，是划分型 DP 的标准拆解方式。
3. **HashSet vs Trie** — HashSet 查询 O(1) 但需要 `substring`；Trie 可以 inline 匹配、省去 substring，适合字典词很长的情况。
4. **与同类型题的关联** — 本质是 [[DP状态转移——枚举最后一段]] 模板的应用，与 [[132.分割回文串 II]] 结构一致，区别只在"合法段"的判断条件。
