## 1. 招聘流程与特点

```
宣讲会 → 线下笔试 → 线下一面（群面，举手抢答）→ 二面（主管/总监面）→ 感谢信 / offer
```

- **笔试**：线下；约 60 分不定项 + 20 分 SQL + 20 分编程。内容 = 408 基础（二叉树、CPU 寄存器、EEPROM）+ Java/C 基础 + 5 道 SQL + 2 道简单算法（合并两个有序链表、求子串首字符出现位置）。
- **节奏快**：一面当晚发邮件、次日二面；笔试到感谢信约 6 天。
- **笔试与往年（22 年）重复率很高** → 建议刷历年真题；分数线偏低（有反馈「四十出头」过线）。

### ⚠️ 保融最大的特点：极度看重在校成绩

面经原文（多篇一致）：
- 「有没有成绩 10% 的说一声，估计说了能直接二面」
- 「二面没有专业问题，你成绩好才能过」
- 「非常非常非常看重成绩，就算你没答好问题，只要在校成绩好就能过」
- 薪资评价原话：「**落户杭州，学历歧视严重，看学校给工资**」

## 2. 一面（线下群面）高频题汇总

群面 7-9 人一组（2 面试官，一个提问一个记录），流程：轮流自我介绍 → 轮流问简历 → **技术抢答环节**。

| 并发 | 线程池核心参数（结合项目拷打）、死锁条件与预防、线程通信、并发编程 |
| 集合 | java 集合、ConcurrentHashMap 与线程安全、线程安全的集合 |
| JVM/类加载 | 双亲委派机制（能否篡改内置类、能否破坏双亲委派） |
| Spring | AOP 如何实现、反射的包位置与调用方式、事务传播机制/传播行为、事务失效场景、SpringBoot 与 Spring 区别、SpringBoot 自动装配原理、Spring/SpringMVC/MyBatis 理解、举例某框架的作用 |
| MySQL | 索引是什么/为什么减少 IO、索引分类、聚簇与非聚簇索引、乐观锁与悲观锁、`delete` 语句返回值、分页查询如何实现、索引（结合项目）、事务、事务嵌套 |

| 微服务 | SpringCloud 各应用之间接口如何互相调用 |

**2026 春招线上单面版本**（非群面）：线程池参数、死锁预防、Redis 持久化、MySQL 索引、线程通信、集合与线程安全、项目拷打、AI coding 经历；无手撕，约半小时。

> - **软测**：一面偏基础（数据库索引、怎么测试错误、HTTP 状态码、测试分类/方法/工具、测试报告与用例组成、Linux），二面只看成绩

> - **运维**：一面问客户反馈类问题，二面问个人信息/项目/工作经历

## 3. 二面准备（15min，主管/总监面）

**定性判断**：一面是群面 → 二面几乎确定是**主管/总监面，聊天为主**，技术八股已在一面考完。
**固定套路**：成绩/在校 → 家庭情况 → Base 地/出差 → 期望薪资 → 发展方向 +（项目简单问问）。

### 3.0 15 分钟时间分配

1. 自我介绍 2min
2. 成绩/在校 3-4min（权重最高）
3. 项目 3-5min（不会深挖）
4. 意愿（Base/出差/薪资）3-4min
5. 反问 1-2min

---

### 3.1 开场自我介绍（必问）

**骨架**：学校专业 + 成绩/荣誉（一句话）→ 技术栈（Java/Spring 系 + 数据库 + 中间件）→ 最有代表性的一个项目（一句话）→ 为什么投保融。

**要点**：不超过 2 分钟；别背简历；留钩子让面试官顺着问。

### 3.2 成绩 / 在校（权重最高，必须提前准备）

| 问题 | 怎么答 |
|------|--------|
| 成绩怎么样？专业排名？ | 如实说。**如果是前 10%，一定要主动说** |
| 为什么不是前 10%？ | ⚠️ 核心题。结构：客观事实（某学期把时间投给了实践）→ 主动补救（成绩提升到什么程度）→ 收获。**禁止**抱怨老师/课程/学校 |
| 挂过科吗？ | 如实。挂了解释原因 + 后续怎么补上 |
| 为什么没拿奖学金？ | 别说「不看重」，说「精力放在项目/实习上，成绩维持中上」 |
| 在校经历 / 最大困难 / 说服别人的经历 | 一律用 **STAR**：情境→任务→你做了什么→结果。准备 2 个万能故事（技术类 + 人际协作类） |

### 3.3 项目（会问，但通常「拷打一下」级别）

| 问题 | 怎么答 |
|------|--------|
| 挑一个项目详细讲讲 | 3 分钟版：做什么（一句话）→ 技术栈 → 我负责的模块 → 最难的一个点怎么解决 → 结果 |
| 用了哪些技术？为什么这么选？ | 说对比：为什么用 Redis（解决什么具体问题，别只说"做缓存"） |
| 遇到过什么问题，怎么排查？ | **见 3.8，这是最容易加分的题** |
| 这个功能你会怎么优化？ | 说 1-2 个真实短板 + 改进思路（加索引/加缓存/异步化）。**别**说「已经很完善」 |
| 是团队项目吗？你做了哪部分？ | 分工清晰可验证。**禁止**把别人的模块说成自己的 |

**坑**：15 分钟里项目只占 3-5 分钟，别主动展开技术细节，等追问再深入。

### 3.4 意愿与稳定性（必问，决定要不要你）

| 问题 | 怎么答 |
|------|--------|
| Base 地能接受吗？ | 明确表态。能接受就说「都能接受，服从安排」。**别含糊**，这是筛人项 |
| 出差接受度？ | ⚠️ 保融问得极频，**明确说能接受**（可补「了解金融 IT 交付需要驻场，我做好了准备」）。答「不太想出差」基本就凉 |
| 期望薪资？ | 提前查行情给**区间**，说「也参考公司标准」。别说「看公司安排」 |
| 还投了哪些公司 / 有 offer 吗？ | 说同类公司但在保融和 X 之间更倾向保融。**别报一堆大厂 offer** |
| 为什么选保融 / 对我们了解多少？ | **见 3.7**，必须能答出「财资科技/司库」这类具体信息 |
| 考研/考公/保研吗？ | 明确「不考，全身心投入工作」 |

### 3.5 职业规划 / 素质类

- **未来 3 年规划**：1 年熟悉业务和代码 → 2-3 年独立负责模块 → 业务+技术双通。别答「3 年当架构师」
- **对这份职业的看法**：能接受从基础做起、接受驻场交付的节奏
- **抗压/加班**：表态能接受阶段性加班/项目期冲刺

### 3.6 优缺点（⚠️ 有明确红线）

#### 优点（自主学习 + 技术兴趣）

**结构**：结论句 → 具体例证 → 落到工作价值。别只说「我爱学习」，必须有事。

**示范稿**：

> 「我的优点是比较能自主驱动，对技术是真有兴趣。举个例子：我自己做了一个个人全栈项目，后端用 Spring Boot 拆了几个微服务、前端 Vue、移动端 Android，还自己写了部署脚本、用 Nginx 和 systemd 把服务跑在服务器上。这个过程没人教，是我遇到问题就自己查文档、读源码、一点点搭起来的。
>
> 我觉得这个习惯对工作有用——**遇到没接触过的技术，我不会先等别人带，会自己先啃出个可用版本**，这样上手新模块会快。」

**要点**：
- 「自己搭服务器 / 写部署脚本」特别值钱，证明你**能独立完整交付**
- 收尾必须落到**工作价值**（上手快、不用人带）

#### ESP32-S3 远程控制空调项目：作为**第二个**例子，控制份量

**价值**：硬件+固件+通信+客户端的完整闭环，是「对技术感兴趣」最硬的证据。

**风险**：跑题 + 面试官怀疑你的职业方向（「这人想做嵌入式？」）——保融最怕招进来又走。

**策略**：
- 看服务端是不是 Java 写的：**是 → 「Java 后端 + IoT 终端」完整链路，很值得讲**；只是板子直连云平台/MQTT → 一句带过，别展开硬件细节
- **必须加一句方向锚定**（抵消风险）

**示范稿**（接在 Java 项目后）：

> 「另外我业余也玩点硬件。我用 ESP32-S3 自己做了一个远程控制空调的小项目——板子连 WiFi，通过红外和 WiFi 下发指令控制空调，服务端我用了 XX（Java 服务 / MQTT）……
>
> 不过**我的职业方向很明确是做 Java 后端**，玩硬件主要是想弄清「一个东西从硬件到云到客户端怎么串起来」，这个全链路视角对我做后端是有帮助的。」

**准备好被追问的两个点**（一句话答上就行，别深聊）：
- 用什么协议控制空调？→ 红外（IR）+ 空调码库
- 怎么远程？→ ESP32 联网后收服务端/MQTT 下发的指令

#### 缺点（终版话术，直接背）

**方向定位**：不说「DP 慢」（面试官会联想「算法基础不行」，且保融笔试就考算法 = 红牌），改成 **「深度思考型」——好处是难的能啃下来，代价是限时出活偏慢**。这是**认知风格**，不是技能缺陷。

**四条措辞要求**：
1. 避开「慢」字，用「想得深/想透」替代
2. 不提具体公司名（说「某次线上笔试」）
3. 重点说「**我最终做出来了**」，弱化「没收尾」
4. 改进方法要说「**提升限时产出效率**」，不要说「补算法短板」

**示范稿**：

> 「我的不足是：**我习惯把问题想透再动手**。好处是遇到比较复杂的、需要绕几个弯的问题我能啃下来，但代价是——**在限时场景里，我出第一个能用的版本会偏慢**。
>
> 举个例子，某次线上笔试有一道变形的 DP。我很确定必须用 DP，但推状态转移花了将近一个小时——**最后思路和代码我都写出来了**，只是时间基本用完了。
>
> 我复盘下来，问题不在于想不出来，而在于**我在限时场景下缺少「先出一版再迭代」的机制**。现在改法有三条：一是按题型整理**状态定义模板**，变形题先做映射再调，不从零找；二是**先用记忆化搜索写出能过的版本**，再优化转移；三是给自己**时间盒**，超时就先交出可运行的方案。这么练之后，限时下的完成率好了不少，还在继续练。」

**两句必带**：
1. 「**问题不在于想不出来，而在于限时场景下缺机制**」——把缺点钉在「流程」而非「能力」上
2. 「这么练之后完成率好了不少」——表示在改，不是只承认问题

**如果被追问**：
- 「工作里交付也会慢吗？」→ 「工作跟笔试不一样，我会**先出可用版本再迭代**，而且『想透』在设计阶段是优势——笔试的问题是没有『先交一版再改』的机制，我现在练的就是切换这个模式的能力」
- 「那题最后过了吗？」→ 「思路和实现都写出来了，收尾的边界处理多花了时间，超时了」（诚实，但把问题界定在**时间**，不碰能力）
- 「还有别的缺点吗？」→ 备用：「**公开表达/汇报偏弱**，技术能讲清但同步进度容易漏背景，现在会先写一句话结论再展开」。**绝对不说**「我没什么缺点」

**风险提醒**：这是防守型打法，**能站住但不算加分** → 讲完 40 秒就停，让他问。⚠️ **不要把「思考久」和「刷题少」挂钩**，那是自证短板。

### 3.7 为什么选保融 / 对我们了解多少（可背）

**示范稿**：

> 「我了解到保融是做**财资科技**的，专注企业**资金管理和司库管理**这个方向，总部在杭州余杭。具体有三点我印象比较深：
>
> 第一，**赛道**上，企业司库正好踩在『数字中国』和企业数字化转型的交汇点上——资金是企业的核心资源，这块需求是刚性的，而且客户主要是大型集团、保险和金融机构，付费能力强。
>
> 第二，**产品**上，你们有面向保险行业的 ATS 资金管理系统，还有微服务、RPA、财资大脑这些技术积累，说明不是纯外包，而是有自己的产品和平台。
>
> 第三，**匹配度**上，我是 Java 后端方向，做的是 Spring 生态这一套，跟你们微服务的技术栈对口；同时我对金融业务有学习意愿——财资这块业务复杂、门槛高，一旦做进去，业务积累本身就有壁垒。
>
> 所以选保融，一是**技术方向对口**，二是**想在金融+资金这条有壁垒的赛道长期沉淀**，三是杭州也是我想留下的城市。」

**追问接法**：
- 「你看好财资科技前景吗？」→ 企业资金数字化是刚需，政策在推「司库体系建设」，大企业从「记账」走向「资金增值」，是上行赛道
- 「你没做过金融业务怎么办？」→ 技术栈通用（Java/Spring/MySQL/Redis），业务可以学；入职后先啃业务流程和产品文档，跟着 mentor 从模块做起（提一句**愿意看业务文档/懂点财务知识**是加分项）
- 「为什么不去大厂？」→ 别说「大厂不要我」。答：我看重**技术+业务双积累**，财资领域业务壁垒更高、更稳定

**两个坑**：① 别把保融说成「银行外包 / 做保险的」，它做的是**企业资金管理软件**；② 别说「投了别的没上所以来你这」。

### 3.8 「遇到什么困难，怎么排查解决的」（最容易加分的一题）

**判断标准**：能不能说出**现象与直觉相反在哪、怎么一步步定位、根因是什么机制、改了什么**。说不出来就别选这个例子。

#### 方案：Seata AT 的「脏读」——用云商城的真实下单链路讲

**为什么用这个**：
- 脏读是 AT 的**机制性局限**（Seata 官方明确「AT 默认全局隔离级别为读未提交」），不是你写错代码 → 逻辑自洽
- 场景**全部落在你项目的真实服务/表/接口上**，面试官追问「具体哪个服务」时答得上
- 修复项全是真技术动作，没有「补 where 条件」这类基础错误

**你项目里的真实事实（话术必须与之一致，别记错）**：

| 事实 | 值 |
|------|-----|
| TM（全局事务发起方） | `mall-order-service` 的 `OrderServiceImpl.add(Order)`，标 `@GlobalTransactional` |
| 事务内 5 步 | `cartFeign.list`（查购物车）→ `skuFeign.decount`（扣库存）→ 插 `order_sku` → 插 `order` → `cartFeign.delete`（清购物车） |
| 分支 RM / 被改的数据 | `mall-goods-service` 的 `shop_goods.sku`，扣减 SQL：`UPDATE sku SET num = num - #{num} WHERE id = #{id} AND num >= #{num}` |
| 读通道（脏读的受害者） | `mall-goods-service` 的 `GET /sku/{id}`（`SkuController.one()` → `getById`，直查 DB，不走缓存） |
| 会触发回滚的路径 | `SkuServiceImpl.decount` 里影响行数 `<= 0` 抛「库存不足！」→ 全局事务回滚（**回滚是常见路径，不是异常**） |
| 事务组 / 版本 | `tx-service-group: tx_shop`、Seata Server 2.0.0、`data-source-proxy-mode: AT` |

**示范稿（可直接背）**：

> 「我在云商城项目的下单链路上用了 Seata 的 AT 模式，选它的理由是**无侵入**——业务代码不用改，框架自动补偿。全局事务标在 `mall-order-service` 的 `add` 方法上，一次下单跨三个服务五步：查购物车、扣库存、写订单明细、写订单、清购物车，其中扣库存落在 `mall-goods-service` 的 `shop_goods.sku` 表上。
>
> 在测试阶段验证「库存不足要回滚」这个用例时，我发现一个隔离性问题：**我用 `GET /sku/{id}` 查库存，在全局事务还没结束的时候，能读到已经被扣减的库存数；等全局事务回滚之后，再查又变回原值。** 也就是说，这个中间态对外是可见的。
>
> **排查过程**：一开始我第一反应是缓存问题——因为 goods 服务上有 `@Cacheable`，前面还有 OpenResty + Nginx 的缓存层，怀疑是缓存里存了脏值。所以我先清了 Redis 缓存、绕过缓存直接查 DB，结果**数据库里查到的也是这个中间值**，缓存被排除了。
>
> 接着我把 order 服务的方法日志、goods 服务的扣减日志、还有这个读请求的访问时间按时间线对齐，看清楚了两件事：**读发生在 `decount` 的本地事务提交之后、全局事务提交（或回滚）之前；而且这个读请求本身根本没有 `@GlobalTransactional`。** 这说明不是我的事务边界写错了。
>
> **根因**：AT 模式一阶段是把业务 SQL（扣库存那条 `UPDATE`）**和 `undo_log` 在同一个本地事务里直接提交**，同时注册分支、申请全局锁。所以从全局事务的视角看，这行数据还是『未提交』的（随时可能被回滚），但对数据库会话来说**已经可见了** —— **AT 的全局隔离级别实际是读未提交**。它的全局锁只防『脏写』（另一个全局事务要改这行会被拦住），**不防『脏读』**（普通 SELECT 直接能读到）。这不是我的代码问题，是这个模式的机制决定的。
>
> **修复我分了三层**：第一，我确认了关键路径**不依赖『读到的库存值』做决策**——下单前的库存判断本来就是靠语句级 CAS（`WHERE id = ? AND num >= ?`）兜的，影响行数为 0 就直接抛「库存不足」，所以交易本身不受脏读影响，这比『先查再扣』稳；第二，**展示层不读实时值**：商品详情这类展示走缓存（`ad_items_skus`，由数据变更事件驱动重建），缓存里存的是最终值，天然规避中间态——真正需要读一致性的查询才值得加 `@GlobalLock` 配合 `SELECT ... FOR UPDATE`，代价是全局锁校验会带来额外开销和锁竞争；第三，我也确认了**秒杀链路本来就没用 Seata**——那条路走的是 Redis 扣减 + MQ 异步落单，用最终一致换吞吐，这正好说明强一致/高并发场景不该硬套 AT。
>
> **复盘结论**：AT 的价值是『**零侵入换最终一致**』，它适合链路长、冲突少、能接受补偿的下单类场景；**把它当强一致方案用是错的**——需要读一致性就显式加 `@GlobalLock`，或者换 TCC。这是我现在做分布式事务选型时最重要的一条判断。」

**这个答案为什么推不翻**：
1. **全部落在真实服务/表/接口上**——`mall-order-service` / `mall-goods-service` / `shop_goods.sku` / `GET /sku/{id}`，追问「哪个服务」答得上
2. **现象与直觉相反**——第一反应是**缓存**（你项目真有三级缓存），排除缓存后才定位到事务隔离级别，这就是排查含金量
3. **无基础错误**——修复项（`@GlobalLock`、展示/校验分离、秒杀不用 AT）全是真技术动作
4. **不需要压测**——「测试阶段验证『库存不足回滚』用例」本地就能做，诚实
5. **结论自带架构判断**——「秒杀链路不用 Seata」是你项目本来就有的设计，讲出来是加分句

**⚠️ 讲之前的前置条件（必做，否则这个故事在你项目里跑不通）**：

你的 `sql/` 里**缺业务库侧的 `undo_log`**（只有 Seata Server 端 4 张表 `global_table`/`branch_table`/`lock_table`/`distributed_lock`）——**现在回滚根本执行不了**，二阶段会直接报错。所以：

1. 在 `shop_goods`、`shop_order` 各建一张官方 `undo_log`（`branch_id` / `xid` / `context` / `rollback_info` / `log_status`）
2. **真的跑通一次失败回滚**（把库存调成不足 → 触发「库存不足！」→ 观察库存被补偿回原值）
3. 补建本身就是加分细节：「**undo_log 必须建在业务库、不是 Seata 库，因为回滚要和业务 SQL 写在同一个本地事务里**」——这是区分「用过」和「配过」的分水岭

**必须能一口气答上的追问**：

| 追问 | 要点 |
|------|------|
| 你项目里谁是 TM、谁扣的库存？ | TM = `mall-order-service` 的 `add`（`@GlobalTransactional`）；扣库存 = `mall-goods-service`（改 `shop_goods.sku`）；清购物车 = `mall-cart-service`（MongoDB） |
| 回滚是怎么触发的？ | `dcount` 里语句级 CAS 影响行数 `<= 0` 抛「库存不足！」→ 全局事务回滚 |
| AT 两个阶段分别做什么？ | 一阶段：拦截业务 SQL → **本地事务提交** + 写 `undo_log`（前/后镜像）+ 注册分支 + 拿全局锁；二阶段：全局提交 → **异步删 undo_log**；全局回滚 → 用 `undo_log` 做**反向补偿** |
| 为什么 AT 是读未提交？ | 一阶段本地事务已经提交了 → 其他会话天然能读到；全局锁是一阶段之后才持有，**只拦写不拦读** |
| `@GlobalLock` 是什么？怎么用？ | Seata 提供的**轻量级全局锁校验**注解：执行 SQL 前先查 `lock_table`，行被别的全局事务持锁则重试/报错。官方用法是配合 `SELECT ... FOR UPDATE`，用来把关键读提升到读已提交 |
| 那脏写怎么防的？ | 写操作会先检查全局锁——另一个全局事务想改同一行必须先拿到锁，拿不到就冲突重试，所以脏写被挡住了 |
| undo_log 建在哪个库？ | **业务库**（`shop_goods` / `shop_order`）。建在 Seata 库就变成跨库操作，会出现「数据改了但 undo_log 没写进去」 |
| 这问题在你项目里造成实际影响了吗？ | ⚠️ **说实话**：「我在测试阶段就发现了，没造成线上影响」 |
| 为什么不直接全加 `@GlobalLock`？ | 全局锁校验有额外开销和锁竞争，**只加在关键读上**；展示类读走缓存规避 |
| 为什么不用 TCC？ | AT 无侵入但隔离性弱；TCC 要自己写 try/confirm/cancel，侵入业务但**一致性和隔离性可控**——强一致刚需选 TCC（⚠️ 加分句，必带） |

#### 讲这段的两条口径要求（必守）

1. 说「**测试阶段验证回滚用例时发现**」，**不要说「上线压测发现」**——没做过压测不能编
2. 必须说出「**不是我的代码问题，是这个模式的机制决定的**」——这句把「发现框架局限」和个人水平切割开

> 备选（如果不想讲 Seata）：用项目里真实发生过、**现象与直觉相反**的隐蔽故障（服务起不来 / 部署后报错 / 定时任务不触发 / 读正常写全挂）。通用结构：**现象 → 误导性线索 → 定位过程 → 根因 → 修复 → 验证 → 复盘**
