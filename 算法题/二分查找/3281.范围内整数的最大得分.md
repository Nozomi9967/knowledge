### 一、 核心关键词：为什么可以用“二分答案”？

题目要求我们：在 $n$ 个区间里各选一个数，使得这 $n$ 个数中**任意两个数之差的绝对值的最小值**最大。

简而言之，题目要我们：**“最大化最小值”**。

在算法题中，看到“最大化最小值”或者“最小化最大值”，通常第一反应就是**二分答案**。

**它的单调性逻辑是这样的：**

假设我们猜测一个得分目标 `score`（即两数之间的最小距离至少为 `score`）：

- 如果我们尝试在每个区间里挑一个数，发现**可以**做到让所有相邻两数的距离都 $\ge \text{score}$，说明这个 `score` 是可行的。那么我们可以尝试更大的目标。
    
- 如果我们发现无论怎么选，都**无法**让所有相邻数的距离都 $\ge \text{score}$，说明目标定高了，必须把目标 `score` 调小。
    

因为这个“可行性”随着 `score` 的增大，会从“一定可行”变成“一定不可行”，具有单调性，所以可以用二分查找来逼近那个“能达到的最大 `score`”。

### 二、 核心难点：怎么写检验函数 `check(score)`？（贪心策略）

二分查找确定了一个 `score` 之后，我们要写一个 `check(score)` 函数来判断这个 `score` 能不能实现。这里题解运用了**贪心算法**。

#### 步骤 1：为什么要对区间排序？

为了让数字之间更好比较，我们应该从左到右、从小到大去选数字。所以，首先要把所有的区间按照左端点 `start[i]` **从小到大进行排序**。

#### 步骤 2：贪心选数

既然我们要确保后面选的数字尽量与前面的数字拉开至少 `score` 的距离，同时又不能超出各自区间的右端点，我们该怎么选？

**贪心法则：为了给后面的数字留出尽可能多的生存空间（也就是让后面的区间更好选数），当前区间的数字选得越小越好！**

我们可以用一个变量 `x` 来记录**上一个区间选好的数字**。

对于第一个区间 `[start[0], start[0] + d]`，为了越小越好，我们毫无疑问直接选它的最左端点：

$$x = start[0]$$

接下来看第二个区间 `[start[1], start[1] + d]`：

由于我们要求任何两个数距离至少为 `score`，那么第二个区间选的数**必须 $\ge x + score$**。

同时，第二区间选的数绝对不能超过它的右边界 `start[1] + d`。

所以会有以下两种情况：

1. **绝对选不出来（返回失败）：**
    
    如果要求的最小位置 $x + score$ 已经**超过**了当前区间的右边界（即 $x + score > start[1] + d$），说明哪怕你取当前区间最大的数，距离上一个数也到不了 `score`。这个 `score` 目标太高了，直接返回 `false`。
    
2. **选得出来（继续贪心）：**
    
    如果 $x + score \le start[1] + d$，说明在这个区间里一定能选出一个合格的数。
    
    根据贪心法则，我们希望这个数**越小越好**。
    
    - 如果 $x + score$ 比当前区间的左边界 `start[1]` 还要小，说明在这个区间里哪怕选最小的 `start[1]`，它跟 `x` 的距离也已经大于等于 `score` 了。此时为了数字最小，我们选 `start[1]`。
        
    - 如果 $x + score$ 落在了当前区间内部，那我们就不得不选 $x + score$。
        
    
    总而言之，新选的数字就是：
    
    $$x = \max(x + score, start[1])$$
    

以此类推，对每一个区间都这么做。如果顺畅地把所有区间都选完了，说明这个 `score` 是可以实现的，返回 `true`。

### 三、 实例图解流程

用示例1来加深理解：`start = [6, 0, 3]`, `d = 2`。

区间长度都是 2。

1. **排序区间：**
    
    - 原数组排序后：`start = [0, 3, 6]`
        
    - 对应的 3 个区间分别是：`[0, 2]`, `[3, 5]`, `[6, 8]`
        

假设二分法当前猜测的 `score = 4`，我们用贪心法来验证 `check(4)`：

- **第 1 个区间 `[0, 2]`：**
    
    尽量选最小的，令第一个数 $x = 0$。
    
- **第 2 个区间 `[3, 5]`：**
    
    下一个数必须 $\ge x + score = 0 + 4 = 4$。
    
    检查区间右边界：$4 \le 5$，说明可以选。
    
    当前区间是 `[3, 5]`，而我们需要 $\ge 4$ 且越小越好，所以在这个区间里我们选 $x = \max(4, 3) = 4$。
    
- **第 3 个区间 `[6, 8]`：**
    
    下一个数必须 $\ge x + score = 4 + 4 = 8$。
    
    检查区间右边界：$8 \le 8$，说明可以选。
    
    当前区间是 `[6, 8]`，我们需要 $\ge 8$ 且越小越好，所以选 $x = \max(8, 6) = 8$。
    

所有区间都成功选出了数字（分别是 0, 4, 8），它们之间的间距都是 4。因此 `check(4)` 返回 `true`。通过二分继续探索，最终可以确定最大可能得分就是 4。

### 四、 代码对照理解 (以 C++ 为例)

结合上面的大白话，再看灵神的标准代码就会清晰很多：

C++

```
class Solution {
public:
    int maxPossibleScore(vector<int>& start, int d) {
        // 1. 排序
        sort(start.begin(), start.end());
        int n = start.size();

        // 2. 确定二分的左右边界
        // 最小间距可能是 0，最大间距不会超过最右端和最左端的差值加 d 
        // 也可以直接把右边界设为 2e9 (即 2000000000)
        long long left = 0;
        long long right = (start.back() + d - start[0]) / (n - 1) + 1;

        // 检验函数：检查间距为 score 时，能否在所有区间选出数
        auto check = [&](long long score) -> bool {
            long long x = start[0]; // 第一个数贪心选第一个区间的左端点
            for (int i = 1; i < n; i++) {
                // 如果要求的下一个数的最小值，超出了当前区间的右边界，说明无法满足
                if (x + score > start[i] + d) {
                    return false;
                }
                // 贪心：在满足 >= x + score 的前提下，选当前区间里尽可能小的数
                x = max(x + score, (long long)start[i]);
            }
            return true;
        };

        // 3. 标准红蓝二分查找（寻找满足 check 的最大值）
        while (left + 1 < right) {
            long long mid = left + (right - left) / 2;
            if (check(mid)) {
                left = mid;  // 满足条件，尝试更大的值
            } else {
                right = mid; // 不满足条件，缩小范围
            }
        }
        return left;
    }
};
```

### 总结

这道题核心就是**两步走**：

1. 用**二分法**去猜那个“最小距离（得分）”是多少。
    
2. 用**贪心法**去验证：从左到右，每个区间都贴着“上一个数 + 猜的距离”的下限来选数，看能不能顺利选到最后一个区间。
