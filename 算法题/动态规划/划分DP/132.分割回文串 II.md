### **这是 LeetCode 132「分割回文串 II」的动态规划解法**

核心思想是两段 DP：先用一个二维表 `isPalindrome[l][r]` 预处理出所有子串是否为回文，再用一维表 `f[r]` 表示前缀 `s[0..r]` 的最少分割次数，通过枚举"最后一段回文"的起点完成状态转移，时间复杂度 $O(n^2)$。

下面分模块解释。

---

### **一、问题本身**

给定字符串 `s`，要求把它切成若干段，每一段都是回文串，求**最少切几刀**。例如 `s = "aab"`，切成 `["aa","b"]` 只需 1 刀；`s = "a"` 本身就是回文，0 刀。

关键观察：如果 `s[0..r]` 本身就是回文，那么这一段不用切（0 刀）；否则我们考虑"最后一段回文" `s[l..r]`，在 `l-1` 与 `l` 之间切一刀，剩下的问题就变成 `s[0..l-1]` 的最少分割数。这正是后面的状态转移依据。

---

### **二、第一部分：回文预处理 `isPalindrome`**

```java
boolean[][] isPalindrome = new boolean[n][n];
for (boolean[] row : isPalindrome) {
    Arrays.fill(row, true);   // 先全部填 true
}
for (int l = n - 2; l >= 0; l--) {
    for (int r = l + 1; r < n; r++) {
        isPalindrome[l][r] = s[l] == s[r] && isPalindrome[l + 1][r - 1];
    }
}
```

`isPalindrome[l][r]` 表示子串 `s[l..r]` 是否为回文。递推依据是回文的定义：

$$
\text{isPalindrome}[l][r] \iff s[l] = s[r] \;\wedge\; \text{isPalindrome}[l+1][r-1]
$$

也就是说，外层两字符相等，且夹在中间的子串也是回文，整个串才是回文。

#### **先把整张表填 `true` 的巧妙之处**

这是这段代码最聪明的小技巧，它一次解决了两个"退化边界"：

- **单字符** `isPalindrome[i][i]`：循环其实不会遍历到 `l == r`（内层 `r` 从 `l+1` 起），所以单字符保持初始值 `true`，正好正确。
- **两字符** `isPalindrome[l][l+1]`：递推式会访问 `isPalindrome[l+1][l]`，此时左下标 `l+1 > 右下标 l`，是一个"非法区间"。但因为初始化为 `true`，结果退化为只判断 `s[l] == s[r]`，恰好就是两字符回文的判据。

如果不预先填 `true`，就必须显式给单字符和两字符这两种长度单独写初始化，代码会更啰嗦。

#### **循环顺序为何这样写**

外层 `l` 从 `n-2` 递减到 `0`，内层 `r` 从 `l+1` 递增到 `n-1`。计算 `isPalindrome[l][r]` 时需要 `isPalindrome[l+1][r-1]`，对应更短的子串（长度 `r-l-1 &lt; r-l+1`）。由于 `l` 是从大到小遍历，`l+1` 那一行已经在上一轮外层算完；而 `r-1 &lt; r`，在同一行里也已先算完。所以依赖关系始终满足，不会读到未计算的值。

---

### **三、第二部分：最少分割 DP `f`**

```java
int[] f = new int[n];
for (int r = 0; r &lt; n; r++) {
    if (isPalindrome[0][r]) {   // 整段 s[0..r] 已是回文，无需切割
        continue;
    }
    int res = Integer.MAX_VALUE;
    for (int l = 1; l &lt;= r; l++) {  // 枚举最后一段回文 s[l..r] 的起点
        if (isPalindrome[l][r]) {
            res = Math.min(res, f[l - 1] + 1);
        }
    }
    f[r] = res;
}
return f[n - 1];
```

#### **状态定义**

`f[r]`：把前缀 `s[0..r]` 分割成全回文子串所需的**最少切割次数**。`f` 默认全 0，因此"整段就是回文"的情形直接跳过，`f[r] = 0`。

#### **状态转移**

当 `s[0..r]` 不是回文时，枚举最后一段回文 `s[l..r]` 的起点 `l`（要求 `l ≥ 1`，因为前面必须还留有内容可切）。这一段内部不用切（它是回文），但在 `l-1` 与 `l` 之间必须切一刀，把前缀 `s[0..l-1]` 和这段回文分开。于是：

$$
f[r] = \min_{\substack{1 \le l \le r \\ \text{isPalindrome}[l][r]}} \bigl(f[l-1] + 1\bigr)
$$

`+1` 就是这一刀；`f[l-1]` 是前半部分的最少切割数，已经在更小的 `r` 时算好了。取所有合法 `l` 中的最小值即得 `f[r]`。

#### **为什么 `l` 从 1 开始**

如果 `l = 0`，意味着"最后一段"就是整个 `s[0..r]`，那等于没切，这种情况已经在上面的 `if (isPalindrome[0][r])` 分支处理过了（值为 0）。所以枚举时 `l` 只需从 1 起，避免重复并把"必须切一刀"的语义表达清楚。

最终答案为 `f[n-1]`，即整个字符串 `s[0..n-1]` 的最少切割次数。

---

### **四、复杂度与可优化点**

- **时间复杂度**：预处理回文表双重循环 $O(n^2)$；主 DP 外层 `r` 走 `n` 次、内层 `l` 最多走 `n` 次，也是 $O(n^2)$。总计 $O(n^2)$。
- **空间复杂度**：`isPalindrome` 二维表占 $O(n^2)$，`f` 占 $O(n)$，合计 $O(n^2)$。

空间还可以进一步优化：由于回文判断只依赖"更短的子串"，可以用中心扩展法在主 DP 内联判断 `isPalindrome[l][r]`，从而把空间降到 $O(n)$；但作者这里选择"预处理 + 主 DP"两段分离的写法，可读性更好，也更容易迁移到 [[131.分割回文串]] 这类需要枚举所有方案的题目上。

---

### **五、一个具体例子走一遍**

以 `s = "aab"`（`n = 3`）为例：

预处理后 `isPalindrome` 表（只看 `l ≤ r` 的有效项）：

| l\r | 0('a') | 1('a') | 2('b') |
|---|---|---|---|
| 0 | T | T("aa") | F("aab") |
| 1 | — | T | F("ab") |
| 2 | — | — | T |

主 DP：

- `r=0`：`isPalindrome[0][0]=T`，跳过，`f[0]=0`。
- `r=1`：`isPalindrome[0][1]=T`，跳过，`f[1]=0`。
- `r=2`：`isPalindrome[0][2]=F`，枚举 `l`：
  - `l=1`：`isPalindrome[1][2]=F`，跳过；
  - `l=2`：`isPalindrome[2][2]=T`，`res = f[1]+1 = 0+1 = 1`。
  - 故 `f[2]=1`。

返回 `f[2] = 1`，即 `"aab"` 最少切 1 刀（`"aa" | "b"`），符合预期。

---

总体来说，这段代码的精髓在于：用"预处理回文表 + 一维 DP 枚举最后一段回文"的两段式结构，把一个看似需要回溯的问题压缩成了 $O(n^2)$ 的纯动态规划；而开头那句 `Arrays.fill(row, true)` 则用一个巧妙的初值同时处理了单字符和两字符两种边界，让递推式可以无特判地统一成立。
