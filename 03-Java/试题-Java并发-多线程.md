1. 介绍一下 Java 的内存模型（JMM），它主要解决了哪三个问题？分别举例说明。

JMM是专门解决多线程并发问题的一套规则

他主要解决三个问题
- 可见性：由于每个线程都有自己的缓存，所以多线程并发修改访问数据时会出现脏读现象，在java中，通过volatile解决这个问题，被volatile修饰的变量在被修改后，最新数据被立刻被刷到主存中，而读操作会从主存拿取最新的数据
- 原子性：原子性最经典的一个例子就是自增操作，它会经历查询值->增加值->写回值，这三个步骤，在多线程并发的情况下，很有可能出现线程A查到值=1，++后，还没写回时，线程B又来查值，查到了=1，最终导致值仅仅+了1，而不是2，在java中，可以通过监视器锁机制来保证多个操作的原子性
- 有序性：由于jvm会对指令进行重排序，这会导致在多线程并发的场景下出现未被初始化的实例被提前使用的现象，在java中，可以对成员变量加volatile修饰来禁止指令重排序

3. 为什么 i++ 不是原子操作？请说明它的执行步骤，以及如何保证其原子性。

原子性：原子性最经典的一个例子就是自增操作，它会经历查询值->增加值->写回值，这三个步骤，在多线程并发的情况下，很有可能出现线程A查到值=1，++后，还没写回时，线程B又来查值，查到了=1，最终导致值仅仅+了1，而不是2，在java中，可以通过监视器锁机制来保证多个操作的原子性

具体执行步骤是，在执行这三个操作前，当前线程先获取当前对象的监视器锁，也就是将这三个操作写在synchronized代码块中，这样其它线程想要对当前对象值进行自增操作时，会被阻塞住，待当前线程自增完毕后，释放锁，其它线程会开始竞争锁，竞争到锁的线程继续操作

4. 什么是指令重排序？为什么会发生重排序？多线程场景下重排序可能带来什么问题？volatile/synchronized 是如何禁止重排序的？

指令重排序指的是，一条java指令会被分为若干个字节码指令，而jvm为了优化效率往往会对指令进行重排序

导致在多线程并发的场景下出现未被初始化的实例被提前使用的现象

可以对成员变量加volatile修饰来禁止指令重排序
