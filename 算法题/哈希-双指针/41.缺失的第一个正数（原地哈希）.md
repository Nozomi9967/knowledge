# 41. 缺失的第一个正数（原地哈希）

## 题目描述

给你一个未排序的整数数组 `nums`，请你找出其中没有出现的**最小正整数**。

- **时间复杂度**：$O(n)$
- **空间复杂度**：$O(1)$（只能使用常数级别的额外空间）

---

## 核心思路

### ① 抽屉原理（确定答案范围）

假设数组长度为 $N$：

- 最理想的情况是数组包含了 $1, 2, 3, \dots, N$，此时缺失的第一个正数是 **$N + 1$**
- 如果数组中缺失了 $1 \sim N$ 中的某一个数，那么答案必定在 **$[1, N]$** 之间
- **结论：答案必然落在区间 $[1, N + 1]$ 之间**
- 所有 $\le 0$ 或 $> N$ 的数都是"无效干扰项"

### ② 原地哈希（In-place Hashing）

由于要求 $O(1)$ 额外空间，不能新建哈希表，但可以**把原数组当成哈希表来用**。

**目标**：把数字 $x$ 放到它应该在的下标位置上。

| 数值 | 应该在的下标 |
|------|-------------|
| 1 | 0 |
| 2 | 1 |
| ... | ... |
| x | `x - 1` |

---

## 算法步骤

1. **第一遍遍历（归位）**：遍历数组，对于当前元素 $x = \text{nums}[i]$：
   - 若 $x$ 在合法范围 $[1, N]$ 内，且 `nums[x - 1] != x`（还没在正确位置），就交换 $x$ 与 `nums[x - 1]`
   - 交换后换过来的新数可能依然不在正确位置，所以用 `while` 循环继续交换，直到：
     - 当前数字不在 $[1, N]$ 范围内；或
     - 当前数字已经回到正确位置；或
     - 目标位置上已和它相等（**避免重复元素死循环**）

2. **第二遍遍历（找缺失）**：检查下标 $i$ 上是否等于 `i + 1`：
   - 若 `nums[i] != i + 1`，说明缺少的就是 **$i + 1$**，直接返回
   - 若全部匹配（$1 \sim N$ 全在），返回 **$N + 1$**

---

## 实例图解

以 `nums = [3, 4, -1, 1]` 为例，$N = 4$：

1. **$i = 0$**：`nums[0] = 3`，应在下标 2。交换 `nums[0]` 与 `nums[2]` → `[-1, 4, 3, 1]`。此时 `nums[0] = -1` 不在 $[1,4]$，停止。
2. **$i = 1$**：`nums[1] = 4`，应在下标 3。交换 `nums[1]` 与 `nums[3]` → `[-1, 1, 3, 4]`。此时 `nums[1] = 1`，应在下标 0。交换 `nums[1]` 与 `nums[0]` → `[1, -1, 3, 4]`。`nums[1] = -1` 不在 $[1,4]$，停止。
3. **$i = 2$**：`nums[2] = 3` 已在正确位置。
4. **$i = 3$**：`nums[3] = 4` 已在正确位置。

**检查**：`nums[0] == 1` ✓；`nums[1] == -1 ≠ 2` → **返回 2**。

## Java 代码

```java
class Solution {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;
        // 第一遍：归位
        for (int i = 0; i < n; i++) {
            // nums[i] 处于 [1, n] 且未在正确位置时交换
            while (nums[i] >= 1 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
                int idx = nums[i] - 1;
                int tmp = nums[i];
                nums[i] = nums[idx];
                nums[idx] = tmp;
            }
        }
        // 第二遍：找第一个不匹配的位置
        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }
        return n + 1;
    }
}
```

---

## 复杂度分析

- **时间复杂度**：$O(n)$。虽然 `while` 嵌套在 `for` 里，但**每次有效的 swap 都会把至少一个数放到最终正确位置**，数组共 $N$ 个位置最多发生 $N$ 次交换，平摊 $O(n)$。
- **空间复杂度**：$O(1)$，原地修改，仅常数个额外变量。

---

## 可迁移心法

**"找缺失/找重复 + 限制 O(1) 空间"的题**，第一反应就是原地哈希——把数组本身当哈希表，用 `nums[x - 1]` 作为"值 x 是否出现"的位标记。

| 变体 | 套路 |
|------|------|
| 缺失的第一个正数（本题） | 归位后找第一个 `nums[i] != i+1` |
| 数组中重复的数字（剑指 03） | 交换归位，遇到 `nums[nums[i]] == nums[i]` 即重复 |
| 找缺失 / 找重复（LeetCode 448 / 645） | 下标映射 + 正负标记 |

**坑位提醒**：原地交换的 `while` 必须加 `nums[nums[i] - 1] != nums[i]` 去重判定，否则有重复元素时会死循环。
