# 塔的视野（单调栈-NGE）

> [!abstract] 塔的视野 — Tower Visibility（塔的视野）
> 有 $n$ 座塔，第 $i$ 座塔向右看，视野会被**右侧第一座高度严格大于自己**的塔截断；若不存在则一直看到队尾。输出每座塔能看到的塔的数量。

## 题目

- **输入**：$n$ 个整数 $h_1, h_2, \ldots, h_n$（$1 \le h_i \le 1000$）。
- **输出**：$n$ 个整数，第 $i$ 个整数表示第 $i$ 座塔向右能够看到的塔的数量。

### 示例

**输入**：

```text
6
4 4 2 6 1 3
```

**输出**：

```text
3 2 1 2 1 0
```

**样例说明**：

- 塔 1（高 4）：右侧第一座严格更高的塔是 6（位置 4），看到范围是 `[4, 2, 6]`，共 **3** 座。
- 塔 2（高 4）：右侧第一座严格更高的塔是 6（位置 4），看到范围是 `[2, 6]`，共 **2** 座（等高的塔不产生截断）。
- 塔 3（高 2）：右侧第一座严格更高的塔是 6（位置 4），看到范围是 `[6]`，共 **1** 座。
- 塔 4（高 6）：右侧没有严格更高的塔，一直看到末尾，看到范围是 `[1, 3]`，共 **2** 座。
- 塔 5（高 1）：右侧第一座严格更高的塔是 3（位置 6），看到范围是 `[3]`，共 **1** 座。
- 塔 6（高 3）：右侧已经没有塔，共 **0** 座。

## 算法核心：单调栈（Monotonic Stack）

本题的本质是经典的 **NGE（Next Greater Element，下一个更大元素）** 问题。同族题：[[739. 每日温度 - 力扣（LeetCode）|739. 每日温度]]、[[496. 下一个更大元素 I - 力扣（LeetCode）|496. 下一个更大元素 I]]、[[503. 下一个更大元素 II - 力扣（LeetCode）|503. 下一个更大元素 II]]。

### 核心转化

对于每一个塔 $i$：

1. 找到它右侧**第一个高度严格大于** $h_i$ 的塔的位置 $j$（下标从 $0$ 开始）。
2. 若存在，则能看到的塔为 $i+1$ 到 $j$，数量为 $j - i$。
3. 若不存在，则能看到直到队尾的所有塔，数量为 $(n - 1) - i$。

### 为什么不用线段树

- **线段树**：虽然通过"区间最大值 + 线段树二分"可以达到 $O(n \log n)$ 且能通过，但代码量大、常数大、容易写错，属于"杀鸡用牛刀"。
- **单调栈**：$O(n)$ 时间 + $O(n)$ 空间，每个元素仅入栈和出栈一次，代码简练。

### 算法步骤

从**右往左**扫描数组，维护一个从栈底到栈顶高度**严格单调递减**的栈（栈中保存下标）：

1. 遇到塔 $i$：只要栈不为空且栈顶塔的高度 $\le h_i$，就弹出栈顶（这些等高或矮的塔会被 $h_i$ 挡住，不可能成为左侧塔的"第一个严格更高阻挡者"）。
2. 弹栈结束后：
   - 栈空 → 右侧没有严格更高的塔，视野数为 $n - 1 - i$。
   - 栈非空 → 栈顶下标就是右侧第一座严格更高的塔，视野数为 $stk\_top - i$。
3. 将当前塔 $i$ 的下标压入栈。

## Java 性能踩坑与优化（TLE 原因分析）

$n = 5 \times 10^5$ 量级时，原生 Java 极易因 **I/O 效率低**导致超时（TLE）：

| 优化前代码问题 | 优化方案 | 优化原理 |
| :--- | :--- | :--- |
| `Scanner in = new Scanner(System.in);` | `StreamTokenizer` / `BufferedReader` | `Scanner` 解析正则慢；字符流缓冲区读取速度快 10~50 倍。 |
| 循环中 `System.out.print()` | `StringBuilder` 一次性输出 | 避免频繁系统调用与同步方法，降低 I/O 阻塞时间。 |
| `LinkedList<int[]>` + 每次 `new int[]` | 手写 `int[] stk` 数组模拟栈 | 避免频繁对象内存分配（GC）与链表节点指针开销。 |

## 优化后的完美通关代码（Java）

```java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        // 1. 使用高效的 StreamTokenizer 替代 Scanner
        StreamTokenizer in = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
        in.nextToken();
        int n = (int) in.nval;

        int[] a = new int[n];
        for (int i = 0; i < n; i++) {
            in.nextToken();
            a[i] = (int) in.nval;
        }

        // 2. 手写轻量级数组栈模拟单调栈（只存储下标）
        int[] stk = new int[n];
        int top = -1;
        int[] b = new int[n];

        // 3. 从右至左单调栈核心逻辑
        for (int i = n - 1; i >= 0; i--) {
            // 条件是 <=：高度相同的塔不会提前截断视野，必须弹出
            while (top >= 0 && a[stk[top]] <= a[i]) {
                top--;
            }
            // 栈空代表右侧无更高阻挡，直接看到队尾；非空则栈顶为首个更高阻挡
            b[i] = (top < 0) ? (n - 1 - i) : (stk[top] - i);
            // 当前下标入栈
            stk[++top] = i;
        }

        // 4. 采用 StringBuilder 拼接，最后一次性输出
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < n; i++) {
            if (i > 0) {
                sb.append(' ');
            }
            sb.append(b[i]);
        }
        sb.append('\n');
        System.out.print(sb);
    }
}
```

## 复杂度对比

- **时间复杂度**：$O(n)$。每个下标最多入栈一次、出栈一次，内层 `while` 总执行次数 $O(n)$。
- **空间复杂度**：$O(n)$。输入数组 `a`、答案数组 `b`、手写栈 `stk` 三个数组。
