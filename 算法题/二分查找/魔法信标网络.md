### **魔法信标网络 — 二分答案 + 贪心验证**

核心思路是**二分答案 + 贪心验证**：先滑动窗口 $O(n)$ 算出每座塔的初始屏障强度，再二分答案 x，用贪心 check 验证"能否用 ≤ κ 个新信标让所有塔强度 ≥ x"。check 中遇到不足的塔，就把缺的信标放在能覆盖它的**最右位置**（贪心正确性：放在更左的位置覆盖范围被严格支配）。时间复杂度 $O(n \log(\max S + \kappa))$，空间 $O(n)$。

---

### **一、题目概述**

n 座哨兵塔沿边境线排列，`T[i]` 是塔 i 已激活的以太信标数量。位于塔 i 的每个信标能覆盖距离 ≤ ρ 的所有塔（即 $[i-\rho, i+\rho]$ 内每座塔各 +1 屏障能量）。

塔 j 的**屏障强度** $S_j$ = 能覆盖到它的所有信标总数。

允许额外部署 κ 个新信标，自由分配到任意塔（同一座塔可放多个）。求：**最低屏障强度能被最大化到多少**。

- $0 \le \rho < n$，$0 \le \kappa \le 10^9$，$1 \le n \le 10^5$，$0 \le T[i] \le 10^5$
- 时间限制 3 秒（C/C++）/ 6 秒（其他语言）

> **示例1**：`ρ=19, κ=100, n=20`，`T=[10,2,5,8,12,1,1,20,4,3,15,6,9,7,11,18,13,14,17,16]` → 输出 `292`

> 半径 19 覆盖全部 20 座塔，每座塔初始强度 $S_j = \sum T = 192$。每个新信标也给所有塔 +1，放 100 个后全部变 192+100=292。

### **二、核心思路拆解**

#### **第一步：滑动窗口算初始强度（$O(n)$）**

塔 j 的初始强度 = 窗口 $[j-\rho,\ j+\rho]$ 内所有 $T$ 之和：

$$S_j = \sum_{k=\max(0,\ j-\rho)}^{\min(n-1,\ j+\rho)} T_k$$

窗口随 j 右移一格，左端可能吐出一个、右端可能吞入一个，均摊 $O(1)$ 维护。

#### **第二步：二分答案（最大化最小值 → 单调性）**

目标"最大化最低强度"是典型的**最大化最小值**，直接枚举/贪心加法都不对（每个新信标影响一片区域，互相耦合），正确套路是二分答案：

- 答案范围 $[0,\ \max S_j + \kappa]$。上界成立：初始最强的那座塔最终强度 ≤ $\max S_j + \kappa$，而所有塔的最低值不会超过它。
- 对每个候选 x，验证"能否用 ≤ κ 个新信标让所有塔强度 ≥ x"。
- **单调性**：x 越大越难达成。如果 x 能达成，任何 x' < x 也能达成（要求更低）；如果 x 达不成，任何 x' > x 也达不成。所以 check 结果是一段 true + 一段 false，二分找交界。

```java
long lo = 0, hi = maxS + kappa;
while (lo < hi) {
    long mid = (lo + hi + 1) >>> 1;   // 向上取整，配 lo = mid 防死循环
    if (check(mid)) lo = mid;
    else hi = mid - 1;
}
System.out.println(lo);
```

### **三、贪心验证 check(x)（核心）**

#### **三个状态变量**

```java
long[] placed = new long[n];   // placed[i]: 在 i 处新增的信标数（账本）
long added = 0;                // 当前窗口 [j-ρ, j+ρ] 内已放置的新信标总数
long used = 0;                 // 全程累计使用
```

`added` 是滑动窗口的"和"：扫描到塔 j 时，窗口正好是 $[j-\rho,\ j+\rho]$，`added` 就是窗口内所有 placed 值之和，即"已经放的、能覆盖到 j 的新信标总数"。

#### **循环体三步**

**① 滑动窗口更新 added（j > 0 时）**

```java
int cl = Math.max(0, j - rho), cr = Math.min(n - 1, j + rho);
if (cl > pl) added -= placed[pl];   // 左端吐出：pl 离开窗口
if (cr > pr) added += placed[cr];   // 右端吞入：cr 进入窗口（注意是 placed[cr] 不是 placed[pr]）
pl = cl; pr = cr;
```

**② 算当前塔实际强度**

```java
long cur = S[j] + added;   // 初始强度 + 窗口内已放置的信标
```

若 `cur >= x`，跳过。

**③ 不够就贪心补信标**

```java
if (cur < x) {
    long need = x - cur;                            // 缺多少补多少
    int pos = Math.min(n - 1, j + rho);            // 放到能覆盖 j 的最右位置
    placed[pos] += need;
    added += need;                                  // 刚放的还在窗口内，added 立刻涨
    used += need;
    if (used > kappa) return false;                // 超限提前剪枝
}
```

### **四、为什么放到"最右位置"是最优的**

塔 j 能被位置 p 覆盖 ⟺ $|p - j| \le \rho$，即 $p \in [j-\rho,\ j+\rho]$。能覆盖 j 的最右位置是 $j + \rho$（不越界时）。

一个放在 p 处的信标，覆盖范围是 $[p-\rho,\ p+\rho]$：

| 放置位置 | 覆盖范围 | 效果 |
|----------|---------|------|
| 放在 $j$（最左） | $[j-\rho,\ j+\rho]$ | 覆盖范围往左漏到已处理的塔 |
| 放在 $j+\rho$（最右） | $[j,\ j+2\rho]$ | 全部往未来方向延伸 |

放到最右位置时，覆盖范围完全往未来延伸，**不浪费任何一个覆盖名额在已经处理过的塔上**（那些塔已保证达标）。放到更左的位置，覆盖范围会往左"漏"到已处理塔——纯浪费。

> [!abstract] 贪心正确性 — 最右放置严格支配
> 任何可行的放置方案，都可以等价转换为全用"最右放置"的方案，且信标数不增。因为把任一信标从位置 p 移到能覆盖同一塔的更右位置 q（q ≥ p），q 的覆盖范围 $[q-\rho, q+\rho]$ 在右侧延伸、左侧收缩，但左侧收缩掉的塔在扫描顺序上已经处理过（已达标），收缩不影响正确性，延伸反而帮助更多未来塔。因此贪心用的信标数最少。

### **五、完整代码**

```java
import java.io.*;

public class Main {
    static int n, rho;
    static long kappa;
    static long[] S;

    public static void main(String[] args) throws IOException {
        DataInputStream in = new DataInputStream(new BufferedInputStream(System.in));
        rho = nextInt(in);
        kappa = nextLong(in);
        n = nextInt(in);
        long[] T = new long[n];
        for (int i = 0; i < n; i++) T[i] = nextLong(in);

        // 滑动窗口求初始强度 S[j] = sum T[max(0,j-rho) .. min(n-1,j+rho)]
        S = new long[n];
        long win = 0;
        int r = Math.min(n - 1, rho);
        for (int k = 0; k <= r; k++) win += T[k];
        int pl = 0, pr = r;
        S[0] = win;
        for (int j = 1; j < n; j++) {
            int cl = Math.max(0, j - rho);
            int cr = Math.min(n - 1, j + rho);
            if (cl > pl) win -= T[pl];
            if (cr > pr) win += T[cr];
            pl = cl; pr = cr;
            S[j] = win;
        }

        long maxS = 0;
        for (int j = 0; j < n; j++) maxS = Math.max(maxS, S[j]);
        long lo = 0, hi = maxS + kappa;          // 答案上界
        while (lo < hi) {
            long mid = (lo + hi + 1) >>> 1;
            if (check(mid)) lo = mid; else hi = mid - 1;
        }
        System.out.println(lo);
    }

    // 验证：能否用 ≤ κ 个新信标，让每座塔强度都 ≥ x
    static boolean check(long x) {
        long[] placed = new long[n];   // placed[i]: 在 i 处新增的信标数
        long added = 0;                // 当前窗口内已放置的新信标总数
        long used = 0;                 // 累计使用
        int r = Math.min(n - 1, rho);
        long pl = 0, pr = r;
        for (int j = 0; j < n; j++) {
            if (j > 0) {
                long cl = Math.max(0, j - rho);
                long cr = Math.min(n - 1, j + rho);
                if (cl > pl) added -= placed[(int) pl];   // 左端点右移，吐出
                if (cr > pr) added += placed[(int) cr];   // 右端点右移，吞入
                pl = cl; pr = cr;
            }
            long cur = S[j] + added;
            if (cur < x) {
                long need = x - cur;
                int pos = (int) Math.min(n - 1, (long) j + rho); // 放到能覆盖 j 的最右位置
                placed[pos] += need;
                added += need;
                used += need;
                if (used > kappa) return false;
            }
        }
        return true;
    }

    // ---- 快读 ----
    private static final byte[] buf = new byte[1 << 16];
    private static int len = 0, idx = 0;
    private static int read(DataInputStream in) throws IOException {
        if (idx >= len) { len = in.read(buf); idx = 0; if (len < 0) return -1; }
        return buf[idx++];
    }
    static long nextLong(DataInputStream in) throws IOException {
        int c; long sign = 1, v = 0;
        do { c = read(in); } while (c != -1 && c <= ' ');
        if (c == '-') { sign = -1; c = read(in); }
        while (c > ' ') { v = v * 10 + c - '0'; c = read(in); }
        return v * sign;
    }
    static int nextInt(DataInputStream in) throws IOException { return (int) nextLong(in); }
}
```

### **六、两个用例的验证**

**用例：ρ=0, κ=3, T=[5,5,5,5]**

每座塔只覆盖自己，初始 $S=[5,5,5,5]$：
- `check(6)`：每座塔都要补 1 个，共需 4 个 > 3 → false
- `check(5)`：不用补 → true

答案 **5** ✓

**示例1：ρ=19, κ=100, n=20**

半径 19 已覆盖全部 20 座塔，每座塔初始强度 $S_j = \sum T = 192$（验证：10+2+5+8+12+1+1+20+4+3+15+6+9+7+11+18+13+14+17+16 = 192）。每个新信标也给所有塔 +1，放 100 个后每座塔都是 192+100=292。

答案 **292** ✓

### **七、复杂度分析**

- **时间复杂度**：初始强度 $O(n)$；二分约 $\log(\max S + \kappa) \approx 35 \sim 47$ 次，每次 check $O(n)$。总共约 $5 \times 10^6$ 量级，稳过。
- **空间复杂度**：$O(n)$。S 数组、placed 数组各 $O(n)$。

### **八、面试话术**

1. **为什么是二分答案而不是直接贪心放？** — 直接贪心"从最低的塔补起"不成立：放一个信标影响一片塔，当前选择会改变后续塔的强度，"每次补最低塔"的局部最优不保证全局最优。而二分把"最优化"翻转为"判定"，判定的贪心是正确的（最右放置严格支配）。
2. **答案上界为什么是 maxS + κ？** — 初始最强的塔最终强度 ≤ 初始强度 + 全部 κ 个信标都覆盖它 = $\max S_j + \kappa$，全塔最低值不可能超过它。
3. **check 里 `added` 为什么能 $O(1)$ 维护？** — 窗口每步只移动一格：左端至多吐出一个、右端至多吞入一个，各一次数组访问。这是"滑动窗口求和"模板。
4. **mid 为什么向上取整？** — `lo = mid` 的更新配上向下取整会导致死循环（mid 恒等于 lo）。`(lo + hi + 1) >>> 1` 保证 mid > lo，循环必然收敛。
5. **`used > kappa` 为什么提前 return？** — 后面只会继续增加 used，已超限就没必要扫完，提前剪枝省时间。
6. **与 [[410. 分割数组的最大值 TODO]] 的异同** — 同是"二分答案 + 贪心 check"：410 的 check 是贪心分段（限制越大段数越少），本题的 check 是贪心放信标（目标越高需要越多）。区别在 check 内部：410 是顺序装袋，本题是滑动窗口维护"已放置量对当前窗口的贡献"。
