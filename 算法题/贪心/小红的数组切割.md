### **小红的数组切割 — 贪心解法**

核心思路是**分解权值 + 贪心选刀**：把每个元素的权值拆成"固定部分"和"随块号变化部分"，发现每次切割的收益恰好等于切割点之后所有 `op` 之和，且各刀收益互相独立，所以只需排序取最大的几刀。时间复杂度 $O(n \log n)$，空间 $O(n)$。

---

### **一、问题本身**

给定长度为 $n$ 的数组 `a` 和长度为 $n$ 的字符串 `s`。最多可将数组切割成 `k` 块。

第 `i` 个元素的权值：

$$\text{weight}(i) = op(i) \times (a_i + j)$$

其中：
- `op(i) = 1` 当 `s[i] = '1'`，`op(i) = -1` 当 `s[i] = '0'`
- `j` 是 `a_i` 所在的块编号（从 1 开始）

求最大总权值。

> 例如 `n=4, k=2, a=[1,2,3,4], s="1001"` → `op=[1,-1,-1,1]`
> 切成 `[1,2,3]` 和 `[4]`，总权值 = 1

---

### **二、关键观察：权值分解**

把 `op(i) × (a_i + j)` 拆成两部分：

$$\underbrace{op(i) \times a_i}_{\text{固定，与切法无关}} + \underbrace{op(i) \times j}_{\text{随块号变化}}$$

**第一部分** `op(i) × a_i` 是固定的，无论怎么切割都不变。

**第二部分** `op(i) × j` 依赖于元素在第几块。所有元素都在第 1 块时（`j=1`），这部分的总值是 `Σ op(i)`。**每在位置 p 切一刀**，p 及之后所有元素的块号都 +1，净收益恰好是：

$$\text{suf}[p] = \sum_{i=p}^{n-1} op(i)$$

即切割点 p 到末尾的 op 后缀和。

**各刀的收益互相独立**——切两刀的收益就是各自 suf 的和，与切了几刀无关。所以只需贪心地挑收益最大的几刀。

---

### **三、算法步骤**

1. **算 base**：所有元素放第 1 块的总权值 = `Σ op(i) × (a_i + 1)`
2. **算后缀和 `suf[p]`**：从位置 p 到末尾的 op 之和
3. **筛出正收益的切割点**（位置 1 到 n-1，即 suf[p] > 0），降序排序，取前 `k-1` 个求和
4. **答案** = `base + 该和`

### **四、代码**

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());
        long k = Long.parseLong(st.nextToken());

        long[] a = new long[n];
        st = new StringTokenizer(br.readLine());
        for (int i = 0; i < n; i++) {
            a[i] = Long.parseLong(st.nextToken());
        }

        String s = br.readLine();
        int[] op = new int[n];
        for (int i = 0; i < n; i++) {
            op[i] = (s.charAt(i) == '1') ? 1 : -1;
        }

        // base：全部放第 1 块的总权值
        long base = 0;
        for (int i = 0; i < n; i++) {
            base += (long) op[i] * (a[i] + 1);
        }

        // 后缀和 suf[p] = op[p] + op[p+1] + ... + op[n-1]
        long[] suf = new long[n];
        suf[n - 1] = op[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            suf[i] = suf[i + 1] + op[i];
        }

        // 收集所有正收益的切割点（位置 1 到 n-1）
        List<Long> gains = new ArrayList<>();
        for (int i = 1; i < n; i++) {
            if (suf[i] > 0) gains.add(suf[i]);
        }

        // 降序排序，取前 k-1 个
        gains.sort(Collections.reverseOrder());
        long add = 0;
        int limit = (int) Math.min(k - 1, gains.size());
        for (int i = 0; i < limit; i++) {
            add += gains.get(i);
        }

        System.out.println(base + add);
    }
}
```

### **五、一个具体例子走一遍**

`n=4, k=2, a=[1,2,3,4], s="1001"` → `op=[1,-1,-1,1]`

**Step 1：算 base**

$$\text{base} = 1 \times 2 + (-1) \times 3 + (-1) \times 4 + 1 \times 5 = 2 - 3 - 4 + 5 = 0$$

**Step 2：算后缀和**

| 位置 p | suf[p] = op[p] + ... + op[3] | 计算 |
|--------|---------------------------|------|
| 3      | op[3] = 1                  | 1    |
| 2      | op[2] + op[3] = -1 + 1    | 0    |
| 1      | op[1] + op[2] + op[3]     | -1   |
| 0      | op[0] + ... + op[3]       | 0    |

**Step 3：筛正收益，取前 k-1=1 个**

切割点只能选位置 1, 2, 3（不能选位置 0，因为第一块至少要有元素）：
- `suf[1] = -1` → 负收益，跳过
- `suf[2] = 0` → 零收益，跳过
- `suf[3] = 1` → 正收益，收录

排序后取 1 个：`add = 1`

**Step 4：答案**

$$\text{ans} = \text{base} + \text{add} = 0 + 1 = 1$$

对应切割方案：在位置 3 切一刀 → `[1,2,3] | [4]`

### **六、为什么不该用 DP**

`d[n][k+2]` 在 `n=10⁵, k=44688` 时是 4.5×10⁹ 个 long ≈ 36GB，远超 512MB 限制。

DP 的问题在于：`d[i][j]` 的那一维 `j`（块数）完全没必要逐个转移。每次切割的收益是**独立且可加的**，直接用贪心排序取 top k-1 就行。DP 是把简单问题搞复杂了。

---

### **七、复杂度分析**

- **时间复杂度**：算 base + 算后缀和 $O(n)$，排序 $O(n \log n)$。总计 $O(n \log n)$。
- **空间复杂度**：`op` 数组 $O(n)$，`suf` 数组 $O(n)$，`gains` 列表 $O(n)$。总计 $O(n)$。

---

### **八、面试话术**

1. **为什么权值可以分解？** — `op(i) × (a_i + j) = op(i) × a_i + op(i) × j`，第一部分固定，第二部分只依赖于块号 j。每切一刀，p 之后所有元素的 j 都 +1，收益 = p 之后 op 之和。
2. **各刀为什么独立？** — 切 p 刀的收益是 suf[p]，切 q 刀的收益是 suf[q]，两者之和就是切两刀的总收益，与顺序无关。
3. **为什么只取前 k-1 个？** — 切成 k 块需要 k-1 刀，所以最多取 k-1 个正收益切割点。如果正收益切割点不足 k-1 个，就全取。
4. **为什么是贪心而不是 DP？** — 因为每刀的收益独立可加，选最大的几刀就是最优的。DP 需要维护块数维度，空间扛不住。
