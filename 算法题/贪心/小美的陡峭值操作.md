# 小美的陡峭值操作

## 一、题目描述

定义一个数组的**陡峭值**为：相邻两个元素之差的绝对值之和，即

$$
\sum_{i=2}^{n} |a_i - a_{i-1}|
$$

现在小美拿到了一个数组，她可以**最多进行 1 次操作**：选择一个区间 `[l, r]`，使得区间内所有元素加 1（也可以不操作）。她希望最终数组的陡峭值尽可能小。

**输入**：第一行正整数 `t`（1 ≤ t ≤ 1000），代表询问次数。每次询问两行：第一行正整数 `n`（2 ≤ n ≤ 10⁵），第二行 `n` 个正整数 `a_i`（1 ≤ a_i ≤ 10⁹）。保证所有询问的 `n` 总和不超过 10⁵。

**输出**：每个询问输出一行，表示陡峭值的最小值。

**样例**：

```
输入：                输出：
2
5
1 4 2 3 4           5    （选区间 [3,4] 加1 → {1,4,3,4,4}）
3
1 2 1               1    （选区间 [1,1] 加1 → {2,2,1}）
```

**时间限制**：C/C++ 1秒，其他语言2秒；**空间限制**：256M / 512M。

---

## 二、核心思路

把区间 `[l, r]` 整体加 1 时，**区间内部的相邻差值全部不变**（两边同时加 1，差不变）。只有**两个边界处**的差值可能变化：

- **左边界 l**：与 `a[l-1]` 的差。若 `a[l-1] > a[l]`（即 `a[l-1]` 是下降对的"高处"），该处差值**减 1**；若 `a[l-1] < a[l]` 则反而**加 1**。
- **右边界 r**：与 `a[r+1]` 的差。若 `a[r+1] > a[r]`，该处差值**减 1**；否则**加 1**。

由于 `l ≤ r` 必须成立，两个"能减 1 的位置"之间有顺序约束：

1. **能减 2** ⇔ 存在一个"下降对"出现在某个"上升对"**之前**（下降对提供左边界，后面的上升对提供右边界，两者可组成合法区间）。例如 `3 1 5`：对 `[2,2]` 加 1 后两处下降对都被消除。
2. **能减 1** ⇔ 只要存在**任意**严格上升对**或**任意**严格下降对**：
   - 有上升对（`a[i] < a[i+1]`）→ 取 `[1, i]`，右边界消除一个上升差；
   - 有下降对（`a[i] > a[i+1]`）→ 取 `[i+1, n]`，左边界消除一个下降差；
3. **全相等**（所有 `a[i] == a[i+1]`）→ 无法减，陡峭值本来就是 0（或保持不变）。

> 记忆点：**"区间整体加减 1 只影响两个边界"** 这类结论在很多题里通用（区间加 c 时边界变化放大 c 倍），遇到"区间操作只看端点效应"的题可以直接套这个分析框架。

## 三、两个易错点（本次踩的坑）

### 坑 1：减 1 的判断漏了"纯下降"的情况

最初的代码里 `one` 只在 **`f`（出现下降）之前**出现过上升时才置 true，导致纯递减数组漏判。**反例**：

```
3 2 1    陡峭值 = 2
```

对 `[3,3]` 加 1 → `3 2 2`，陡峭值 = 1。但原代码中 `f=true` 之后没再出现上升，`one`、`two` 均为 false，`inc=0`，错误输出 2。

**修复**：下降对本身（`f`）也足以减 1（取后缀区间 `[i+1, n]` 即可），所以判断条件应为 `one || f`；同时 `one` 的记录不再需要受 `!f` 限制。修正后的统计逻辑：

```java
if (pre > cur) {
    f = true;
    one = true;          // 存在下降对，单独也能减1
} else if (pre < cur) {
    if (f) two = true;   // 先降后升 → 能减2
    else   one = true;   // 存在上升对
}
```

最终取值：

```java
int inc = 0;
if (two)      inc = 2;
else if (one) inc = 1;    // one 现在包含"有上升对"或"有下降对"两种情况
System.out.println(sum - inc);
```

### 坑 2：sum 必须用 long

`n` 最大 10⁵，`a_i` 最大 10⁹，相邻差最大接近 10⁹，总和最大约 `10⁵ × 10⁹ = 10¹⁴`，**远超 int 上限（约 2.1 × 10⁹）**，会溢出。所以：

```java
long sum = 0;               // 累加器用 long
sum += Math.abs(cur - pre); // int 相减本身不会溢出（差 < 10⁹）
```

注意：`Math.abs(cur - pre)` 是 int 运算，结果在 int 范围内没问题；溢出风险只在**累加**这一步，累加器必须声明为 `long`。

## 四、AC 代码（Java）

```java
import java.util.Scanner;

// 注意类名必须为 Main, 不要有任何 package xxx 信息
public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int t = in.nextInt();
        while (t-- > 0) {
            int n = in.nextInt();
            int pre = -1, cur = 0;
            long sum = 0;                 // 坑2：用 long 防溢出
            boolean f = false;            // 是否出现过下降对 (a[i] > a[i+1])
            boolean two = false, one = false;
            while (n-- > 0) {
                cur = in.nextInt();
                if (pre == -1) {          // 第一个元素
                    pre = cur;
                    continue;
                }
                sum += Math.abs(cur - pre);
                if (pre > cur) {
                    f = true;
                    one = true;           // 坑1：有下降对就能减1
                } else if (pre < cur) {
                    if (f) two = true;    // 先降后升 → 减2
                    else   one = true;
                }
                pre = cur;
            }
            int inc = 0;
            if (two)      inc = 2;
            else if (one) inc = 1;
            System.out.println(sum - inc);
        }
    }
}
```

## 五、复杂度与验证

- **时间复杂度**：每个询问 O(n)，总 O(Σn) = O(10⁵)，远在限制内。
- **空间复杂度**：O(1)，不存数组，边读边算。

### 样例验证

| 输入 | 原陡峭值 | 判断 | 结果 |
|---|---|---|---|
| `1 4 2 3 4` | 3+2+1+1=7 | `4→2` 降，`2→3` 升 → two=true | 7−2=**5** ✓ |
| `1 2 1` | 1+1=2 | `2→1` 降，之后无升 → one=true | 2−1=**1** ✓ |
| `3 2 1` | 1+1=2 | 纯下降 → one=true（修复后） | 2−1=**1** ✓ |
