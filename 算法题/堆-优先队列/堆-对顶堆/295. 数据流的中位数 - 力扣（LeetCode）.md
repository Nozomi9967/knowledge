**中位数** 是有序整数列表中的中间值。如果列表的大小是偶数，则没有中间值，中位数是两个中间值的平均值。

- 例如 `arr = [2,3,4]` 的中位数是 `3` 。
- 例如 `arr = [2,3]` 的中位数是 `(2 + 3) / 2 = 2.5` 。

实现 MedianFinder 类:

- `MedianFinder()` 初始化 `MedianFinder` 对象。
- `void addNum(int num)` 将数据流中的整数 `num` 添加到数据结构中。
- `double findMedian()` 返回到目前为止所有元素的中位数。与实际答案相差 `10^-5` 以内的答案将被接受。

**示例 1：**

```
输入
["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
[[], [1], [2], [], [3], []]
输出
[null, null, null, 1.5, null, 2.0]

解释
MedianFinder medianFinder = new MedianFinder();
medianFinder.addNum(1);    // arr = [1]
medianFinder.addNum(2);    // arr = [1, 2]
medianFinder.findMedian(); // 返回 1.5 ((1 + 2) / 2)
medianFinder.addNum(3);    // arr[1, 2, 3]
medianFinder.findMedian(); // return 2.0
```

**提示:**

- `-10^5 <= num <= 10^5`
- 在调用 `findMedian` 之前，数据结构中至少有一个元素
- 最多 `5 * 10^4` 次调用 `addNum` 和 `findMedian`

## 大小堆讲解
https://leetcode.cn/problems/find-median-from-data-stream/solutions/3015873/ru-he-zi-ran-yin-ru-da-xiao-dui-jian-ji-4v22k/


这段代码是求解 **"数据流中的中位数"**（LeetCode 295）的经典且非常优雅的解法。核心思路是：**使用两个"对顶堆"（一个大顶堆 + 一个小顶堆），将所有数据动态地平分成"较小的一半"和"较大的一半"。**

---

### 1. 核心设计（双堆模型）

* **`left`（大顶堆 / Max-Heap）：**
  * 存储数据流中**较小的那一半**元素。
  * 堆顶是较小部分里的**最大值**（离中位数最近）。
* **`right`（小顶堆 / Min-Heap）：**
  * 存储数据流中**较大的那一半**元素。
  * 堆顶是较大部分里的**最小值**（离中位数最近）。

**维持的平衡规则：**

1. **大小关系：** `left` 中的所有元素 $\le$ `right` 中的所有元素。
2. **数量关系：**
   * 总元素为**偶数**时：`left.size() == right.size()`
   * 总元素为**奇数**时：`left.size() == right.size() + 1`（约定多出的一个放在 `left`）

---

### 2. 方法解析

#### (1) `addNum(int num)` —— 动态平衡维护（最精妙的部分）

代码并没有写复杂的 `if (num < left.peek())` 等条件判断，而是利用堆自身的排序特性完成元素的分配：

* **情况一：当前两堆元素数量相等 `left.size() == right.size()`**
  * **目标：** 新增一个元素后，总数变为奇数，需要让 `left` 的数量比 `right` 多 1。
  * **做法：**
    1. 先把 `num` 放进 `right`（小顶堆会自动排序）。
    2. 取出 `right` 的堆顶（即整个数据流中偏小部分的那个临界值），放进 `left`。
  * **结果：** 既保证了 `left` 多一个元素，又保证了 `left` 的所有元素仍然 $\le$ `right` 的所有元素。
* **情况二：`left` 比 `right` 多 1 个元素**
  * **目标：** 新增一个元素后，总数变为偶数，需要让 `right` 增加 1 个元素使两者相等。
  * **做法：**
    1. 先把 `num` 放进 `left`（大顶堆会自动排序）。
    2. 取出 `left` 的堆顶（即整个数据流中偏大部分的那个临界值），放进 `right`。
  * **结果：** 两堆数量重新相等，且依然保持大小分界清晰。

#### (2) `findMedian()` —— 获取中位数

由于分界点就在两个堆的堆顶，查询非常快（$O(1)$ 时间）：

* 如果两堆**元素数量相等**（偶数个）：
  * 中位数为两个堆顶的平均值：`(left.peek() + right.peek()) / 2.0`
* 如果两堆**元素数量不等**（奇数个）：
  * 中位数就是元素多一个的 `left` 的堆顶：`left.peek()`

---

### 3. 实例走查（以加入 `[5, 2, 4, 3]` 为例）

1. **加入 5：**
   * 初始两堆空，数量相等 $\rightarrow$ 5 进 `right` $\rightarrow$ `right` 弹出 5 进 `left`。
   * 状态：`left = [5]`, `right = []`。中位数 = 5.0。
2. **加入 2：**
   * 数量不等 $\rightarrow$ 2 进 `left`（`left` 变成 [5, 2]）$\rightarrow$ `left` 弹出最大值 5 进 `right`。
   * 状态：`left = [2]`, `right = [5]`。中位数 = (2 + 5) / 2 = 3.5。
3. **加入 4：**
   * 数量相等 $\rightarrow$ 4 进 `right`（`right` 变成 [4, 5]）$\rightarrow$ `right` 弹出最小值 4 进 `left`。
   * 状态：`left = [4, 2]`, `right = [5]`。中位数 = 4.0。
4. **加入 3：**
   * 数量不等 $\rightarrow$ 3 进 `left`（`left` 变成 [4, 3, 2]）$\rightarrow$ `left` 弹出最大值 4 进 `right`。
   * 状态：`left = [3, 2]`, `right = [4, 5]`。中位数 = (3 + 4) / 2 = 3.5。

---

### 4. 复杂度分析

* **时间复杂度：**
  * `addNum(num)`：每次插入涉及堆的入堆和出堆，时间复杂度为 $O(\log n)$。
  * `findMedian()`：直接查看堆顶，时间复杂度为 $O(1)$。
* **空间复杂度：**
  * 存储所有元素，空间复杂度为 $O(n)$。


```java
class MedianFinder {

  

    private PriorityQueue<Integer> left=new PriorityQueue<>(Collections.reverseOrder());

    private PriorityQueue<Integer> right=new PriorityQueue<>();

  

    public MedianFinder() {

    }

    public void addNum(int num) {

        if(left.size()==right.size()){

            right.offer(num);

            left.offer(right.poll());

        }else{

            left.offer(num);

            right.offer(left.poll());

        }

    }

    public double findMedian() {

        if(left.size()==right.size()) return left.peek()/2.0+right.peek()/2.0;

        return (double)left.peek();

    }

}

  

/**

 * Your MedianFinder object will be instantiated and called as such:

 * MedianFinder obj = new MedianFinder();

 * obj.addNum(num);

 * double param_2 = obj.findMedian();

 */
```
