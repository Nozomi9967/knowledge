一个观光景点由它的名字 `name` 和景点评分 `score` 组成，其中 `name` 是所有观光景点中 **唯一** 的字符串， `score` 是一个整数。景点按照最好到最坏排序。景点评分 **越高** ，这个景点越好。如果有两个景点的评分一样，那么 **字典序较小** 的景点更好。

你需要搭建一个系统，查询景点的排名。初始时系统里没有任何景点。这个系统支持：

- **添加** 景点，每次添加 **一个** 景点。
- **查询** 已经添加景点中第 `i` **好** 的景点，其中 `i` 是系统目前位置查询的次数（包括当前这一次）。
	- 比方说，如果系统正在进行第 `4` 次查询，那么需要返回所有已经添加景点中第 `4` 好的。

注意，测试数据保证 **任意查询时刻** ，查询次数都 **不超过** 系统中景点的数目。

请你实现 `SORTracker` 类：

- `SORTracker()` 初始化系统。
- `void add(string name, int score)` 向系统中添加一个名为 `name` 评分为 `score` 的景点。
- `string get()` 查询第 `i` 好的景点，其中 `i` 是目前系统查询的次数（包括当前这次查询）。

### 注解版

```java
import java.util.PriorityQueue;

class SORTracker {
    // 景点的类，定义好排序规则
    class Location implements Comparable<Location> {
        String name;
        int score;

        public Location(String name, int score) {
            this.name = name;
            this.score = score;
        }

        @Override
        public int compareTo(Location o) {
            // 分数高的排在前面
            if (this.score != o.score) {
                return Integer.compare(o.score, this.score); 
            }
            // 分数一样时，名字字典序小的排在前面
            return this.name.compareTo(o.name);
        }
    }

    // left 是大根堆（在 Location 已经自定义好比较器的前提下，反向排序就是大根堆）
    // 里面维护排名前 count 的元素，堆顶是这 count 个元素中“最差”的一个
    private PriorityQueue<Location> left;
    
    // right 是小根堆，里面维护排名在 count 之后的元素，堆顶是其中“最好”的一个
    private PriorityQueue<Location> right;
    
    private int count; // 记录 get 被调用的次数

    public SORTracker() {
        // left 的堆顶是“最差”的，所以传入反向比较器
        left = new PriorityQueue<>((a, b) -> b.compareTo(a));
        // right 的堆顶是“最好”的，使用默认的自然排序
        right = new PriorityQueue<>();
        count = 0;
    }
    
    public void add(String name, int score) {
        Location node = new Location(name, score);
        
        // 对应原题解中：如果新加的景点比 cur 还要好（即排在 left 的范围内）
        if (!left.isEmpty() && node.compareTo(left.peek()) < 0) {
            left.offer(node);
            // 为了保持 left 的大小正好是 count，把 left 堆顶最差的那个挤到 right 里去
            right.offer(left.poll());
        } else {
            // 如果新加的景点比 cur 差，直接放到 right 堆
            right.offer(node);
        }
    }
    
    public String get() {
        // 因为 get 次数增加，相当于原题解中指针 cur 后移一位。
        // 这意味着原来在 right 堆顶（第 count+1 好的景点）现在正式进入前 count 强的名单中。
        if (!right.isEmpty()) {
            left.offer(right.poll());
        }
        
        // 此时 left 的堆顶正好就是我们要找的第 count 个（从1开始算起）最好景点
        String res = left.peek().name;
        
        // 准备下一次查询：count 自增，我们需要提前把 right 堆顶最好的一个放到 left 里，
        // 这样下一次调用 get 时，left 堆顶依然是那个时刻正确的答案。
        // 注意：这里的 count 表示完成了当前这次查询
        count++; 
        
        return res;
    }
}
```



# LeetCode 2102. 序列顺序查询处理器 (SORTracker) 对话归档

---

## 1. 核心算法思想：对顶堆（Dual Heaps）

由于每次调用 `get` 后，下一次查询的排名正好 $+1$，因此可以用两个堆将全量数据按“好”与“差”切分成两部分：

* **`left` 堆（大根堆）**：存放当前**排名前 $k$ 的最好景点**。堆顶（`left.peek()`）是这 $k$ 个里面“最差”的守门员（也就是当前 `get` 的答案）。
* **`right` 堆（小根堆）**：存放**剩余名次靠后的景点**。堆顶（`right.peek()`）是这些候补里面“最好”的，随时准备晋级。

### 动态平衡机制
* **`get()`**：排行榜名额扩大 1 个。将 `right` 堆顶最好的后备军弹出，送入 `left` 堆。此时 `left` 堆顶就是精准的答案。
* **`add()`**：新景点与 `left` 守门员对比。如果比守门员更优秀，送入 `left` 堆；由于 `left` 名额满了，其堆顶最差的守门员会被挤出并扔进 `right` 堆。反之，直接扔进 `right` 堆。

---

## 2. Java 核心避坑指南

1. **显式实现接口**：内部类必须明确写上 `implements Comparable<Location>`，否则 `@Override public int compareTo` 会报编译错误。
2. **Integer 包装类型地址陷阱**：如果分数声明为 `Integer score`，使用 `this.score != o.score` 判定时，一旦数值超出 `[-128, 127]`，`!=` 比较的是**内存地址**而非数值大小，会导致逻辑彻底错乱。**必须统一使用基本数据类型 `int`**。

---

## 3. 完美 AC 版 Java 代码

```java
import java.util.PriorityQueue;

class SORTracker {

    // 1. 定义景点实体类，显式实现 Comparable 接口
    class Location implements Comparable<Location> {
        public String name;
        public int score; // 关键：使用 int 规避 Integer 地址比较陷阱

        Location() {}

        Location(String name, int score) {
            this.name = name;
            this.score = score;
        }

        @Override
        public int compareTo(Location o) {
            // 规则 1：分数高的排在前面（降序）
            if (this.score != o.score) {
                return Integer.compare(o.score, this.score);
            }
            // 规则 2：分数一样，名字字典序小的排在前面（升序）
            return this.name.compareTo(o.name);
        }
    }

    private PriorityQueue<Location> left;  // 排名前 k 的高端局（大根堆）
    private PriorityQueue<Location> right; // k 名开外的后备局（小根堆）

    public SORTracker() {
        // 使用 Lambda 表达式将 Location 的自然序反转，从而建立大根堆
        left = new PriorityQueue<Location>((a, b) -> b.compareTo(a));
        // 使用默认自然序建立小根堆
        right = new PriorityQueue<Location>();
    }
    
    public void add(String name, int score) {
        Location l = new Location(name, score);
        
        // 如果 left 不为空且新景点比 left 堆顶的守门员还要好（compareTo 返回负数）
        if (!left.isEmpty() && l.compareTo(left.peek()) < 0) {
            left.offer(l);              // 新景点晋级进入 left
            right.offer(left.poll());   // left 堆顶最差的守门员被淘汰至 right
        } else {
            right.offer(l);             // 否则直接放入候补 right 堆
        }
    }
    
    public String get() {
        // 每次调用 get，从候补 right 堆顶挑出最好的晋级到 left
        if (!right.isEmpty()) {
            left.offer(right.poll());
        }

        // 此时 left 的堆顶正好是当前扩展名次后的“守门员”
        return left.peek().name;
    }
}
