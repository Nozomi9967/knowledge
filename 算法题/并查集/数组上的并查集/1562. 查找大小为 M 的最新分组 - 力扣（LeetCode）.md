[1562\. 查找大小为 M 的最新分组](https://leetcode.cn/problems/find-latest-group-of-size-m/)


提示

给你一个数组 `arr` ，该数组表示一个从 `1` 到 `n` 的数字排列。有一个长度为 `n` 的二进制字符串，该字符串上的所有位最初都设置为 `0` 。

在从 `1` 到 `n` 的每个步骤 `i` 中（假设二进制字符串和 `arr` 都是从 `1` 开始索引的情况下），二进制字符串上位于位置 `arr[i]` 的位将会设为 `1` 。

给你一个整数 `m` ，请你找出二进制字符串上存在长度为 `m` 的一组 `1` 的最后步骤。一组 `1` 是一个连续的、由 `1` 组成的子串，且左右两边不再有可以延伸的 `1` 。

返回存在长度 **恰好** 为 `m` 的 **一组 `1`** 的最后步骤。如果不存在这样的步骤，请返回 `-1` 。

**示例 1：**

```
输入：arr = [3,5,1,2,4], m = 1
输出：4
解释：
步骤 1："00100"，由 1 构成的组：["1"]
步骤 2："00101"，由 1 构成的组：["1", "1"]
步骤 3："10101"，由 1 构成的组：["1", "1", "1"]
步骤 4："11101"，由 1 构成的组：["111", "1"]
步骤 5："11111"，由 1 构成的组：["11111"]
存在长度为 1 的一组 1 的最后步骤是步骤 4 。
```

**示例 2：**

```
输入：arr = [3,1,5,4,2], m = 2
输出：-1
解释：
步骤 1："00100"，由 1 构成的组：["1"]
步骤 2："10100"，由 1 构成的组：["1", "1"]
步骤 3："10101"，由 1 构成的组：["1", "1", "1"]
步骤 4："10111"，由 1 构成的组：["1", "111"]
步骤 5："11111"，由 1 构成的组：["11111"]
不管是哪一步骤都无法形成长度为 2 的一组 1 。
```

**示例 3：**

```
输入：arr = [1], m = 1
输出：1
```

**示例 4：**

```
输入：arr = [2,1], m = 2
输出：2
```

**提示：**

- `n == arr.length`
- `1 <= n <= 10^5`
- `1 <= arr[i] <= n`
- `arr` 中的所有整数 **互不相同**
- `1 <= m <= arr.length`

---


```java
class Solution {

    public int findLatestStep(int[] arr, int m) {

        int n = arr.length;

        int[] length = new int[n + 2];  // length[i] 记录包含位置 i 的段的长度

        int count = 0;  // 大小为 m 的段数

        int result = -1;

        for (int day = 1; day <= n; day++) {

            int pos = arr[day - 1];

            int leftLen = length[pos - 1];    // 左边相邻段的长度

            int rightLen = length[pos + 1];   // 右边相邻段的长度

            int newLen = leftLen + rightLen + 1;  // 合并后的长度

            // 更新新段的两端端点的长度

            length[pos - leftLen] = newLen;

            length[pos + rightLen] = newLen;

            // 更新大小为 m 的段数

            if (leftLen == m) {

                count--;

            }

            if (rightLen == m) {

                count--;

            }

            if (newLen == m) {

                count++;

            }

            // 如果存在大小为 m 的段，更新答案

            if (count > 0) {

                result = day;

            }

        }

        return result;

    }

}
```

**执行流程示例：​**

假设 `arr = [3,2,5,2,2], m = 1`：

|day|pos|leftLen|rightLen|newLen|length 数组|count|result|
|---|---|---|---|---|---|---|---|
|1|3|0|0|1|[0,0,0,1,0,0,0]|1|1|
|2|2|0|1|2|[0,0,2,2,0,0,0]|0|1|
|3|5|0|0|1|[0,0,2,2,0,1,0]|1|3|
|4|2|2|2|5|[0,5,5,5,5,1,0]|0|3|
|5|2|5|1|7|[0,7,7,7,7,7,7]|0|3|

**时间和空间复杂度：​**

- **时间复杂度**：O(n)，每个位置只处理一次
- **空间复杂度**：O(n)，用于存储长度数组

这个方案的妙处在于：只在段的端点处记录长度，当合并段时直接更新两端的长度值，避免了遍历整个段的开销。

---

如果leftLen和rightLen都是2，newLen=5，

length[pos - leftLen] = newLen; length[pos + rightLen] = newLen;

那你只更新了两段的点的长度，中间那俩点呢


你问得很好！这是这个算法的**巧妙之处**。

中间那两个点**不需要更新**，因为我们**永远不会查询它们**。

让我用具体例子解释：

**假设场景：**
- `pos = 4, leftLen = 2, rightLen = 2, newLen = 5`
- 这意味着：位置 2-3 是一段长度为 2 的 1，位置 4 是新的 1，位置 5-6 是一段长度为 2 的 1

```
位置:  1  2  3  4  5  6  7
值:    0  1  1  1  1  1  0
       └─左段─┘  └─右段─┘
          新的合并段: 2-6，长度5
```

**更新操作：**
```java
length[pos - leftLen] = newLen;   // length[2] = 5 (左段的起点)
length[pos + rightLen] = newLen;  // length[6] = 5 (右段的终点)
```

**为什么中间的 3, 4, 5 不需要更新？**

因为在后续的操作中，我们**只会查询新设为 1 的位置的左右邻居**。对于位置 2-6 这个合并段中的任何内部位置（3, 4, 5），它们永远不会被设为 1（因为 `arr` 是 1 到 n 的排列，每个位置只会被设一次）。

**只有段的端点会被查询：**
- 如果下一次设置位置 1 为 1，会查询 `length[0]` 和 `length[1]`（左端点）
- 如果下一次设置位置 7 为 1，会查询 `length[6]` 和 `length[7]`（右端点）

中间的位置 3, 4, 5 永远不会成为新设置的位置，所以不需要维护它们的长度值。这就是为什么只需要更新两个端点！


## 另一种做法


```java
class Solution {
    int[] parent;
    int[] size;

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    public int findLatestStep(int[] arr, int m) {
        int n = arr.length;
        parent = new int[n + 2];
        size = new int[n + 2];
        boolean[] active = new boolean[n + 2];

        for (int i = 1; i <= n; i++) {
            parent[i] = i;
            size[i] = 1;
        }

        int count = 0;
        int answer = -1;

        for (int step = 1; step <= n; step++) {
            int x = arr[step - 1];
            active[x] = true;

            if (m == 1) count++;

            // 与左侧相邻的已点亮位置合并
            if (active[x - 1]) {
                count = union(x, x - 1, m, count);
            }

            // 与右侧相邻的已点亮位置合并
            if (active[x + 1]) {
                count = union(x, x + 1, m, count);
            }

            if (count > 0) {
                answer = step;
            }
        }

        return answer;
    }

    private int union(int a, int b, int m, int count) {
        int rootA = find(a);
        int rootB = find(b);

        if (rootA == rootB) return count;

        if (size[rootA] == m) count--;
        if (size[rootB] == m) count--;

        parent[rootA] = rootB;
        size[rootB] += size[rootA];

        if (size[rootB] == m) count++;

        return count;
    }
}

```

这里开 `n + 2`，主要是为了**方便处理边界位置**。

数组下标通常对应字符串位置 `1` 到 `n`，额外留出下标 `0` 和 `n + 1` 作为哨兵：

- `0` 在最左边，`n + 1` 在最右边。
- 检查位置 `x` 的左右邻居时，可以直接访问 `x - 1` 和 `x + 1`，不用额外担心越界。
- 在并查集代码里，`active[0]` 和 `active[n + 1]` 默认是 `false`，因此不会把哨兵位置合并进真实区间。

所以 `parent`、`size`、`active` 都可以开 `n + 2`，有效下标是 `0` 到 `n + 1`。严格来说，并查集节点只需要 `1` 到 `n`，开 `n + 1` 也能写；多出的两个边界位置只是让邻居判断更简洁、更安全。
