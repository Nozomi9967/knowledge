### 第 1 题（10 分）

**请简述 B+Tree 相比 B 树和二叉树的优势。为什么 B+Tree 更适合作为数据库索引的数据结构？**

> 提示：从磁盘 IO 次数、非叶子节点存储、范围查询、树退化等角度回答。

B+Tree相比二叉树树更宽，树高更低，磁盘IO次数少
B+Tree非叶子节点存储索引，只有叶子节点存储数据，所以树高比B树更低，磁盘IO次数更少
并且B+Tree叶子节点首尾指针相连，构成双向链表，范围查询无需回表，效率更高

### 二、简答题要点

**第 1 题要点：**
- B+Tree 非叶子节点仅存索引，不存数据 → 节点存储密度高 → 树层数少 → 磁盘 IO 次数少
- 数据仅存于叶子节点，且叶子节点通过双向链表相连 → 范围查询只需遍历叶子节点链表，无需回溯父节点
- 二叉树在极端情况下会退化为链表，查询效率骤降；B+Tree 是多叉树，天然矮胖，不会退化

**第 2 题要点：**
1. **连接器**：TCP 三次握手、校验用户名密码、读取用户权限
2. **查询缓存**（MySQL 8.0 已移除）：检查是否命中缓存
3. **解析 SQL**：词法分析 + 语法分析，构建 SQL 语法树
4. **执行 SQL**：
   - prepare 阶段：检查表和字段是否存在，将 `*` 替换为所有字段
   - optimize 阶段：优化器制定执行计划（如选择哪个索引）
   - execute 阶段：根据执行计划从存储引擎读取记录并返回

**第 3 题要点：**
- 读提交：每个语句执行前创建 Read View
- 可重复读：启动事务时创建 Read View，整个事务复用同一个
- Read View 可见性判断规则：
  - `trx_id < min_trx_id` → 可见（已提交）
  - `trx_id >= max_trx_id` → 不可见（未来事务）
  - `min_trx_id <= trx_id < max_trx_id` → 是否在 m_ids 中，在则不可见，否则可见

**第 4 题要点：**
- 语句 A：✅ 能用。（a, b）都匹配最左前缀
- 语句 B：❌ 不能用。跳过了 a，直接以 b 开头，不满足最左匹配
- 语句 C：✅ 部分能用。a 可以走索引过滤，c 无法用到联合索引（跳过了 b）
- 语句 D：✅ 部分能用。a > 10 是范围查询，a 可以用索引，但 b 无法用到（范围查询后停止匹配）
- 语句 E：✅ 全部能用。a >= 10 的范围查询不会导致停止匹配（`>=`、`<=`、`BETWEEN`、like 前缀匹配不会停止匹配），所以 (a, b, c) 全部可用

**第 5 题要点：**
- 流程：主库写入 binlog → 从库 IO 线程连接主库 log dump 线程 → 拉取 binlog 写入 relay log → 从库 SQL 线程读取 relay log 回放
- 同步复制：等待所有从库确认 → 数据一致性最好，延迟最高
- 异步复制：不等待从库 → 性能最好，主从可能不一致
- 半同步复制：等待至少一个从库确认 → 折中方案

**第 6 题要点：**
- 两阶段提交：将 redo log 写入拆为 prepare 和 commit 两个阶段，确保 redo log 与 binlog 逻辑一致
- 为什么需要：防止主库重启后，redo log 和 binlog 一个写了、一个没写，导致主从数据不一致
- prepare + binlog 已写入 → **应该提交**。因为 binlog 一旦落盘，从库就会读到并执行，如果主库回滚则主从不一致
