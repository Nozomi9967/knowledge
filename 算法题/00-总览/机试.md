## 六、答题技巧（华为机考）

- 3 题分值不均，**先做第 1、2 题保证拿分，第三题留足时间**；若第三题卡住，暴力/部分分也要写。
- 题目描述长、场景多，**先提取输入输出格式**，再识别底层算法类型。

## 七、高频集合方法速查（笔试/机试代码）

### List 转 int[]

```java
List<Integer> list = new ArrayList<>();
int[] arr = list.stream().mapToInt(Integer::intValue).toArray();
```

### String 去前导零

```java
replaceAll("^0+","")
```

### 快速求 int[] 的和（机试最优一行）

```java
int sum = Arrays.stream(nums).sum();
```

- `Arrays.stream(int[])` 返回的是 **IntStream（原始类型流，不装箱）**，底层就是遍历累加，JIT 还可能向量化，快且简洁
- 等价手写循环（同样快，直观）：

```java
int sum = 0;
for (int x : nums) sum += x;
```

- ❌ 避免 `Arrays.stream(nums).reduce(0, Integer::sum)` —— reduce 用装箱的 binary operator，慢
- ❌ 避免先转 `List<Integer>` 再流式求和 —— 双重装箱，数据量大时可能 TLE

### 快速求 int[] 的 max / min（机试最优一行）

```java
int max = Arrays.stream(nums).max().orElse(Integer.MIN_VALUE);
int min = Arrays.stream(nums).min().orElse(Integer.MAX_VALUE);
```

- `IntStream.max()` 返回 `OptionalInt`（因为数组可能为空），机试数组非空时直接 `getAsInt()` 或 `orElse()` 兜底
- 手写循环（同样快）：

```java
int max = Integer.MIN_VALUE;
for (int x : nums) max = Math.max(max, x);
```

- 空数组时手写循环会返回 `Integer.MIN_VALUE`，注意题目是否保证非空

### ArrayDeque 双端队列

ArrayDeque 作为栈使用时，栈顶在左边，所以 `pollFirst = poll`。完整速记见 [[Deque 方法速记（栈 vs 队列）]]（栈 push/pop/peek vs 队列 offer/poll/peek，空时行为区别）。

## 八、StreamTokenizer 使用教程（机试必背 IO 模板）

### 为什么用它

华为机考输入规模大，`Scanner` 很慢（同步、正则解析），大数据量时容易 TLE。`StreamTokenizer` 是流式分词器，**比 BufferedReader.readLine + split 还快**，是机试最快的读入方式之一。

| 读入方式 | 速度 | 说明 |
|----------|------|------|
| Scanner | 慢 | 同步 + 正则，大数据量易 TLE |
| BufferedReader + split | 中 | 需自己解析，够用 |
| **StreamTokenizer** | **快** | 流式分词，native 级别解析，机试首选 |

### 标准模板（读数字）

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        StreamTokenizer in = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
        // 每次读取前必须手动调用 nextToken() 前进到下一个 token
        in.nextToken(); int n = (int) in.nval;      // 读第一个数
        in.nextToken(); int m = (int) in.nval;      // 读第二个数

        int[] arr = new int[n];
        for (int i = 0; i < n; i++) {
            in.nextToken(); arr[i] = (int) in.nval; // 循环读 n 个数
        }
        System.out.println(n + " " + m);
    }
}
```

### 读字符串

```java
StreamTokenizer in = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
in.nextToken(); String s = in.sval;   // 读一个单词（非数字 token）
in.nextToken(); String t = in.sval;
```

### 关键 API

| API | 作用 |
|-----|------|
| `nextToken()` | **前进到下一个 token**，返回该 token 类型；第一次读取也要先调用 |
| `nval` | 当前 token 是数字时的值（**double 类型，要强转 int**；为什么是 double、以及 2^53 精度上限见下方坑 6） |
| `sval` | 当前 token 是单词时的字符串值 |
| `TT_EOF` | 读到输入末尾（值为 -1），判断输入结束用 `type == TT_EOF` |
| `TT_NUMBER` | 当前 token 是数字 |
| `TT_WORD` | 当前 token 是单词 |
| `TT_EOL` | 当前 token 是行尾 |

### 常见坑（必看）

1. **读数字必须强转**：`nval` 是 double，直接赋给 int 会编译错误，要 `(int) in.nval`。
2. **每次读取都要 nextToken()**：它不会自动前进，漏一次就漏一个数。
3. **默认忽略空白符**：空格、换行、Tab 都会跳过，所以多行/多空格输入都没问题。
4. **单字符标点会被单独返回**：输入里有逗号、冒号、括号这类分隔符时，`nextToken()` 返回的是该字符的 ASCII 值（如 `','` 返回 44），需要自己判断跳过：

```java
// 输入形如 "3,5,7"（逗号分隔），循环读：
while (in.nextToken() != StreamTokenizer.TT_EOF) {
    if (in.ttype == StreamTokenizer.TT_NUMBER) {
        int x = (int) in.nval;   // 取数字
        // 处理 x ...
    }
    // 逗号会返回字符 ','，直接跳过不处理
}
```

5. **字符串 token 默认规则**：`sval` 只认「字母/数字/下划线」组成的单词，带特殊符号的长串可能被拆开；机试里字符串题如果复杂，建议用 `BufferedReader.readLine()` 整行读更稳。

6. **`nval` 为什么是 double + 超过 2^53 静默丢精度**（⚠ 本节最危险的一条）：`StreamTokenizer` 是 JDK 1.0 的**通用词法分析器**，不是为「读整数」设计的。它默认开启的 `parseNumbers()` 把 `0-9`、`.`、`-` 都当数字字符，所以它认得的「数字」包含小数和负数（`3.14`、`-2.5`）——既然要能装小数，数字槽位就只能是浮点型。于是 JDK 只给了 `nval` 这一个字段，**没有 `ival`、没有 `lval`**，所有数字都从这个 `double` 出来，这就是必须写 `(int) in.nval` 的根因。内部实现也很朴素：逐位 `v = v * 10 + digit` 累加进一个 `double`。代价是 `double` 尾数只有 53 位，能精确表示的整数上限是 2^53 = 9007199254740992（约 9.0×10^15），超过就丢精度——**不报错、不抛异常，只是答案错**：

```java
// 输入 1000000000000000001  (10^18 + 1)
in.nextToken();
long x = (long) in.nval;   // 得到 1000000000000000000 —— 末位的 1 没了
```

在 1e18 量级，相邻两个 `double` 之间的间隔已经是 128，加个 1 直接被舍掉。选型规则：

| 数据范围 | 能不能用 `StreamTokenizer` |
|---|---|
| `int` 范围（±2.1×10^9） | 能，放心用 |
| `long` 但 ≤ 9×10^15 | 能，`(long) in.nval` 精确 |
| 题目出现 10^18 / 明确说 `long` 上限 | **不能**，换 `BufferedReader` + `Long.parseLong` |

7. **不认科学计数法和 `+` 号**：`1e9` 会被切成数字 `1` 加单词 `e9`，`+5` 的 `+` 被当普通字符单独返回。和第 4、5 条同源——它只是个粗糙词法器，不是完整的数字解析器。

### 一个完整示例（读 n 个逗号分隔的数并求和）

```java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        StreamTokenizer in = new StreamTokenizer(new BufferedReader(new InputStreamReader(System.in)));
        long sum = 0;
        while (in.nextToken() != StreamTokenizer.TT_EOF) {
            if (in.ttype == StreamTokenizer.TT_NUMBER) {
                sum += (int) in.nval;
            }
        }
        System.out.println(sum);
    }
}
```

### 附：`BufferedReader.readLine()` 用法（字符串题首选）

`StreamTokenizer` 只擅长「一个一个数字往外吐」。一旦输入里带特殊符号、要保留原样的字符串、或者需要按行处理，就改成 `readLine()` 整行读进来自己切。

**固定三件套**（`main` 必须 `throws IOException`，否则编译不过）：

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        String line = br.readLine();     // 读一整行
        System.out.println(line);
    }
}
```

**三条核心行为（记住这三条就不会用错）：**

| 表达式 | 结果 |
|---|---|
| `br.readLine()` | 返回这一行的内容，**已自动去掉行尾的 `\n` / `\r` / `\r\n`** |
| 读到输入末尾 | 返回 **`null`**——判结束用 `!= null`，不是判空串 |
| 遇到空行 | 返回 `""`（长度 0 的空串，**不是** `null`） |

**四种最常见的输入格式**

① 第一行 n，第二行 n 个空格分隔的数（机试最常见）：

```java
int n = Integer.parseInt(br.readLine().trim());
int[] a = Arrays.stream(br.readLine().trim().split("\\s+"))
                .mapToInt(Integer::parseInt).toArray();
```

② 一行里有几个数（用 `StringTokenizer`，不走正则，比 `split` 快）：

```java
StringTokenizer st = new StringTokenizer(br.readLine());
int n = Integer.parseInt(st.nextToken());
int m = Integer.parseInt(st.nextToken());
```

③ 不告诉你有几行，读到 EOF 为止（多组数据）：

```java
String line;
while ((line = br.readLine()) != null) {
    if (line.isEmpty()) continue;    // 跳过空行
    // 处理这一行 ...
}
```

④ 逗号分隔（华为爱出）：直接 `line.split(",")`；如果形如 `"3, 5, 7"` 带空格，用 `line.split(",\\s*")`。

**六个坑（每一个都真的会挂测试点）：**

1. **`split(" ")` 遇到连续空格会切出空串**：`"1  2".split(" ")` → `["1", "", "2"]`，紧接着 `parseInt("")` 抛 `NumberFormatException`。统一写 `split("\\s+")`。
2. **行首有空格时 `split("\\s+")` 第一个元素是空串**：`" 1 2".split("\\s+")` → `["", "1", "2"]`。所以 **`trim()` 和 `split("\\s+")` 要一起用**，只用一个都不安全。
3. **`Integer.parseInt` 不容忍任何空白**：`parseInt(" 5")` 直接抛 `NumberFormatException`，行尾多打一个空格就挂。`trim()` 当成肌肉记忆。
4. **判结束必须用 `null`**：写成 `while (!line.isEmpty())`，中间遇到空行会提前退出，读到末尾 `line == null` 还会先 NPE。标准写法就是 `while ((line = br.readLine()) != null)`。
5. **同一道题别混用 `StreamTokenizer` 和 `readLine()`**：`StreamTokenizer` 内部就是从这个 `BufferedReader` 的缓冲区取数据的，两个交替读会丢内容。一道题只选一种读法。
6. **两个 `nextToken()` 同名但返回类型完全不同**：`StringTokenizer.nextToken()` 返回 **`String`**（所以外面要套 `Integer.parseInt`），而 `StreamTokenizer.nextToken()` 返回的是 **`int` token 类型码**，值要另外从 `nval` / `sval` 取。写成 `Integer.parseInt(in.nextToken())` 就是拿类型码当数字解析。

| 对比项 | `StringTokenizer`（配 `readLine()` 用） | `StreamTokenizer`（独立读入用） |
|---|---|---|
| `nextToken()` 返回 | `String`，就是内容本身 | `int` 类型码（`TT_NUMBER = -2`、`TT_EOF = -1`、`TT_WORD = -4`） |
| 怎么拿到值 | 返回值直接用，`parseInt` 转数字 | 数字在 `nval`（`double`，要强转），字符串在 `sval` |
| 需要 `trim()` 吗 | **不需要**，切出的 token 不含分隔符和空白 | 不需要，默认跳过所有空白 |
| 取完了再调 | 抛 `NoSuchElementException`，**不返回 `null`**——个数不定时用 `while (st.hasMoreTokens())` | 返回 `TT_EOF`（-1） |

注意第 3 行：`StringTokenizer` 这条路径**不需要 `trim()`**，这是它相比上面第 2、3 条（`split("\\s+")` 必须配 `trim()`）唯一省事的地方。

**输出也别逐行 `System.out.println`**：`System.out` 是 autoflush 的，每次 `println` 都会真的 flush 一次，几万行就能把时间耗光。

```java
StringBuilder sb = new StringBuilder();
for (int x : ans) sb.append(x).append('\n');
System.out.print(sb);        // 攒完一次性输出

// 或者用 PrintWriter
PrintWriter pw = new PrintWriter(new BufferedWriter(new OutputStreamWriter(System.out)));
pw.println(ans);
pw.flush();                  // ⚠ 忘了 flush 就一个字都不输出
```

**怎么选：**

| 输入长什么样 | 用什么 |
|---|---|
| 纯数字、量大（10⁵ 以上） | `StreamTokenizer` |
| 要保留原始字符串、含特殊符号 | `BufferedReader.readLine()` |
| 按行处理，每行格式还不一样 | `BufferedReader.readLine()` |
| 数字但要按行分组（每行个数不固定） | `readLine()` + `StringTokenizer` |
| —— | 任何情况都别用 `Scanner`（10⁵ 行以上 TLE） |

## 九、PriorityQueue 速查（刷题高频）

> **一句话：** 一个「自动把优先级最高的元素放到队头」的堆。Java 默认**小根堆**（`peek()/poll()` 拿最小值）。

### 三个核心方法

| 方法 | 作用 |
|------|------|
| `offer(x)` | 加入元素 |
| `peek()` | 查看堆顶，不删除 |
| `poll()` | 取出并删除堆顶 |

### 大根堆（三种写法，全部防溢出）

```java
// 方式 1：Collections 自带的反向比较器（非常简洁）
PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());

// 方式 2：Comparator 方法引用（静态方法，与方式 1 等价，少一个 import java.util.Collections 的顾虑）
PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());

// 方式 3：手写 lambda，Integer.compare 交换参数顺序
PriorityQueue<Integer> pq = new PriorityQueue<>(
    (a, b) -> Integer.compare(b, a)
);
```

- 三种效果完全相同：堆顶是**最大值**，`poll()` 从大到小出
- 都别写成 `(a, b) -> b - a`：相减在 ±10⁹ 量级会**整数溢出**、比较结果错乱（见上文「比较器里禁止写 a - b」）
- 默认构造 `new PriorityQueue<>()` 是**小根堆**；传比较器后完全由比较器决定堆顶
- 对 `int[]` 元素做自定义比较同理，把 lambda 参数换成数组：`new PriorityQueue<>((a, b) -> Integer.compare(b[0], a[0]))`（按第 0 个元素的大根堆）

### 按数组第 2 个元素排序（int[] 最常见）

```java
new PriorityQueue<>((a, b) -> a[1] - b[1]);   // 距离排序 = Dijkstra 核心
```

### 多条件排序（用 Integer.compare 防溢出）

```java
new PriorityQueue<>((a, b) -> {
    if (a[0] != b[0]) return Integer.compare(a[0], b[0]);
    return Integer.compare(a[1], b[1]);
});
```

### 对象排序

```java
new PriorityQueue<>((a, b) -> Integer.compare(a.age, b.age));
```

### ⚠ 最大坑：PQ 不是「完全有序的数组」

内部是堆，**只保证堆顶最优**，`System.out.println(pq)` 输出不保证有序。想按序取出必须：

```java
while (!pq.isEmpty()) System.out.println(pq.poll());
```

### 和 Deque 对比

| 数据结构 | 加入 | 查看最优 | 删除最优 |
|----------|------|----------|----------|
| `Deque` 当栈 | `push` | `peek` | `pop` |
| `Deque` 当队列 | `offer` | `peek` | `poll` |
| `PriorityQueue` | `offer` | `peek` | `poll` |

区别：Deque 按进出位置决定顺序；PQ 不管谁先进，**优先级最高的先出**。

### 刷题信号

看到「每次取最小/最大」「Top K」「第 K 大/小」「合并多个有序序列」「最短路(Dijkstra)」→ 立刻想到 `PriorityQueue`。

## 十、TreeMap 速查（有序 Key 的 Map，刷题高频）

> **一句话：** 基于**红黑树**的 `NavigableMap`，**始终按 Key 大小自动排序**。插入/删除/查找均为 $O(\log N)$。

### 核心特性

- **自动排序**：默认 Key 升序（自然顺序），构造时可传 `Comparator` 自定义（如降序）。
- **Key 不能为 null**：插入/查询要靠 `compareTo/compare` 比较 Key，null 会抛 `NullPointerException`（**Value 可以为 null**）。
- **非线程安全**：多线程访问需 `Collections.synchronizedSortedMap(new TreeMap<>(...))` 包裹。

### 最值与边界查询（刷题极常用）

| 方法 | 功能 | 示例（keys = [5,10,20]） |
|------|------|------|
| `firstKey()` / `lastKey()` | 最小 / 最大 Key | `5` / `20` |
| `firstEntry()` / `lastEntry()` | 最小 / 最大键值对 | `5="B"` / `20="C"` |
| `floorKey(K)` | ≤ K 的最大 Key | `floorKey(12)` → `10` |
| `ceilingKey(K)` | ≥ K 的最小 Key | `ceilingKey(12)` → `20` |
| `lowerKey(K)` | < K 的最大 Key | `lowerKey(10)` → `5` |
| `higherKey(K)` | > K 的最小 Key | — |

### 子集截取

```java
SortedMap<Integer, String> sub = map.subMap(5, 20);              // [5,20) 前闭后开
NavigableMap<Integer, String> sub2 = map.subMap(5, true, 20, true); // [5,20] 显式开闭
```

### 频数统计 + 滑动窗口（核心套路）

维持窗口内数值分布、随时取极值：

```java
TreeMap<Integer, Integer> window = new TreeMap<>();

// 进窗口
window.put(x, window.getOrDefault(x, 0) + 1);
// 取当前窗口极差
int diff = window.lastKey() - window.firstKey();
// 出窗口
window.put(x, window.get(x) - 1);
if (window.get(x) == 0) window.remove(x);   // 频数为 0 必须删 Key，保证 firstKey/lastKey 正确
```

### 三大 Map 选型

| 类型 | 底层 | Key 排序 | 查找/增删 | 适用场景 |
|------|------|----------|-----------|----------|
| `HashMap` | 哈希表 | 无序 | $O(1)$ | 绝大多数纯 Key-Value 查找 |
| `LinkedHashMap` | 哈希表 + 双向链表 | 按插入/访问顺序 | $O(1)$ | 保持插入顺序 / LRU 缓存 |
| `TreeMap` | 红黑树 | 按 Key 大小 | $O(\log N)$ | 取极值、范围查询、维护动态有序集合 |

### 刷题信号

看到「动态维护有序集合」「滑动窗口取极值」「区间/邻近查询」「按 Key 排序」→ 想到 `TreeMap`。

## 十一、ArrayList 排序速查

> **一句话：** `list.sort(Comparator)` 最常用，核心记住比较器返回值语义：**`< 0` → a 排前面；`> 0` → b 排前面；`= 0` → 顺序无所谓**。

### 基础：升序 / 降序

```java
list.sort(Integer::compareTo);                  // 升序
Collections.sort(list);                         // 等价升序

list.sort(Comparator.reverseOrder());           // 降序（推荐）
list.sort((a, b) -> b - a);                     // 降序（可用，但 b-a 有溢出风险）
```

### `ArrayList<int[]>` 按某个下标排序（高频）

```java
list.sort((a, b) -> a[0] - b[0]);   // 按第 0 个元素升序
list.sort((a, b) -> b[1] - a[1]);   // 按第 1 个元素降序
```

### 多条件排序

先按 `a[0]` 升序、相同再按 `a[1]` 降序：

```java
list.sort((a, b) -> {
    if (a[0] != b[0]) return a[0] - b[0];
    return b[1] - a[1];
});
```

更推荐用 `Comparator` 链式（防溢出、可读性好）：

```java
list.sort(
    Comparator.comparingInt((int[] a) -> a[0])
              .thenComparingInt(a -> -a[1])
);
```

### `ArrayList<String>`

```java
list.sort(String::compareTo);            // 字典序
list.sort(Comparator.reverseOrder());    // 倒序
```

### ⚠ 核心坑：大数别写 `a - b`

涉及 int 大数时不要习惯性写 `a - b`，可能**整数溢出**导致排序错乱。用 `Integer.compare(a, b)` 更稳：

```java
list.sort((a, b) -> Integer.compare(a, b));   // 升序（防溢出）
```

## 十二、树状数组（Fenwick Tree）速查

> **一句话：** 单点更新 + 前缀和查询都是 $O(\log N)$ 的静态数组数据结构。经典应用：**求每个元素左边/右边比它大的元素个数**（逆序对类问题），配合**离散化**处理值域大的情况。

> **前置知识：** 模板里的步长 `i & -i`（lowbit，取出最低位的 1）是整个结构的地基——`tree[i]` 管辖区间恰好是 `(i - lowbit(i), i]`。补码推导、边界（`x = 0` 返回 0，所以 `while (i > 0)` 必须判）、以及位运算符全部坑点见 [[位运算操作符与lowbit速查]]。

### 完整模板（离散化 + 左/右逆序计数）

```java
int n = a.length;
int[] left = new int[n];
int[] right = new int[n];

// 离散化：把值域压缩到 [1, n]，rank 即排名
int[] b = a.clone();
Arrays.sort(b);

Fenwick tree = new Fenwick(n);

// 从左往右：左边比 a[i] 大的数量 = 左边总数(i) - 左边 <= a[i] 的数量
for (int i = 0; i < n; i++) {
    int rank = Arrays.binarySearch(b, a[i]) + 1;   // a[i] 的排名（1 基）

    left[i] = i - tree.query(rank);                // i - 前缀和(<= rank)

    tree.add(rank, 1);                             // 把 a[i] 的 rank 加入计数
}

// 从右往左：右边比 a[i] 大的数量
tree = new Fenwick(n);

for (int i = n - 1; i >= 0; i--) {
    int rank = Arrays.binarySearch(b, a[i]) + 1;

    right[i] = (n - 1 - i) - tree.query(rank);     // 右边总数 - 右边 <= a[i] 的数量

    tree.add(rank, 1);
}

class Fenwick {
    int[] tree;

    Fenwick(int n) {
        tree = new int[n + 1];
    }

    void add(int i, int x) {                       // 单点更新：i 位置 +x
        while (i < tree.length) {
            tree[i] += x;
            i += i & -i;                           // 向上跳到下一个覆盖区间
        }
    }

    int query(int i) {                             // 前缀和：求 [1, i] 之和
        int sum = 0;
        while (i > 0) {
            sum += tree[i];
            i -= i & -i;                           // 向下跳到上一个区间
        }
        return sum;
    }
}
```

### 核心套路拆解

| 步骤 | 作用 | 代码 |
|------|------|------|
| 离散化 | 值域大时压缩成排名 1~n，数组才能开得下 | `Arrays.sort(b)` + `binarySearch + 1` |
| `add(rank, 1)` | 标记当前元素已出现 | 每次遍历到一个元素就插入 |
| `query(rank)` | 统计已出现的 ≤ 当前值的个数 | 前缀和 |
| `总数 - query(rank)` | 得到 **比当前元素大的数量** | `i` 或 `(n-1-i)` 是已扫过的总数 |

### 常见变形

- **右边比它小的数量**：`right[i] = tree.query(rank - 1)`（严格小于，不用总数减）
- **左边比它小的数量**：`left[i] = tree.query(rank - 1)`
- **全局逆序对总数**：从左往右累加 `left[i]`（或 `i - query(rank)` 求和）
- **求第 K 大 / 前缀第 K 小**：配合二分 + `query` 在树状数组上跳（`findKth`）

### ⚠ 易错点

1. **rank 从 1 开始**：`binarySearch + 1`，否则 `query(0)` 死循环/下标越界。
2. **`i & -i`** 是取最低位 1（lowbit），更新向上、查询向下，方向别搞反。
3. **重复元素**：离散化用 `binarySearch` 时相同值 rank 相同，天然去重，无需额外处理。
4. 模板中"比它大"用的是 `总数 - query(rank)`（含等于），若要"严格大于"需 `总数 - query(rank)` 且 query 用 rank 前再处理等于的情况；**严格小于**用 `query(rank - 1)`。

### 刷题信号

看到「逆序对」「左边/右边有多少个比它大/小」「区间内小于 x 的个数」「动态求第 K 小」→ 想到**树状数组 + 离散化**。

## 十三、上取整恒等式（整数除法必背）

> **一句话：** 当 `a` 为**非负整数**、`b` 为**正整数**时，
> $$\left\lceil \frac{a}{b} \right\rceil = \left\lfloor \frac{a+b-1}{b} \right\rfloor$$
> 即 Java 里直接写 `(a + b - 1) / b`，不用浮点、不用判断。

### 为什么成立

设 `a = k·b + r`（`k = ⌊a/b⌋`，余数 `0 ≤ r &lt; b`）：

- **`r = 0`（整除）**：左边 `⌈a/b⌉ = k`。右边分子 `= k·b + b - 1`，落在 `[k·b, (k+1)·b)` 内，取下整还是 `k` ✅
- **`r &gt; 0`（不整除）**：左边 `⌈a/b⌉ = k + 1`。右边分子 `= k·b + r + b - 1`，因为 `1 ≤ r ≤ b-1`，所以分子落在 `[(k+1)·b, (k+2)·b)` 内，取下整正好 `k + 1` ✅

**直觉理解**：`+ (b-1)` 就是「先垫满一格再向下取整」——不足一整份的零头被垫到下一个整数倍，恰好等价于向上进位。

### Java 写法对比

```java
// ✅ 推荐：一行，无分支，a >= 0 且 b > 0 时正确
int c = (a + b - 1) / b;

// ✅ 等价：显式判余，可读性好，且不会因 a+b-1 溢出
int c = a / b + (a % b == 0 ? 0 : 1);

// ✅ Java 18+ 才有，机试环境多为 Java 8/11，别依赖
int c = Math.ceilDiv(a, b);

// ❌ 千万别用浮点：double 精度丢失，大数会算错
int c = (int) Math.ceil((double) a / b);
```

### 两个坑

| 坑 | 说明 | 对策 |
|----|------|------|
| **溢出** | `a` 接近 `Integer.MAX_VALUE` 时 `a + b - 1` 会溢出成负数 | 转 `long` 计算，或改用 `a / b + (a % b == 0 ? 0 : 1)` 写法 |
| **a 为负数时失效** | 恒等式在数学上对负数也成立（用 floor 定义），但 **Java 的 `/` 是向零截断而非向下取整**，负数结果会错。例：`a = -4, b = 3`，正确答案 `⌈-4/3⌉ = -1`，而 Java 算 `(-4+2)/3 = -2/3 = 0` ❌ | 只在 `a ≥ 0` 时用这个公式；有负数就用 `Math.ceil` 前先分类，或 `-((-a) / b)` |

补一条对照：`a ≥ 0, b &gt; 0` 时**下取整** `⌊a/b⌋` 就是 Java 的 `a / b`，什么都不用加——上取整才需要补 `b-1`。

### 机试里什么时候用

- **分组 / 分批**：`n` 个物品每批装 `k` 个，要几批 → `(n + k - 1) / k`
- **二分答案的 check 函数**：几乎必用。如「每小时吃 `speed` 根香蕉，吃完 `pile` 根要几小时」→ `(pile + speed - 1) / speed`，见 [[3296.移山所需的最少秒数]]、[[410. 分割数组的最大值 TODO|410. 分割数组的最大值]]
- **数组分块 / 二维展平**：算行数 `(n + cols - 1) / cols`
- **资源调度类场景题**：华为常考「至少需要多少台机器/多少车次」，本质都是上取整

## 十四、测试点思维（提交前自测清单）

> [!tip] 核心心态
> **代码能跑 ≠ 能拿分**。题面给的样例通常只覆盖最平凡的情况，分数藏在隐藏用例里。在「代码已经能跑」的前提下，把剩余时间花在造测试点上比重写算法划算——过样例但漏边界，常见结果是只拿 30% 分；补两三个边界用例就能满分。

### 1. 边界值 —— 失分第一名

| 维度 | 要试的值 |
|------|---------|
| 规模 | n = 1、n = 2、n = 上限（10⁵ / 10⁶）、n = 0（若题目允许） |
| 数值 | 0、负数、上限值、`Integer.MAX_VALUE` 附近 |
| 容器 | 空数组、空串、空集合、只有一个元素 |
| 结构 | 全部相同、全部不同、只有两种值 |

**做法**：读完题第一件事把数据范围抄在纸上，然后针对 `1 ≤ n ≤ 10⁵` 这类约束**手动跑两端**。n = 1 专杀「取前一个 / 后一个」的越界代码；n = 上限暴露 TLE 与溢出。

### 2. 等价类划分

把输入按「行为应该相同」分组，每组取一个代表 + 每组的边界。以判断三角形类型为例：

| 等价类 | 用例 |
|--------|------|
| 等边 | (3,3,3) |
| 等腰 | (3,3,5)、(5,5,7) |
| 直角 | (3,4,5) |
| 一般三角形 | (4,5,6) |
| 非法：两边和不大于第三边 | (1,1,10)、(1,2,3)（退化） |
| 非法：非正数 | (0,1,2)、(-1,2,3) |

分组的意义是**用最少的用例覆盖最多的分支**：同一等价类里多试几个纯属浪费时间，跨类漏一个就是丢分。

### 3. 状态转移

有状态机 / 循环 / 递归时，专测「第一次、中间、最后一次」：

- **循环**：首次迭代（变量初始化好了吗）、最后一次（`i + 1` 越界吗）、只循环一次、一次都不进
- **递归**：深度 0、深度 1、最大深度
- **状态机**：合法路径走全 + 非法转移（重复支付、跳过发货直接收货）+ 超时 / 回滚分支

### 4. 特殊数据模式

| 模式 | 用例 | 会炸什么 |
|------|------|---------|
| 已排序 / 逆序 | [1,2,3] / [3,2,1] | 快排退化、贪心假设失效 |
| 大量重复 | [1,1,1,2,2] | 去重逻辑、双指针跳过条件 |
| 非严格递增 | [1,2,2,3] | 把「严格」写成了 `≤` |
| 极端稀疏 | [1, 1000000] | 拿值当下标开数组直接爆内存（要离散化） |
| 全同一个值 | [5,5,5,5] | 除以「不同值个数」时除零 |

### 5. 按算法类型的必测点

| 算法类型 | 必测点 |
|---------|--------|
| 排序 | 已排序、逆序、重复元素、单元素、是否要求稳定 |
| 二分 | 目标不存在、目标在两端、多个相等值、答案正好是上下界 |
| 双指针 / 滑窗 | 窗口从未满足条件、整个数组都满足、长度 1 |
| DP | 初始化边界 `dp[0]`、无解时返回 -1 还是 0、只有一个物品 |
| 图论 | 单点图、不连通、自环、重边、有向环、n 个点 0 条边 |
| 字符串 | 空串、单字符、全相同、含空格 / 特殊字符、大小写 |
| 树 | 单节点、只有左链（退化成链表）、完全二叉树、空树 |

### 6. 提交前检查清单（每题过一遍）

```
□ n = 1 / 只有一个元素能跑对
□ 空输入、空串、空集合不抛异常
□ 数据范围上限不溢出（累加器、乘积一律 long）
□ 数组开够大（下标从 1 开始要开 n+1）
□ i-1 / i+1 会不会越界
□ 除数可能为 0
□ 浮点比较用 epsilon，输出按题目要求保留位数
□ 循环终止条件、递归 base case 存在且正确
□ 比较符号方向没写反（> 写成 <、≥ 写成 >）
□ 多组输入之间全局 / static 变量已清空
□ 输出格式：换行、分隔符、末尾空格、大小写
□ 用 n = 10⁵ 随机数据跑一遍，看会不会 TLE
```

### 7. OJ 环境特有的失分点

- **多组输入没清空状态**：全局数组、`static` 计数器、`StringBuilder` 带着上一组的脏值进入第二组数据。典型症状是「样例全对、提交 WA」。
- **读到 EOF 才停**：组数不确定时用 `while (in.nextToken() != StreamTokenizer.TT_EOF)`，见上文「StreamTokenizer 使用教程」。
- **输出没批量化**：10⁵ 行逐行 `System.out.println` 足以 TLE。攒进 `StringBuilder` 末尾一次输出，或用 `PrintWriter` 并**记得 `flush()`**。
- **`HashMap` 遍历顺序不确定**：要求有序输出时必须显式排序或换 `TreeMap`（见「TreeMap 速查」），别指望 `HashMap` 的迭代顺序。
- **宁可拿部分分**：写不出正解就交暴力。第三题 200 分，暴力拿一半远好过 0 分。

## 十五、Java 机试坑点速查

### 1. 溢出与数值

```java
// int 上限 2147483647 ≈ 2.1×10⁹：10⁵ 个 10⁵ 相加就是 10¹⁰，直接爆
long sum = 0;
for (int x : nums) sum += x;      // ✅ 累加器一律 long

long p1 = (long) a * b;           // ✅ 先转 long 再乘
long p2 = a * b;                  // ❌ 右边算完已截断，赋给 long 也救不回来

int mid1 = (l + r) >>> 1;         // ✅ 无符号右移，l+r 溢出也能得到正确中点
int mid2 = l + (r - l) / 2;       // ✅ 另一种防溢出写法

// 整数除法是「向零截断」，既不是四舍五入也不是向下取整
5 / 2;    //  2
-5 / 2;   // -2（不是 -3！负数场景见上文「上取整恒等式」）

// 浮点不能用 == 比较
if (Math.abs(a - b) < 1e-9) { }   // ✅
// 保留两位输出用 String.format("%.2f", x)，别自己乘 100 取整
```

### 2. 装箱与比较

```java
Integer a = 127, b = 127;   a == b;   // true —— 命中 [-128,127] 的 Integer 缓存
Integer c = 128, d = 128;   c == d;   // false —— 超出缓存，比的是引用
c.equals(d);                          // ✅ 包装类型一律 equals
c.intValue() == d.intValue();         // ✅ 或先拆箱成 int

// 比较器里禁止写 a - b：相减溢出会让排序结果错乱
Arrays.sort(arr, (x, y) -> x[0] - y[0]);                  // ❌
Arrays.sort(arr, (x, y) -> Integer.compare(x[0], y[0]));  // ✅

// map.get 返回 null，自动拆箱成 int 时 NPE
int v1 = map.get(k);                  // ❌ key 不存在直接 NullPointerException
int v2 = map.getOrDefault(k, 0);      // ✅
```

`compareTo` / `compare` 的返回值语义：**负数 = 小于，0 = 相等，正数 = 大于**，升序比较器就是「前者小返回负数」。

### 3. 集合

```java
// 遍历时修改 → ConcurrentModificationException
for (Integer x : list) if (x == 2) list.remove(x);   // ❌
list.removeIf(x -> x == 2);                          // ✅
// ⚠ 更阴的是删「倒数第二个」元素时不抛异常，hasNext() 直接为 false，循环静默提前结束

// List.remove 有两个重载，靠参数类型区分，极易写错
list.remove(2);                    // 删下标 2
list.remove(Integer.valueOf(2));   // 删值为 2 的第一个元素

// contains 用 Set，别用 List
list.contains(x);   // O(n)，10⁵ 次调用 = 10¹⁰ 次比较，必 TLE
set.contains(x);    // O(1)
// 但按下标取值 list.get(i) 是 O(1)，别为了这个换成 Set

map.put(null, 1);   // HashMap 允许一个 null 键；TreeMap 不允许（要比较，直接 NPE）
```

集合遍历删除的完整原理见 [[ConcurrentModificationException 详解（for-each remove 问题）]]。

### 4. 字符串

```java
new String("hello") == "hello";   // false，比的是引用
"hello".equals(s);                // ✅ 常量写在前面还能顺手防 s == null

// 循环里用 + 拼接是 O(n²)（每次新建对象），一律 StringBuilder
StringBuilder sb = new StringBuilder();
sb.append(x);

// split 会丢掉尾部空串！
"a,b,,".split(",");       // 长度 2 → ["a","b"]        ❌ 不是 4
"a,b,,".split(",", -1);   // 长度 4 → ["a","b","",""]  ✅
// 分隔符是正则：split("\\."), split("\\|") 必须转义

s.charAt(i) - '0';        // 字符转数字；char 参与算术会自动提升为 int
```

字符串拼接在不同 JDK 下的编译差异见 [[循环内字符串拼接性能分析（JDK 8 vs JDK 17）]]；StringBuilder 的完整方法速查见 [[机试#十六、StringBuilder / String 速查（字符串题主力）]]。

### 5. 递归与栈

- Java **没有尾递归优化**，递归深度受线程栈限制（默认 512KB~1MB，约 1 万~几万层）。
- `n ≤ 10⁵` 且结构可能退化成链（一条链的树、菊花图、链状图）时，DFS 必然 `StackOverflowError` → **改迭代 + `ArrayDeque` 显式模拟栈**。
- 机试可用的偷懒做法：把逻辑丢进一个大栈线程里跑。

```java
public static void main(String[] args) {
    new Thread(null, () -> solve(), "solve", 1 << 26).start();  // 64MB 栈
}
```

- 递归三查：base case 存在、每次调用规模严格变小、返回值真的被接收了。

栈溢出与 OOM 的区别见 [[StackOverflowError与OutOfMemoryError（虚拟机栈）]]。

### 6. 排序（真实雷区）

| 调用 | 底层算法 | 风险 |
|------|---------|------|
| `Arrays.sort(int[])` 等原始类型 | 双轴快排（Dual-Pivot QuickSort） | **最坏 O(n²)**，OJ 上存在针对性构造的数据能卡到 TLE；不保证稳定 |
| `Arrays.sort(Integer[])` / `Collections.sort` | TimSort（归并变种） | 稳定，保证 O(n log n)，代价是装箱开销 |

`Arrays.sort(int[])` 莫名 TLE 时先怀疑被卡快排，对策是**装箱成 `Integer[]` 再排**，或排序前随机打乱。一般题目不会卡，但这是每年都有人栽的坑。

稳定性只在「多关键字分步排序」时才要求；排原始类型数值时稳不稳定没有区别。相关：上文「ArrayList 排序速查」的大数 `a - b` 坑。

手写排序模板（归并 + 随机化三路快排）见 [[912.排序数组]]——机试手撕排序优先用归并，模板固定且不会被卡。

### 7. 输入输出

```java
// Scanner 慢（正则解析 + 同步），10⁵ 行以上会 TLE
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
String line = br.readLine();

// 纯数字输入的最快选择：StreamTokenizer（见上文第八节完整教程）
StreamTokenizer in = new StreamTokenizer(new BufferedInputStream(System.in));
in.nextToken();
int n = (int) in.nval;
```

三档速度：`Scanner` ≪ `BufferedReader` ＜ `StreamTokenizer`。数字用 StreamTokenizer，字符串用 BufferedReader。

### 8. 一句话记忆

| 数字 / 结论                                        | 用途                  |
| ---------------------------------------------- | ------------------- |
| `Integer.MAX_VALUE` = 2³¹−1 = 2147483647       | 超过 2.1×10⁹ 一律 long  |
| `Long.MAX_VALUE` ≈ 9.2×10¹⁸                    | long 也有上限，连乘时仍要估算   |
| Integer 缓存区间 = [−128, 127]                     | 包装类型永远别用 `==`       |
| `List.contains` O(n) / `HashSet.contains` O(1) | 判重换 Set             |
| String 不可变                                     | 循环拼接换 StringBuilder |
| `compare` 返回负 / 0 / 正 = 小于 / 等于 / 大于           | 写比较器不用猜方向           |
| 递归深度上限约 1 万~几万                                 | 10⁵ 规模的链式 DFS 必须改迭代 |

## 十六、StringBuilder / String 速查（字符串题主力）

> 循环拼接一律用 StringBuilder（见上文「4. 字符串」）；`reverse()` / `deleteCharAt()` 是回文、模拟、大数运算题的常用招式。

### 构造与清空

| 写法 | 说明 |
|------|------|
| `new StringBuilder()` | 默认容量 16，扩容按 `2 × 旧容量 + 2` |
| `new StringBuilder("abc")` | 用字符串初始化，容量 = `len + 16` |
| `new StringBuilder(100)` | 预分配容量，**已知结果长度时用**，避免多次扩容拷贝 |
| `sb.setLength(0)` | **清空但保留底层数组**，多组输入/多轮循环首选（比 `new` 快） |
| `sb.delete(0, sb.length())` | 等价清空，可读性差，少用 |

### 常用 API

| 方法 | 作用 | 复杂度 |
|------|------|--------|
| `append(x)` | 追加任意类型（char/String/int/…），返回 this，可链式 | 均摊 O(1) |
| `insert(i, x)` | 在下标 i 处插入 | O(n) |
| `setCharAt(i, c)` | 改下标 i 的字符 | O(1) |
| `charAt(i)` | 取下标 i 的字符 | O(1) |
| `deleteCharAt(i)` | 删下标 i 的字符 | O(n) |
| `delete(l, r)` | 删 `[l, r)` 区间 | O(n) |
| `replace(l, r, s)` | 用 s 替换 `[l, r)` | O(n) |
| `reverse()` | 原地反转，返回 this | O(n) |
| `substring(l, r)` | 返回 **String**（新对象，不是 StringBuilder） | O(n) |
| `indexOf(s)` / `lastIndexOf(s)` | 查子串，找不到返回 −1 | O(n) |
| `length()` | 当前字符数（是方法，不是字段） | O(1) |
| `toString()` | 转成 String | O(n) |

### 机试高频用法

```java
// 1. 反转字符串 / 回文判断
String rev = new StringBuilder(s).reverse().toString();
boolean isPal = s.equals(rev);

// 2. append(char) 和 append(int) 完全不同（坑！）
sb.append('a');        // 追加字符 → "a"
sb.append(97);         // 追加数字 97 → "97"，不是 'a'
sb.append((char) 97);  // 强制转 char 才是 "a"

// 3. 逐位构造（大数加法 / 进制转换）
for (int i = a.length() - 1; i >= 0; i--) sb.append(digit[i]);

// 4. 多组输入清空复用
sb.setLength(0);

// 5. 结果一次输出（避免 10⁵ 次 println TLE）
System.out.print(sb);
```

### 坑点

- **`length` 是方法**：`sb.length()`，写成 `sb.length` 编译不过（只有数组才是 `arr.length`）。
- **`reverse()` 原地改并返回 this**：`new StringBuilder(s).reverse()` 不会动原串 `s`；但对同一个 `sb` 连调两次会转回来。
- **`substring()` 返回 String 不是 StringBuilder**，链式调用会断在类型上。
- **比较内容必须 `toString().equals(...)`**：StringBuilder 没覆写 `equals`，`sb1 == sb2` 比的是引用。
- **`append(null)` 会写入字面量 `"null"`**（4 个字符），不是空串。
- **非线程安全**：单线程机试用 StringBuilder；多线程才用 StringBuffer（方法同步，更慢）。

关联：[[循环内字符串拼接性能分析（JDK 8 vs JDK 17）]]。

## 十七、Java 类初始化顺序（笔试/机试常考）

> **一句话：** 类初始化时，JVM 把**静态变量赋值语句**和**静态代码块**按它们在源码里出现的先后顺序，合并成一个 `<clinit>()` 方法，从头到尾跑一遍。**谁写在后面谁后执行，谁在后面谁覆盖**。

### 验证代码

```java
public class StaticOrderDemo {
    static int a = initA();        // ① 静态变量赋值（位置在前）

    static {                       // ② 静态代码块
        System.out.println("static block: a = " + a);
        b = 20;
    }

    static int b = initB();        // ③ 静态变量赋值（位置在后）

    static int initA() {
        System.out.println("initA");
        return 10;
    }

    static int initB() {
        System.out.println("initB");
        return 30;
    }

    public static void main(String[] args) {
        System.out.println("main: a = " + a + ", b = " + b);
    }
}
```

**输出：**

```
initA
static block: a = 10
initB
main: a = 10, b = 30
```

### 三个关键点

1. **按源码顺序执行**，不是"所有赋值先跑完再跑块"。合并成 `<clinit>()` 后从头跑一遍，所以是 ①→②→③。

2. **能证明顺序的是 `b` 的值**：静态块里先 `b = 20`，但 `b` 的赋值语句写在块**后面**，`static int b = initB()` 后执行又把 `b` 覆盖成 **30**。最终打印 `b = 30` 而不是 20。若顺序反过来（赋值在前、块在后），`b` 最终就是 20——**谁在后面谁覆盖**。

3. **`a` 的赋值在块之前**，所以块里读到的是 `10`，不是默认值 0。

### 配套结论（常一起考）

| 场景 | 行为 |
|------|------|
| `类名.class` | 编译期确定类型，**不触发**类初始化 |
| `Class.forName(name)` | 默认**加载并初始化**（跑 `<clinit>`） |
| `Class.forName(name, false, loader)` | 只加载不初始化 |
| `ClassLoader.loadClass(name)` | **只加载不初始化**，`<clinit>` 延迟到首次主动使用（`new` / 调静态方法 / 访问静态字段） |

经典用例：JDBC 驱动加载 `Class.forName("com.mysql.cj.jdbc.Driver")` 就是利用驱动类静态块向 `DriverManager` 注册自己。

关联：[[Java基础热门面试题-1]]（反射与注解一节 · `Class.forName` vs `loadClass`）。
