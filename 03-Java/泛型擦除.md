
### **类型擦除是 Java 泛型的一种编译期优化机制，它在编译后的字节码中移除泛型类型信息，保持与非泛型代码的兼容性**

## 类型擦除的核心作用

**1. 向后兼容性**

Java 5 引入泛型时，需要与 Java 1.4 及之前的非泛型代码兼容。通过类型擦除，泛型代码编译后的字节码与非泛型代码完全一致，这样就不需要改变 JVM 和运行时环境。

```java
// 泛型代码
List<String> list = new ArrayList<>();
list.add("hello");

// 编译后被擦除为
List list = new ArrayList();
list.add("hello");
```

**2. 减少运行时开销**

如果 JVM 在运行时维护泛型信息，会增加内存占用和性能开销。通过类型擦除，泛型只存在于编译期，运行时没有额外负担。

**3. 简化 JVM 设计**

不需要为泛型在 JVM 层面做特殊处理，保持 JVM 的简洁性和稳定性。

## 类型擦除的具体过程

编译器会按照以下规则进行擦除：

**无界类型参数 → Object**

```java
public class Box<T> {
    private T value;
}
// 擦除后
public class Box {
    private Object value;
}
```

**有界类型参数 → 上界**

```java
public class NumberBox<T extends Number> {
    private T value;
}
// 擦除后
public class NumberBox {
    private Number value;
}
```

**方法中的泛型 → 插入强制转换**

```java
public <T> T getValue(Box<T> box) {
    return box.get();  // 返回 T
}
// 擦除后
public Object getValue(Box box) {
    return (T) box.get();  // 编译器插入强制转换
}
```

## 类型擦除带来的限制

正因为类型擦除，Java 泛型有一些你可能会遇到的限制：

**不能创建泛型数组**

```java
// ❌ 编译错误
List<String>[] arrays = new List<String>[10];

// ✅ 可以用通配符
List<?>[] arrays = new List<?>[10];
```

**不能使用基本类型作为类型参数**

```java
// ❌ 编译错误
List<int> list = new ArrayList<>();

// ✅ 用包装类
List<Integer> list = new ArrayList<>();
```

**运行时无法获取泛型信息**

```java
List<String> list = new ArrayList<>();
// ❌ 运行时获取不到 String 类型信息
if (list instanceof List<String>) { }  // 编译错误

// ✅ 只能这样检查
if (list instanceof List) { }  // 可以，但不知道具体的类型参数
```

**不能在 catch 中使用泛型异常**

```java
// ❌ 编译错误
try {
    // ...
} catch (List<String> e) {
    // ...
}
```

## 总结

类型擦除是 Java 泛型的折中方案：在**编译期提供类型安全检查**，但在**运行时完全移除泛型信息**。这样既保证了代码的类型安全，又不增加运行时开销，还维持了与旧代码的兼容性。虽然这带来了一些限制，但对于绝大多数实际应用场景来说，已经足够了。
