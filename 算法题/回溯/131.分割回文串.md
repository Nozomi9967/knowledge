### **LeetCode 131「分割回文串」是「回溯枚举切割点 + 预判回文」的组合：回溯负责枚举所有切法（每个位置切或不切），预处理一张 `isPal[i][j]` 表让回文判断变成 O(1)，整体从暴力的 O(n·2^n) 降到 O(2^n)。**

### **一、问题本身**

把字符串切成若干段，要求每段都是回文，返回所有切法。

```
s = "aab"
[a,a,b] / [aa,b]  →  两种
```

---

### **二、为什么需要预处理回文表**

如果每次切完都去判断「这一段是不是回文」，单次判断 O(n)，总复杂度会退化成 O(n·2^n)（n=16 时就接近千万级），虽然本题 n ≤ 16 能过，但这是一种浪费。

**回文判断本身可以做 DP 预处理**：

```
isPal[i][j] = (s[i] == s[j]) && (j - i <= 2 || isPal[i+1][j-1])
```

含义：两端字符相同，且里面那段（或长度 ≤ 3 的退化情况）也是回文。`j - i <= 2` 覆盖了长度 1（`i==j`）、长度 2（`i+1==j`）、长度 3（`i+1==j-1`）三种必然回文的情况。

**这个式子的遍历顺序必须是 `i` 从大到小、`j` 从小到大**，因为 `isPal[i][j]` 依赖 `isPal[i+1][j-1]`（左下方）。

---

### **三、代码**

```java
class Solution {
    public List<List<String>> partition(String s) {
        int n = s.length();
        boolean[][] isPal = new boolean[n][n];

        // 预处理：i 从后往前，j 从 i 到 n-1
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                if (s.charAt(i) == s.charAt(j) && (j - i <= 2 || isPal[i + 1][j - 1])) {
                    isPal[i][j] = true;
                }
            }
        }

        List<List<String>> res = new ArrayList<>();
        backtrack(s, 0, isPal, new ArrayList<>(), res);
        return res;
    }

    private void backtrack(String s, int start, boolean[][] isPal,
                           List<String> path, List<List<String>> res) {
        if (start == s.length()) {          // 切到末尾，收集一组解
            res.add(new ArrayList<>(path));
            return;
        }
        for (int end = start; end < s.length(); end++) {
            if (!isPal[start][end]) continue;   // 剪枝：这一段不是回文，直接跳过
            path.add(s.substring(start, end + 1));
            backtrack(s, end + 1, isPal, path, res);
            path.remove(path.size() - 1);       // 回溯
        }
    }
}
```

**回溯的关键结构**：`start` 表示"下一段从哪开始"，`end` 枚举"当前段到哪结束"。选了一个合法的回文段就递归处理 `end+1`，回来时撤销选择。

---

### **四、复杂度**

| 项 | 复杂度 |
|---|---|
| 预处理 | O(n²) |
| 回溯 | O(n · 2^n) —— n 个位置每个有两种状态（切/不切），每组解拷贝 O(n) |
| 空间 | O(n²)（回文表） + O(n)（递归栈） |

n ≤ 16 时 2^16 = 65536，完全可行。

### **五、另一种思路：中心扩展判回文**

不预处理，而是在回溯时用双指针现场判断：

```java
private boolean isPalindrome(String s, int l, int r) {
    while (l < r) {
        if (s.charAt(l++) != s.charAt(r--)) return false;
    }
    return true;
}
```

代码更短，但每次判断 O(n)，总复杂度 O(n · 2^n) 的常数更大。**如果 n 很小（≤ 16），这种写法更清晰；如果 n 到 2000（如 132 题求最少切割次数），就必须用 DP 而不是回溯了。**

---

### **六、易错点**

1. **回文表遍历顺序错**：`i` 必须从 `n-1` 往下，因为依赖 `i+1`
2. **`j - i <= 2` 漏了**：小于等于 2 时不用看内部，直接判定为回文
3. **回溯时忘了 `remove`**：路径污染，所有结果都会变长
4. **`res.add(path)` 而不是 `new ArrayList<>(path)`**：存的是引用，最后全是空列表
5. **`start == s.length()` 作为终止条件**：是 `==` 不是 `>=`，虽然 `>=` 也不会错
6. **和 132 混淆**：132 只问「最少切几刀」，用一维 DP（`dp[i]` = 前 i 个字符的最少切割数）而不是枚举所有方案

---

### **七、进阶：132 题的最少切割**

如果题目改成"求最少切割次数"，回溯就不可行了（n 到 2000），要换成 DP：

```java
// dp[i] = 前 i 个字符的最少切割次数
// dp[i] = min(dp[j] + 1) 对所有 isPal[j][i-1] 为 true 的 j
```

**同一个回文预处理表，两种用法**：131 拿它剪枝枚举方案，132 拿它做 DP 转移。
