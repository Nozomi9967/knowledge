### **星际跃迁的稳定信标 — 最大和谐频率 + 质数数位和**

核心思路是**拆成两个子问题**：① 用 LeetCode 738 模板求"不超过 f 的最大各位非递减数"（从右往左扫描，遇逆序减位并标记，其后全填 9）；② 判断该数的数位和是否为质数（数位和上限 162，试除极快）。主流程反复取最大和谐频率、不满足就减一继续，直到找到解或 f ≤ 0。时间复杂度近似 $O(18 \times \sqrt{162})$ 每次，空间 $O(18)$。

---

### **一、题目概述**

星际舰队需锁定一个"跃迁信标频率" $f$（正整数），在引擎最大频率 $F_{max}$ 范围内找满足多重约束的**值最大**的频率。

频率 f 必须同时满足三个条件：

1. **频率上限**：$f \le F_{max}$，且 $1 \le F_{max} \le 10^{18}$。
2. **和谐频率**：f 的各位数字从高位到低位**非递减**。例如 `123`、`111`、`399` 是和谐频率；`121`、`897` 不是。
3. **质数能量签名**：$S(f) = f$ 的各位数字之和，必须为质数。

**输出**：满足全部条件的最大和谐频率 f；若不存在则返回 `-1`。

**示例：**

| 输入 | 输出 | 说明 |
|------|------|------|
| `888` | `788` | 数位和 7+8+8=23 为质数 |

求解路径：`888`(和 24 非质) → `799`(和 25 非质) → `789`(和 24 非质) → `788`(和 23 质数)。

---

### **二、核心思路**

本题分两个子问题：求"不超过某值的最大和谐频率"，以及"判断数位和是否为质数"。

#### **子问题 1：最大和谐频率（LeetCode 738 单调递增数字）**

给定 f，求 $\le f$ 的最大各位非递减数。采用**从右往左**扫描：

- 遇到 `a[i] < a[i-1]` 时，令 `a[i-1]--` 并记录位置 `mark = i`。
- 扫描完成后，将 `mark` 及之后的所有位填 `9`。
- 这样减 1 的连锁反应会自动向左传播，保证结果是合法的非递减序列。

> 注意：从左往右只改一处不向左回溯是错的，例如 `3329` 会错误返回 `3299`（3>2 不合法）。

#### **子问题 2：数位和质数判定**

- 累加各位数字得到 `sum`。
- `sum < 2` 直接返回 `false`（0、1 非质数）。
- 用 $O(\sqrt{sum})$ 试除判定。

> 注意：判断对象是**数位和**，不是原数本身；原数最大为 $10^{18}$，数位和最大为 $18 \times 9 = 162$，试除很快。

#### **主流程**

从 $F_{max}$ 出发，反复取"不超过当前值的最大和谐频率"，检查数位和是否为质数：

- 是 → 输出该值。
- 否 → 令 $f = t - 1$，继续向更小候选搜索。
- 直到 $f \le 0$ 仍无解，输出 `-1`。

> 复杂度：非递减数总数有限（18 位以内约 $\binom{27}{9} \approx 312$ 万个），每次 `findUp` 为 $O(18)$，6 秒内足够。

### **三、完整代码**

```java
import java.util.*;

public class Main {

    // 不超过 f 的最大和谐频率（各位非递减）
    public static long findUp(long f){
        if(f < 10) return f;                      // 一位数本身就是和谐的
        char[] a = Long.toString(f).toCharArray();
        int n = a.length;
        int mark = n;                              // mark 之后全部置 '9'
        for(int i = n - 1; i > 0; i--){            // 从右往左
            if(a[i] < a[i-1]){
                a[i-1]--;
                mark = i;                          // 标记减 1 的位置
            }
        }
        for(int i = mark; i < n; i++) a[i] = '9';
        long res = 0;
        for(int i = 0; i < n; i++){
            if(res == 0 && a[i] == '0') continue;  // 跳过高位被减成 0 的前导 0
            res = res * 10 + (a[i] - '0');
        }
        return res;
    }

    // 数位和是否为质数
    public static boolean isZhi(long f){
        int sum = 0;
        while(f != 0){
            sum += f % 10;
            f /= 10;
        }
        if(sum < 2) return false;                 // 0、1 不是质数
        for(int i = 2; (long)i * i <= sum; i++){
            if(sum % i == 0) return false;
        }
        return true;
    }

    public static void main(String[] args){
        Scanner sc = new Scanner(System.in);
        long f = sc.nextLong();
        while(f > 0){
            long t = findUp(f);
            if(isZhi(t)){
                System.out.print(t);
                return;
            }
            f = t - 1;                             // 找下一个更小的和谐频率
        }
        System.out.print(-1);
    }
}
```

### **四、一个具体例子走一遍**

**`F_max = 888`：**

1. `findUp(888)`：从右往左扫，"8<8"、"8<8" 都不满足（相等不算逆序），mark 保持 n → 返回 888。`isZhi(888)`：和 24，非质数。

   实际流程按示例：`findUp(888)=888`（和24非质）→ `f=887`，`findUp(887)=779`（和23质数）→ 输出 779？

   检查 findUp(888)：从右往左扫 `[8,8,8]`，`a[2] < a[1]`？8<8 否。`a[1] < a[0]`？8<8 否。mark=n → 返回 888。没错，findUp(888)=888。

   但 888 的数位和 24 非质数 → 主循环 `f = 887` → findUp(887)：`[8,8,7]`，`a[2]=7 < a[1]=8` → a[1]=7，mark=2；`a[1]=7 < a[0]=8` → a[0]=7，mark=1 → 填 9 → 779 → 和 23 质数 → 输出 779？

   重新手算 findUp(887)：char[] = ['8','8','7']，n=3，mark=3。
   - i=2: a[2]='7' < a[1]='8' → a[1]-- → '7'，mark=2
   - i=1: a[1]='7' < a[0]='8' → a[0]-- → '7'，mark=1
   - 填 9：a[1..2] = '9','9' → "799"

   findUp(887) = 799，不是 779！我之前算错了。799 数位和 25 非质数 → f=798 → findUp(798)：['7','9','8']，i=2: '8'<'9' → a[1]='8'，mark=2；i=1: '8'<'7'？否。填 9：a[2]='9' → "789"。和 24 非质 → f=788 → findUp(788)：['7','8','8']，无逆序 → 788，和 23 质数 → 输出 788 ✓

   完美，和示例一致。走例：
   - 888 → 和24 非质

### **五、复杂度分析**

- **时间复杂度**：每次 `findUp` $O(18)$，质数判定 $O(\sqrt{162})$。主循环最多迭代到无解（约 312 万个非递减数），最坏 $O(\binom{27}{9} \times 18)$，6 秒内足够。
- **空间复杂度**：$O(18)$，只存数字字符数组。

---

### **六、易错点**

1. **一位数直接返回 0**：用 `while(f!=0)` 把 f 消成 0 后再 `if(d.size()==1) return f;` 会返回 0，导致 $F_{max}=2$ 这种本应输出 2 的用例被判 `-1`。
2. **只向右改不向左传播**：从左往右扫，第一次遇到 `a>b` 只把 `a--` 后填 9，不检查减 1 后是否破坏左边非递减，会产生非法解（如 `3299`）。
3. **质数判定的对象错位**：误用原数而非数位和判断，`sum<2` 的情况会漏判。
4. **前导 0 处理**：高位被减成 0 时，拼数时需跳过，否则可能得到位数不对的结果。

### **七、面试话术**

1. **为什么从右往左扫？** — 逆序对 `a[i] < a[i-1]` 必须把左边那位减 1 才能恢复非递减；减 1 后可能又破坏更左边的非递减，从右往左扫会让"连锁减位"自然传播，且最终 `mark` 之后全填 9 保证最大。
2. **为什么数位和判质数很快？** — $F_{max} \le 10^{18}$ 最多 18 位，数位和上限 $18 \times 9 = 162$，$\sqrt{162} \approx 12.7$，试除至多 12 次。
3. **主循环为什么能保证找到最优？** — `findUp(f)` 返回 $\le f$ 的最大和谐数，若它不满足质数条件，任何更大的和谐数都已排除（它就是最大的），只需在 `f = t - 1` 的范围内继续，因此第一个命中的就是全局最大解。
4. **与 LeetCode 738 的关系** — 738 只求"最大单调递增数字"，本题在其基础上叠加质数数位和约束并允许向更小搜索，主循环的迭代思想是新增考点。
