树可以看成是一个连通且 **无环** 的 **无向** 图。

给定一个图，该图从一棵 `n` 个节点 (节点值 `1～n`) 的树中添加一条边后获得。添加的边的两个不同顶点编号在 `1` 到 `n` 中间，且这条附加的边不属于树中已存在的边。图的信息记录于长度为 `n` 的二维数组 `edges` ， `edges[i] = [a_i, b_i]` 表示图中在 `ai` 和 `bi` 之间存在一条边。

请找出一条可以删去的边，删除后可使得剩余部分是一个有着 `n` 个节点的树。如果有多个答案，则返回数组 `edges` 中最后出现的那个。

**示例 1：**

![](https://pic.leetcode.cn/1626676174-hOEVUL-image.png)

```
输入: edges = [[1,2], [1,3], [2,3]]
输出: [2,3]
```

**示例 2：**

![](https://pic.leetcode.cn/1626676179-kGxcmu-image.png)

```
输入: edges = [[1,2], [2,3], [3,4], [1,4], [1,5]]
输出: [1,4]
```

**提示:**

- `n == edges.length`
- `3 <= n <= 1000`
- `edges[i].length == 2`
- `1 <= ai < bi <= edges.length`
- `ai != bi`
- `edges` 中无重复元素
- 给定的图是连通的

---



```java
class Solution {

    public int[] findRedundantConnection(int[][] edges) {

        int n=edges.length;

        int[] p=new int[n+1];

        for(int i=1;i<=n;i++) p[i]=i;

  

        for(int[] e:edges){

            int x=e[0],y=e[1];

            int rootX=find(p,x);

            int rootY=find(p,y);

            if(rootX==rootY) return new int[]{x,y};

            union(p,x,y);

        }

  

        return new int[]{1,2};

    }

  

    public int find(int[] p,int x){

        if(p[x]==x) return x;

  

        return p[x]=find(p,p[x]);

    }

  

    public void union(int[] p,int x,int y){

        int rootX=find(p,x);

        int rootY=find(p,y);

        if(rootX!=rootY){

            p[rootX]=rootY;

        }

    }

}
```

## 为什么「第一条成环的边」就是「edges 中最后出现的答案」

初读容易觉得矛盾：题目要「最后出现的那个」，代码却在第一次 `rootX==rootY` 时就 `return`。其实这两句话指向**同一条边**，理由分两步。

### 第一步：可行答案的集合 = 环上的所有边

题目条件是 `n == edges.length`（n 个点、n 条边）且图连通。n 个点连通至少要 n-1 条边，多出来的这 1 条恰好制造**唯一一个环**。

- 删掉环上任意一条边 → 剩下 n-1 条边仍连通且无环 → 是树，**合法答案**
- 删掉环外任意一条边 → 那条边是桥，图断成两块 → **非法**

所以「如果有多个答案」指的就是环上有多条边都能删，答案集合严格等于环边集合。题目要求返回其中在 `edges` 里下标最大的那条。

#### 为什么不会有多个环

题面没有一句「本图只有一个环」，但下面三条任意一条就把它锁死了：

1. **题面其实说过。** 「该图从一棵 n 个节点的树中添加**一条**边后获得」——树本身无环，任意两点间只有唯一路径，加一条边只会在这条路径上闭合出一个环。加一条边，就是一个环。
2. **数据规模不允许第二个。** 连通图的圈秩（独立环个数）= E - V + 1。这里 V = n（节点值 1～n 全都在），E = `edges.length` = n，圈秩 = n - n + 1 = **1**。这不是题目「忘了限制」，而是在这个点数边数下根本数不出第二个环。
3. **否则题目本身无解。** 题目要删**一条**边就得到树。若有 2 个独立环，至少要删 2 条边才能变成树，那这题就不存在合法答案了。

顺带说清这个前提有多要紧：第二步的证明用到了「整图去掉一条环边就是一棵树」，这句只在单环时成立。真拿一个双环图来跑，比如 `[[1,2], [2,3], [1,3], [3,4], [4,5], [3,5]]`（V=5、E=6、连通，圈秩 2，两个环是 1-2-3-1 和 3-4-5-3），代码会在下标 2 的 `[1,3]` 第一次冲突就返回，而下标 5 的 `[3,5]` 其实也是一次冲突——「第一次冲突 = 最后出现的候选」立刻失效。所以这个提前 return 的正确性**建立在题目的单环保证之上**，不是普适结论。

### 第二步：第一次检测到成环的位置，必然就是最后出现的那条环边

设环边在输入中的下标是 i₁ &lt; i₂ &lt; … &lt; iₖ（iₖ 就是最后出现的那条）。

- **在 iₖ 之前不可能冲突。** 处理到 iₖ 之前，已加入的边全部取自「整图去掉边 iₖ」这个集合，而整图去掉一条环边就是一棵树，树的任意子集都是森林——森林无环，所以 `find` 永远撞不上 `rootX==rootY`。
- **到 iₖ 一定冲突。** 此时 i₁…iₖ₋₁ 已全部合并，环上除 iₖ 以外的那条路径已经把它的两个端点连通了，于是 `rootX==rootY` 成立。

第一次冲突不早也不晚，正好落在 iₖ 上。**「第一个被检测到成环」和「最后出现在 edges 中」是同一条边的两种说法**，所以提前 return 不但正确，还省掉了后续遍历。

### 用示例 2 走一遍

`edges = [[1,2], [2,3], [3,4], [1,4], [1,5]]`，环是 1-2-3-4-1，环边下标为 0、1、2、3，最后出现的是下标 3 的 `[1,4]`。

| 处理 | 边 | 两端此前是否同根 | 动作 |
|:---:|:---:|:---:|---|
| edges[0] | [1,2] | 否 | union → {1,2} |
| edges[1] | [2,3] | 否 | union → {1,2,3} |
| edges[2] | [3,4] | 否 | union → {1,2,3,4} |
| edges[3] | [1,4] | **是** | 返回 `[1,4]` ✅ |

示例 1 `[[1,2], [1,3], [2,3]]` 同理：三条边本身就是环，最后出现的 `[2,3]` 正是第一次冲突处，输出 `[2,3]`。

### 一句话面试话术

> 因为 n 个点配 n 条边而且图连通，所以整张图里有且只有一个环，能删的边就只能是环上的边。按输入顺序做并查集的时候，环上最后出现的那条边到来之前，已经加进去的边构成的是森林，不可能成环；而它一到，环上其余部分早就把它的两个端点连通了。所以第一次 `find` 撞上同一个根的那条边，就是环上下标最大的那条，直接返回就行，不用再往后扫。

### 两个实现细节

- 末尾的 `return new int[]{1,2}` 是不可达的兜底分支，题目保证答案一定存在。
- `union` 内部又调了一次 `find`，而循环里已经算出 `rootX/rootY`，可以直接写 `p[rootX]=rootY;` 省掉两次查找。本题 n ≤ 1000，仅路径压缩已足够，不加按秩合并也不会超时。
