### **LeetCode 416「分割等和子集」是 01 背包的判定型：把数组分成两个和相等的子集，等价于「能否从数组里选出若干个数，使它们的和恰好等于 `sum/2`」。`dp[j]` 表示容量 `j` 能否被恰好装满，转移是 `dp[j] = dp[j] || dp[j-num]`，一维数组必须倒序遍历。**

### **一、问题本身**

给一个正整数数组，判断能否分成两个元素和相等的子集。

```
nums = [1,5,11,5]
sum = 22，target = 11
能凑出 11 → [11] 和 [1,5,5]  →  true
```

---

### **二、问题转化（关键一步）**

"分成两个和相等的子集" 等价于 "是否存在一个子集，其和等于 `sum/2`"——因为剩下的那部分和自然也等于 `sum/2`。

于是问题变成：**从数组里挑若干数，能否恰好凑出 `target = sum/2`**。这就是标准的 01 背包「能否装满」问题：物品是数组元素，每个只能用一次，背包容量是 `target`。

---

### **三、两个剪枝（先做，能省很多）**

```java
int sum = 0, max = 0;
for (int x : nums) { sum += x; max = Math.max(max, x); }

if (sum % 2 != 0) return false;          // 和为奇数，不可能平分
int target = sum / 2;
if (max > target) return false;          // 单个元素超过一半，它自己就装不下
```

第二个剪枝很重要：`nums = [1,2,5]` 时 `sum=8`、`target=4`，但 5 > 4，直接返回 false，省掉整个 DP。

---

### **四、状态定义与代码**

**状态**：`dp[j]` = 能否用数组中已遍历的元素凑出和 `j`（布尔）。

**转移**（对每个数 `num`，从 `target` 倒序到 `num`）：

```
dp[j] = dp[j] || dp[j - num]
```

含义是"不选 num 也能凑出 j" 或者 "选了 num 之后剩下的 j-num 能凑出"。

```java
class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0, max = 0;
        for (int x : nums) { sum += x; max = Math.max(max, x); }
        if (sum % 2 != 0) return false;
        int target = sum / 2;
        if (max > target) return false;

        boolean[] dp = new boolean[target + 1];
        dp[0] = true;                       // 和为 0 总可以（一个都不选）

        for (int num : nums) {
            for (int j = target; j >= num; j--) {   // 必须倒序
                dp[j] = dp[j] || dp[j - num];
            }
        }
        return dp[target];
    }
}
```

---

### **五、为什么必须倒序（高频追问）**

一维 01 背包的核心陷阱：如果**正序**遍历 `j`，`dp[j-num]` 可能已经被本轮刚更新的值污染——那等于同一个数被用了多次，变成了「完全背包」。

举例：`nums = [1]`，`target = 2`。正序时 `dp[1] = dp[1] || dp[0] = true`，接着 `dp[2] = dp[2] || dp[1] = true`——但数组里只有一个 1，不可能凑出 2。这就是"一物多用"的错误。

倒序时，`dp[j-num]` 永远是上一轮（还没考虑当前 num）的状态，保证每个数只用一次。

**记法：01 背包倒序，完全背包正序。**

---

### **六、复杂度与易错点**

| 项 | 复杂度 |
|---|---|
| 时间 | O(n × target)，target = sum/2 |
| 空间 | O(target) |

**易错点**：

1. **忘了判奇偶**：和为奇数直接 false
2. **忘了 `max > target` 剪枝**：能做出来但慢，且某些用例会误判（DP 本身不会错，只是浪费）
3. **正序遍历**：变成完全背包，答案偏乐观
4. **`dp[0] = true` 漏了**：只有和为 0 可行，其他全 false，结果永远是 false
5. **`target` 可能为 0**（数组只有一个 0）：`sum=0` 是偶数，`target=0`，`dp[0]=true` 返回 true，逻辑正确

### **七、延伸：从判定到求方案**

- **494 目标和**：给每个数加正负号凑 target，本质是同一个 01 背包，只是转移从"或"变成"加法计数"
- **1049 最后一块石头的重量 II**：也是划分等和子集，求 `sum - 2×最接近一半的子集和`
- **如果要输出具体方案**（哪些数凑成了 target）：需要二维 dp 加回溯，一维滚动存不下路径
