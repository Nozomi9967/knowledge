# 图

## 一、邻接矩阵存储

用一个 $n \times n$ 的二维数组 `a[][]` 表示 n 个顶点的图，`a[i][j]` 记录顶点 i 到顶点 j 的边：

- **无权图**：有边记 1，无边记 0
- **带权图**：有边记权值 w，无边记 0 或 $\infty$
- **主对角线** `a[i][i]`：无自环时恒为 0

**空间复杂度固定 $O(n^2)$**，与边数无关——所以边少的稀疏图更适合用邻接表存，稠密图才用邻接矩阵。

### 无向图 → 对称矩阵

无向图里「i 和 j 相连」等价于「j 和 i 相连」，所以 `a[i][j] = a[j][i]` 恒成立，矩阵**关于主对角线对称**。这就是本题答案。

> 有向图不保证对称：i→j 有边不代表 j→i 有边，所以有向图的邻接矩阵一般不对称。

## 二、邻接矩阵 vs 邻接表

**邻接表**：给每个顶点挂一条链表（或动态数组），链表里存它的所有邻居。无向图里一条边 `(u,v)` 会在 u 和 v 两条链表里各存一次，所以共 $2e$ 个表项（e 为边数）。

记 n = 顶点数、e = 边数、$deg(u)$ = 顶点 u 的度：

| 操作 / 维度 | 邻接矩阵 | 邻接表 |
| --- | --- | --- |
| 空间 | $O(n^2)$（与边数无关） | $O(n+e)$（无向图存 $2e$ 项） |
| 判断 u、v 是否相邻 | $O(1)$ 直接查 `a[u][v]` | $O(deg(u))$ 遍历 u 的链表 |
| 遍历 u 的所有邻居 | $O(n)$ 扫一整行（含大量 0） | $O(deg(u))$ 只走真实邻居 |
| 加一条边 | $O(1)$ | $O(1)$ 头插 |
| 删一条边 | $O(1)$ | $O(deg(u))$ 先找到再删 |
| 适用场景 | 稠密图、频繁查「两点是否相邻」 | 稀疏图、以「遍历邻居」为主 |

**怎么选：**

- 稠密图（$e$ 接近 $n^2$），或算法核心是「频繁判断任意两点是否相邻」→ 邻接矩阵，$O(1)$ 查询且缓存友好。
- 稀疏图（$e \ll n^2$，现实里绝大多数图都是）→ 邻接表，空间省、遍历邻居快。
- **绝大多数图算法（BFS、DFS、Dijkstra、拓扑排序）都在「遍历某点的邻居」，所以默认用邻接表**——这也是 LeetCode 图题几乎清一色建邻接表的原因（见 [[207.课程表]]）。

> [!tip] 一句话记忆
> 矩阵是「查得快、费空间」，表是「省空间、遍历快」。图稀疏就用表，图稠密或狂查相邻就用矩阵。

## 附：无向完全图

**定义：** 任意两个不同顶点之间都有一条边相连的无向图。

- **边数**：$n$ 个顶点的无向完全图有 $\dfrac{n(n-1)}{2}$ 条边。
- **每个顶点的度**：都是 $n-1$（和其余 $n-1$ 个顶点各连一条）。
- **邻接矩阵**：除主对角线上为 0 外，其余全为 1，故它是**稠密**（绝不稀疏）且**对称**的矩阵——这也解释了上面例题 B 错的原因。
- **记忆**：$n$ 个点两两连线，就是 $n$ 选 2，即 $C_n^2 = \dfrac{n(n-1)}{2}$。

## 三、例题

> [!question] 若采用邻接矩阵存储一个 n 个顶点的无向图，则该邻接矩阵是一个（ ）
> A. 上三角矩阵　B. 稀疏矩阵　C. 对角矩阵　D. 对称矩阵
>
> **答案：D（对称矩阵）**

**逐项分析：**

- **A 上三角矩阵** ❌：上三角要求主对角线**以下**元素全为 0；无向图邻接矩阵下三角有值（和上三角镜像相等），不可能只有上三角有值。
- **B 稀疏矩阵** ❌：稀疏只是「可能」而非「必然」——完全图除主对角线外全是 1，是稠密矩阵。
- **C 对角矩阵** ❌：对角矩阵要求非主对角线元素全为 0；只要图里有任意一条边，主对角线之外就有非零元素。
- **D 对称矩阵** ✅：由无向图 `a[i][j]=a[j][i]` 的本质决定。

## 四、几种特殊矩阵定义速查

设主对角线为从左上到右下的 `a[i][i]`：

| 矩阵类型 | 定义 | 一句话记忆 |
| --- | --- | --- |
| 对称矩阵 | 满足 `a[i][j] = a[j][i]`，关于主对角线镜像对称 | 沿主对角线对折能重合 |
| 上三角矩阵 | 主对角线**以下**元素全为 0（只有上半 + 对角线有值） | 值都在右上 |
| 下三角矩阵 | 主对角线**以上**元素全为 0（只有下半 + 对角线有值） | 值都在左下 |
| 对角矩阵 | 除主对角线外元素全为 0 | 只有对角线有值 |
| 稀疏矩阵 | 非零元素远少于零元素（经验上非零占比 &lt; 5%），是**相对/不必然**的描述 | 零多得压倒性 |

**几个易混辨析：**

- **对称 ≠ 上三角**：对称是「上下两半镜像相等」，上三角是「下半全 0」；两者只有当矩阵退化为对角矩阵时才可能同时成立。
- **对角矩阵是上三角、也是下三角的特例**（上半下半都为 0，只剩对角线）。
- **稀疏是「量」的相对概念**，没有硬性阈值；上三角 / 对角 / 对称是「结构」上的绝对定义。完全图的邻接矩阵是对称的，但绝不稀疏。

## 五、笔试易错点

1. **别把对称看成上三角**——本题最大的坑。无向图两个方向都有值，是对称不是上三角。
2. **稀疏不必然**——看到「稀疏」先警惕，它依赖边的多少，不是无向图的固有属性。
3. **有向图邻接矩阵一般不对称**，别把无向图的结论套到有向图上。
4. **存储选型**：邻接矩阵 $O(n^2)$ 空间、判断两点是否相邻 $O(1)$；稀疏图省空间用邻接表，但判相邻要遍历链表。

## 六、最小生成树（MST）

**先定义生成树**：连通图的**生成树**，是包含全部 n 个顶点、恰好 **n−1** 条边、且**无环**的极小连通子图——少一条边就不连通，多一条边就成环。**最小生成树（Minimum Spanning Tree, MST）**则是所有生成树里**边权之和最小**的那一棵，解决的是"用最低成本把所有点连成一片"的问题（如铺路、拉网线、建电网）。

**三条必记性质：**

- **边数固定**：n 个顶点的生成树恰好 **n−1** 条边。
- **权值唯一、树形不一定唯一**：MST 的**总权值是唯一**的，但存在**等权边**时可能有多棵不同的 MST。
- **权值互不相同 → MST 唯一**：所有边权两两不等时，MST 唯一。

**两大贪心算法**——都用贪心，区别在"**从一个点往外扩**"还是"**从全局边里挑**"：

### ① Prim（普里姆）——点驱动

从一个起点开始，每次从"还没入树的点"里挑一个**离当前生成树最近的点**，连同那条最短的边一起并入树，直到 n 个点全部入树。

- 适合**稠密图**（点少、边多）。
- 朴素实现 $O(n^2)$；用堆维护候选边可优化到 $O(e\log n)$。

### ② Kruskal（克鲁斯卡尔）——边驱动

把**所有边按权值从小到大排序**，依次尝试加入：如果这条边两端**不在同一个连通块**，就加入；否则跳过（会成环）。直到选够 **n−1** 条边为止。

- 适合**稀疏图**。
- 复杂度 $O(e\log e)$，主要开销在**排序**上。
- 判"两端是否已连通"用 **并查集**——这是并查集最经典的应用。（见 [[684. 冗余连接 - 力扣（LeetCode）]]）

两种算法对比：

| 维度 | Prim | Kruskal |
| --- | --- | --- |
| 驱动方式 | 从点扩张 | 从边挑选 |
| 主要数据结构 | 优先队列 / 最短边数组 | 排序 + 并查集 |
| 时间复杂度 | 朴素 $O(n^2)$、堆优化 $O(e\log n)$ | $O(e\log e)$ |
| 适合图 | **稠密图**（$e$ 接近 $n^2$） | **稀疏图**（$e \ll n^2$） |
| 实现要点 | 维护每个点"到生成树的最短边" | 排序后并查集判环 |

> [!tip] 一句话记忆
> **点少边多用 Prim，边少点多用 Kruskal**；Kruskal 的本质就是"**排序 + 并查集**"，按边权从小到大能加就加。

**为什么贪心一定得到全局最优？** 靠两条性质撑住：

- **切割性质（cut property）**：把点集任意切成两部分，横跨这条"切割"的**最小权边**，一定在某棵 MST 里。
- **环性质（cycle property）**：任意一个环里**权值最大的那条边**，一定不在任何 MST 里（除非有等权边）。

Prim 每次在"已入树点 vs 未入树点"这个切割上取最小边；Kruskal 每次挑的边等价于避开环里最大边——所以两者都能得到最优解。

**易错点：**

- **MST 不等于最短路**：MST 保证的是"全图连通总成本最小"，**不保证任意两点间路径最短**；求点对最短路要用 Dijkstra / Floyd，别和 MST 混（见 [[3604. 有向图中到达终点的最少时间 - 力扣（LeetCode）]]）。
- **Kruskal 选够 n−1 条边就停**，不是把所有能加的边都加进去。
- **图不连通时没有生成树**（也就没有 MST），此时求的是"**最小生成森林**"。
- **等权边会导致多解**，题目问"唯一吗"先看有没有等权边。
