## 一、基础概念与数据类型（6 题）

### 1. JVM、JDK、JRE 三者是什么关系？【高频】

> **知识点跳转：** [[Java基础面试题#JVM、JDK、JRE三者关系？]]

**追问：** Java 是解释执行还是编译执行？为什么说它"解释和编译都有"？

---

**参考答案 ✅**

这三个的关系我从包含和分工来说。**JRE** 是 Java 运行环境，里面是 JVM 加上核心类库，只有运行需求的人装它就够了；**JDK** 是 Java 开发工具包，它**包含了整个 JRE**，还额外加了 javac 编译器、调试器、javadoc 这些开发工具。所以三者是层层包含的关系：**JDK 包含 JRE，JRE 包含 JVM**。JVM 在最底层，负责把字节码翻译成机器码并执行，是跨平台的关键；JRE 是给"只跑不写"的人用的；JDK 是给开发者用的。

> **追问参考答：** Java 是先编译再解释、两者都有。源码先被 javac **编译**成字节码（.class），这一步是编译；运行时 JVM 用解释器**逐条解释**字节码执行，同时对热点代码用 JIT（即时编译器）直接**编译**成机器码缓存下来，下次直接用。所以它不是纯解释也不是纯编译，而是"编译成字节码 + 运行时解释加 JIT"。

### 2. Java 为什么是跨平台的？「一次编写，到处运行」是怎么实现的？【高频】

> **知识点跳转：** [[Java基础面试题#Java为什么是跨平台的？]]

**追问：** 编译型语言和解释型语言的区别？JVM 的字节码和操作系统的关系？

---

**参考答案 ✅**

Java 跨平台靠的是中间加了一层——**字节码和 JVM**。我们写的源码不直接编译成某台机器的机器码，而是编译成统一的、跟平台无关的**字节码**。真正运行的时候，不同的操作系统上装的是各自版本的 JVM，每个 JVM 负责把**同一份字节码**翻译成当前平台的机器码。所以"一次编写、到处运行"的原理就是：**源码 → 字节码（平台无关）→ 各平台 JVM 把它翻译成机器码**。这就是 Sun 那句 "write once, run anywhere"。

> **追问参考答：** 编译型语言（C/C++）是先把源码直接编译成**当前平台**的机器码，换平台就得重编；解释型语言（Python）是运行时由解释器逐行翻译执行、**不生成独立的可执行文件**（CPython 内部 import 时会先编译成 `.pyc` 字节码，但整体仍以解释执行为主）。Java 介于两者之间。JVM 是字节码和操作系统之间的**桥梁**：字节码是统一的，JVM 各自适配平台，所以真正屏蔽平台差异的是 JVM 本身，字节码只是一种中间格式。

### 3. Java 是值传递还是引用传递？【高频】

> **知识点跳转：** [[Java基础面试题#值传递和引用传递的区别？]]

**追问：** 传一个对象进去，在方法里换掉引用（`obj = new O()`），外部为什么看不到变化？

---

**参考答案 ✅**

一句话：**Java 只有值传递**，对基本类型和引用类型都是值传递。基本类型传的是值的**拷贝**；引用类型传的也是值——只不过这个"值"是**引用的拷贝**（一个指向对象的地址副本）。所以你在方法里给形参重新赋值（`obj = new O()`），外部变量不变，因为你改的是形参这个引用副本，不是外部那个引用；但如果通过引用去改对象**内部的字段**（`obj.setX()`），外部能看到，因为两个引用指向同一个堆对象。

> **追问参考答：** `obj = new O()` 外部看不到，因为参数是引用的**副本**，重新赋值只是让形参指向新对象，外部引用还指着旧对象；`obj.setXxx(...)` 外部能看到，因为改的是同一个堆对象。所以别叫"引用传递"，标准说法是"**基本类型传值、引用类型传引用地址的值**"，本质都是值传递。

### 4. 八种基本数据类型有哪些？各占多少字节？【高频】

> **知识点跳转：** [[Java基础面试题#八种基本的数据类型]] · [[Java基础面试题#int和long是多少位，多少字节的？]]

**追问：** 为什么 Java 要保留基本类型而不是全用对象？引用类型占用几字节？

---

**参考答案 ✅**

八种基本类型按字节数说：**byte 1 字节、short 2 字节、char 2 字节、int 4 字节、long 8 字节、float 4 字节、double 8 字节、boolean 通常按 1 字节算**（虚拟机规范没规定死，实际取决于 JVM）。int 是 4 字节、long 是 8 字节。

> **追问参考答：** 保留基本类型，是因为 Java 一开始就定位成"性能好、接近机器"的语言——基本类型直接存栈上、不要对象头和堆分配，效率高、省内存。引用类型存的是对象地址，在 64 位 JVM 开启**压缩指针**时是 4 字节，不压缩是 8 字节。

### 5. int 和 Integer 的区别？为什么要有包装类？Integer 缓存机制是怎么样的？【高频】

> **知识点跳转：** [[Java基础面试题#Java为什么要有Integer？]] · [[Java基础面试题#说一下 integer的缓存]]

**追问：** `Integer a = 127; Integer b = 127; a == b` 和 `Integer a = 128; Integer b = 128; a == b` 结果分别是什么？为什么？

---

**参考答案 ✅**

int 是**基本类型**直接存值；Integer 是它的**包装类**，是引用类型、是 Object 的子类。为什么要有包装类？因为集合、泛型只能装对象，装不了基本类型，所以要包一层才能放进 ArrayList 或当泛型参数；顺带还带来了自动装箱（int 自动变 Integer）和拆箱（Integer 自动变 int）。

**Integer 缓存**是关键：`Integer.valueOf()` 会缓存 **-128 到 127** 这个区间，这个范围内的值返回的是**同一个缓存对象**。

> **追问参考答：** `Integer a = 127; b = 127; a == b` 是 **true**——都在缓存范围，指向同一个缓存对象；`Integer a = 128; b = 128; a == b` 是 **false**——超出缓存范围，各自 new 了对象，地址不同。所以比较 Integer 的值相等要用 `equals` 或 `intValue()`，绝不能用 `==`。

### 6. 什么是自动装箱/拆箱？为什么要用 BigDecimal 而不是 double？【中频】

> **知识点跳转：** [[Java基础面试题#装箱和拆箱是什么？]] · [[Java基础面试题#为什么用bigDecimal 不用double ？]]

**追问：** BigDecimal 的坑有哪些？`new BigDecimal(0.1)` 和 `BigDecimal.valueOf(0.1)` 有什么区别？

---

**参考答案 ✅**

**自动装箱**是基本类型自动转包装类，比如 `Integer i = 10`，编译器自动调 `Integer.valueOf(10)`；**拆箱**反过来，`int a = i` 自动调 `i.intValue()`。注意拆箱会有 NPE 风险：如果包装类是 null，拆箱就空指针。

为什么用 BigDecimal 不用 double？因为 **double 底层是 IEEE 754 二进制浮点**，很多十进制小数（比如 0.1）在二进制里是无限循环小数，存不精确，做金额计算会有误差（`0.1 + 0.2 != 0.3`）。BigDecimal 用**十进制精确表示**，适合金额、精度敏感的场景。

> **追问参考答：** BigDecimal 两个坑：① 构造方式——`new BigDecimal(0.1)` 传的是 double，会得到 `0.10000000000000000555...`，不精确，应该用 `BigDecimal.valueOf(0.1)` 或 `new BigDecimal("0.1")` 传字符串；② 除法可能抛 `ArithmeticException`（除不尽时），必须指定舍入模式和精度（`setScale`）。

## 二、String 与字符串（4 题）

### 7. String、StringBuffer、StringBuilder 的区别？【高频】

> **知识点跳转：** [[Java基础面试题#String、StringBuffer、StringBuilder的区别和联系]]

**追问：** 三者的线程安全性？StringBuilder 为什么快？什么场景用哪个？

---

**参考答案 ✅**

三个我都说清楚区别和取舍。**String 不可变**，每次拼接都会 new 一个新对象，循环里大量拼接性能很差；**StringBuilder 可变**，底层是可变字符数组，直接往数组里追加、不产生新对象，速度快，但**线程不安全**；**StringBuffer 和 StringBuilder 几乎一样**，区别是 StringBuffer 的方法加了 `synchronized`，**线程安全**但慢一些。

原则是：单线程拼接用 **StringBuilder**（最快），需要多线程共享安全才用 StringBuffer，不需要拼接的就用 String。

> **追问参考答：** String 不可变最安全、可进常量池复用、hashCode 能缓存；StringBuilder 最快但并发会数据错乱；StringBuffer 加 synchronized 保证安全、代价是性能。**日常单线程、局部变量拼接用 StringBuilder 就够**，别为了"保险"用 StringBuffer 而白丢性能。

### 8. String 为什么设计成不可变的？不可变有什么好处？【高频】

> **知识点跳转：** [[Java基础面试题#String、StringBuffer、StringBuilder的区别和联系]]

**追问：** 不可变是怎么实现的？（final 修饰字符数组 + 没有修改方法）不可变带来的好处（线程安全、常量池复用、hash 缓存）？

---

**参考答案 ✅**

String 不可变，是因为它的内部实现：底层是一个 `private final byte[]`（JDK 8 是 char[]）数组，字段 private + final，**String 类本身也是 final** 不能被继承，而且它**没有提供任何修改内部数组的方法**（concat、replace 这些都会返回新对象），所以创建后内容就固定了。

不可变的好处：① **线程安全**——String 可安全地被多线程共享、不用同步；② **常量池复用**——值不变所以同一字面量能安全复用；③ **hashCode 可缓存**——内容不变，第一次算完能存下来，当 HashMap 的 key 很高效；④ **防篡改**——当参数传递安全。

> **追问参考答：** 不可变靠 `private final` 数组 + final 类 + 无修改方法实现。好处是线程安全、常量池复用、hash 缓存、防篡改。**这也是 String 适合做 HashMap key 的原因**——key 需要稳定，不可变正好满足。

### 9. 字符串常量池是什么？`new String("abc")` 和直接赋值 `"abc"` 有什么区别？【中频】

> **知识点跳转：** [[Java基础面试题#String、StringBuffer、StringBuilder的区别和联系]]

**追问：** 字符串常量池在哪个位置？（JDK 7 前后变化）`"a" + "b"` 在编译期和运行期分别怎么处理？

---

**参考答案 ✅**

字符串常量池是 JVM 里专门缓存字符串字面量的一块区域。这个问题的核心就一句话：**直接赋值 `"abc"` 指向常量池里的对象，`new String("abc")` 则在堆上新建一个对象**。

分开看两种写法。**`String s1 = "abc"`**：JVM 先去常量池找有没有 `"abc"`，有就把池里那个对象的引用直接赋给 s1、复用同一个对象，没有就在常量池创建一个再返回引用——所以 s1 指向的是**常量池对象**。**`String s2 = new String("abc")`**：分两步，先检查常量池（没有就把 `"abc"` 放进去），然后 `new` **强制在堆上创建一个全新的 String 对象**，s2 指向的是**堆里这个新对象**，新对象内部的 value 数组复用常量池里的字符。

再用 `==` 和 `equals` 验证。`==` 比的是**引用地址**、`equals` 比的是**字符内容**：所以 `s1 == s2` 结果是 **false**（一个在常量池、一个在堆），`s1.equals(s2)` 结果是 **true**（内容相同）；而两个字面量 `"abc" == "abc"` 是 **true**，因为它们都指向常量池同一个对象。

`intern()` 的作用是把堆对象"拉回"常量池——常量池已有相同字符串就返回池里的引用，没有就把当前字符串放进去、再返回池里的引用；所以 `new String("abc").intern() == "abc"` 是 **true**。

对象数量是经典考点：`new String("abc")` **最多创建 2 个对象**——常量池 1 个（池里没有时才建）加堆里 1 个；如果常量池已经有 `"abc"`，就只新建 1 个堆对象。

使用上，日常一律用字面量 `"abc"`，复用常量池、省内存；`new String("abc")` 强制在堆上多建对象，不要手写。补充一点：JDK 9 之后 String 底层从 `char[]` 改成 `byte[]`，但常量池和 `new` 的语义不变。

> **追问参考答：** 先答常量池位置——JDK 6 它在方法区（永久代），**JDK 7 之后移到了堆里**。再答 `"a" + "b"` 怎么处理，关键看参加拼接的是不是编译期常量。`"a" + "b"` 两个都是字面量、都属于编译期常量，javac 会做**常量折叠**，编译阶段就直接算出 `"ab"`，字节码等价于 `String s = "ab"`，运行期根本没有拼接动作、也不会生成 StringBuilder，而且 `"ab"` 会进常量池——所以 `"a" + "b" == "ab"` 是 **true**，指向常量池同一个对象。反过来，只要有一个普通变量参与，比如 `String a = "a"; String s = a + "b";`，常量折叠就失效，编译期会生成 `new StringBuilder(a).append("b").toString()`，拼接推迟到**运行期**执行，而且 `toString()` 是在**堆上新建**一个 String、不进常量池，所以 `s == "ab"` 是 **false**。再补一个常考的：`final String a = "a"` 因为 final 直接赋值字面量，编译器也当它是编译期常量，`a + "b"` 照样触发常量折叠，结果等价 `"ab"`、`s == "ab"` 是 **true**。所以核心就是分清两条路——**编译期常量折叠** 和 **运行期 StringBuilder 拼接**。最后留个易混题：`new String("a") + new String("b")` 创建几个对象？堆上两个 new String、常量池里 `"a"` `"b"` 两个，运行期走 StringBuilder、最后 `toString()` 在堆上再生成一个 `"ab"`，而这个 `"ab"` **不在常量池**。

### 10. 循环内用 `+` 拼接字符串为什么慢？JDK 8 和 JDK 17 有什么区别？【中频·加分】

> **知识点跳转：** [[循环内字符串拼接性能分析（JDK 8 vs JDK 17）]]

**追问：** JDK 8 的 `+` 编译成什么？JDK 17 引入 `invokedynamic` 和 `StringConcatFactory` 后为什么更快？

---

**参考答案 ✅**

根因是：String 不可变，**每次拼接都会 new 一个新对象**。循环里用 `+`，10 万次循环就产生 10 万多个短命对象，把 Eden 区打满、频繁触发 Minor GC——**CPU 飙高其实是 GC 压力，不是拼接本身慢**。

JDK 8 里 `s = s + x` 会被编译成 `new StringBuilder().append(s).append(x).toString()`，也就是**每次循环都 new 一个 StringBuilder**。JDK 9 之后改成 `invokedynamic` + `StringConcatFactory`，单次拼接更省（少了 StringBuilder 和一次数组复制），**但它只优化单次拼接、不会跨循环累加**，循环里每次照样 new 一个 String，GC 压力一样。

所以要解决就一招——**把 StringBuilder 提到循环外，只 new 一次**：

```java
StringBuilder sb = new StringBuilder();
for (...) { sb.append(...); }
String result = sb.toString();
```

对象分配从"每次循环一次"降到"全程一次"，GC 压力就没了。

> **追问参考答：** 一句话——String 不可变，循环里 `+` 每次都产生新对象、打满 Eden、频繁 GC，才是 CPU 飙高的原因。JDK 9+ 的 invokedynamic 只是把单次拼接做快，不解决循环累积问题，所以**无论哪个版本，循环里拼字符串都要把 StringBuilder 提到循环外**。

## 三、面向对象（5 题）

### 11. 封装、继承、多态三大特性怎么理解？多态体现在哪几个方面？【高频】

> **知识点跳转：** [[Java基础面试题#怎么理解面向对象？简单说说封装继承多态]] · [[Java基础面试题#多态体现在哪几个方面？]]

**追问：** 多态的前提是什么？（继承 + 重写 + 父类引用指向子类对象）编译时看什么类型、运行时看什么类型？

---

**参考答案 ✅**

**封装**是把数据和操作它的方法绑在一起，用访问修饰符控制外部访问、只暴露必要接口，隐藏细节、提高安全性。**继承**是子类复用父类的属性和方法还能扩展，体现 is-a，减少重复代码。**多态**是同一个方法调用作用在不同对象上有不同表现，让调用方只依赖抽象、不关心具体类型。

多态体现在**四个方面**：① **方法重载**——同类中同名不同参，**编译时**就确定调哪个，是编译时多态；② **方法重写**——子类覆盖父类方法，运行时按对象实际类型调，是**实现多态的主要方式**；③ **接口与实现**——多个类实现同一接口，用**接口类型的引用**调用它们，面对不同实现保持一致的调用方式；④ **向上/向下转型**——父类（或接口）引用指向子类对象是向上转型，运行时采用不同子类实现；向下转型是转回子类类型，但要先 `instanceof` 判断，否则 `ClassCastException`。

> **追问参考答：** 多态的前提是**继承（或接口实现）+ 重写 + 父类/接口引用指向子类对象**。**编译时看声明类型**（父类/接口），决定能不能调这个方法；**运行时看实际类型**（子类对象），决定调哪个实现。所以 `Animal a = new Cat(); a.sound()`——编译时看 Animal 有没有 sound、运行时调 Cat 的 sound。注意**重写是运行时多态（主要方式）、重载是编译时多态**，别混为一谈。

### 12. 重载（Overload）和重写（Override）的区别？【高频】

> **知识点跳转：** [[Java基础面试题#重载与重写有什么区别？]]

**追问：** 方法签名包含什么？重载能不能只改返回值？`@Override` 注解的作用？

---

**参考答案 ✅**

**重载**是同一个类里**方法名相同、参数列表不同**（个数/类型/顺序不同），跟返回值无关，是**编译时**多态。**重写**是子类重新定义父类的方法，方法名、参数列表、返回值都要一致（返回值可协变），是**运行时**多态。

几个坑：① 重载**不能只改返回值**——方法签名不含返回值，只改返回值不叫重载（编译报错）；② 重写访问权限不能比父类更严；③ 重写抛的受检异常不能比父类更宽。

> **追问参考答：** 方法签名 = **方法名 + 参数列表**，不含返回值，所以只改返回值不算重载。`@Override` 是给编译器的检查注解，能帮你确认真的重写了父类方法（方法名拼错会报错），防止意外写成新方法。

### 13. Java 抽象类和接口的区别？【高频】

> **知识点跳转：** [[Java基础面试题#Java抽象类和接口的区别是什么？]]

**追问：** 接口里能定义哪些方法？（JDK 8 default、static、private）一个类能同时继承抽象类和实现多个接口吗？为什么 Java 只支持单继承？

---

**参考答案 ✅**

**抽象类**（abstract class）可以有抽象方法、普通方法、字段、构造器；**接口**（interface）JDK 8 前只能有抽象方法和常量，JDK 8 起可以有 default/static 方法，JDK 9 起可以有 private 方法。

区别分几点：① 抽象类能有字段和构造器，接口不能有构造器、字段默认 `public static final`；② 一个类只能**继承一个抽象类**，但能**实现多个接口**，接口弥补单继承局限；③ 抽象类表达 is-a 的模板关系，接口表达 can-do 的能力契约；④ 抽象类适合有共享状态的模板，接口适合定义规范。

> **追问参考答：** 接口里能有抽象方法、default、static、private 方法（JDK 9+），**不能有构造器**。Java 单继承是为了避免**菱形继承**导致的二义性——两个父类有同名方法子类不知道该用谁；接口可以多实现，因为接口方法都是抽象的、实现类自己定义，无冲突（JDK 8 后 default 方法冲突需要显式覆盖解决）。

### 14. final 和 static 的作用分别是什么？【高频】

> **知识点跳转：** [[Java基础面试题#Java 中 final 作用是什么？]] · [[Java基础面试题#Java 中 static的作用是什么？]] · [[Java变量分类与默认值]]

**追问：** `final` 修饰变量、方法、类分别代表什么？`static` 修饰的资源为什么不建议作锁对象？

---

**参考答案 ✅**

**final** 修饰变量——赋一次值后不能再改；修饰方法——不能被重写；修饰类——不能被继承（String、Integer 都是 final 类）。**static** 是类级别的资源——修饰变量叫类变量（所有实例共享一份），修饰方法叫类方法（不用实例就能调），静态代码块在类加载时执行一次。

> **追问参考答：** final 变量里，**引用类型 final 修的是"引用不能变"，对象内部仍可改**；final 方法不能重写、final 类不能继承。static 资源是类级别、所有实例共享一份、生命周期跟类绑定，所以**不要用 static 对象当锁**——它被所有实例共享，锁的粒度过大；而且 static 集合若一直持有对象，会成为 GC Root 导致内存泄漏。

### 15. 静态内部类和非静态内部类的区别？【中频】

> **知识点跳转：** [[Java基础面试题#非静态内部类和静态内部类的区别？]] · [[Java内部类]]

**追问：** 非静态内部类为什么能直接访问外部类的成员？静态内部类需要外部类实例吗？为什么建议用静态内部类（可重入性/内存泄漏角度）？

---

**参考答案 ✅**

**静态内部类**不持有外部类引用，属于外部类本身，直接 new、不需要外部类实例。**非静态内部类**隐式持有外部类实例引用，必须先有外部类实例才能创建（`outer.new Inner()`），它能直接访问外部类成员（包括私有的）。

> **追问参考答：** 非静态内部类能访问外部类成员，是因为编译器给它加了一个指向外部类实例的字段 `this$0`，访问外部成员时通过它——所以它**必须持有外部类实例**。静态内部类不需要外部类实例。面试建议**优先静态内部类**：非静态内部类持有外部类引用，若外部类是大对象，内部类存活会拖住外部类不好回收（可能泄漏），且多一份引用开销。

## 四、Object 与 equals/hashCode（4 题）

### 16. Object 类有哪些常用方法？【中频】

> **知识点跳转：** [[Java基础面试题#Object类有哪些方法？]]

**追问：** `clone()` 和 `finalize()` 的注意事项？`getClass()` 和 `Object.class` 的区别？

---

**参考答案 ✅**

Object 是所有类的基类，常用方法有：`toString()`（默认返回"类名@hashCode 十六进制"）、`equals(Object)`（默认比较引用）、`hashCode()`（默认按内存地址生成）、`getClass()`（返回运行时类对象）、`clone()`（浅拷贝，需实现 Cloneable）、`finalize()`（回收前调用，JDK 9 已废弃）、`wait()/notify()/notifyAll()`（线程协作）。

> **追问参考答：** `clone()` 必须实现 Cloneable 否则抛 `CloneNotSupportedException`，且默认是**浅拷贝**；`finalize()` 在 JDK 9 被标记废弃，因为调用时机不可控、性能差，别依赖它做资源清理。`getClass()` 是拿**运行时**对象的 Class；`Object.class` 是**编译期**就确定的类字面量——反射里两者常用来对比。

### 17. `==` 和 `equals` 的区别？【高频】

> **知识点跳转：** [[Java基础面试题#== 与 equals 有什么区别？]]

**追问：** `equals` 在 Object 里默认比较什么？为什么自定义类要重写 `equals`？

---

**参考答案 ✅**

`==` 比的是**内存地址/引用**：基本类型比值，引用类型比是不是同一个对象。`equals` 是方法，Object 默认实现就是 `==`，但很多类重写了它：String、Integer 重写后比的是**内容**。所以 `new String("x") == new String("x")` 是 false（不同对象），`.equals()` 是 true（内容相同）。

> **追问参考答：** Object 的 `equals` 默认比的就是引用（同一对象），所以自定义类不重写，`==` 和 `equals` 结果一样、都是比地址。要按业务逻辑比内容（比如两个学生学号相同就算相等），**必须重写 equals**，否则 equals 和 ==️没区别。

### 18. 为什么要重写 `equals` 也必须重写 `hashCode`？两者的约定关系？【高频】

> **知识点跳转：** [[Java基础面试题#hashcode和equals方法有什么关系？]]

**追问：** `equals` 相等是不是 `hashCode` 一定相等？反过来成立吗？为什么？

---

**参考答案 ✅**

因为 HashMap/HashSet 这类基于哈希的集合有个**约定**：`equals` 相等的两个对象，`hashCode` **必须相等**。集合先用 hashCode 定位桶，再用 equals 判断桶内是否真相等。只重写 equals 不重写 hashCode，会出现两个逻辑相等（equals=true）但 hashCode 不同的对象被放进**不同的桶**，集合里就有"重复元素"，get 也可能拿不到。

> **追问参考答：** `equals` 相等 → `hashCode` **必须**相等；反过来 `hashCode` 相等 → `equals` **不一定**相等（哈希碰撞，两个不同对象可能 hashCode 相同，再靠 equals 精确区分）。**原因**：哈希表先算桶位置（用 hashCode）再用 equals 桶内匹配；若 equals 相等而 hashCode 不同，同一逻辑对象就被散到不同桶，导致重复或查不到。

### 19. 一个类只重写了 `equals` 没重写 `hashCode`，放进 HashMap 会发生什么？【高频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 用 `get` 拿不到已经 put 进去的值的原因是什么？怎么避免？

---

**参考答案 ✅**

这就是经典的 **HashMap 丢值问题**。假如一个类只重写 equals、没重写 hashCode，那两个 equals 相等的对象，hashCode 还是 Object 默认的地址哈希、通常不一样。put 第二个对象时，HashMap 用**它自己的 hashCode** 算到别的桶，就当成一个不相关的 key 插进去了。之后 get 用 equals 相等的 key，hashCode 和 put 的不同、定位到别的位置，就**查不到**了——表里（哈希数组）其实有两个 equals 相等但 hashCode 不同、落在不同桶的 entry，还可能重复。

> **追问参考答：** 根因是**哈希值和逻辑相等不一致**。HashMap 用 hashCode 找桶、用 equals 找精确元素，两者必须配套。只重写 equals，equals 相等的对象散到了不同桶，get 用新 key（不同的 hashCode）定位到不同桶、找不到原 entry。**避免方法就是同时重写 equals + hashCode**，让 equals 相等的对象 hashCode 一样。

## 五、集合框架（7 题）

### 20. ArrayList 和 LinkedList 的区别？【高频】

> **知识点跳转：** [[Java基础面试题#java 容器都有哪些？]]

**追问：** 两者各自适用什么场景？ArrayList 的扩容机制？LinkedList 真的是"插入快"吗？

---

**参考答案 ✅**

**ArrayList** 底层是动态数组，随机访问快（`get(i)` 直接算偏移量 O(1)），尾部插入快，但中间插入删除要移动元素 O(N)。**LinkedList** 底层是双向链表，随机访问慢 O(N)（要遍历），头尾插入删除快 O(1)。

**关键坑**：LinkedList 说的"插入快"**只在头尾成立**——中间插入虽然改指针是 O(1)，但**找那个位置要 O(N) 遍历**，整体并不快。日常绝大多数场景用 ArrayList，它缓存友好、随机访问快。

> **追问参考答：** ArrayList 适合"读多、按索引随机访问、尾部追加"，LinkedList 适合"频繁头尾插入删除"（队列/栈）。ArrayList 扩容是 **1.5 倍**（`oldCapacity + (oldCapacity >> 1)`），每次扩容复制整个数组，最好能预估容量。LinkedList"插入快"是误导——中间插入仍要 O(N) 找位置，只有两端才是 O(1)。

### 21. HashMap 的底层原理？1.7 和 1.8 的区别？【高频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 1.8 引入了什么？（红黑树）链表树化的条件？（长度 > 8 且容量 ≥ 64）

---

**参考答案 ✅**

HashMap 底层是"数组 + 链表"（1.7）和"数组 + 链表 + 红黑树"（1.8）。key 的 hashCode 经**扰动函数**处理、对数组长度取模算出桶下标；哈希冲突时同桶用链表串起来。

1.7 和 1.8 的区别：① 1.8 引入**红黑树**，单桶链表长度超 8 且容量 ≥ 64 时转红黑树，查询从 O(N) 降到 O(logN)；② 1.8 头插法改成**尾插法**，避免并发扩容链表成环死循环；③ 1.8 扰动函数和扩容做了优化（扩容不用重算 hashCode）。

> **追问参考答：** 1.8 引入红黑树优化长链表查询；**树化条件是链表长度 > 8 且数组容量 ≥ 64**（容量不够时优先扩容而不是树化）；头插改尾插，避免 1.7 并发扩容成环死循环。

### 22. HashMap 的扩容机制？什么情况下链表转红黑树？【高频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 为什么容量必须是 2 的幂？扩容后一个节点怎么判断去旧位置还是新位置？

---

**参考答案 ✅**

HashMap 在 `size > 阈值`（阈值 = 容量 × 加载因子，默认 16 × 0.75 = 12）时扩容，数组**翻倍**（16→32）并重新散列。1.8 做了优化：因为容量是 2 的幂，扩容后一个节点是留在原地还是移到"原下标 + 旧容量"，**只看它 hashCode 新增的那一位（高位）是 0 还是 1**——0 留原位、1 移到 `旧下标 + 旧容量`，不用重算 hash。

> **追问参考答：** 树化条件是**长度 > 8 且容量 ≥ 64**。扩容后节点去旧位置还是新位置：看 `hash & 旧容量`（即新增高位），0 留原位、1 移到 `原下标 + 旧容量`。**为什么容量是 2 的幂**——`(n-1) & hash` 等价于 `hash % n`（n 为 2 的幂时），位运算比取模快，且扩容正好能利用高位判断，简单高效。

### 23. HashMap 为什么线程不安全？【高频】

> **知识点跳转：** [[ConcurrentHashMap_1.7_vs_1.8]]

**追问：** 1.7 并发扩容为什么会成环（死循环）？ConcurrentHashMap 怎么解决？

---

**参考答案 ✅**

HashMap 不是线程安全的。**1.7 的坑**：多线程并发 put 触发扩容时用**头插法**重排，两个线程同时操作可能形成**环形链表**，之后 get 某个 key 可能死循环（CPU 100%）。**1.8 改成尾插法**解决了成环，但并发 put 仍有**数据丢失**（两个线程 put 同一桶，一个覆盖另一个）、**size 不准**、结构错乱。替代方案是 ConcurrentHashMap 或 `Collections.synchronizedMap`。

> **追问参考答：** 1.7 并发扩容头插法导致链表成环死循环；1.8 尾插法不成了，但并发 put 会覆盖丢数据、size 不准。ConcurrentHashMap 1.8 用「**空桶 CAS + 单桶 synchronized**」保证安全，把锁粒度从整个分段细化到**单个桶**。

### 24. HashSet 是怎么保证元素唯一性？【中频】

> **知识点跳转：** [[Java基础面试题#java 容器都有哪些？]]

**追问：** HashSet 底层是什么？去重依赖 `equals` 还是 `hashCode`？

---

**参考答案 ✅**

HashSet 底层就是 **HashMap**，`add(e)` 把元素当 key，value 存一个固定的占位对象（`PRESENT`）。去重靠 HashMap 的 **key 唯一性**：先算 hashCode 定位桶，再用 equals 判断桶内有没有相同 key，有就不插（add 返回 false）。

> **追问参考答：** HashSet 底层是 HashMap。去重**同时依赖 hashCode 和 equals**——先 hashCode 定位桶（快速排除），再 equals 精确判断（内容相等才算重复）。只要两者按业务逻辑重写一致（equals 相等则 hashCode 相等），去重就正确；只重写一个都会导致去重失效或元素重复。

### 25. Collection 和 Collections 的区别？【低频·加分】

> **知识点跳转：** [[Java基础面试题#Collection 和 Collections 有什么区别？]]

**追问：** `Collections.` 常用来做什么？（synchronizedList、unmodifiableList、sort）

---

**参考答案 ✅**

`Collection` 是**接口**，是集合框架的顶层接口之一，List、Set、Queue 都继承它，定义了 `add/remove/size/iterator` 等通用方法。`Collections` 是**工具类**（全是静态方法），不能实例化，提供集合操作：`sort` 排序、`synchronizedList` 返回线程安全 List、`unmodifiableList` 返回只读 List 等。一句话——Collection 是集合的**接口规范**，Collections 是集合的**工具类**。

> **追问参考答：** Collections 常用：`sort`、`reverse`、`synchronizedList/Map`（包装成线程安全）、`unmodifiableList/Map`（只读）、`emptyList` 等。注意 synchronized 包装是方法级同步，性能不如 ConcurrentHashMap / CopyOnWriteArrayList。

### 26. for-each 遍历时 `remove` 为什么抛 `ConcurrentModificationException`？怎么正确删除？【中频】

> **知识点跳转：** [[ConcurrentModificationException 详解（for-each remove 问题）]]

**追问：** fail-fast 机制是什么？三种修复方案（Iterator.remove / fori / removeIf）各自适用？

---

**参考答案 ✅**

for-each 底层是 **Iterator**；集合（ArrayList 等）自己维护 `modCount`（结构性修改计数），迭代器内部则维护自己的 `expectedModCount`。每次 `next()` 检查两者是否相等，不等就抛 `ConcurrentModificationException`（**fail-fast** 机制）。用 `list.remove()` 删除会改集合的 `modCount`，但迭代器的 `expectedModCount` 没同步，下次 next 就抛异常。

> **追问参考答：** **fail-fast** 就是"快速失败"——发现并发/结构性修改就尽早抛异常，而不是等出问题才暴露。三种修复：① `iterator.remove()`（会同步更新 expectedModCount）；② 普通 for 倒序遍历（自己控下标）；③ `list.removeIf(predicate)`（JDK 8，内部正确处理）。单线程优先 **removeIf**；多线程用 CopyOnWriteArrayList（弱一致）。

## 六、异常处理（3 题）

### 27. Java 异常体系是怎样的？Error 和 Exception 的区别？【高频】

> **知识点跳转：** [[Java基础面试题#介绍一下Java异常]]

**追问：** 运行时异常（RuntimeException）和非运行时异常的区别？`finally` 里抛异常会怎样？

---

**参考答案 ✅**

Throwable 是顶层，下面分两大类：**Error** 和 **Exception**。**Error** 是程序无法处理的严重错误，比如 `OutOfMemoryError`、`StackOverflowError`，是 JVM 层面的问题，通常不该 catch。**Exception** 是程序可捕获处理的错误，下面又分**受检异常**（checked，编译期强制处理，如 IOException）和**运行时异常**（unchecked，运行时才抛，如 NPE、数组越界）。

> **追问参考答：** 运行时异常是**程序逻辑问题**（NPE、越界、除零），编译器不强制；非运行时（受检）异常是**外部资源/IO** 类，编译期强制 try-catch 或 throws。**`finally` 里抛异常会覆盖掉 try 里的返回值或原异常**，所以要小心别在 finally 里抛异常或 return。

### 28. 受检异常（checked）和非受检异常（unchecked）的区别？为什么 Java 要区分？【中频】

> **知识点跳转：** [[Java基础面试题#Java为什么区分受检异常和非受检异常？]]

**追问：** 什么样的异常该声明为受检？为什么很多人觉得受检异常是个设计失误？

---

**参考答案 ✅**

**受检异常**继承自 Exception（不含 RuntimeException），编译器**强制**处理——要么 try-catch 要么 throws，不处理编译不过。**非受检异常**包括 **RuntimeException 和 Error**（两者继承自不同的分支，但同属 unchecked 家族），编译器不强制，运行时才抛。

为什么区分？受检异常代表**可预期、需要调用方决定怎么兜底的外部失败**，比如文件不存在、网络失败，强制调用方想清楚；非受检异常代表**程序逻辑 bug**（传错参数、空指针），靠修代码而不是 catch，所以不强制。

> **追问参考答：** 该声明为受检的是"外部资源、IO、编译期可预期但调用方必须应对"的异常，比如 SQLException、IOException。很多人认为受检异常是**设计失误**——它强制层层 throws、污染方法签名，而且很多时候调用方也没法处理、只能继续抛。实践中很多框架（如 Spring）默认把受检异常**包装成非受检运行时异常**（DataAccessException）统一处理。

### 29. `finally` 什么时候不会执行？`try` 里 `return "a"`、`finally` 里 `return "b"` 返回什么？【高频】

> **知识点跳转：** [[Java基础面试题#try{return “a”} finally{return “b”}这条语句返回啥]]

**追问：** `finally` 里改返回值会影响结果吗？`System.exit()` 放在哪里会跳过 `finally`？

---

**参考答案 ✅**

`finally` 几乎总执行，但有**两种不执行**：① 在 try/catch 里调 `System.exit()` 强制退出 JVM；② JVM 崩溃、线程被 kill 等极端情况。

`try { return "a"; } finally { return "b"; }` 返回 **"b"**——因为 finally 在 return 之前执行，且 finally 里的 return 会**覆盖** try 里的 return。

> **追问参考答：** finally 里的 return 会**覆盖** try/catch 的返回值，所以结果是 b；若 finally 里只是普通语句、没有 return，返回值还是 try 里的。`System.exit(0)` 无论放 try 前还是 try 里，都会直接退出 JVM、**跳过 finally**。另外 finally 里若抛异常，也会覆盖 try 的返回值/异常。

## 七、泛型（2 题）

### 30. 什么是泛型？有什么好处？【中频】

> **知识点跳转：** [[Java基础面试题#什么是泛型？]] · [[泛型通配符、泛型方法与桥方法#一、类型参数 T 与通配符 ? 的区别]]

**追问：** `<T extends Number>` 和 `<? extends Number>`、`<? super Integer>` 的区别？（PECS 原则）

---

**参考答案 ✅**

泛型是 Java 提供的类型参数化机制。类、接口和方法在定义时用类型参数（如 `T`、`E`）占位，不指定具体类型，使用时再传入实际类型，例如 `List<String>` 表示只能存放字符串的列表。

它的第一个核心价值是编译期类型安全。在没有泛型的时代，集合存的都是 `Object`，取出元素时必须手动强转，类型不对就会在运行时抛出 `ClassCastException`。引入泛型后，编译器会检查每一次 `add` 和 `get` 的类型是否匹配，错误在编译阶段就会被发现，同时也省去了大量强制转换代码。

第二个价值是代码复用。例如定义一个 `Box<T>` 类，它既可以装 `Integer`，也可以装 `User`，无需为每种类型单独编写一套类。泛型方法和泛型接口也是同样的思路，使通用算法和数据结构可以在不牺牲类型安全的前提下被广泛复用。

第三个价值是提升可读性。看到 `Map<String, List<Order>>` 就能直接知道这个结构的键和值分别是什么，减少了阅读代码时对类型的猜测。

需要补充的是，Java 泛型采用类型擦除实现。编译后泛型信息会被擦除，`List<String>` 和 `List<Integer>` 在运行时都是 `List`。因此泛型只在编译期生效，不能用于 `instanceof` 判断，也不能直接创建泛型数组，而且泛型参数只能是引用类型，不能是基本类型，所以要用 `Integer` 而不是 `int`。理解这一点，有助于解释为什么泛型不会带来额外的运行时开销，也能说明它存在的一些限制。

> **追问参考答：** 

这三者的区别可以从"是否需要命名"和"约束方向"两个角度理解。

`<T extends Number>` 是**类型参数**，它在类或方法声明时出现，表示 `T` 必须是 `Number` 或其子类。`T` 有名字，可以在方法体内当作类型使用，比如声明局部变量 `T value`，也可以多次引用同一个 `T` 来表达"输入与输出是同一类型"的关系。例如 `static <T extends Number> double sum(List<T> list)`，就能保证列表元素一定是数字类型，并在方法内调用 `doubleValue()`。

`<? extends Number>` 和 `<? super Integer>` 是**通配符**，它们只出现在使用处，比如变量、参数或返回值的类型中，代表一个未知但满足约束的类型。通配符没有名字，因此不能在方法体内当作类型名使用，也不能用来声明类或方法的类型参数。

PECS 原则即 Producer Extends、Consumer Super，用来指导通配符的选择。

`? extends Number` 表示上界，实际类型可能是 `Integer`、`Double` 等 `Number` 的任意子类。由于编译器无法确定具体是哪一种子类，写入任何值都可能破坏类型安全，比如不能把 `Integer` 放进一个实际可能是 `List<Double>` 的集合，因此只能读取，读取出来的元素一定是 `Number`。这种结构适合做生产者，例如 `double total(List<? extends Number> src)` 只负责遍历读取。

`? super Integer` 表示下界，实际类型是 `Integer` 或其父类，如 `Number`、`Object`。写入 `Integer` 永远是安全的，因为它一定能放进这些父类容器中，但读取时只能得到 `Object`，无法确定具体类型。因此它适合做消费者，例如 `void fill(List<? super Integer> dst)` 只负责往里写入整数。

举例来说，`Collections.copy(dest, src)` 的签名就体现了 PECS：源列表用 `? extends T` 读取，目标列表用 `? super T` 写入。

### 31. 泛型擦除是怎么回事？为什么 Java 用擦除而不是具体化（reification）？【中频·加分】

> **知识点跳转：** [[泛型擦除]] · [[泛型通配符、泛型方法与桥方法#五、桥方法（Bridge Method）]]

**追问：** 擦除带来了哪些限制？（不能 `new T()`、不能 `instanceof T`、不能创建泛型数组）为什么桥方法会被编译器生成？

---

**参考答案 ✅**

泛型擦除指**Java 泛型只在编译期存在**，编译成字节码后类型信息被擦掉，泛型被替换成它的上界（`<T>` 擦成 Object，`<T extends Number>` 擦成 Number）。所以运行时 JVM 不知道泛型，`List<String>` 和 `List<Integer>` 运行时是同一个类。

为什么用泛型擦除？主要有三个原因：① **向后兼容**——Java 1.5 引入泛型时，为了不破坏已有代码和已编译的字节码（老二进制继续能跑），所以用擦除，让泛型不产生新的运行时类型信息；② **减少运行时开销**——擦除后运行时不必为每个泛型参数保留类型、也没有额外的类型检查/转换开销；③ **简化 JVM 设计**——泛型只在编译期解决，JVM 不必为泛型新增指令和类型系统。对比 C# 是具体化（reification，运行时保留泛型类型）。

> **追问参考答：** 擦除的限制——不能 `new T()`（不知道构造器）、不能 `instanceof T`（类型被擦）、不能 `new T[]`（数组要知道运行时类型）。**桥方法**：当子类重写泛型父类方法时（如 `class MyList extends ArrayList<String>` 重写返回 String 的 get），编译器在子类生成一个返回 Object 的桥方法转发到真实方法，用来**让 JVM 的动态分派能对上父类签名**（`get(int):Object`），否则重写不生效。

## 八、反射与注解（3 题）

### 32. 什么是反射？反射能做什么？【高频】

> **知识点跳转：** [[Java基础面试题#什么是反射？]]

**追问：** `Class.forName` 和 `ClassLoader.loadClass` 的初始化区别？反射获取私有成员要怎么做？

---

**参考答案 ✅**

反射是 Java 在运行时检查和操作类结构的能力。JVM 每加载一个类，都会在方法区生成一个对应的 `Class` 对象，它保存了类名、字段、方法、构造器、注解等元信息。通过这个对象，程序可以在运行时动态创建实例、调用方法（`Method.invoke`）、读写字段（`Field.get/set`）以及读取注解。框架中常见的 Spring 依赖注入、MyBatis 结果映射、JUnit 测试发现，以及 JDK 动态代理，底层都依赖反射。

获取 `Class` 对象主要有三种方式：`类名.class` 在编译期确定类型，不会触发类初始化；`对象.getClass()` 需要已有实例；`Class.forName("全限定名")` 在运行时按名称加载。

`Class.forName` 与 `ClassLoader.loadClass` 的核心区别在于初始化。`Class.forName(name)` 默认会加载并**初始化**类，即执行静态代码块和静态变量的赋值，例如经典的 JDBC 驱动加载 `Class.forName("com.mysql.cj.jdbc.Driver")` 就是利用驱动类的静态块向 `DriverManager` 注册自己。`Class.forName(name, false, loader)` 可以只加载不初始化。`ClassLoader.loadClass(name)` 只完成加载，不执行初始化，因此类的静态代码块要等到首次主动使用（如 `new`、调用静态方法）时才会执行。

访问私有成员的做法是先通过 `getDeclaredField` 或 `getDeclaredMethod` 获取成员（这两个方法可以拿到私有成员，而 `getField`、`getMethod` 只能拿到公开成员），再调用 `setAccessible(true)` 关闭访问检查，之后即可读写或调用。需要注意，`getDeclaredXxx` 只返回当前类声明的成员，不包含父类成员。从 Java 9 开始，若目标类位于未开放对应包的模块中，`setAccessible(true)` 会抛出 `InaccessibleObjectException`，需要使用 `--add-opens` 参数开放包。

反射也有代价。它的调用比直接调用慢，且会绕过编译期的类型检查，运行时才暴露错误；破坏私有成员的封装也会带来维护风险。因此在性能敏感的路径上应尽量缓存 `Method` 和 `Field` 对象，业务代码则应避免过度使用。

> **追问参考答：** `Class.forName()` 会**触发类初始化**（执行 static 块）；`ClassLoader.loadClass()` **只加载不初始化**（默认不执行 static 块），这是关键区别。访问私有成员要 `setAccessible(true)`（可能抛异常），JDK 9+ 模块化后跨模块访问要加 `--add-opens`。

### 33. 反射在平时写代码或框架中有什么应用场景？【高频】

> **知识点跳转：** [[Java基础面试题#反射在你平时写代码或者框架中的应用场景有哪些?]]

**追问：** Spring IOC 是怎么用反射的？反射有没有性能问题？为什么框架层离不开反射？

---

**参考答案 ✅**

反射在日常开发中很少直接出现，却是绝大多数主流框架的底层基础。典型场景包括：Spring 通过反射创建 Bean 和注入依赖；MyBatis 通过反射把结果集字段映射到 Java 对象的属性；JUnit 通过反射扫描带 `@Test` 注解的方法并逐个调用；JDBC 的 `DriverManager` 通过反射加载驱动类；JDK 动态代理则基于反射生成代理对象并转发方法调用。业务代码中，也常见用反射实现通用工具，比如根据配置动态选择实现类、通用的对象拷贝和序列化。

> **追问参考答：** 

Spring IOC 的工作流程可以拆成几步来理解。启动时，容器按照配置的包路径扫描类，识别 `@Component`、`@Service` 等注解，这一步通常通过读取类文件的元数据完成，不必先把所有类都加载进来。确定需要管理的类之后，容器加载对应的 `Class` 对象，通过反射调用构造器创建实例；如果构造器带参数，就递归解析参数对应的 Bean 再传入，这就是构造器注入。对于 `@Autowired` 标注的字段，容器通过 `Field.setAccessible(true)` 和 `Field.set` 直接写入依赖，这是字段注入；对于 Setter 注入，则通过 `Method.invoke` 调用 setter 方法。实例创建和依赖装配完成后，容器还会通过反射查找 `@PostConstruct` 标注的方法并调用，完成初始化回调。整个过程中，业务类无需自己 `new` 依赖对象，控制权从代码转移到了容器，这就是"控制反转"的含义。

反射确实有性能开销。直接调用方法由 JIT 优化后几乎没有额外成本，而反射调用需要经过访问权限检查、参数装箱拆箱、方法查找等步骤，早期 JDK 中还会通过本地方法实现，开销更明显。JDK 后来通过 MethodHandle 和动态生成字节码等方式降低了反射成本，但在高频路径上依然不可忽视。因此框架普遍做了缓存：启动时把 `Class`、`Constructor`、`Method`、`Field` 等对象缓存起来，运行时直接复用，避免重复查找；Spring 的 Bean 定义和元数据也会缓存，把反射成本摊薄到启动阶段，运行期的调用开销便大幅降低。

框架之所以离不开反射，根本原因在于框架开发者写代码时并不知道使用者会定义哪些类、哪些字段、哪些方法。Spring 无法预先知道用户会写多少个 Service，MyBatis 也无法预知用户的实体类结构，这些信息只能在运行时通过反射探知。正是这种"编译期未知、运行期已知"的特性，支撑了 IOC 的依赖装配和 AOP 的动态代理，也使框架能够以注解和配置的方式对业务代码实现解耦。


### 34. 注解的原理？注解是怎么被解析的？【中频】

> **知识点跳转：** [[Java基础面试题#能讲一讲Java注解的原理吗？]] · [[Java基础面试题#对注解解析的底层实现了解吗？]]

**追问：** 注解的保留策略（Retention）有哪些？运行时解析和编译时解析（APT）的区别？

---

**参考答案 ✅**

注解本质上是给代码打标记的元数据,自己不改变程序逻辑,真正的行为是由框架或工具读取注解以后触发的。底层上,注解是一个继承了 Annotation 接口的接口。用反射调用 getAnnotation() 的时候,JVM 会从 class 文件里读出注解的成员值,放进一个叫 memberValues 的 Map,再用 JDK 动态代理生成一个 $Proxy 对象,它的 InvocationHandler 是 AnnotationInvocationHandler。所以调用 anno.value() 并不是真的执行了什么代码,而是被转发到这个 handler,去 Map 里按方法名查出预先存好的值。

解析方式主要有两种。一种是运行时反射解析,要求保留策略是 RUNTIME,Spring 的 @Autowired 就是这样。另一种是编译期处理,通过注解处理器 APT 在 javac 编译阶段扫描注解并生成代码,没有运行时反射开销,比如 MapStruct。Lombok 稍微特殊,它借助注解处理器的入口,直接修改编译器内部的语法树来生成 getter 和 setter。

保留策略 Retention 有三种:SOURCE 只留在源码里,编译就丢弃,比如 @Override;CLASS 会编进字节码但运行时不保留,是默认值;RUNTIME 运行时保留,可以被反射读取。两种解析的区别在于,运行时解析发生在运行期,靠反射,有一点性能开销,适合框架做注入、代理这类动态逻辑;编译时解析发生在编译期,靠 APT,没有运行时开销,适合生成代码或做编译检查。

另外,@Override 是个例外,它由 javac 原生检查,在语法树层面核对是否真的重写了父类方法,不走 APT,所以不能和 Lombok 归为一类。

> **追问参考答：**

保留策略 Retention 有三种。SOURCE 只存在于源码里,编译时就丢弃了,比如 @Override、@SuppressWarnings。CLASS 会写进字节码,但运行时 JVM 不会加载,反射读不到,这是默认值,一些字节码增强工具会用到。RUNTIME 会写进字节码,运行时也保留,可以通过反射读取,Spring 的 @Autowired 就是这一类。

运行时解析和编译时解析的区别,先看时机。运行时解析发生在程序运行期,要求注解必须是 RUNTIME,靠反射加动态代理读取注解,再执行注入、代理这类逻辑,灵活,但有反射开销。编译时解析发生在 javac 编译期,注解是 SOURCE 或 CLASS 就够了,靠注解处理器 APT 扫描注解,主要用来生成新的源码或资源文件,或者做编译检查,运行时没有额外开销。典型代表,运行时这边是 Spring,编译时这边是 MapStruct 和 Lombok。

要注意两点。第一,APT 标准做法只能生成新文件,不能修改已有源码。Lombok 能直接改语法树,是因为它用了编译器的内部 API,属于非标准做法。第二,@Override 是例外,它由 javac 原生检查,在语法树层面核对是否真的重写了父类方法,不走 APT,不能和 Lombok 归为一类。

## 九、Java 8 新特性（4 题）

### 35. Java 8 有哪些新特性？【高频】

> **知识点跳转：** [[Java基础面试题#Java 8 你知道有什么新特性？]]

**追问：** 你实际工作中最常用到哪些？（Lambda / Stream / Optional / 方法引用 / 默认方法）

---

**参考答案 ✅**

Java 8 的新特性可以分为语言层面和库层面两类理解。语言层面的核心是 Lambda 表达式与函数式接口。Lambda 允许用简洁的语法把一段行为作为参数传递，例如 `list.forEach(x -> System.out.println(x))`，它的前提是目标类型是只有一个抽象方法的函数式接口，`@FunctionalInterface` 注解用于在编译期校验这一约束。方法引用是 Lambda 的进一步简写，如 `System.out::println`、`String::length`。接口的 `default` 与 `static` 方法则允许在接口中提供实现，使接口可以在不破坏已有实现类的前提下向后扩展，`Collection.stream()` 正是通过默认方法加入到已有集合接口中的。

库层面最具代表性的是 Stream API 和 Optional。Stream 以声明式的方式处理集合，常见写法是 `filter` 过滤、`map` 映射、`collect` 收集。它的关键特性是惰性求值：中间操作只是记录流水线，直到遇到 `collect` 等终结操作才真正执行，同时支持并行流，可以用 `parallelStream()` 切换。Optional 用于表达"可能为空的返回值"，它强制调用方显式处理空值的情况，相比到处判断 `null` 更清晰。需要注意的是，Optional 更适合作为返回值使用，不宜作为字段或方法参数，直接调用 `get()` 而不做判空同样有风险，应优先使用 `orElse`、`orElseGet` 或 `ifPresent`。

日期时间 API（`LocalDate`、`LocalDateTime` 等）是另一项实用改进。旧的 `Date` 与 `SimpleDateFormat` 是可变且非线程安全的，新 API 全部不可变，线程安全，并且语义更清晰。并发方面，`CompletableFuture` 支持异步任务的编排，例如 `thenApply`、`thenCombine` 和 `allOf`，`ConcurrentHashMap` 也做了改进。

> **追问参考答：** 

实际工作中最常用的是 Lambda、Stream、Optional、方法引用和新日期 API。我最常见的场景是用 Stream 对集合做过滤、转换和分组，例如 `stream().filter().map().collect(Collectors.toList())`，代码比传统循环更直观；Optional 主要用于处理数据库查询或 Service 层可能为空的返回值，减少空指针的防御代码；CompletableFuture 则用于并行调用多个下游接口，再配合自定义线程池汇总结果，缩短接口响应时间。需要提醒的是，Stream 不应滥用，过长的链式调用可能降低可读性和调试便利性，复杂逻辑仍应拆分为普通方法。


### 36. 函数式接口是什么？常用的有哪些？【中频】

> **知识点跳转：** [[Java基础面试题#函数式接口]] · [[Function 和 Consumer（函数式接口）]]

**追问：** `@FunctionalInterface` 注解的作用？`Function`、`Consumer`、`Supplier`、`Predicate` 各自怎么用？

---

**参考答案 ✅**

函数式接口就是只有一个抽象方法的接口,可以额外带 default 方法和 static 方法。因为只有一个抽象方法,所以可以直接用 Lambda 表达式或方法引用来代替匿名内部类去实现它。Lambda 本质上就是在给这个唯一的抽象方法提供实现。另外要注意,如果接口里重新声明了 Object 类的公有方法,比如 equals,它不算抽象方法,不影响函数式接口的判定。Runnable、Comparator 都是典型例子,Comparator 里虽然有 equals 声明,但它依然是函数式接口。

内置的常用接口在 java.util.function 包里,主要是四个。Function 是一个入参一个返回值,用来做转换,方法是 apply。Consumer 是一个入参没有返回值,用来消费,方法是 accept。Supplier 是没有入参但返回一个值,用来供给,方法是 get。Predicate 是一个入参返回 boolean,用来判断,方法是 test。可以用"转换、消费、供给、判断"四个动词对应记忆。

追问一,@FunctionalInterface 的作用。它是给编译器看的约束,标上以后,编译器会检查接口是否只有一个抽象方法,多了或者一个都没有就直接编译报错。它不是必须的,不加注解只要满足条件,同样能用 Lambda,但加上可以防止后人往接口里误加抽象方法,把已有的 Lambda 代码全部搞坏,同时也起到文档说明的作用。

追问二,四个接口怎么用。Function 比如 Stream 的 map,传入字符串返回长度,就是把 T 转成 R。Consumer 比如 forEach,拿到每个元素去打印或者处理,不需要返回结果。Supplier 比如 Optional 的 orElseGet,或者延迟创建对象、懒加载,调用 get 的时候才真正产生值。Predicate 比如 Stream 的 filter,对每个元素返回 true 或 false 决定是否保留,还可以用 and、or、negate 组合多个条件。

补充一个容易被追问的点:这四个接口还有扩展形式,比如 BiFunction、BiConsumer、BiPredicate 是两个入参,UnaryOperator 是入参和返回值类型相同的 Function,BinaryOperator 是两个同类型入参返回同类型结果,还有 IntFunction、ToIntFunction 这类基本类型特化版本,用来避免自动装箱带来的开销。

### 37. Lambda 表达式的原理？和匿名内部类有什么区别？【中频】

> **知识点跳转：** [[Java基础面试题#Lambda 表达式了解吗？]]

**追问：** Lambda 捕获外部变量为什么要 `final`/effectively final？Lambda 是无状态的单例吗？

---

**参考答案 ✅**

Lambda 本质上是语法糖,用更简洁的写法替代匿名内部类,比如 new Thread(() -> ...) 替代 new Thread(new Runnable(){...})。它对应的是一个函数式接口,求值得到的是这个接口的一个实例,所以也是个 Object,可以赋给 Object 变量、放进集合,但 Java 不保证它对应某个具体的实现类,也不保证每次拿到的是同一个实例。

编译原理上,编译期 Lambda 体会被编译成本类里的一个私有合成方法,名字形如 lambda$main$0,调用点处生成一条 invokedynamic 指令,带上 bootstrap 方法的参数。运行期第一次执行到这个调用点时,invokedynamic 交给 bootstrap 方法,也就是 LambdaMetafactory.metafactory,去动态生成并链接出函数式接口的实现,产出一个 CallSite,之后这个调用点直接复用。

和匿名内部类的区别,首先是产物不同。匿名内部类在编译期就会生成独立的 Outer$1.class 文件,而 Lambda 不生成这个 class 文件,只多一个合成方法。所以说 Lambda 更省,真正的含义是少写代码、类文件产物通常更少,至于运行时的性能和内存,不能一概而论。其次是 this 的含义不同,匿名内部类里的 this 指匿名对象自己,Lambda 里的 this 指外层类的对象。另外在异常方面,java.util.function 里的接口都不声明 checked 异常,所以 Lambda 里调用会抛 checked 异常的方法,必须自己 try-catch 或封装,匿名内部类实现这些接口时也是同样的限制,这不是谁更强的区别。

追问一,捕获外部变量为什么要求 final 或 effectively final。所谓捕获,就是 Lambda 用到了它所在代码块之外定义的局部变量。Lambda 捕获的是变量值的副本,如果这个变量之后还能被修改,Lambda 里的值和外面的值就会不一致,行为不确定。再加上局部变量在栈上,Lambda 可能在别的线程、变量生命周期结束之后才执行,所以语言层面直接强制它不可变。effectively final 指的是虽然没写 final,但赋值之后再也没改过。如果确实需要修改,通常用数组、AtomicInteger 这类容器包一层,改的是容器内容而不是变量引用。

追问二,Lambda 是不是单例,要分两种情况。不捕获外部变量的 Lambda,JVM 会把它常量化,同一个调用点反复复用同一个实例,等价于单例。捕获了变量的 Lambda,每次求值都要绑定捕获的值,所以每次都会新建实例,不是单例。因此不能一概而论,而且这属于实现细节,规范并不保证,代码不应该依赖 Lambda 的实例是否相同。

>追加补充：

invokedynamic 是 JVM 的一条字节码指令(JDK 7 引入,JDK 8 开始被 Lambda 使用)。普通的 invokevirtual、invokestatic 等指令,在编译期就确定了"调用哪个类的哪个方法"。invokedynamic 不一样,它把"调用到底链接到哪里"这件事推迟到运行期,第一次执行时才决定,决定之后就固定下来。所以它给了语言实现者一个运行期自定义方法链接逻辑的钩子,Lambda、字符串拼接(JDK 9 之后的 StringConcatFactory)都靠它实现。

bootstrap 方法(引导方法)就是 invokedynamic 第一次执行时被 JVM 回调的那个方法,负责决定这个调用点具体该链接到哪个目标方法。它的信息存在 class 文件的 BootstrapMethods 属性里,invokedynamic 指令通过常量池指向它。JVM 调用它时会传入三类参数:一个 Lookup 对象(代表调用方的访问权限)、调用点的名字和类型(比如要产出哪个函数式接口),以及编译期附带的静态参数(比如指向那个合成方法 lambda$main$0 的句柄)。它的返回值是一个 CallSite 对象,里面装着真正的调用目标。

LambdaMetafactory.metafactory 就是 Lambda 使用的那个具体的 bootstrap 方法,位于 java.lang.invoke 包。它拿到上面的参数后,在运行期生成一个实现了目标函数式接口的类(底层用 ASM 生成字节码,生成的是 Hidden Class 或匿名类),这个类里的接口方法会去调用 lambda$main$0 这个合成方法。然后它返回一个 CallSite,绑定的目标要么是"直接返回一个单例实例"(不捕获变量时),要么是"用捕获的值构造新实例"的工厂(捕获变量时)。

连起来看整个流程:第一次执行到 Lambda 所在位置,JVM 遇到 invokedynamic,发现还没链接,就回调 LambdaMetafactory.metafactory,生成实现类并产出 CallSite,JVM 把 CallSite 绑定到这个调用点。之后再执行到这里,不再走引导流程,直接调用已链接的目标。这也解释了前面说的"不捕获变量的 Lambda 是同一个实例,捕获变量的每次新建实例"。

### 38. Stream 的常用 API？它和普通集合操作有什么区别？【中频】

> **知识点跳转：** [[Java基础面试题#Java中stream的API介绍一下]] · [[StreamAPI]]

**追问：** 惰性求值（中间操作 vs 终止操作）？`map`、`flatMap`、`collect` 的用法？并行流什么时候别用？

---

**参考答案 ✅**

Stream 是 JDK 8 引入的集合处理 API,它不存储数据,只是对数据源(集合、数组等)构建一条处理流水线。操作分两类:中间操作是惰性的,返回新的 Stream;终止操作负责触发执行并返回结果。中间操作常用的有 filter 过滤、map 映射、flatMap 扁平化、sorted 排序、distinct 去重、limit 截取、skip 跳过、peek 查看元素(多用于调试)。终止操作常用的有 collect 收集、forEach 遍历、reduce 聚合、count 计数、min 和 max、findFirst 和 findAny,以及 anyMatch、allMatch、noneMatch 这几个匹配判断。

和普通集合操作的区别有三点。第一是声明式,写的是"我要什么",而不是"怎么循环",代码更简洁。第二是惰性求值,中间操作不会立即执行,遇到终止操作才把整条流水线一次性跑完,而且元素是逐个穿过整条流水线的,不会每一步都生成一个中间集合。第三是内部迭代,遍历由框架控制,所以切换成并行处理很方便。另外要注意,Stream 是一次性的,终止操作执行后再使用同一个流会抛 IllegalStateException,同时 Stream 不会修改原数据源。

追问一,惰性求值。filter、map 这类中间操作只是把步骤登记下来,直到 collect、forEach 这类终止操作才真正执行。还支持短路,比如 limit、findFirst、anyMatch,满足条件就提前停止,不会处理剩余元素,对无限流尤其重要。

追问二,map、flatMap、collect 的用法。map 是一对一转换,每个元素变成另一个元素。flatMap 会把每个元素各展开成一个流，再合并成一个大流 , 典型写法是list.stream().flatMap(List::stream),把嵌套集合拍平成一层。collect 用来收尾,配合 Collectors 把结果收成 List、Set、Map,比如 Collectors.toList()、toMap()、groupingBy() 分组、joining() 拼接字符串。这里有个坑,toMap 遇到重复的 key 会抛异常,需要传第三个参数指定合并规则。

追问三,并行流什么时候别用。parallelStream 底层默认用公共的 ForkJoinPool,只适合 CPU 密集、数据量大、并且无共享状态的场景。数据量小时,拆分和合并的开销反而比收益大;有共享可变状态时会有线程安全问题,结果可能出错;涉及频繁 IO 或阻塞操作时,会占满公共线程池,拖慢其他使用并行流的任务;另外数据源本身难以拆分时,比如 LinkedList,效果也很差,而 ArrayList 和数组拆分就很友好。

## 十、IO/NIO（2 题）

### 39. BIO、NIO、AIO 的区别？【高频】

> **知识点跳转：** [[Java基础面试题#BIO、NIO、AIO区别是什么？]]

**追问：** 同步/异步、阻塞/非阻塞这两个维度怎么理解？NIO 通常对应什么模型？

---

**参考答案 ✅**

判断同步还是异步，关键看**结果由谁通知、数据从内核拷贝到用户空间是否由应用发起并等待**。同步是应用自己发起读写并等待结果返回，异步是应用只提交请求，由操作系统完成读写后通知应用。判断阻塞还是非阻塞，关键看**调用在数据未就绪时是否立即返回**。阻塞调用会挂起当前线程直到数据就绪，非阻塞调用则立即返回一个状态，让线程可以去做别的事情。

BIO 即同步阻塞 IO。每个连接通常分配一个线程，`accept` 之后对 `read` 或 `write` 的调用会一直阻塞，线程在数据到来之前什么也做不了。连接数增加时线程数随之膨胀，上下文切换和内存开销会迅速变大，因此并发能力有限。它的优点是模型简单，适合连接数少、并发低的场景，例如早期的小型内部服务或教学示例。

NIO 即同步非阻塞 IO，在 Java 中以 Channel、Buffer、Selector 三个核心组件体现。Channel 支持非阻塞读写，数据未就绪时立即返回；Selector 则允许一个线程同时监听多个 Channel 的就绪事件，这就是 IO 多路复用。它对应操作系统的 select、poll 和 epoll 模型，Linux 下的 Java NIO 底层通常基于 epoll。需要注意的是，NIO 的数据拷贝仍由应用线程在收到就绪通知后自己完成，因此它依然属于同步模型。正是因为一个线程可以管理大量连接，NIO 能够有效应对 C10K 这类高并发问题，Netty、Tomcat 的 NIO 连接器、Redis 的事件循环都是这一思路的典型应用。

AIO 即异步非阻塞 IO，对应 Java 中 `AsynchronousSocketChannel` 等 API。应用发起读写后立即返回，操作系统完成数据拷贝后通过 `CompletionHandler` 回调或 `Future` 通知应用，整个过程无需应用轮询。理论上它最符合异步模型，但 Linux 对真正的异步文件 IO 支持有限，Java 的 AIO 在 Linux 下底层仍依赖 epoll 模拟，实际性能优势并不明显，因此业务中使用较少，Netty 也选择了 NIO 而非 AIO。

### 40. NIO 的核心组件和原理？【中频】

> **知识点跳转：** [[Java基础面试题#NIO是怎么实现的？]]

**追问：** Channel、Buffer、Selector 三者的关系？IO 多路复用（select/poll/epoll）解决了什么？

---

**参考答案 ✅**

NIO 有三个核心组件:Channel、Buffer 和 Selector。Channel 是通道,和传统流不同,流是单向的,Channel 是双向的,既能读也能写。Buffer 是缓冲区,数据必须先读到 Buffer 里再处理,写出去时也要先写进 Buffer,所以说 NIO 是面向缓冲区的,而传统 IO 是面向流的。Selector 是多路复用器,一个 Selector 可以注册多个 Channel,监听它们的可读、可写、可连接、可接受等事件,这样单个线程就能管理大量连接。

NIO 的底层原理就是 IO 多路复用。把多个 Channel 的 IO 事件交给操作系统内核去监视,在 Linux 上是 select、poll 或 epoll,只有真正就绪的事件才会通知程序去处理,线程不用阻塞在某一个连接上。

追问一,三者的关系。Channel 负责数据的读写,数据都要经过 Buffer。Selector 管理多个 Channel,Channel 需要先设置成非阻塞模式,再注册到 Selector 上并声明感兴趣的事件。线程调用 select 方法等待,有事件就绪后返回就绪的 SelectionKey 集合,线程再遍历这些 key,拿到对应的 Channel 去读写 Buffer。需要注意,FileChannel 不能切换成非阻塞模式,所以不能注册到 Selector,Selector 主要用于 SocketChannel 和 ServerSocketChannel 这类网络通道。

追问二,IO 多路复用解决了什么。它解决的是怎么用一个线程管理很多连接的问题。传统 BIO 是一个连接对应一个线程,连接一多,线程数暴涨,内存和上下文切换的开销都很大,而且大部分线程其实在阻塞等数据。多路复用由内核批量监视多个文件描述符,有数据就绪才返回,不需要每个连接一个线程。

select、poll、epoll 的区别:select 有 fd 数量上限,默认 1024,每次调用都要把 fd 集合从用户态拷贝到内核态,返回后还要线性遍历所有 fd 找出就绪的,复杂度是 O(n)。poll 用链表存储,去掉了数量上限,但仍然是线性遍历。epoll 是事件驱动,通过 epoll_ctl 把 fd 注册到内核里的红黑树,只需注册一次,就绪的 fd 会放进就绪链表,epoll_wait 直接返回就绪的事件,不用遍历全部,所以获取就绪事件接近 O(1),也没有 fd 数量上限。

最后补充两点。第一,epoll 的优势在连接数多、活跃连接少的场景最明显,如果连接少或者几乎都活跃,差距不大。第二,NIO 本身还是同步非阻塞,线程在 select 时依然会阻塞,真正的异步是 AIO,而 Netty 就是在 NIO 基础上封装的,解决了原生 NIO 编程复杂、空轮询 bug 等问题。

## 十一、深拷贝 / 序列化 / 设计模式（4 题）

### 41. 深拷贝和浅拷贝的区别？怎么实现深拷贝？【中频】

> **知识点跳转：** [[Java基础面试题#深拷贝和浅拷贝的区别？]]

**追问：** `Object.clone()` 默认是深拷贝还是浅拷贝？深拷贝的三种实现（重写 clone、序列化、手动构造）的取舍？

---

**参考答案 ✅**

**浅拷贝**只复制对象本身、**不复制内部的引用类型属性**，拷贝对象与原来**共享**内部引用——改一个影响另一个。**深拷贝**不仅复制对象本身，还**递归复制**内部所有引用对象，拷贝后与原对象**完全独立**。三种实现：① 重写 `clone()` 逐层手动复制；② **序列化**——序列化再反序列化（简单，要求实现 Serializable、稍慢）；③ 手动 new 构造逐字段深赋值（最可控）。

> **追问参考答：** `Object.clone()` 默认是**浅拷贝**——基本类型字段复制值，引用类型字段只复制引用地址，所以内部对象还是共享的。三种实现取舍：序列化最简单但要求实现接口且慢，重写 clone 要逐层处理，手动构造最可控但代码多。**业务共识**：能靠"不可变对象""不共享可变引用"避免就尽量别依赖深拷贝。

### 42. Java 序列化和反序列化？`transient` 关键字的作用？【中频】

> **知识点跳转：** [[Java基础面试题#怎么把一个对象从一个jvm转移到另一个jvm?]]

**追问：** 序列化怎么实现？`serialVersionUID` 是干什么的？不指定会怎样？

---

**参考答案 ✅**

序列化是把对象转成字节流，反序列化是把字节流还原成对象，用来持久化或跨 JVM 传输。类实现 `Serializable` 接口就能用 `ObjectOutputStream` 序列化、`ObjectInputStream` 反序列化。**`transient`** 修饰的字段**不参与序列化**，反序列化后是默认值（对象 null、基本类型默认值）——用来标记不该持久化的字段，比如密码、临时缓存。

> **追问参考答：** 序列化靠实现 `Serializable`（无方法的标记接口）+ ObjectOutputStream/InputStream。**`serialVersionUID`** 是序列化版本号，保证反序列化时类结构和序列化时一致；不指定的话 JVM 按类的结构自动算一个，**一旦类结构改了、自动值就变，反序列化旧数据会抛 `InvalidClassException`**。所以最好**显式指定**一个，这样加字段等改动也尽量兼容。注意 static 字段（类级别）和 transient 字段都不参与序列化。

### 43. 单例模式有哪几种写法？为什么要用 `volatile` + DCL？【高频】

> **知识点跳转：** [[DCL（Double-Checked Locking）单例完整展开]]

**追问：** DCL 为什么要加 `volatile`（指令重排）？枚举单例为什么被认为最好？

---

**参考答案 ✅**

单例保证全局只有一个实例。写法：**饿汉式**（类加载就 new，安全但可能浪费）、**懒汉式**（用时才 new，要加锁）、**DCL 双重检查锁**（volatile + 两次判空 + 锁）、**静态内部类**（类加载时初始化，安全又懒加载）、**枚举**（最简洁，天然防反射/反序列化破坏）。

**DCL 为什么要加 volatile**：`instance = new Singleton()` 不是原子的，编译成多条指令——① 分配内存、② 初始化对象、③ 引用指向内存。没有 volatile，CPU/编译器可能**指令重排**把 ③ 提到 ② 之前，另一个线程判断 `instance != null` 为 true 后拿到一个**还没初始化完**的对象。volatile 禁止重排，保证"引用指向"必定在"初始化"之后。

> **追问参考答：** DCL 加 volatile 是**禁止指令重排序**、防拿到"半初始化"对象；不加会出现"判断非空但对象还没构造完"。**枚举单例最好**，因为枚举天然单例（JVM 保证），且**反序列化无法创建新实例**（枚举反序列化返回已有实例）、**反射也无法破坏**（枚举构造器反射会抛 IllegalArgumentException），而普通单例要额外处理反射和反序列化破坏。

### 44. 责任链、策略、模板方法分别是什么？各适用什么场景？【中频】

> **知识点跳转：** [[设计模式（笔试面试常考）]]

**追问：** 你在实际项目里用过哪个？策略模式和状态模式的区别？责任链怎么避免层层 if-else？

---

**参考答案 ✅**

**责任链**：请求沿一条链传递，每个节点决定自己处理还是传给下一个，典型是 Servlet Filter、MyBatis 拦截器、Netty pipeline——好处是解耦调用方和具体处理者、方便动态加节点、避免一堆 if-else。**策略**：定义一组可互换算法、运行时动态选择，把"用什么算法"和"算法实现"分离，典型是 Comparator、支付方式选择。**模板方法**：抽象类定义算法骨架（固定步骤顺序），把可变步骤延迟到子类，公共逻辑在父类、变化留给子类。

> **追问参考答：** **策略 vs 状态**——策略是"同一对象在不同场景换算法"，对象状态不变、由外部选择；状态是"对象内部状态变化导致行为变化"，对象自己维护状态切换（如订单状态机）。**责任链避免层层 if-else**：把每个校验/处理逻辑抽成一个 Handler 串成链，请求沿着处理器链依次传递，符合条件的处理器负责处理，新增节点只加一个 Handler、不改原逻辑。**实际项目**：支付网关集成用策略模式按支付方式选实现，参数校验用责任链。
