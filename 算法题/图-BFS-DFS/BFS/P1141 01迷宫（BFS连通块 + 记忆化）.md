# P1141 01迷宫（BFS 连通块 + 记忆化）

## 题目

https://www.luogu.com.cn/problem/P1141

`n×n` 的 01 矩阵，规则：站在 0 上只能走到相邻的 1，站在 1 上只能走到相邻的 0（即**只能走到与自己数字不同的相邻格**）。`m` 次询问，每次问从某格出发能到达多少个格子（含自身）。

数据范围：`n ≤ 1000`（即最多 10⁶ 个格子），`m ≤ 10⁵`。

## 核心洞察：可达关系对称 → 同一连通块答案相同

「A 能到 B」等价于「B 能到 A」（走的边是无向的），所以**可达性是一个等价关系**，整张图被划分成若干**连通块**。同一个连通块里的**每一格答案都相同**，都等于这个块的大小。

于是关键优化是**记忆化**：`m` 次询问最多 10⁵ 次，但只要某格所在的块已经算过，直接查表 O(1) 返回。**每个格子最多被一次 BFS 覆盖**，总遍历量 O(n²)，与询问次数无关。这就是能扛住 `n=1000, m=10⁵` 的原因——否则每次询问都 BFS 就是 10⁵ × 10⁶ = 10¹¹ 必然 TLE。

## 题解：手写队列 BFS + 一次回填整块

```java
import java.io.*;
import java.util.*;

public class Main {
    static final int[] dx = {0, 0, 1, -1};
    static final int[] dy = {1, -1, 0, 0};

    static int n, m;
    static int[][] g;
    static int[][] ans;                 // -1 未处理；-2 本轮已入队；>=1 该块大小
    static int[] qx, qy;                // 手写队列，同时充当回填清单

    public static void main(String[] args) throws IOException {
        final String NL = System.lineSeparator();
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in), 1 << 16);
        StringTokenizer st = new StringTokenizer(br.readLine());
        n = Integer.parseInt(st.nextToken());
        m = Integer.parseInt(st.nextToken());

        g = new int[n + 2][n + 2];
        for (int i = 1; i <= n; i++) {
            String s = br.readLine();
            for (int j = 1; j <= n; j++) g[i][j] = s.charAt(j - 1) - '0';
        }

        ans = new int[n + 2][n + 2];
        for (int i = 0; i <= n + 1; i++) Arrays.fill(ans[i], -1);

        qx = new int[n * n + 2];        // 单次 BFS 最多覆盖整张图
        qy = new int[n * n + 2];

        StringBuilder sb = new StringBuilder();
        for (int k = 0; k < m; k++) {
            st = new StringTokenizer(br.readLine());
            int x = Integer.parseInt(st.nextToken());
            int y = Integer.parseInt(st.nextToken());
            if (ans[x][y] == -1) bfs(x, y);
            sb.append(ans[x][y]).append(NL);
        }
        System.out.print(sb);
    }

    static void bfs(int x, int y) {
        int head = 0, tail = 0;
        qx[tail] = x; qy[tail] = y; tail++;
        ans[x][y] = -2;
        while (head < tail) {
            int cx = qx[head], cy = qy[head]; head++;
            int code = g[cx][cy];
            for (int d = 0; d < 4; d++) {
                int nx = cx + dx[d], ny = cy + dy[d];
                if (nx < 1 || nx > n || ny < 1 || ny > n) continue;
                if (ans[nx][ny] != -1) continue;     // 已入队或已成块
                if (g[nx][ny] == code) continue;     // 必须走到数字不同的格子
                ans[nx][ny] = -2;
                qx[tail] = nx; qy[tail] = ny; tail++;
            }
        }
        for (int i = 0; i < tail; i++) ans[qx[i]][qy[i]] = tail;   // tail 就是块大小
    }
}
```

## 逐点拆解

### 1. `ans` 数组一箭三雕（状态 + 记忆化 + 答案）

`ans[i][j]` 用三种取值把「访问标记 + 记忆化缓存 + 最终答案」合并进一个数组，省掉单独的 `visited`：

| 值 | 含义 |
|----|------|
| `-1` | 未处理（初始态） |
| `-2` | 本轮 BFS 已入队，但块大小还没算出来（防重复入队） |
| `>= 1` | 该格所在块的大小（最终答案，也是记忆化缓存） |

主循环里 `if (ans[x][y] == -1) bfs(x, y)`——只有没算过才跑 BFS，跑完整块都被填成块大小，后续落在同块的询问全部 O(1) 命中。

### 2. 队列数组 `qx/qy` 同时充当「回填清单」

这是本代码最漂亮的一处。手写队列里塞的正是本连通块的所有格子，BFS 结束时 `tail` 恰好等于块大小，且 `qx[0..tail-1]` 就是块内全部坐标。所以最后一行：

```java
for (int i = 0; i < tail; i++) ans[qx[i]][qy[i]] = tail;
```

**一遍扫过队列，把整块所有格子一次性填成块大小**——不需要另开数组记录块成员。`tail` 既是队尾指针又是块大小，一物两用。

### 3. `-2` 标记为什么必要（防重复入队）

入队时立刻置 `-2`，判邻居时 `if (ans[nx][ny] != -1) continue` 跳过所有非 -1 的格子。如果只在**出队时**才标记，同一个格子可能被多个邻居重复塞进队列，队列溢出 + 重复计数。**入队即标记**是 BFS 防重的铁律。

### 4. 手写队列 + 哨兵边界 —— 卡常细节

- **手写数组队列**代替 `ArrayDeque`：n=1000 时单块可能有 10⁶ 个格子，`m` 次询问下对象队列的装箱/GC 开销可能超时。`qx/qy` 开成 `n*n+2` 长度，单次 BFS 最多覆盖整图，够用且复用。
- **`n+2` 的哨兵边界**：数组开大一圈，配合 `nx<1||nx>n` 判断，避免下标 -1 越界（虽然这里已显式判边界，哨兵让后续扩展更安全）。
- **`StringBuilder` 攒输出**：10⁵ 行结果一次性 `System.out.print(sb)`，逐行 `println` 会因 autoflush 超时（见 [[机试#7. 输入输出]]）。
- **`BufferedReader` + 16KB 缓冲**读入：n=1000 有百万级字符，`Scanner` 必 TLE。

### 5. 转移条件 `g[nx][ny] == code` 才跳过

题目规则是「只能走到数字**不同**的相邻格」，所以数字**相同**时 `continue` 跳过。`code = g[cx][cy]` 是当前格的值，邻居值等于它就不能走。别写反成 `!=` 跳过。

## 复杂度

- 时间 `O(n² + m)`：每格最多被一次 BFS 访问（记忆化保证），加上 m 次 O(1) 查表
- 空间 `O(n²)`：`g` + `ans` + 队列数组

**关键对比**：暴力「每次询问都 BFS」是 `O(m · n²) = 10⁵ × 10⁶ = 10¹¹` 必 TLE；记忆化把它压到 `O(n² + m) ≈ 10⁶`。这道题的分水岭就在**认出「同块答案相同」并缓存整块**。

## 通用套路：连通块 + 询问 → 一次遍历回填整块

这是一类高频模型的模板：**图被划分成连通块，每次询问某点所在块的某个聚合属性（大小/颜色/是否含特定点）**。套路固定：

1. 每格一个「块 ID / 块属性」缓存数组，初始未染色
2. 遍历/询问时若该格未染色，就 BFS/DFS 整块，**同时算出块属性**
3. **一次性把整块所有格子染成同一属性**
4. 后续同块查询 O(1)

洛谷 P1451（求块数与最大块）、LC 内的岛屿系列都是这个模型的变体。DFS 版见 [[算法题/图-BFS-DFS/DFS/200.岛屿数量.md]]、[[695. 岛屿的最大面积 - 力扣（LeetCode）]]（求块大小，与本题回填思路一致，只是不带记忆化查询）。
