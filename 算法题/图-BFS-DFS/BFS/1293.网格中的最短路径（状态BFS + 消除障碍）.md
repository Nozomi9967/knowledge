# 1293. 网格中的最短路径（状态 BFS + 消除障碍）

## 题目

`m×n` 网格，`0` 空地 `1` 障碍。从 `(0,0)` 走到 `(m-1,n-1)`，每步四方向，**最多可以消除 k 个障碍**，求最短步数，不可达返回 -1。

https://leetcode.cn/problems/shortest-path-in-a-grid-with-obstacles-elimination/

## 一句话核心

普通网格最短路是「坐标」二维 BFS；本题多了「还能消几次障碍」这个维度，**状态必须是 `(x, y, 剩余消除次数)` 三元组**，`visited` 也必须是三维的。这是「状态 BFS」的入门题——**当到达同一格子的『代价/资源』不同会影响后续可达性时，就得把资源并进状态**。

## 我的错误解法（输出 26，预期 20）

```java
class Solution {

    public static final int[] dx=new int[]{0,0,1,-1};
    public static final int[] dy=new int[]{1,-1,0,0};

    public int shortestPath(int[][] grid, int k) {
        int m=grid.length,n=grid[0].length;
        Deque<int[]> d=new LinkedList<>();
        d.offer(new int[]{0,0,0});
        boolean[][] v=new boolean[m][n];      // ❌ bug2：二维 visited
        v[0][0]=true;
        int dis=0;
        while(!d.isEmpty()){
            dis++;
            int s=d.size();
            while(s-->0){
                int[] cur=d.poll();
                int ck=cur[0],x=cur[1],y=cur[2];   // ck = 已用消除次数，for 循环共用
                for(int i=0;i<4;i++){
                    int nx=dx[i]+x;
                    int ny=dy[i]+y;
                    if(nx==m-1&&ny==n-1) return dis;   // ❌ bug 隐患：进障碍合法性判断之前
                    if(nx<0||ny<0||nx>=m||ny>=n||v[nx][ny]||(grid[nx][ny]==1&&ck>=k)) continue;
                    if(grid[nx][ny]==1) ck++;          // ❌ bug1：ck 被四个邻居继承
                    d.offer(new int[]{ck,nx,ny});
                    v[nx][ny]=true;
                }
            }
        }
        return -1;
    }
}
```

## 三个 bug（26 就是它们合起来的结果）

### bug 1：`ck` 在邻居循环里被「继承」了

`ck`（已用消除次数）应该是**每个邻居单独算**的局部量，但代码里它是整个 `for` 循环共用的变量。只要某个邻居是障碍且合法，`ck++` 一执行，**紧接着处理的下一个邻居就带着这个被加过的值入队**——本该 `ck=0` 的格子，状态里变成了「已经用过 1 次消除」。

拿 `26/20` 那组用例走一遍就看得清（行列从 0 起）：处理到 `(2,0)@0` 时，右邻居 `(2,1)` 是墙且没访问过 → 合法 → `ck` 变 1 → **紧接着下面的 `(3,0)` 就被写成 `ck=1` 入队**。此后整条第 0 列、第 11 行走廊状态全带 `ck=1`，走到 `(11,7)` 时程序「以为」唯一的消除次数已花光，踩最后那堵墙 `(11,8)` 的一步被拦下。

> 修：`int nr = rest - grid[nx][ny];` **在循环体内对每个邻居单独算**，绝不写成共享变量 `ck++`。

### bug 2：二维 `visited` 根本不成立（本题的题眼）

```java
boolean[][] v = new boolean[m][n];   // ❌
```

本题状态是 `(x, y, 剩余次数)`。**同一个格子，用掉 0 次消除到达、和用掉 1 次消除到达，是两个完全不同的状态**——前者可能后面寸步难行，后者却能打通最后一段。用 `boolean[m][n]` 只标记一次，等于把「更晚到达但剩余次数更多」的更优状态当重复剪掉，答案要么偏大要么 -1。

> 修：`boolean[m][n][k+1]`，第三维就是剩余消除次数。

### bug 3（隐藏）：终点判断放在障碍合法性之前

`if(nx==m-1&&ny==n-1) return dis;` 写在越界/障碍判断**之前**。若终点本身是障碍（如 `[[0,0],[0,1]], k=0`，正解 -1），代码会在第一步直接返回。**终点判断应放到出队时做**才稳——出队即定步数、天然满足 BFS 最短。

### 三者合起来为什么恰好是 26

正解 20 步是「沿第 0 列下到 `(11,0)` → 第 11 行右到 `(11,7)` → 踩墙 `(11,8)`（用掉唯一一次消除）→ `(11,9)`」。但 bug 1 让状态到 `(11,7)` 时 `ck` 已是 1，踩墙那步被判不可行，BFS 只能绕右边空地多走一圈（`(11,7)→(10,7)→…→(8,9)→…→(11,9)`），恰好多 6 步 = 26。

## 修正解法一：三维 visited（最直观）

```java
import java.util.*;

class Solution {
    private static final int[] DX = {0, 0, 1, -1};
    private static final int[] DY = {1, -1, 0, 0};

    public int shortestPath(int[][] grid, int k) {
        int m = grid.length, n = grid[0].length;
        if (k >= m + n - 2) return m + n - 2;   // 剪枝：够消，曼哈顿直达

        boolean[][][] seen = new boolean[m][n][k + 1];   // 状态 = (x, y, 剩余次数)
        Deque<int[]> q = new ArrayDeque<>();
        q.offer(new int[]{0, 0, k});
        seen[0][0][k] = true;

        int dist = 0;
        while (!q.isEmpty()) {
            for (int sz = q.size(); sz > 0; sz--) {
                int[] cur = q.poll();
                int x = cur[0], y = cur[1], rest = cur[2];
                if (x == m - 1 && y == n - 1) return dist;   // 出队时判终点
                for (int d = 0; d < 4; d++) {
                    int nx = x + DX[d], ny = y + DY[d];
                    if (nx < 0 || ny < 0 || nx >= m || ny >= n) continue;
                    int nr = rest - grid[nx][ny];   // 每个邻居单独算，绝不复用
                    if (nr < 0) continue;           // 消除次数不够，进不去
                    if (seen[nx][ny][nr]) continue;
                    seen[nx][ny][nr] = true;
                    q.offer(new int[]{nx, ny, nr});
                }
            }
            dist++;
        }
        return -1;
    }
}
```

## 修正解法二：只记「见过的最大剩余次数」（省内存）

k 很大时三维数组占 `O(mnk)`。可以每格只记见过的**最大剩余次数**，空间降到 `O(mn)`：后到但剩余更多的状态仍有价值，所以只有 `nr <= best[nx][ny]` 才剪。

```java
int[][] best = new int[m][n];
for (int[] row : best) Arrays.fill(row, -1);
Deque<int[]> q = new ArrayDeque<>();
q.offer(new int[]{0, 0, k});
best[0][0] = k;

int dist = 0;
while (!q.isEmpty()) {
    for (int sz = q.size(); sz > 0; sz--) {
        int[] cur = q.poll();
        if (cur[0] == m - 1 && cur[1] == n - 1) return dist;
        for (int d = 0; d < 4; d++) {
            int nx = cur[0] + DX[d], ny = cur[1] + DY[d];
            if (nx < 0 || ny < 0 || nx >= m || ny >= n) continue;
            int nr = cur[2] - grid[nx][ny];
            if (nr < 0 || nr <= best[nx][ny]) continue;   // 剩余次数没变多就没必要重进
            best[nx][ny] = nr;
            q.offer(new int[]{nx, ny, nr});
        }
    }
    dist++;
}
return -1;
```

## 复杂度

- 状态数 = `m × n × (k+1)`，每个状态最多扩展一次 → 时间 `O(m·n·k)`
- 空间：三维版 `O(mnk)`，最大剩余版 `O(mn)`
- **BFS 层序扩展天然保证「第一次到终点即最短」，不需要 Dijkstra/排序**（每步代价都是 1，是无权图最短路）

## 通用套路：什么时候要把「资源」并进状态

这题是「**状态 BFS**」模型的代表。判据：**普通坐标 BFS 里，如果「到达某格时携带的某种资源量」会影响之后能不能走 / 走多远，那这个资源量必须进状态维度，visited 也要相应升维。**

常见的资源维度：

| 维度 | 例题 |
|------|------|
| 剩余消除障碍次数 | 本题 1293 |
| 已收集钥匙的集合（状态压缩位掩码） | 864. 获取所有钥匙 |
| 当前步的奇偶 / 时间模某数 | 带周期性障碍的网格 |
| 剩余油量 / 剩余生命 | 各类游戏地图题 |

核心心法一句话：**「同一个格子、不同资源量 = 不同状态，不能用一个 visited 标记糊掉。」** 你这题的 26 就是把三维状态压成二维 visited 的直接后果。
