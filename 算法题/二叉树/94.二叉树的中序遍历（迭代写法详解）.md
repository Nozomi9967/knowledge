# 94.二叉树的中序遍历（迭代写法详解）

https://leetcode.cn/problems/binary-tree-inorder-traversal/

> [!info] 说明
> 原文来自带交互模拟器的讲解，其中"上面的模拟器 / 自动播放 / 上一步 / 下一步"等交互元素未收录到笔记中，用正文的「完整走一遍」步骤表代替。

中序遍历的迭代写法确实是初学时最容易卡住的地方。

### **核心就一句话：用栈模拟递归的"回溯"——一路向左压栈，弹出即访问，然后转向右子树**

### **先看代码，它只由两个阶段组成**

```java
public List<Integer> inorderTraversal(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {   // 还有活干，就继续
        while (cur != null) {                   // 阶段 A：一路向左
            stack.push(cur);
            cur = cur.left;
        }
        cur = stack.pop();                      // 阶段 B：弹出最左节点
        result.add(cur.val);                    // 访问它
        cur = cur.right;                        // 转向右子树
    }
    return result;
}
```

整段代码其实就是两个动作在反复交替。**阶段 A**（内层 while）：中序是"左 → 根 → 右"，所以必须先摸到最左下角。怎么摸？沿着左孩子一路往下走，路过的节点全部压栈——压栈不是为了访问它们，而是为了**记住回去的路**。**阶段 B**（后面三行）：左链走到头后，栈顶就是当前应该访问的那个"最左"节点，弹出、加入结果，然后 `cur = cur.right` 转向它的右子树，让右子树整体重复同样的流程。

### **栈里存的到底是什么（理解的关键不变量）**

很多人看不懂，是因为把栈当成"待访问列表"去理解，越想越乱。正确的心智模型是：**栈里存的是"左子树已经处理完、但自己还没被访问"的祖先节点**。由此得到一个始终成立的不变量——**栈顶永远是下一个该输出的节点**。

为什么？因为中序里"左 → 根"的顺序，在栈结构里天然成立：节点 X 压栈时，X 的所有左后代一定在它上面（后压的在上面），所以它们一定先于 X 被弹出访问。等轮到 X 弹出时，它左边的所有节点恰好都输出完了，正是"轮到根"的时刻。栈在这里扮演的角色，就是递归版本里系统调用栈的角色。

对照递归版本看会更清楚：

```java
void inorder(TreeNode node) {
    if (node == null) return;
    inorder(node.left);    // ← 对应阶段 A：递归向左 = 压栈
    result.add(node.val);  // ← 对应阶段 B：递归返回 = 弹栈后访问
    inorder(node.right);   // ← 对应阶段 B：转向右子树
}
```

递归中 `inorder(node.left)` 调用结束返回到 node 的那一刻，就等价于迭代版里 `stack.pop()` 弹出 node 的那一刻。递归靠系统帮你回溯，迭代靠你自己压栈回溯——仅此而已。

### **为什么外层条件是 `||` 而不是 `&&`**

这个条件表达的是"任务的两个来源"：`cur != null` 说明有新节点要下去处理（阶段 A 有活干）；`!stack.isEmpty()` 说明还有祖先节点压在那儿等着被访问（阶段 B 有活干）。**两个都空了，整棵树才处理完**。

用 `&&` 会直接出 bug。比如刚弹出了节点 4，`cur = 4.right = null`，此时栈里还压着 2 和 1 呢——如果条件是 `&&`（要求 cur 非空**且**栈非空），循环立刻终止，2、1、5 全丢。相反，前几轮栈是空的、只有 cur 非空，也说明 `||` 两侧各覆盖了对方管不到的情况。

### **完整走一遍**

```text
        1
       / \
      2   3
     / \    \
    4   5    7
```

| 阶段 | 发生的事 | 栈（底→顶） | result |
|---|---|---|---|
| A | 依次压入 1、2、4，cur 到 null | 1, 2, 4 | [] |
| B | 弹出 4 访问；4 无右孩子 | 1, 2 | [4] |
| B | cur=null，内层 while 直接跳过；弹 2，转右到 5 | 1 | [4, 2] |
| A | 压入 5，cur 到 null | 1, 5 | [4, 2] |
| B | 弹出 5；5 无右孩子 | 1 | [4, 2, 5] |
| B | 弹出 1，转右到 3 | [] | [4, 2, 5, 1] |
| A | 压入 3，cur 到 null | 3 | [4, 2, 5, 1] |
| B | 弹出 3，转右到 7 | [] | [4, 2, 5, 1, 3] |
| A+B | 压入 7 后随即弹出访问 | [] | [4, 2, 5, 1, 3, 7] |

结束：cur 为 null 且栈空，输出 `[4, 2, 5, 1, 3, 7]`——正好是升序，这也是 BST 的经典性质（中序遍历 BST 得到有序序列，面试常考）。

### **最容易卡住的三个点**

**第一：cur 变成 null 了，内层 while 下一轮怎么又跑起来了？** 因为 `cur = cur.right` 之后，右孩子可能非空，甚至自己拖着一整条左链（比如 7）。所以每转向右子树后，都要重新执行一轮阶段 A。null 只是"这半边没了"，不代表"整个循环该结束"。

**第二：节点会不会被重复压栈？** 不会。节点弹出后，cur 只会走到它的**右**孩子，永远不会再回到它或它的左子树，所以每个节点一生只进出栈一次，总复杂度是严格的 O(n)。

**第三：记不住模板怎么办？** 压成一句口诀——**"压左、弹出、转右"**，配上前置条件"cur 非空或栈非空"。面试前默写一遍递归版再对着改，基本不会错。

最后一个 Java 细节：代码里用的是 `Deque` + `ArrayDeque` 而不是老式的 `java.util.Stack`，因为后者继承自 Vector、加锁且性能差，官方文档也推荐用 Deque 代替；另外 `ArrayDeque` 不允许压入 null，而本算法从来不 push null，正好安全。
