## 一、Spring

### 1. @Autowired 默认按字段名还是按类型装配？

**核心结论：默认按类型（byType），不是按字段名。字段名只在「同类型有多个 Bean」时作为备选匹配规则。**

完整规则（三级）：
1. **优先 byType**：先去 IoC 容器找和目标属性/方法参数**类型完全匹配**的 Bean，找到就注入，**不看变量名**。
2. **同类型多个 Bean（歧义）**：byType 匹配出多个候选时，**再拿字段名去匹配 Bean 的 name**，名字一致的被选中。
3. **强制按名**：`@Qualifier("beanName")` 指定 Bean 名，优先级高于字段名。

易混点：
- `@Resource`（JSR 规范，Java 原生）：**默认 byName，找不到再 byType**，顺序和 `@Autowired` 相反。
- `@Autowired` 是 Spring 专属注解。

一句话记忆：
> `@Autowired` 先按类型找；类型找到多个，才拿字段名去匹配 Bean 名字。

### 2. Class.forName 里"驱动注册自己"的"自己"指什么？

**核心结论：指的是 `com.mysql.cj.jdbc.Driver` 这个驱动类的「实例对象」——static 块里 `new Driver()` 出来的那个对象。**

过程拆解：
1. `Class.forName("com.mysql.cj.jdbc.Driver")` 加载并**初始化** Driver 类 → 触发**静态代码块**。
2. Driver 源码静态块：`DriverManager.registerDriver(new Driver())` —— `new Driver()` 就是**实例化当前这个驱动类**，再把这个**实例**注册进 `DriverManager`。
3. `DriverManager` 内部维护一份已注册驱动**实例**列表；后续 `getConnection()` 遍历列表，让各驱动去解析 url、创建连接。

两个概念别搞混：
- `com.mysql.cj.jdbc.Driver`：**类**（模板）
- `new Driver()`：**类的实例对象**（static 块里 new 出来注册的那个）

对比 `ClassLoader.loadClass`：
- `loadClass` **只加载、不初始化**，static 块不执行 → `registerDriver` 不运行，驱动不注册。
- 所以早期 JDBC 必须用 `Class.forName` 靠初始化触发静态块注册驱动。
- JDBC 4.0 之后通过 **SPI 自动发现**驱动，已不需要手写 `Class.forName`。

（关联：[[重写loadClass与findClass的区别]]、[[Class 类详解]]、[[SPI详解]]）

## 二、Java 基础

### 3. 抽象类能被抽象类继承吗？

**核心结论：可以，而且很常见。**

规则要点：
1. 抽象类继承抽象类，**不需要实现父抽象类的抽象方法**——父类抽象方法可以继续留着，交给后面**具体子类**实现。
2. 抽象子类也可以**选择性实现一部分**父抽象方法，剩下继续抽象。
3. 不能做的事：
   - 抽象类**不能被 `final` 修饰**（final 禁止继承，矛盾）。
   - 抽象类**不能实例化**（无论父类是不是抽象类）。

一句话记忆：
> abstract 类 extends abstract 类 ✔；抽象类延续抽象契约，把方法实现交给下层具体类。

追问：接口能继承接口吗？——**能，且可以多继承接口（用 extends）**。

（关联：[[Java基础面试题]]、[[Java基础热门面试题-1]]）

### 4. 静态代码块 / 构造代码块 / 构造方法的执行顺序

**核心结论：静态代码块 → 构造代码块 → 构造方法。**

- 静态属**类级别**，**只执行一次**；构造块、构造方法属**实例级别**，每次 `new` 都执行。

单个类（无继承）输出顺序：
```
静态代码块
构造代码块
构造方法
构造代码块   ← new 第二次
构造方法
```

有继承关系时（面试高频）：
1. 父类静态代码块
2. 子类静态代码块
3. 父类构造代码块
4. 父类构造方法
5. 子类构造代码块
6. 子类构造方法

> 核心记忆：**静态优先，父类优先；静态只跑一次。实例部分：父构造块 → 父构造器，再子构造块 → 子构造器。**

补充考点：
1. 静态代码块 `static{}`：类初始化时执行（触发时机：new、反射 `Class.forName`、访问静态变量/方法），只执行一次。
2. 构造代码块 `{}`：创建对象时、构造方法之前执行，每次 new 都执行。
3. 静态代码块**不能访问非静态成员**；构造代码块可以访问实例变量。
4. 静态块执行时机早于构造块，**甚至可以不创建对象就执行**（如直接调用静态方法）。

（关联：[[Java变量分类与默认值]]、[[类初始化的主动引用与被动引用]]、[[Java基础面试题]]）

### 5. Java 中提供图形化组件的包是？

**核心结论：`java.awt`（AWT）和 `javax.swing`（Swing）。**

| 包 | 全称 | 特点 |
|----|------|------|
| `java.awt` | Abstract Window Toolkit | 早期图形包，**重量级**组件，依赖本地操作系统组件 |
| `javax.swing` | Swing | 在 AWT 之上构建，**轻量级**，大部分组件自己绘制，不依赖本地原生控件 |

小记忆：
- `java.awt` → 重量级
- `javax.swing` → 轻量级，组件类大多以 **J** 开头（`JFrame`、`JButton`、`JPanel`）

拓展：JavaFX 是更新的 GUI，但基础题问"图形组件包"，默认答 **AWT + Swing**。

## 三、JDBC

### 6. JDBC 中提供连接的是？

**核心结论：`DriverManager`（`java.sql.DriverManager`），用静态方法 `getConnection()` 获取连接。**

```java
Connection conn = DriverManager.getConnection(url, user, password);
```

坑题区分：
- **DriverManager**：提供/获取连接
- **Driver**：驱动接口，底层真正和数据库交互，一般不直接调用
- **Connection**：代表**已拿到的连接对象**（是连接本身，不是"提供连接"），可创建 Statement
- **Statement**：执行 SQL
- **ResultSet**：结果集

一句话：**JDBC 中提供数据库连接的是 DriverManager。**

## 四、Linux / 操作系统

### 7. Linux 文件访问权限那几位？

**核心结论：`ls -l` 输出 10 个字符 = 1 位文件类型 + 9 位权限；9 位权限分 u/g/o 三组，每组 rwx。**

以 `-rwxr-xr--` 为例：
- **第 1 位**：文件类型（**不是权限**）——`-` 普通文件、`d` 目录、`l` 软链接
- **后 9 位**才是权限，分三组：
  1. 前 3 位 `u`（user）：文件所有者权限
  2. 中 3 位 `g`（group）：所属用户组权限
  3. 后 3 位 `o`（other）：其他用户权限

数值：`r=4`、`w=2`、`x=1`，每组相加，用**3 位八进制**表示（`755`、`644`）。
例 `-rw-r--r--` → u:rw-=6，g:r--=4，o:r--=4 → **644**。

追加考点——额外 3 位特殊权限（完整 mode 共 12 bit，写在八进制最前面）：
- `4` setuid
- `2` setgid
- `1` sticky（粘滞位）
例：`4755` = setuid + rwxr-xr-x。

> 面试问"文件访问权限"默认答 **9 位、ugo 三组、每组 rwx**；问 chmod 数字权限默认 3 位八进制。

小坑：目录的 `x` 不是执行，是**能否进入目录（cd）**；目录 `r` 只是看列表，`w` 是删/建文件。

（关联：[[OS八股]]、[[OS 名词解释速查]]）

## 五、软件工程

### 8. 瀑布模型八个阶段可以缩为哪三阶段？

**核心结论：计划阶段（软件定义时期）、开发阶段（软件开发时期）、运行阶段（运行维护时期）。**

8 个细分阶段归为 3 大阶段：
1. **计划阶段（软件定义）**：问题定义、可行性研究、需求分析
2. **开发阶段（软件开发）**：概要设计、详细设计、编码、综合测试
3. **运行阶段（运行维护）**：运行与维护

> 背诵：**定义(计划) → 开发 → 运行维护**。

补充：瀑布模型特点——线性顺序、文档驱动；缺点是**需求必须提前明确，后期变更代价巨大**。

## 六、MySQL

### 9. INSERT 语句怎么写？

标准写法（指定字段，推荐，可读性强，顺序可换）：
```sql
INSERT INTO 表名(字段1,字段2,字段3) VALUES(值1,值2,值3);
```

其他写法：
- **简写**（不写字段，必须按表结构顺序给**所有列**赋值，不推荐）：
```sql
INSERT INTO user VALUES(2,"lisi",22);
```
- **批量插入**（性能更好）：
```sql
INSERT INTO user(name,age) VALUES ("wangwu",18),("zhaoliu",25);
```
- **查询结果插入**（insert ... select）：
```sql
INSERT INTO user_backup(id,name,age) SELECT id,name,age FROM user;
```
- **插入或忽略**：
```sql
INSERT IGNORE INTO user(id,name) VALUES(1,'test');
```

坑点：
1. 字符串、日期要加**单引号**（双引号部分数据库不兼容）。
2. 值和字段**数量、类型一一对应**。
3. 主键若自增，可以不写主键字段，数据库自动生成。

> 背诵模板：`INSERT INTO 表(列) VALUES(值)`。

### 10. UPDATE 语句？

基础语法：
```sql
UPDATE 表名 SET 字段1=值1, 字段2=值2 [WHERE 条件];
```

⚠️ **面试高频大坑：WHERE 子句千万不能省略！**
```sql
UPDATE user SET age=25;  -- 不带 WHERE：更新整张表所有行！非常危险
```

其他：
- 多条件：`UPDATE user SET age=30 WHERE id>10 AND name='lisi';`
- 基于自身字段修改：`UPDATE user SET age = age + 1;`

补充考点：
1. 书写顺序：**UPDATE → SET → WHERE**（书写顺序与底层解析顺序不同）。
2. 开发中一般**用主键做 WHERE 条件**，保证只更新单行。
3. 事务场景下，update 会加锁。

> 配套记忆：INSERT 新增，UPDATE 修改，DELETE 删除，SELECT 查询。

### 11. UPDATE 能 JOIN 吗？

**核心结论：MySQL 支持 `UPDATE ... JOIN` 做多表更新。**

```sql
UPDATE 表1
JOIN 表2 ON 表1.关联字段 = 表2.关联字段
SET 表1.字段 = 表2.字段
WHERE 筛选条件;
```

另一种等价写法（逗号，等价 inner join）：
```sql
UPDATE user u, order o
SET u.balance = u.balance - o.amount
WHERE u.id = o.user_id AND o.status=1;
```

⚠️ 重点：
1. **Oracle 不支持 `UPDATE ... JOIN` 语法**，Oracle 多表更新要用子查询；MySQL 可以。
2. 一定要加 WHERE，否则大范围更新。
3. 若关联后表 1 匹配到**多行表 2 记录**，**最后一条匹配结果生效**，易出数据错乱——尽量保证一对一。
4. 可以用 `LEFT JOIN`，左表全匹配，右表没有的字段为 null。

> 一句话背诵：**MySQL 支持 update join 做多表更新；Oracle 不支持该语法，需子查询实现。**

### 12. 添加表字段怎么写？

**核心结论：`ALTER TABLE 表名 ADD 字段名 类型 [约束];`（DDL 语句）。**

```sql
ALTER TABLE user ADD email VARCHAR(50);
ALTER TABLE user ADD phone CHAR(11) NOT NULL DEFAULT '';
```

指定字段位置（MySQL 特有）：
```sql
ALTER TABLE user ADD age INT AFTER name;   -- 放在 name 后面
ALTER TABLE user ADD id BIGINT FIRST;      -- 放在第一个
```

一次加多个字段：
```sql
ALTER TABLE user ADD addr VARCHAR(100), ADD gender TINYINT;
```

配套考点（ALTER 系列）：
- 修改类型：`ALTER TABLE user MODIFY email VARCHAR(100);`
- 改名+改类型：`ALTER TABLE user CHANGE email user_email VARCHAR(100);`
- 删除字段：`ALTER TABLE user DROP COLUMN email;`

⚠️ 坑点：
- 属于 DDL，**MySQL 8.0 以前大表 ALTER 会锁表**，线上大表不能随便直接执行。
- Oracle、SQL Server **不支持 AFTER / FIRST** 调整字段顺序。

> 背诵短句：`ALTER TABLE 表 ADD 字段 类型`。

### 13. 唯一索引和主键索引有什么区别？

**核心结论：主键是一种特殊的唯一索引；主键不能为 NULL，唯一索引允许 NULL（可多个 null）。**

| 维度           | 主键索引 PRIMARY KEY            | 唯一索引 UNIQUE                           |
| ------------ | --------------------------- | ------------------------------------- |
| NULL 约束      | **不允许 NULL**                | **允许 NULL**，可多条 null（null ≠ null，不冲突） |
| 数量           | 一张表**最多 1 个**               | 一张表**可建多个**                           |
| 索引结构（InnoDB） | **聚簇索引**，数据行存在叶子节点          | **二级索引**，叶子存主键值，需回表                   |
| 自动创建         | 主键自动创建主键索引                  | 唯一约束自动创建唯一索引                          |
| 自增           | 常搭配 `auto_increment`（MySQL） | 不能直接自增                                |

示例 SQL：
```sql
ALTER TABLE user ADD PRIMARY KEY (id);
ALTER TABLE user ADD UNIQUE uk_email(email);
```

坑点：
1. 唯一索引可含多个列（联合唯一），主键也可为联合主键。
2. 联合主键：多字段合在一起唯一，所有字段都不能为 NULL。
3. **InnoDB 必须要有主键**；没指定时 MySQL 会自动生成隐藏 rowid 作为聚簇索引。

> 极简背诵：主键——一张表只能一个、不能 null、聚簇索引；唯一索引——可以多个、允许 null、二级索引。

**「可多个 NULL」是什么意思、为什么：** 指的是**唯一索引允许同一列里出现多行 NULL，它们不算重复、不触发唯一性冲突**。

```sql
CREATE TABLE user (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(64) UNIQUE
);

INSERT INTO user (email) VALUES (NULL);        -- ✅ 通过
INSERT INTO user (email) VALUES (NULL);        -- ✅ 又通过了，不报错
INSERT INTO user (email) VALUES (NULL);        -- ✅ 还能再插
INSERT INTO user (email) VALUES ('a@x.com');   -- ✅ 通过
INSERT INTO user (email) VALUES ('a@x.com');   -- ❌ ERROR 1062 Duplicate entry
```

根因是 SQL 的**三值逻辑**：唯一性约束的本质是判断"表里是否已有某行的值 **=** 我要插入的值"，而 NULL 表示**未知**，任何与 NULL 的比较结果都是 **UNKNOWN**，不是 TRUE：

```
'a@x.com' = 'a@x.com'   → TRUE     → 重复，拒绝插入
NULL      = NULL        → UNKNOWN  → 不算重复，放行
```

约束只在比较结果为 **TRUE** 时才拒绝，UNKNOWN 不触发。顺带记住：**判断 NULL 必须用 `IS NULL`**——写 `WHERE email = NULL` 永远查不到行（结果 UNKNOWN 被过滤掉），同一个根因。主键列**隐式带 NOT NULL**，所以主键上根本不存在"多行 NULL"这种情况。

⚠ **跨库差异**（面试加分）：这是 **MySQL 的行为，不是所有数据库都一样**——MySQL / PostgreSQL / Oracle 的 UNIQUE 都允许多个 NULL；**SQL Server 只允许 1 个**（它把 NULL 当确定值参与唯一性判断）。所以答"唯一索引允许多个 NULL"时最好补一句「**在 MySQL 里**」。衍生问题：MySQL 的 UNIQUE 无法表达"最多只能有一个 NULL"，要这个语义通常用**哨兵值**代替 NULL（如空串 `''`——空串是确定值、能参与唯一判断）。
