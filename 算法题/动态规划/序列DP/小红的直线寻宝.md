# 小红的直线寻宝

## 题目描述

有 $n$ 块直线排列的地砖，小红从第一块地砖**之前**出发。每回合前进 $1$、$2$ 或 $3$ 块，并自动拾取落脚砖上的宝物。要求在**不超过 $m$ 回合**内**恰好到达**最后一块地砖，求可携带的最大宝物价值；无法到达输出 `-1`。

**数据范围：** $5 \le n \le 10000$，$2 \le m \le 5000$，宝物价值 $\in [0, 5]$。

**时间限制：** C/C++ 2 秒，其他语言 4 秒。**空间限制：** C/C++ 256M，其他语言 512M。

### 示例

**示例 1**

输入：

```
5 3
1 2 1 1 3
```

输出：

```
6
```

说明：依次落在第 2、4、5 块地砖（走 2、2、1 步），价值 $2 + 1 + 3 = 6$。

**示例 2**

输入：

```
10 3
0 0 3 1 2 3 0 0 0 0
```

输出：

```
-1
```

说明：三回合最多前进 $3 \times 3 = 9$ 格，无法从地砖外到达第 10 块。

## 思路分析

### 状态定义

`d[i][j]`：**恰好用 $j$ 回合**到达第 $i$ 块地砖时的最大宝物价值。

- `i = 0` 表示起点（第一块地砖之前），`i = 1..n` 对应第 1 到第 $n$ 块地砖。
- `j = 0..m` 表示已使用的回合数。
- 初始化全部为 `-1`（不可达），`d[0][0] = 0` 为唯一初始状态。

### 状态转移

要到达第 $i$ 块地砖，上一回合只能落在第 $i-1$、$i-2$、$i-3$ 块之一（即步长为 $1/2/3$）。因此从 `j-1` 回合的前驱中取最大可达值，再加上当前地砖的宝物价值：

$$
d[i][j] = \max_{k \in \{\max(0,i-3)\,..\,i-1\}} \bigl(d[k][j-1]\bigr) + a[i-1]
$$

其中 $k$ 是前驱地砖编号，需保证 $d[k][j-1] \neq -1$（前驱可达）。若所有前驱都不可达，则 $d[i][j] = -1$。

### 答案

$$
\text{ans} = \max_{j=1}^{m} d[n][j]
$$

若全为 `-1` 则输出 `-1`。

## 循环结构说明

```java
for (int i = 1; i <= n; i++) {              // 枚举地砖
    for (int j = 1; j <= Math.min(i, m); j++) {  // 枚举回合（不超过 i 和 m）
        for (int k = Math.max(0, i - 3); k < i; k++) {  // 枚举步长前驱
            if (d[k][j-1] != -1)
                d[i][j] = Math.max(d[i][j], d[k][j-1] + a[i-1]);
        }
        if (i == n) ans = Math.max(ans, d[i][j]);  // 到达终点时更新答案
    }
}
```

- `j` 上界取 `Math.min(i, m)`：到达第 $i$ 块至少需要 $\lceil i/3 \rceil$ 回合、至多 $i$ 回合，所以 $j \le i$；同时受 $m$ 限制。
- `k` 从 `Math.max(0, i-3)` 开始：前驱只能在 $[i-3, i-1]$ 范围内，且不能为负（起点为 0）。
- `a[i-1]`：因为 `a` 数组是 0-indexed，而 `d` 的 `i` 是 1-indexed。

## 完整代码

```java
import java.util.*;

// 注意类名必须为 Main, 不要有任何 package xxx 信息
public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt(), m = in.nextInt();
        int[][] d = new int[n + 1][m + 1]; // d[i][j]: 恰好用 j 回合到达第 i 块的最大价值
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = in.nextInt();
        for (int i = 0; i <= n; i++) Arrays.fill(d[i], -1);
        d[0][0] = 0; // 起点（第一块地砖之前）
        int ans = -1;
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= Math.min(i, m); j++) {
                for (int k = Math.max(0, i - 3); k < i; k++) {
                    if (d[k][j - 1] != -1)
                        d[i][j] = Math.max(d[i][j], d[k][j - 1] + a[i - 1]);
                }
                if (i == n) ans = Math.max(ans, d[i][j]); // 到达终点更新答案
            }
        }
        System.out.println(ans);
    }
}
```

## 复杂度分析

| 维度 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | $O(n \cdot m)$ | 三重循环，但最内层步长固定为 3，常数级 |
| 空间 | $O(n \cdot m)$ | 二维数组 `d[n+1][m+1]` |

$n \cdot m \approx 10000 \times 5000 = 5 \times 10^7$ 个 `int`，约占 $200\text{MB}$，在 512M 限制下可过。若需进一步优化空间，可用**滚动数组**将 `d` 压缩为一维，空间降至 $O(n)$。

---

## 滚动数组优化版（可选）

由于 `d[i][j]` 只依赖 `j-1` 回合的值，可将二维压缩为一维：

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt(), m = in.nextInt();
        int[] a = new int[n + 1];
        for (int i = 1; i <= n; i++) a[i] = in.nextInt();

        int[] dp = new int[n + 1];
        Arrays.fill(dp, -1);
        dp[0] = 0;

        int ans = -1;
        for (int j = 1; j <= m; j++) {
            int[] next = new int[n + 1];
            Arrays.fill(next, -1);
            for (int i = 1; i <= n; i++) {
                int best = -1;
                for (int k = 1; k <= 3; k++) {
                    int prev = i - k;
                    if (prev >= 0 && dp[prev] != -1)
                        best = Math.max(best, dp[prev]);
                }
                if (best != -1) next[i] = best + a[i];
            }
            dp = next;
            ans = Math.max(ans, dp[n]);
        }
        System.out.println(ans);
    }
}
```

空间降至 $O(n)$，时间复杂度不变。

## 补充辨析：为什么归为序列DP，而不是划分DP

初看 `d[i][j] = max_k d[k][j-1] + a[i]` 这个式子，会觉得很像**划分DP**——因为两者的递推骨架完全一样：

```
dp[i][j] = 对前驱 k 取最值( dp[k][j-1] + 最后一段的贡献 )
```

但决定一个问题是「划分DP」还是「序列DP（跳台阶/线性DP）」，看的不是骨架，而是**「最后一段」是什么**：

| 判别维度 | 划分DP（如 [[410.分割数组的最大值-划分DP]]、[[813.最大平均值和的分组]]） | 本题 |
|---|---|---|
| 切点 k 的范围 | 整段 `[j-1, i-1]`，**任意位置都能切** | 只有 `{i-1, i-2, i-3}` **三个固定前驱** |
| 「段」的代价 | 依赖**整段内容**（段和 / 是否回文 / 是否在字典里） | **只看落脚点 a[i]**，中间被跳过的地砖不取 |
| j 的含义 | 段数（划分本身就是目标） | 回合数**上限**（限步约束） |
| 内层复杂度 | 枚举 k 是 $O(n)$，总 $O(n^2 m)$ | 内层固定 3 个前驱，总 $O(nm)$ |

本题从第 1 块跳到第 4 块时，被跨过的第 2、3 块**完全不参与收益**（示例1 印证：落在 2、4、5，跳过 1、3）。而真正的划分DP里，每一段是「切出来、整体结算」的连续块，段内每个元素都属于那一块。

> [!note] 为什么会有「像划分DP」的错觉
> 任何一个「走法」都**等价于**一种划分：落脚点 $i_0=0<i_1<\dots<i_t=n$ 把 `[1,n]` 切成 $t$ 段，每段长度恰好 $\in\{1,2,3\}$。所以本题**确实能改写成划分**——分成若干「长度 $\le 3$ 的连续段」，段收益 = 段末元素。只是这个划分的「段代价」退化成了只看端点、且段长有界，于是它从「$O(n)$ 切点任选」坍塌成「固定窗口的跳台阶 DP」。**骨架相同，本质不同**——这就是它留在序列DP 的真正理由。
