```java

class Solution {
    public double separateSquares(int[][] squares) {
        long totArea = 0;
        TreeMap<Integer, Long> diff = new TreeMap<>();
        for (int[] sq : squares) {
            int y = sq[1];
            long l = sq[2];
            totArea += l * l;
            diff.merge(y, l, Long::sum);
            diff.merge(y + (int) l, -l, Long::sum);
        }

        long area = 0;
        long sumL = 0;
        int preY = 0; // 不好计算下一个 y，改成维护上一个 y
        for (var e : diff.entrySet()) {
            int y = e.getKey();
            area += sumL * (y - preY); // 底边长 * 高 = 新增面积
            if (area * 2 >= totArea) {
                return y - (area * 2 - totArea) / (sumL * 2.0);
            }
            preY = y;
            sumL += e.getValue(); // 矩形底边长度之和
        }
        return -1;
    }
}
```
复杂度分析
时间复杂度：O(nlogn)，其中 n 是 squares 的长度。瓶颈在排序/维护有序集合上。
空间复杂度：O(n)。



这段代码用了一个非常巧妙的**一维扫描线（Scanline）结合差分**的思想。

虽然题目看似是关于二维正方形的，但因为我们要找的是一条**水平线 $y$**，使得这条线上下两部分的面积相等。这意味着，我们**根本不需要关心正方形在 $x$ 轴上的具体位置**。我们只需要关心在不同的 $y$ 高度区间内，正方形的“投影总宽度”是多少。

下面我为你拆解灵神（@endlesscheng）这段代码是如何用上差分的：

## 1. 核心思路：将二维面积转化为“一维积分”

当我们从下往上（沿 $y$ 轴正方向）扫描时，图形的面积是随着 $y$ 的增加而不断累加的。

- 在某个特定的高度区间 $(y_{i}, y_{i+1})$ 内，正方形的总宽度是固定不变的（假设为 `sumL`）。
    
- 那么在这个区间内，增长的面积就是：**$\text{底边总长度} \times \text{高度差}$**，即 `sumL * (y - preY)`。
    

## 2. 为什么能用差分？

因为正方形是连续的。对于一个左下角在 $(x, y)$、边长为 $l$ 的正方形：

- 它从高度 $y$ 开始出现，贡献了长度 $l$。
    
- 它到高度 $y + l$ 结束，不再贡献长度。
    

如果我们把 $y$ 轴看作一条直线，这就变成了一个典型的**区间修改问题**：在区间 $[y, y+l)$ 上，覆盖的长度增加了 $l$。

既然是区间修改，自然可以用**差分数组**来优化：

- 在左端点 $y$ 处：`diff[y] += l` （代表从这里开始，底边总长度增加了 $l$）
    
- 在右端点 $y + l$ 处：`diff[y + l] -= l` （代表从这里开始，底边总长度减少了 $l$）
    

## 3. 代码细节逐行解析

### 第一步：构建差分表（TreeMap）

因为 $y$ 的坐标可能很大且稀疏，普通的数组放不下，所以代码用了 `TreeMap`。`TreeMap` 会自动把 $y$ 坐标**从小到大排序**，这正好满足了我们从下往上扫描的需求。

Java

```
for (int[] sq : squares) {
    int y = sq[1];
    long l = sq[2];
    totArea += l * l; // 累加总面积
    
    // 差分核心：y 点上升 l，y+l 点下降 l
    diff.merge(y, l, Long::sum);
    diff.merge(y + (int) l, -l, Long::sum);
}
```

### 第二步：前缀和还原（扫描线过程）

接下来，通过遍历 `TreeMap`，其实就是在做**差分数组的前缀和还原**。前缀和还原出来的 `sumL`，就是当前高度位置的总底边长度。

Java

```
long area = 0;
long sumL = 0;
int preY = 0; 

for (var e : diff.entrySet()) {
    int y = e.getKey();
    
    // 【关键】先计算从上一个 y 到当前 y 之间累积的面积
    // 因为在这个高度差 (y - preY) 内，底边总长一直保持为 sumL 没变
    area += sumL * (y - preY); 
    
    // 如果当前累积的面积的 2 倍已经 >= 总面积了，说明切分线就在 [preY, y] 之间
    if (area * 2 >= totArea) {
        // 通过数学公式精确计算出截断的浮点数 y 位置，直接返回
        return y - (area * 2 - totArea) / (sumL * 2.0);
    }
    
    preY = y;         // 更新上一个 y 坐标
    sumL += e.getValue(); // 【差分还原】加上当前的差分值，得到下一个区间的总长度
}
```

## 4. 最后的数学小推导（怎么算返回值的？）

当发现 `area * 2 >= totArea` 时，说明我们**走过头了**。当前的 `area` 已经超出了总面积的一半（$\text{totArea} / 2$）。

我们需要从当前的 $y$ 往回退一点点，退多少呢？

假设需要往回退的高度为 $\Delta y$，那么需要减去的面积就是 $\sum L \times \Delta y$。

我们可以列出方程，让回退后的面积刚好等于总面积的一半：

$$\text{area} - \text{sumL} \times \Delta y = \frac{\text{totArea}}{2}$$

解这个方程求 $\Delta y$：

$$\text{sumL} \times \Delta y = \text{area} - \frac{\text{totArea}}{2}$$

$$\text{sumL} \times \Delta y = \frac{2 \times \text{area} - \text{totArea}}{2}$$

$$\Delta y = \frac{2 \times \text{area} - \text{totArea}}{2 \times \text{sumL}}$$

所以最终切分线的位置就是 $y - \Delta y$，对应了代码里的：

`y - (area * 2 - totArea) / (sumL * 2.0)`。这一步直接避免了二分查找浮点数带来的精度问题和循环开销，非常优雅。
