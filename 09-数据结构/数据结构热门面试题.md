## 一、线性表（5 题）

### 1. 数组和链表的区别？各自适合什么场景？【高频】

> **知识点跳转：** [[Java基础热门面试题-1#20. ArrayList 和 LinkedList 的区别？【高频】]]

**追问：** Java 里 ArrayList 的扩容机制？LinkedList 真的是"插入快"吗？

---

**参考答案 ✅**

数组是一块连续的内存，我拿到首地址和下标之后，就能用首地址加上下标乘元素大小直接算出目标地址，所以随机访问是常数时间；代价是长度固定，中间插入删除要整体搬移元素。链表靠指针把分散的结点串起来，插入删除只要改几个指针，但它没有下标寻址能力，想找第 n 个结点只能从头一个个走过去。

所以选型上，数组适合读多写少、需要频繁按下标访问的场景，链表适合长度变化大、经常在头尾增删的场景。落到 Java 里就是 ArrayList 和 LinkedList 的选择，但这里有一个必须纠正的说法：链表所谓插入快只在头尾成立，中间插入虽然改指针是常数时间，可要先花线性时间找到那个位置，整体并不快。

> **追问参考答：** ArrayList 默认容量是 10，扩容时新容量等于旧容量加上旧容量右移一位，也就是 1.5 倍，每次扩容都要把整个数组复制过去，所以能预估容量就直接指定，省掉多次扩容。LinkedList 的头部尾部操作确实是常数时间，所以它适合当队列或栈，但随机访问和中间插入都慢，而且每个结点都要存前后两个指针、内存不连续、缓存不友好，日常绝大多数场景还是用 ArrayList。

### 2. 栈和队列有什么区别？Java 里该怎么选实现类？【高频】

> **知识点跳转：** [[Deque 方法速记（栈 vs 队列）]] · [[155.最小栈]]

**追问：** Deque 的方法为什么分成"两套"？ArrayDeque 有什么限制？

---

**参考答案 ✅**

栈是后进先出，只在同一端进出；队列是先进先出，一端进另一端出。这两个结构本身很简单，难点在于 Java 里到底用哪个类去实现。

老式的 Stack 类继承自 Vector，每个方法都加了 synchronized，单线程下白白付出加锁开销，已经不建议用了。LinkedList 也能当栈和队列，但它是链表，每个结点有额外的指针开销，内存不连续、缓存也不友好。现在标准的做法是 ArrayDeque，它是循环数组实现的，头尾操作都是均摊常数时间，既能当栈也能当队列，性能和内存都优于前两者。

> **追问参考答：** Deque 把每一类操作都提供了两套方法，区别在失败时的行为：add、remove、element 这一组失败时抛异常，offer、poll、peek 这一组失败时返回特殊值，offer 失败返回 false，poll 和 peek 在空队列时返回 null。用的时候两组不能混着记，容易记串。ArrayDeque 的限制是不能存 null，因为内部用 null 当作 poll 和 peek 的失败标志。

### 3. 什么是单调栈？它为什么能做到 O(n)？【中频】

> **知识点跳转：** [[739. 每日温度 - 力扣（LeetCode）]]

**追问：** 接雨水用单调栈怎么做？单调栈和单调队列有什么区别？

---

**参考答案 ✅**

单调栈就是栈里始终保持一个单调递增或者单调递减的序列，专门用来找每个元素左边或右边第一个比它大或者比它小的元素。拿找下一个更大元素来说，我维护一个从栈底到栈顶递减的栈，遍历到新元素时，把所有比它小的栈顶元素依次弹出来，这些弹出来的元素它们的下一个更大元素就是当前这个新元素，弹完再把自己压进去。

它之所以是 O(n)，是因为每个元素最多进栈一次、出栈一次，总的进出次数是两倍的 n，而不是对每个元素都往后扫一遍，所以总代价是线性的。

> **追问参考答：** 接雨水那道题的单调栈做法是维护一个递减栈存下标，遇到比栈顶高的柱子就说明形成了凹槽，弹出栈顶当作凹槽底，用新的栈顶和当前柱子算宽度、用两者高度的较小值减去底的高度算水深，累加起来。它和单调队列的区别是单调队列维护一个滑动窗口内的最值，两头都会出队，队列头部是最值，用来解决滑动窗口最大值这类问题。

### 4. 循环队列怎么判空判满？为什么常用"牺牲一个空间"的办法？【中频】

> **知识点跳转：** [[Deque 方法速记（栈 vs 队列）]]

**追问：** 两种判满方式各自的取舍？

---

**参考答案 ✅**

循环队列用一个数组加上队头和队尾两个下标，靠取模把下标绕回头部，这样普通队列出队之后前面空出来的空间就能重复利用。

判空判满的麻烦在于，如果只看两个下标是否相等，空和满这两种状态的表现完全一样，区分不开。常见做法有两种：一种是牺牲一个存储位置，规定队尾加一再取模等于队头就是满，两个下标相等就是空，代价是永远浪费一个格子；另一种是额外用一个 size 变量记录元素个数，空间一点不浪费，判空判满也更直观。

> **追问参考答：** 工程里更推荐用 size 变量那种，因为它把空和满这两个状态彻底分开，代码里不用再记"满其实是差一格"这种隐式约定，出错概率更低。牺牲一格的做法胜在不需要额外字段，在一些对内存抠得很死、或者题目明确要求不准加计数字段的场景才用。

### 5. 什么是前缀和与差分？它们是一对什么关系？【中频】

> **知识点跳转：** [[560.和为K的子数组]]

**追问：** 它们共同的弱点是什么？怎么弥补？

---

**参考答案 ✅**

前缀和是把原数组预先累加一遍，得到一个累加数组，这样任意一个区间的和就能用两次前缀和相减在常数时间算出来，预处理是线性的。差分是它的逆操作：如果要对原数组做很多次区间加减，就在差分数组的左端点加、在右端点后面一位减，每次修改是常数时间，最后对整个差分数组求一次前缀和，就能还原出被修改后的原数组。

所以这两个是一对互逆的工具，前缀和把"多次查询"变便宜，差分把"多次修改"变便宜，用哪个取决于你是查得多还是改得多。

> **追问参考答：** 它们共同的弱点是不支持在线修改，因为原数组里某个位置一变，前缀和就全得重算，差分的还原也同理。要既支持单点修改又支持区间查询，就上树状数组或者线段树，两者都是对数时间，树状数组代码短、适合单点加加区间和，线段树更通用、能做区间修改和区间最值，还能配懒标记。

## 二、哈希表（4 题）

### 6. HashMap 的底层结构是怎样的？JDK 1.8 为什么引入红黑树？【高频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 为什么树化阈值是 8、退化阈值是 6？为什么还要求数组长度不小于 64？

---

**参考答案 ✅**

JDK 1.7 的时候 HashMap 底层是数组加链表，数组的每个位置是一个桶，元素按哈希值落到某个桶里，冲突了就在桶里挂成链表。这样做的隐患是链表一旦变长，查找就从常数时间退化成线性时间。

到了 1.8，为了给这种极端情况兜底，引入了红黑树：当某个桶的链表长度超过 8，并且数组长度不小于 64 的时候，就把这条链表转成红黑树，这样最坏情况下查找也从线性变成对数级别。所以 1.8 的完整结构是数组加链表加红黑树。

> **追问参考答：** 阈值选 8 的依据来自源码注释里给的泊松分布计算，在负载因子 0.75 下，随机哈希时一个桶里链表长度达到 8 的概率大约只有千万分之一，真到了这个长度说明哈希函数质量太差或者被人恶意构造了，这时候才值得付出树化的代价。退化阈值用 6 而不是 7，是为了和 8 之间留出一段缓冲，避免元素数在临界点上下抖动时反复树化又退化。要求数组长度不小于 64，是因为数组太小的时候桶本来就少、容易冲突，这种情况下应该先扩容把桶铺开，而不是急着把某条长链表升级成红黑树。

### 7. 哈希冲突有哪几种解决方法？HashMap 用的是哪种？【中频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 开放定址法删除元素时要注意什么？

---

**参考答案 ✅**

常见的有四种。第一种是链地址法，冲突的元素挂在同一个桶里组成链表或者树，HashMap 用的就是它，长链表用红黑树兜底。第二种是开放定址法，冲突了就按某种探测序列去找下一个空位，线性探测、二次探测、再哈希都属于这一类。第三种是再哈希法，准备多个不同的哈希函数，第一个算出来的位置被占了就换下一个。第四种是公共溢出区，所有冲突的元素统一丢到一个地方。

要特别对比一下，Java 里 HashMap 用的是链地址法，而 ThreadLocalMap 用的是开放定址法的线性探测，这两个放在一起问是常考的对比点。

> **追问参考答：** 开放定址法里删除元素不能直接把位置置空，否则会把后面元素的探测链截断，导致它们查找不到，正确做法是打一个墓碑标记表示这里曾经有元素、现在已删除但探测还要继续，ThreadLocalMap 就是用 key 为 null 的哨兵结点来表示这种已删除状态。

### 8. HashMap 的容量为什么必须是 2 的幂？扩容时做了什么优化？【高频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 默认初始容量和负载因子是多少？已知要存 100 个元素，初始容量该设多少？

---

**参考答案 ✅**

因为算下标用的是容量减一再和哈希值做与运算，只有容量是 2 的幂的时候，容量减一的二进制才是低位全 1，哈希值的每一位才能真正参与到下标计算里，分布才均匀。如果容量不是 2 的幂，容量减一中间会出现 0，某些下标永远取不到，冲突概率就会上升。

扩容时的优化在于，容量翻倍之后元素的新位置只有两种可能，要么留在原来那个位置，要么在原来位置加上原容量那个位置，1.8 只要判断哈希值在扩容新增的那一位是 0 还是 1 就能直接决定归属，不需要像 1.7 那样把每个元素重新算一遍哈希和下标。

> **追问参考答：** 默认初始容量是 16，负载因子是 0.75，扩容阈值等于容量乘负载因子，也就是 16 乘 0.75 等于 12，元素数超过阈值就触发扩容，每次扩到原来的两倍。已知要存 100 个元素的话，用 100 除以 0.75 大约是 134，再向上取到 2 的幂就是 256，直接传这个值进去就能避免中间多次扩容。

### 9. 为什么 HashMap 的 key 一般用不可变类？自定义 key 要注意什么？【中频】

> **知识点跳转：** [[HashMap Java 面试题完整详解（口述版）]]

**追问：** 用可变对象当 key、之后再改字段，会发生什么？

---

**参考答案 ✅**

因为 key 的哈希值决定了它落在哪个桶里。如果这个对象的内容可以被修改，放在里面之后哈希值就可能变化，那么它在物理上还留在原来的桶里，可是我用新的哈希值去找它会定位到别的桶，结果就是找不到，等于这个键值对凭空消失了，但内存里还留着一条取不出来的记录。

所以推荐用 String、Integer 这些不可变类当 key，它们的内容不会变，哈希值算一次还能缓存下来。自定义类当 key 的话，一定要同时正确重写 hashCode 和 equals，保证 equals 判定相等的两个对象 hashCode 也相等，而且用来参与这两个方法的字段一旦放进 map 就不要再改。

> **追问参考答：** 拿可变对象当 key、修改它参与哈希的字段之后，用这个 key 去 get 会返回 null，因为它已经跑到错误的桶里去了；但它占用的那条 entry 还在原桶里，只能靠迭代器才能看到，这就是典型的"内存泄漏"式的隐性 bug。要修的话只能重新 put 一个新的 key，旧的记录要手动清理。

## 三、树（7 题）

### 10. 满二叉树、完全二叉树、严格二叉树怎么区分？二叉树有哪些必背性质？【笔试高频】

> **知识点跳转：** [[树#二、二叉树的特殊形态]] · [[树#十一、笔试计算题速查]]

**追问：** 叶子数等于度为 2 的结点数加一，这个怎么推导？

---

**参考答案 ✅**

满二叉树要求每一层都填满、叶子全部在最底层；完全二叉树松一点，只要求除最后一层以外都填满，最后一层的结点从左往右连续排列；严格二叉树只看每个结点的度必须是 0 或者 2，不要求叶子都在同一层。

所以满二叉树一定是完全二叉树，反过来不成立。最容易错的是把"每个结点的度是 0 或 2"直接当成满二叉树，那其实只是严格二叉树，满二叉树还额外要求每层填满、叶子全在最底层。

必背性质里最重要的是叶子数等于度为 2 的结点数加一，另外还有完全二叉树有 n 个结点时高度是 log2n 向下取整再加一，叶子数是 n 除以 2 向上取整。

> **追问参考答：** 推导方式是设结点总数为 n，度为 0、1、2 的结点数分别是 n0、n1、n2，那么 n 等于三者之和；再从边的角度数一遍，除根以外每个结点都恰好有一条从父结点指向它的边，所以边数是 n 减一，而从度的角度数边数是 n1 加两倍的 n2，两式联立就能得到 n0 等于 n2 加一。

### 11. 二叉树的四种遍历分别是什么？由遍历序列怎么还原一棵树？【笔试高频】

> **知识点跳转：** [[树#三、二叉树的遍历]] · [[102.二叉树的层序遍历]]

**追问：** 为什么对 BST 来说中序遍历就是升序序列？

---

**参考答案 ✅**

四种遍历是按根被访问的时机命名的，先序是根左右，中序是左根右，后序是左右根，层序则是从上到下、每层从左到右。还原整棵树的关键在于，先序、后序、层序这三种都负责找到根，中序负责用这个根把序列切成左右子树两段。

所以先序加中序能唯一确定一棵树，后序加中序也行，层序加中序同样可以。但只有先序加后序不行，因为分不清左右子树的边界在哪里，只有在树是满二叉树这种特殊情况下才唯一。

> **追问参考答：** 对二叉搜索树来说，中序遍历的顺序正好是从小到大，所以判断一棵树是不是合法的 BST，最快的办法就是做一次中序遍历，看结果是不是严格递增。另外实现手段上记两条：层序遍历用队列做 BFS，先序遍历用栈做非递归或者直接递归。

### 12. 什么是二叉搜索树？它最大的问题是什么？【高频】

> **知识点跳转：** [[树#六、二叉搜索树（BST，二叉排序树）]]

**追问：** BST 删除一个有两个孩子的结点，该怎么删？

---

**参考答案 ✅**

二叉搜索树对任意一个结点，左子树上的所有结点都小于它，右子树上的所有结点都大于它，所以它的中序遍历出来就是一个升序序列。查找、插入、删除在树比较平衡的时候平均都是对数时间。

它最大的问题是会退化：如果按一个有序序列依次插入，每个新结点都挂在同一侧，树就变成一条斜链，查找直接退化到线性时间，跟链表没区别。正因为如此才需要平衡机制来兜底，AVL 树要求左右子树高度差不超过 1，红黑树只要求近似平衡，两者都把最坏情况拉回到对数级别。

> **追问参考答：** 删除分三种情况。删叶子结点直接删掉就行。结点只有一个孩子，就用它唯一的那个孩子顶替它的位置。结点有两个孩子，就用它的中序前驱也就是左子树里最右的结点，或者中序后继也就是右子树里最左的结点，把值替换过来，然后再去删那个前驱或者后继结点，注意替换的是值、删掉的是那个叶子位置上的结点。

### 13. AVL 树和红黑树有什么区别？为什么 Java 里选红黑树？【高频】

> **知识点跳转：** [[树#七、平衡二叉树（AVL 树）]] · [[树#八、红黑树]]

**追问：** 红黑树的五条性质是什么？为什么说它是近似平衡？

---

**参考答案 ✅**

AVL 树是严格平衡，任何一个结点左右子树的高度差绝对值都不超过 1，所以树更低、查找更快；代价是插入删除之后为了维持这个严格条件，可能要沿路径一路旋转到根，调整代价高。

红黑树是近似平衡，它靠五条颜色规则保证最长路径不超过最短路径的两倍，所以树会稍微高一点、查找略慢，但插入删除最多几次旋转就能恢复平衡。工程上增删往往比查询更频繁，红黑树用一点点查询性能换来了更低的调整成本，所以 TreeMap、TreeSet，以及 HashMap 桶里那棵树，选的都是红黑树。

> **追问参考答：** 五条性质是：每个结点非红即黑；根结点是黑；每个叶子也就是 NIL 空结点是黑；红结点的两个孩子必须是黑，也就是不能出现连续两个红结点；从任意一个结点到它所有后代叶子的路径上，黑结点的数目相同。由第四条和第五条可以推出最长路径不超过最短路径的两倍，所以树高不超过两倍的 log2(n+1)，这就是它"近似平衡"的由来。

### 14. B 树和 B+ 树有什么区别？为什么 MySQL 用 B+ 树做索引？【高频】

> **知识点跳转：** [[树#九、B 树与 B+ 树]] · [[MySQL索引]]

**追问：** 那为什么不用红黑树或者哈希表？

---

**参考答案 ✅**

两者都是多路平衡查找树，区别集中在数据放在哪、叶子连不连。B 树的每个结点都可能存数据，关键字只出现一次，查找可能还没走到叶子就在非叶结点命中了。B+ 树只有叶子结点存数据，非叶结点只存索引，所有关键字都会在叶子结点里再出现一次，而且叶子结点之间用链表顺序相连。

MySQL 选 B+ 树有两条理由。一是非叶结点不存数据，同样一个 16KB 的页就能放下更多索引项，树变得更矮更胖，查一次要走的磁盘 IO 次数更少；二是叶子结点有链表，做范围查询的时候顺着链表往后扫就行，B 树得靠中序遍历收集关键字。

> **追问参考答：** 不用红黑树是因为红黑树是二叉的，每个结点只有两个孩子，数据量大起来树就很高，查一次要走很多层、很多次磁盘 IO。不用哈希表是因为哈希索引只支持等值查询，做不了范围查询和排序，而实际业务里范围条件和 order by 非常常见，而且哈希冲突严重时性能也会退化。

### 15. 树和森林怎么转成二叉树？有什么容易记错的对应关系？【笔试中频】

> **知识点跳转：** [[树#五、树、森林与二叉树的转换]]

**追问：** 森林里叶结点的个数，怎么从转换后的二叉树上看出来？

---

**参考答案 ✅**

用的是孩子兄弟表示法，每个结点的左指针指向它的第一个孩子，右指针指向它的下一个兄弟。所以一棵树转成二叉树之后，根结点一定没有右子树。如果是一片森林，各棵树的根再通过右指针串成一条链，就整体转成了一棵二叉树。

最容易记错的是遍历的对应关系：树的先根遍历对应转换后二叉树的先序遍历，而树的后根遍历对应的是二叉树的中序遍历，不是后序遍历。这个坑几乎每次考试都有人踩。

> **追问参考答：** 森林的叶结点个数等于转换后二叉树里左孩子指针为空的结点个数。因为左指针只表示"有没有第一个孩子"，森林里是叶结点就意味着没有孩子，也就没有第一个孩子，左指针自然为空，反过来也成立。作为对照，二叉树里右孩子指针为空的结点个数等于兄弟链的条数，也就是森林里非叶结点的个数加一，这两个数千万别混。

### 16. 什么是前缀树？它适合解决什么问题？【中频】

> **知识点跳转：** [[208.实现前缀树]]

**追问：** 前缀树和哈希表比，各有什么优劣？

---

**参考答案 ✅**

前缀树也叫字典树或者 Trie，它把字符串按字符一层层挂到树上，从根到某个结点的路径就是一段前缀，结点上再打一个标记表示到这里是不是一个完整的单词。

它的好处有两条：一是插入和查询的复杂度只和字符串的长度有关，和一共有多少个单词无关；二是天然支持前缀匹配，比如输入法的联想词、搜索引擎的提示词，还有判断一个前缀是不是某个单词的前缀这种查询。它的代价在空间，如果字符集很大、或者单词之间没什么公共前缀，树上的结点会非常稀疏，很吃内存。

> **追问参考答：** 哈希表只能做整个串的精确匹配，做不了前缀查询，这是它的先天短板；而前缀树支持前缀查询、还支持按字典序把所有单词遍历出来。反过来，哈希表的平均查询是常数时间、空间也更省，前缀树每次查询要沿字符走一条路径、常数比哈希大，所以如果只需要精确判断某个完整字符串在不在集合里，用哈希表更划算。

## 四、堆与优先队列（3 题）

### 17. 什么是堆？为什么堆可以用数组来存？【高频】

> **知识点跳转：** [[排序算法笔试对照总表#四、建堆与堆相关的高频考法]]

**追问：** 建堆的时间复杂度为什么是 O(n)，不是 O(n log n)？

---

**参考答案 ✅**

堆是一棵完全二叉树，同时满足堆序：大根堆里每个结点都不小于它的孩子，小根堆里每个结点都不大于它的孩子，所以堆顶就是整个堆里的最值。

它之所以能用数组来存，关键就在于它是完全二叉树：除最后一层外都填满，最后一层从左连续排列，把它按层序放进数组不会有空位。于是结点之间的父子关系就能用下标公式直接算出来，下标从零开始的话，结点 i 的左孩子是 2i 加 1、右孩子是 2i 加 2、父结点是 i 减 1 再除以 2。这样就不用存指针，省下了一大笔内存，而且数组连续、缓存友好。

> **追问参考答：** 建堆是从最后一个非叶结点开始往前，对每个结点做一次向下调整。每个结点调整的代价是它自己的高度，而高度越大的结点数量越少，把每一层的结点个数乘上这一层的高度再求和，这个总和被 n 这个量级卡住，是线性的，所以建堆是 O(n)。真正花 O(n log n) 的是建堆之后的排序阶段，也就是反复把堆顶和堆尾交换、堆大小减一、再对堆顶向下调整，一共做 n 减一次。

### 18. PriorityQueue 的底层是什么？默认是大根堆还是小根堆？【中频】

> **知识点跳转：** [[机试#九、PriorityQueue 速查（刷题高频）]]

**追问：** 插入和删除的复杂度是多少？并发场景怎么办？

---

**参考答案 ✅**

PriorityQueue 底层就是一个数组实现的二叉堆，默认是小根堆，所以 peek 和 poll 拿出来的是当前的最小值。要改成大根堆，就在构造的时候传一个反向比较器，最省事的是传 Collections.reverseOrder 或者 Comparator.reverseOrder，也可以自己写一个 lambda 把参数顺序倒过来。

这里有个必须记住的坑：比较器里千万不要写成两个数相减然后返回，因为两个大整数相减会溢出，溢出之后比较结果就彻底乱了，标准写法是用 Integer.compare 比大小。

> **追问参考答：** 插入是先把元素放到堆尾再向上筛，删除堆顶是把堆尾换到根再向下筛，两个都是 O(log n)，取堆顶是 O(1)。PriorityQueue 不是线程安全的，并发场景用 PriorityBlockingQueue，它是无界的；如果需要按到期时间取元素，用 DelayQueue，它底层也是优先级队列，常用于订单超时关闭、定时任务这类场景。

### 19. TopK 问题为什么用小根堆而不是大根堆？【高频】

> **知识点跳转：** [[215. 数组中的第K个最大元素]] · [[排序算法笔试对照总表#四、建堆与堆相关的高频考法]]

**追问：** 内存装不下全部数据的时候怎么办？

---

**参考答案 ✅**

求前 K 大的元素，标准做法是维护一个大小固定为 K 的小根堆。元素一个个往里放，堆还没满就直接放；堆满了就把它和堆顶比一下，如果它比堆顶大，说明堆顶这个当前最小值肯定挤不进前 K 名，就把堆顶弹掉、把它放进去；如果它比堆顶小，直接丢掉就行。这样遍历一遍，堆里剩下的就是最大的 K 个，时间复杂度是 n 乘 log K，额外空间只有 K。

口诀是求大用小、求小用大：求前 K 大用小根堆，求前 K 小用大根堆。因为要用堆顶那个最容易被淘汰的元素当守门员，堆顶越小，淘汰的门槛就越高，答案才留得住。

> **追问参考答：** 数据量太大、内存装不下的时候，可以用分治加哈希的思路：按某个哈希值把数据拆到多个小文件里，保证相同的元素落到同一个文件，然后每个文件单独求自己的前 K，最后把各个文件的结果归并起来再求一次。另一个方向是快速选择，用快排划分的思想每次只递归包含答案的那一侧，平均能做到线性时间。堆还有一个高频配套场景是合并 K 个有序链表，把每条链的头结点放进小根堆，每次取出最小的接到结果后面。

## 五、图（4 题）

### 20. 图的两种存储结构有什么区别？该怎么选？【笔试中频】

> **知识点跳转：** [[图#一、邻接矩阵存储]] · [[图#二、邻接矩阵 vs 邻接表]]

**追问：** n 个顶点的无向图用邻接矩阵存，这个矩阵一定有什么性质？

---

**参考答案 ✅**

邻接矩阵用一个 n 乘 n 的二维数组，a[i][j] 记录 i 到 j 有没有边、或者边的权值，空间固定是 n 平方，跟边的多少没关系，判断两点是否相邻是常数时间，但遍历一个点的所有邻居要扫一整行、里面还夹着大量零。邻接表是给每个顶点挂一条链表或动态数组，存它的所有邻居，空间是 n 加边数这个量级，无向图里每条边会在两端的链表里各存一次，也就是 2e 个表项，遍历邻居很快，但判断两点是否相邻要挨个走链表。

所以一句话说，矩阵是查得快、费空间，表是省空间、遍历快。稠密图用矩阵，稀疏图用表；而 BFS、DFS、Dijkstra、拓扑排序这些算法的核心动作都是遍历某个点的邻居，所以默认都建邻接表。

> **追问参考答：** 无向图的邻接矩阵一定是对称矩阵，因为 i 和 j 相连等价于 j 和 i 相连，所以 a[i][j] 等于 a[j][i]。但它不一定稀疏，完全图的邻接矩阵除了主对角线之外全是 1，是稠密的，所以"稀疏矩阵"不是无向图邻接矩阵的固有属性。有向图的邻接矩阵一般不具对称性，因为 i 到 j 有边不代表 j 到 i 也有边。

### 21. BFS 和 DFS 有什么区别？各自适合什么场景？【中频】

> **知识点跳转：** [[207.课程表]] · [[102.二叉树的层序遍历]]

**追问：** 拓扑排序怎么实现？结果唯一吗？

---

**参考答案 ✅**

BFS 是广度优先，一层一层往外扩，用队列实现；DFS 是深度优先，一条路走到黑再回溯，用栈或者递归实现。BFS 天然适合求无权图的最短路和按层扩散的问题，因为它第一次到达某个点时走的层数就是最少的；DFS 适合判断连通性、枚举所有路径、回溯搜索，还有拓扑排序和检测环。

这里有个容易答错的点：BFS 只在所有边权相同、通常就是权值都是 1 的时候才等价于最短路，带权图上"层数少"并不代表"总花费小"，那就必须用 Dijkstra。

> **追问参考答：** 拓扑排序就是在有向无环图上排出一个线性顺序，让所有边的方向都是从前往后。Kahn 算法的做法是统计每个点的入度，把入度为零的点先入队，每出队一个点就把它指向的那些点的入度减一，减到零再入队，如果最后输出的点数少于总点数，说明图里有环。拓扑序一般不唯一，只有当图里存在一条经过所有点的路径时，顺序才唯一。

### 22. Dijkstra 算法解决什么问题？为什么它不能处理负权边？【中频】

> **知识点跳转：** [[Dijkstra 模板与变体谱系]]

**追问：** 有负权边怎么办？它和 BFS、Prim 分别有什么区别？

---

**参考答案 ✅**

Dijkstra 求的是带权图上单源点到其余各点的最短路，前提是所有边权非负。它的做法是贪心：每次从来没确定的点里挑一个当前距离最小的，把它标记成已确定，再用它去松弛它指向的邻居，更新邻居的距离。

它不能处理负权边的原因就在这个贪心上。这个算法正确性的前提是"某个点一旦被取出，它的最短距离就再也不会变小了"，可是只要存在负权边，一个已经出队的点完全可能通过后面某条负权边被绕回来、距离变得更小，这个前提就崩了，贪心随之失效。

> **追问参考答：** 有负权边就用 Bellman-Ford，它对所有边做多轮松弛，能处理负权，还能检测负权环，SPFA 是它常用的一种队列优化实现，最坏复杂度是点数乘边数。和 BFS 的区别是 BFS 只看层数、等价于边权全为 1 的 Dijkstra，Dijkstra 看的是累计权值。和 Prim 的区别是目标不同：Prim 求的是让全图连通的最小生成树，Dijkstra 求的是一个点到其他点的最短路径，两者虽然都是"每次挑最近的点"的贪心，但更新的口径不一样。

### 23. 什么是最小生成树？Prim 和 Kruskal 该怎么选？【中频】

> **知识点跳转：** [[图#六、最小生成树（MST）]] · [[684. 冗余连接 - 力扣（LeetCode）]]

**追问：** 最小生成树唯一吗？它和最短路是一回事吗？

---

**参考答案 ✅**

最小生成树是在一个连通无向图里，选出恰好 n 减一条边把所有顶点连成一片、而且边权之和最小的那棵生成树。Prim 是从一个点出发往外扩，每次挑一个离当前生成树最近的点和最短的那条边并进来，适合稠密图，朴素实现是 n 平方，用堆优化可以到边数乘 log。Kruskal 是把所有边按权值从小到大排序，依次尝试加入，如果这条边两端已经连通就跳过，否则加入，判连通用的是并查集，适合稀疏图，复杂度主要花在排序上。

记法就一句：点少边多用 Prim，边少点多用 Kruskal。Kruskal 的本质可以概括成排序加并查集。

> **追问参考答：** 最小生成树的总权值是唯一的，但树的形态不一定唯一，只有当所有边权两两不相同的时候才唯一，存在等权边时就可能有多棵不同的最小生成树。它和最短路不是一回事，最小生成树保证的是把全图连起来总成本最低，并不保证任意两点之间的路径最短，求两点最短路要用 Dijkstra 或者 Floyd，这两个概念千万别混。另外图不连通的时候没有生成树，求的是最小生成森林。

## 六、工程数据结构（4 题）

### 24. 什么是跳表？为什么 Redis 的 ZSet 用它而不用红黑树？【高频】

> **知识点跳转：** [[跳表（Skip List）详解#五、Redis ZSet 中的跳表]] · [[Redis底层编码标准答案#5. ZSet]]

**追问：** 为什么 ZSet 还要配一个哈希表？

---

**参考答案 ✅**

跳表是在有序链表上又加了多层索引，底层是包含全部元素的有序链表，越往上层元素越稀疏，查找时从最高层开始往右走，走过头就下降一层，这样把链表的线性查找加速到对数级别。它的层高是随机决定的，Redis 里用四分之一的概率往上加一层、最多三十二层，所以它只在概率意义上平衡，不需要像红黑树那样维护旋转和染色。

Redis 的 ZSet 选它，一是范围查询方便，找到起点之后顺着 forward 指针一路往右就能扫完整个区间，红黑树得靠中序遍历去收集；二是实现简单，插入删除只改局部指针，没有旋转染色这一堆调整。所以在这类"范围操作加排名"是核心需求的排行榜场景里，跳表更划算。

> **追问参考答：** 因为跳表擅长的是范围查询和排名，但按 member 精确查分数这个动作它不占优势，所以 Redis 在跳表之外又配了一个 dict 哈希表，负责常数时间地把 member 定位到 score，像 ZSCORE、ZINCRBY 走的是哈希表，ZRANGE、ZRANGEBYSCORE、ZRANK 走的是跳表。另外跳表每个结点还带一个 span 跨度字段，记录到下一个结点跨了多少个底层结点，靠它才能让查排名也是对数的，不用遍历全表去数。

### 25. 布隆过滤器是什么？为什么它能解决缓存穿透？【高频】

> **知识点跳转：** [[什么是缓存雪崩、击穿、穿透？#缓存穿透]]

**追问：** 为什么说它"说不存在一定准确"？它能删除元素吗？

---

**参考答案 ✅**

布隆过滤器由一个位图数组和若干个哈希函数组成。写入一个元素的时候，用它算出来的几个哈希值把位图上对应的位置都置成一；查询的时候也用同样的方式算出这几个位置，只要其中有一个是零，就说明这个元素肯定没有写入过，如果全都是位一，那只能说它可能存在。

所以它给出的否定是确定的，肯定却只是概率性的，会有误判。防缓存穿透就是靠这一点：请求先过布隆过滤器，如果它说不存在就直接返回空，不用去查数据库，于是大量查询不存在数据请求就被挡在数据库外面了。

> **追问参考答：** 说不存在一定准确，是因为只要元素写入过，它对应的那几个位就必然被置成了一，如果某一位还是零，说明从来没有元素把它置成一，这个元素自然不可能在集合里；反过来全是位一却可能是好几个别的元素把这几位置成了一，这就产生了误判。它不支持删除，因为一个位置可能被多个元素共用，把某一位清零会把别的元素也一起误判成不存在，要支持删除就得用计数的布隆过滤器，把每个位置换成一个小计数器，删除时减一。误判率由位图长度、哈希函数个数和元素数量共同决定，位图越长、哈希函数个数配得越合适，误判率就越低。

### 26. LRU 缓存怎么用两个结构做到常数时间？【高频】

> **知识点跳转：** [[146.LRU缓存]] · [[手撕#146.LRU 缓存]]

**追问：** Java 里怎么用 LinkedHashMap 快速实现？

---

**参考答案 ✅**

LRU 淘汰的是最久没有被使用过的元素，所以要同时满足两个能力：一是按 key 常数时间定位到结点，二是能快速知道谁是最久未使用的并且把它删掉。做法就是哈希表加双向链表：哈希表负责 key 到结点的定位，双向链表负责维护使用顺序，越靠头部越新。

每次 get 或者 put 命中已有的 key，就把对应结点从链表里摘下来重新挂到头部；插入新元素时如果超出容量，就删掉链表的尾结点，同时把哈希表里对应的键也删掉。这里必须用双向链表，因为删除一个结点时要能直接拿到它的前驱，单链表做不到常数时间删除。

> **追问参考答：** 用 LinkedHashMap 会省事很多，构造的时候把 accessOrder 设成 true，它就按访问顺序而不是插入顺序来维护内部链表，再重写 removeEldestEntry 方法，一旦大小超过容量就返回 true，它就会自动淘汰最老的结点。手写的话就是那道 LRU 缓存题的标准模板：一个哈希表加一条带哨兵头尾的双向链表，把"摘下来、挂到头部"和"删掉尾部"抽成两个私有方法。

### 27. 并查集是什么？它为什么几乎可以当成常数时间？【中频】

> **知识点跳转：** [[684. 冗余连接 - 力扣（LeetCode）]]

**追问：** 路径压缩和按秩合并分别解决什么问题？只做其中一个够吗？

---

**参考答案 ✅**

并查集维护的是一堆不相交集合的合并和查询，它能回答两个核心问题：某个元素属于哪个集合，以及两个元素在不在同一个集合里。实现上每个元素记一个父结点，一路往上找到根就是它所属集合的代表，合并两个集合就是把其中一棵树的根挂到另一棵的根下面。

它快在两个优化。一个是路径压缩，find 的时候顺手把路径上经过的结点都直接挂到根上，让树迅速变扁；另一个是按秩或者按大小合并，把矮树挂到高树下面，别让树越长越高。这两个优化一起用，均摊复杂度是反阿克曼函数的级别，这个函数增长极慢，实际用的时候基本可以当成常数看待。

> **追问参考答：** 路径压缩解决的是"查询路径太长"，它把一条长链压扁，让下次查这些结点时一步到位；按秩合并解决的是"合并时把树越接越高"，它保证树高不会失控地增长。只做路径压缩不做按秩合并，最坏情况下树还是可能被接得很高，复杂度会差一些，所以标准实现是两个一起上。它最典型的应用是 Kruskal 里判断加一条边会不会成环，还有判断无向图的连通分量、以及处理冗余连接这类题。

## 七、复杂度与选型（3 题）

### 28. 常见数据结构的操作复杂度怎么记？选型上有什么口诀？【必背】

> **知识点跳转：** [[排序算法笔试对照总表#一、复杂度与稳定性总表（骨架）]] · [[机试#十、TreeMap 速查（有序 Key 的 Map，刷题高频）]]

**追问：** 什么时候必须从哈希表换成 TreeMap？

---

**参考答案 ✅**

数组按索引访问是常数时间，中间插入删除是线性时间。链表两端插入删除是常数时间，随机访问是线性时间。哈希表平均是常数时间，最坏退化到线性或者对数。平衡二叉搜索树增删查都是对数时间。堆的插入和删除是对数时间，取堆顶是常数时间。B+ 树这类磁盘结构不按内存操作次数算，而是按磁盘 IO 次数算，树高通常只有几层。

选型的口诀是：要按下标随机读就用数组；要频繁在两端增删就用链表或者双端队列；要按 key 快速查就用哈希表；要维护有序、做范围查询和取最值就用 TreeMap 这类平衡树；要频繁取最值就用堆；数据量到了数据库那个量级就轮到 B+ 树。

> **追问参考答：** 分水岭是"要不要按顺序取"。哈希表查得快、平均常数，但它不维护顺序，一旦题目要取最小最大的 key、要取某一个 key 的前后邻居、要截取一个区间的子表，哈希表就无能为力了，这时候必须换成 TreeMap，它有 firstKey、lastKey、floorKey、ceilingKey 这些方法，代价是操作从常数变成对数。再一个维度是内存和速度的取舍，跳表、布隆过滤器这些都是拿空间换时间。

### 29. 为什么 Arrays.sort 排基本类型数组最坏可能是平方级？【机试高频】

> **知识点跳转：** [[机试#十五、Java 机试坑点速查]] · [[912.排序数组]]

**追问：** 那排序的稳定性怎么记？

---

**参考答案 ✅**

因为 Java 对基本类型数组用的是双轴快速排序。快排本身是不稳定的，最坏情况是平方级，遇到特意构造的针对性数据会被卡到超时，这在机考里是一个真实存在的坑。而对象数组用的是 TimSort，它是归并排序的变种，稳定、而且保证最坏也是 n 乘 log n，代价是排序过程中要装箱、多一层对象开销，所以通常反而更慢。

规避办法有两个：把基本类型数组装箱成包装类数组再排，或者排序前先随机打乱破坏那个针对性构造。如果要在机试里手写排序，优先用归并排序的模板，行为固定、不会被卡。

> **追问参考答：** 稳定性是说排完之后数值相等的元素相对次序保持不变。不稳定的有四个：快速排序、希尔排序、简单选择排序、堆排序；稳定的也有四个：直接插入、冒泡、归并、基数排序。口诀是"快些选堆不稳定"，注意这里的选择说的是简单选择排序。要稳定排序又不能用工具类的时候，就用归并排序。

### 30. 树状数组是干什么的？它比前缀和强在哪？【中频】

> **知识点跳转：** [[机试#十二、树状数组（Fenwick Tree）速查]] · [[机试#十五、Java 机试坑点速查]]

**追问：** 树状数组和线段树怎么选？

---

**参考答案 ✅**

树状数组解决的是"既能单点修改、又要能快速查区间和"这一类问题。它的单点更新和前缀和查询都是对数时间，核心技巧是那个 lowbit，也就是取出一个数最低位的一：更新的时候不断往 i 加上 lowbit 往上跳，查询的时候不断往 i 减去 lowbit 往下跳，数组里每个位置管的区间正好是 (i 减 lowbit(i), i]。

它比普通前缀和强就强在支持修改。前缀和把区间查询做到常数时间，但代价是原数组一改就全得重算，等于是"只读"的结构；树状数组把两种情况都压到对数时间，属于读写比较均衡的折中。

> **追问参考答：** 树状数组代码短、常数小，适合单点加加区间和、以及求逆序对这类"数左边或右边有多少个比它大或比它小"的问题，值域大的时候先做离散化把值压缩到一到 n。线段树更通用，能做区间修改、区间最值、区间合并，代价是代码长、常数大、空间也大，需要懒标记才能把区间修改压到对数时间。机试里能用树状数组解决的就别上线段树，写起来快很多。
