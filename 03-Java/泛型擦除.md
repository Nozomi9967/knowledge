### **类型擦除是 Java 泛型的一种编译期优化机制，它在编译后的字节码中移除泛型类型信息，保持与非泛型代码的兼容性**

## 类型擦除的核心作用

**1. 向后兼容性**

Java 5 引入泛型时，需要与 Java 1.4 及之前的非泛型代码兼容。通过类型擦除，泛型代码编译后的字节码与非泛型代码完全一致，这样就不需要改变 JVM 和运行时环境。

```java
// 泛型代码
List<String> list = new ArrayList<>();
list.add("hello");

// 编译后被擦除为
List list = new ArrayList();
list.add("hello");
```

**2. 减少运行时开销**

如果 JVM 在运行时维护泛型信息，会增加内存占用和性能开销。通过类型擦除，泛型只存在于编译期，运行时没有额外负担。

**3. 简化 JVM 设计**

不需要为泛型在 JVM 层面做特殊处理，保持 JVM 的简洁性和稳定性。

## 类型擦除的具体过程

编译器会按照以下规则进行擦除：

**无界类型参数 → Object**

```java
public class Box<T> {
    private T value;
}
// 擦除后
public class Box {
    private Object value;
}
```

**有界类型参数 → 上界**

```java
public class NumberBox<T extends Number> {
    private T value;
}
// 擦除后
public class NumberBox {
    private Number value;
}
```

**方法中的泛型 → 插入强制转换**

```java
public <T> T getValue(Box<T> box) {
    return box.get();  // 返回 T
}
// 擦除后 — 方法签名 T 替换为 Object，方法体不变
public Object getValue(Box box) {
    return box.get();
}
// 编译器在调用处插入强制转换：
String s = getValue(box);  // 编译为 String s = (String) getValue(box);
```

## 类型擦除带来的限制

正因为类型擦除，Java 泛型有一些你可能会遇到的限制：

**不能创建泛型数组**

根本原因是**数组的协变 + 运行时类型检查**与**泛型擦除**两套机制冲突了。

```java
// 编译错误
List<String>[] arrays = new List<String>[10];
```

### 为什么冲突？

数组是协变的——`String[]` 可以赋给 `Object[]`。同时，数组在运行时检查实际元素类型，往 `String[]` 放 `Integer` 会立刻报 `ArrayStoreException`。

但泛型参数会被擦除：`List<String>` 和 `List<Integer>` 在运行时都只是 `List`。如果允许创建泛型数组，就可能发生以下危险情况：

```java
List<String>[] stringLists = new List<String>[1];

// 数组协变：List<String>[] 可以被当作 Object[] 使用
Object[] objects = stringLists;

// 运行时看到的元素类型只是 List，所以允许放入 List<Integer>
objects[0] = List.of(123);

// 编译器仍相信这里取到的一定是 String
String s = stringLists[0].get(0); // 运行时 ClassCastException！
```

JVM 只能确认放进去的是某种 `List`，却无法确认它是不是 `List<String>`。为了避免把这个隐患埋进类型系统，Java 禁止直接创建"具体泛型类型"的数组。

### 替代方案对比

| 写法 | 能否编译 | 说明 |
|------|---------|------|
| `List<?>[] arrays = new List<?>[10];` | 编译通过 | 元素类型未知，可安全存放任何 `List<T>` |
| `List[] arrays = new List[10];` | 编译通过（unchecked 警告） | 原始类型，绕开泛型检查，不推荐 |
| `List<List<String>> lists = new ArrayList<>();` | 编译通过 | 用嵌套集合代替泛型数组，推荐 |

**`List<?>[]` 为什么可以？** 因为 `?` 表示"元素类型未知的 List"，你可以安全地把任何 `List<T>` 放进数组。但由于元素类型未知，取出时只能当作 `Object`，不存在类型安全的隐患。

多数情况下更适合直接用嵌套集合 `List<List<String>>`，既保留泛型类型安全，也不需要处理泛型数组的问题。

### 协变与不变（Covariance & Invariance）

**数组是协变的：**

```java
String[] names = {"Alice", "Bob"};
Object[] values = names;  // 可以：String[] 是 Object[] 的子类型
```

但这也带来风险——编译器把 `values` 看成 `Object[]`，允许放 `Integer`；但它实际指向的是 `String[]`，运行时会检查并抛出 `ArrayStoreException`：

```java
Object[] values = new String[2];
values[0] = "正常";
values[1] = 123;  // 编译能过，但运行时报 ArrayStoreException
```

**泛型是不变的（Invariant）：**

虽然 `String` 是 `Object` 的子类，但 `List<String>` **不能**当作 `List<Object>` 使用：

```java
List<String> strings = List.of("A");
// List<Object> objects = strings;  // 编译错误
```

如果允许，就可以通过 `objects` 往原本只应装字符串的列表里加入其他对象，破坏类型安全。

**泛型用通配符表达"只读意义上的协变"：**

```java
List<String> strings = List.of("A", "B");
List<? extends Object> objects = strings;  // 可以

// 能读
Object x = objects.get(0);

// 不能安全地写（除了 null）
// objects.add("C");  // 编译错误
```

快速记忆：

| 类型 | 关系 |
|------|------|
| `String[]` → `Object[]` | **数组协变** |
| `List<String>` → `List<Object>` | **泛型不变**（不允许） |
| `List<String>` → `List<? extends Object>` | **受限协变**（只读安全） |

**不能使用基本类型作为类型参数**

```java
// 编译错误
List<int> list = new ArrayList<>();

// 用包装类
List<Integer> list = new ArrayList<>();
```

**运行时无法获取泛型信息**

```java
List<String> list = new ArrayList<>();
// 运行时获取不到 String 类型信息
if (list instanceof List<String>) { }  // 编译错误

// 只能这样检查
if (list instanceof List) { }  // 可以，但不知道具体的类型参数
```

**不能在 catch 中使用泛型异常**

```java
// 编译错误
try {
    // ...
} catch (List<String> e) {
    // ...
}
```

## 总结

类型擦除是 Java 泛型的折中方案：在**编译期提供类型安全检查**，但在**运行时完全移除泛型信息**。这样既保证了代码的类型安全，又不增加运行时开销，还维持了与旧代码的兼容性。虽然这带来了一些限制，但对于绝大多数实际应用场景来说，已经足够了。

## 面试题 1：什么是Java泛型中的类型擦除？它设计的核心作用是什么？

Java泛型的类型擦除是编译期的一种优化机制，编译阶段会把代码里的泛型类型信息全部移除，最终生成的字节码和没有用泛型的普通代码完全一致。它设计的核心作用主要有三个：第一是实现向后兼容，Java 5刚引入泛型的时候需要兼容Java 1.4及之前的非泛型代码，擦除后泛型代码的字节码和旧代码没有区别，不需要改动JVM和运行时环境就能支持；第二是减少运行时开销，如果JVM要在运行时维护泛型信息，会增加内存占用和性能消耗，擦除后运行时不需要处理泛型，没有额外负担；第三是简化JVM设计，不需要在JVM层面为泛型做特殊处理，保证JVM的简洁和稳定。

## 面试题 2：Java类型擦除的具体执行规则是什么？请结合无界类型参数、有界类型参数、方法泛型三种场景分别说明。

类型擦除的执行规则分三种场景：第一是无界类型参数，直接擦除为`Object`，比如泛型类`Box<T>`，擦除后成员变量`T`就变成`Object`类型；第二是有界类型参数，擦除为上界类型，比如`NumberBox<T extends Number>`，擦除后成员变量`T`就变成它的上界`Number`；第三是方法中声明的泛型，方法签名的泛型返回类型会被擦除为`Object`，编译器在调用该方法的地方插入强制类型转换，比如`T getValue(Box<T> box)`这个方法，擦除后返回值变成`Object`，编译器会在调用处自动加上强转，而不是在方法体内部插入转换。

## 面试题 3：类型擦除给Java泛型带来了哪些限制？请结合“不能创建泛型数组”和“不能使用基本类型作为类型参数”这两个限制，说明原因和正确的替代写法。

你问的这两个限制的原因分别是：第一，不能创建泛型数组，核心是数组的协变和运行时类型检查机制与泛型擦除冲突了——数组支持协变（`String[]`可以赋给`Object[]`），运行时还会检查实际元素类型，但泛型参数在运行时被擦除（`List<String>`和`List<Integer>`都只是`List`），JVM无法确认放入的是不是声明类型的元素，如果允许就可能出现运行时`ClassCastException`，所以Java禁止创建具体泛型类型的数组，替代方案是用通配符`List<?>[]`或直接用嵌套集合`List<List<T>>`；第二，不能使用基本类型作为类型参数，是因为擦除后类型参数会被替换为`Object`，而基本类型不能直接赋值给`Object`，所以编译器禁止，正确的替代写法是用对应的包装类，比如`List<int>`不合法，要写成`List<Integer>`。

## 面试题 4：为什么Java中运行时无法获取泛型的类型信息？请结合`instanceof`的使用场景说明。

根本原因是类型擦除会在编译阶段把泛型类型信息全部移除，运行时字节码里只保留原始类型，没有泛型参数的信息。比如`List<String> list`在运行时实际就是普通的`List`类型，所以如果写`if (list instanceof List<String>)`这种代码，编译器会直接报错，因为运行时根本不存在`List<String>`这个类型，只能写成`if (list instanceof List<?>)`的形式，但这种方式只能判断是不是`List`的原始类型，没法知道具体的类型参数是`String`还是其他类型。

## 面试题 5：经常有人说Java泛型是“伪泛型”，结合类型擦除的原理和带来的影响，你如何理解这个说法？

这个说法是有道理的，核心原因就是Java泛型的实现完全依赖类型擦除，它只在编译期提供类型安全检查，运行时完全移除了泛型类型信息，不像真正在运行时保留泛型信息的泛型实现。这种折中方案虽然带来了向后兼容、无运行时开销的好处，但也带来了一系列固有限制，比如无法创建泛型数组、无法使用基本类型作为类型参数、运行时无法获取泛型信息、不能在`catch`中使用泛型异常等，这些限制本质都是类型擦除导致的，所以很多人会把这种基于擦除实现的泛型叫做“伪泛型”。
