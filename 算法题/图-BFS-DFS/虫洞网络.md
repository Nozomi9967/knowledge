### **虫洞网络 — 虚拟节点建图 + Dijkstra 最短路**

核心思路是**虚拟节点建图**：把每个虫洞网络看作一个"虚拟节点"，星系是真实节点。星系 → 网络边权为 C（付费激活），网络 → 星系边权为 0（网络内免费跳跃）。这样把"穿越多个网络"问题转化为标准的单源最短路，用 Dijkstra 求解。时间复杂度 $O((N+M)\log(N+M))$，空间 $O(N+M)$。

---

### **一、问题本身**

$M$ 个独立的虫洞网络，网络 $i$ 覆盖 $n_i$ 个星系集合 $W_i$，进入网络需支付跃迁成本 $C_i$，进入后网络内任意两星系免费瞬时跳跃。

从起点星系 $S_{start}$ 到目标星系 $S_{dest}$，途中可能穿越多个网络。从一个网络 $W_i$ 到另一个网络 $W_j$ 必须经过共同中转星系 $\in W_i \cap W_j$，再支付 $C_j$。

求最小总能量。无法抵达或耗能超过 $E_{total}$ 输出 -1。

- 星系编号 $0 \le s \le 500$，$1 \le M \le 50$，$C_i \le 10$，$n_i \le 10$，$E_{total} \le 500$

> **示例1**：`M=1, S=45, D=103, E=383`，网络含 {45,103,182,198,244,306,416,460,490}，C=1
> 45 和 103 在同一网络 → only pay C=1 → 输出 `1`

> **示例2**：`M=4, S=14, D=19, E=99`
> 起点 14 仅在网络3（C=6, 含 14），目标 19 不在任何网络中 → 无法抵达 → 输出 `-1`

---

### **二、关键观察：网络内 = 完全图但只建一条"虚拟节点"边**

如果朴素建图——把每个网络内所有星系两两连边——$n_i$ 个星系要建 $O(n_i^2)$ 条边。但题目 $n_i \le 10$，边数不算大，朴素建图也能过。

更优雅的做法是**虚拟节点 trick**：

- 给每个网络 $i$ 一个虚拟节点 $v_i$（编号从 501 起，避开真实星系编号 0..500）
- 对网络 $i$ 中的每个星系 $g$：
  - 加边 `g → v_i`，权值 $C_i$（从星系进入网络，付费激活）
  - 加边 `v_i → g`，权值 `0`（进入网络后跳到任意成员星系，免费）

这样网络内"任意两星系免费互通"被压缩成"过虚拟节点中转、走两条边、只付一次 C"。$n_i$ 个星系只需 $O(n_i)$ 条边，且付费恰好一次。

**为什么付费只算一次？** — `g_in → v_i`（付费 $C_i$）→ `v_i → g_out`（0）。从 $g_{in}$ 到 $g_{out}$ 走两条边，总权值 $C_i$，对应"激活网络 $i$ 一次后在网络内跳一次"。如果还要在网络内继续跳，从 $g_{out}$ 再走 `g_out → v_i`(C)→`v_i → g_other`(0) 又付一次——这就错了！

> ⚠ **关键修正**：虚拟节点建图让"每次进入网络都付费"。但题意是"**激活一次**后网络内无限次免费跳跃"。上述朴素虚拟节点会让多次网络内跳跃被重复计费。

**正确处理**：Dijkstra 正是从星系节点出发计算路径，重复"进出网络"的路径必然不是最短（多付了 C），Dijkstra 自然会避开它——**只要 $C_i > 0$**，"付费两次"的路径严格劣于"付费一次的路径"，不会出现在最短路径里。所以虚拟节点建图在此题语境下是正确的，因为**最短路只会选每条网络付费一次的最优方案**。

---

### **三、算法步骤**

1. **建图**：真实星系节点 $0 \dots 500$，虚拟网络节点 $501 \dots 500+M$。对每个网络 $i$ 的每个成员星系 $g$：加 `g→v_i` 权 C，`v_i→g` 权 0。
2. **Dijkstra**：从 $S_{start}$ 出发，堆优化，求到所有节点（含虚拟节点）的最短距离。
3. **取答案**：`dist[S_dest]` 即最小能量。若为 `INF` 或 `> E_total`，输出 -1。

**节点总数** $N = 501 + M \le 551$，边数 $\le \sum 2n_i \le 1000$，规模很小。

### **四、代码**

```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        StreamTokenizer in = new StreamTokenizer(
            new BufferedReader(new InputStreamReader(System.in)));
        in.nextToken(); int M  = (int) in.nval;
        in.nextToken(); int SS = (int) in.nval;
        in.nextToken(); int SD = (int) in.nval;
        in.nextToken(); int E  = (int) in.nval;

        int G = 501;          // 星系编号 0..500
        int base = G;         // 网络虚拟节点编号从 501 起
        int N = G + M;        // 总节点数
        List<int[]>[] adj = new ArrayList[N];
        for (int i = 0; i < N; i++) adj[i] = new ArrayList<>();

        for (int i = 0; i < M; i++) {
            in.nextToken(); int C = (int) in.nval;
            in.nextToken(); int n = (int) in.nval;
            int v = base + i;                 // 网络 i 的虚拟节点
            for (int j = 0; j < n; j++) {
                in.nextToken(); int g = (int) in.nval;
                adj[g].add(new int[]{v, C});  // 星系 -> 网络：付费
                adj[v].add(new int[]{g, 0});  // 网络 -> 星系：免费
            }
        }

        // Dijkstra
        final long INF = Long.MAX_VALUE;
        long[] dist = new long[N];
        Arrays.fill(dist, INF);
        dist[SS] = 0;
        PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[0]));
        pq.offer(new long[]{0, SS});
        boolean[] vis = new boolean[N];

        while (!pq.isEmpty()) {
            long[] cur = pq.poll();
            long d = cur[0];
            int u = (int) cur[1];
            if (vis[u]) continue;
            vis[u] = true;
            if (u == SD) break;               // 已取出目标，提前结束
            for (int[] e : adj[u]) {
                int to = e[0], w = e[1];
                if (d + w < dist[to]) {
                    dist[to] = d + w;
                    pq.offer(new long[]{dist[to], to});
                }
            }
        }

        if (dist[SD] == INF || dist[SD] > E) System.out.println(-1);
        else System.out.println(dist[SD]);
    }
}
```

### **五、一个具体例子走一遍**

**示例1**：`M=1, S=45, D=103, E=383`，网络0：`C=1, 星系={45,103,182,198,244,306,416,460,490}`

建图（虚拟节点记为 $v_0$，编号 501）：

```
45  --(1)--> v_0 --(0)--> 103, 182, ... , 490
103 --(1)--> v_0 --(0)--> 45, 182, ...
... 每个成员星系 g 都连 g--1->v_0--0->其他成员
```

Dijkstra 从 45 出发：
- dist[45] = 0
- 取出 45，松弛：dist[v_0] = 1（走 45→v_0 付费 1）
- 取出 v_0 (d=1)，松弛所有 `v_0→g`：dist[103]=1, dist[182]=1, ... dist[490]=1
- 取出 103 (d=1) == 目标，提前结束

输出 `dist[103] = 1`，未超 E=383 → 输出 **1** ✓

### **六、复杂度分析**

- **时间复杂度**：$O((N+M)\log(N+M))$。$N=501+M \le 551$，边数 $\le 2\sum n_i \le 1000$，Dijkstra 堆操作总成本极小。
- **空间复杂度**：$O(N+M)$，邻接表 + dist 数组 + vis 数组。

---

### **七、虚拟节点建图详解**

> [!abstract] 虚拟节点建图 — Virtual Node Construction（虚拟节点建图）
> 当一组节点互相之间有"同权值"或"零权值"连接关系时，引入一个虚拟中转节点代替完全图，把 $O(n^2)$ 条边压缩到 $O(n)$ 条。常见于"团体/网络/车间内互通"类问题。
>
> 对本题：网络内 $n_i$ 个星系任意互通且只需付费一次，朴素建图 $O(n_i^2)$。引入虚拟节点 $v_i$ 后，"进网络付费、出网络免费"两条规则用 $2n_i$ 条边即可表达。
>
> 面试高频考点：① 哪些问题适合用虚拟节点（团体内零成本互通、并查集的图论化）；② 何时会重复计费（多次进出团体）以及为什么 Dijkstra / 最优性会规避；③ 也可用并查集但 Dijkstra 能处理带权"激活成本"。

---

### **八、面试话术**

1. **为什么用虚拟节点而不是完全图？** — 网络内 $n_i$ 个星系两两互通，朴素需 $O(n_i^2)$ 条边；引入虚拟节点后只需 $2n_i$ 条边（进网络付费、出网络免费），规模降一个数量级。
2. **会不会重复计费？** — 虚拟节点建图让每次"进网络"都付费，理论上重复进出会重复付费。但因为 $C_i > 0$，重复付费的路径严格劣于只付一次的路径，Dijkstra 求最短路自然会避开它，所以答案正确。这也是为什么 $C_i$ 必须 $>0$（题目给 $1 \le C_i \le 10$，满足）。
3. **为什么用 Dijkstra 而非 BFS？** — 边权不统一（付费 $C_i$ 与免费 0 混合），BFS 只能处理 0/1 边权（用 0-1 BFS），这里 $C_i$ 取值范围 $1 \dots 10$，必须用通用 Dijkstra。
4. **能不能用并查集？** — 如果只问"能否抵达"，可以：起点终点同在网络即连通。但题目要求"最小能量"，网络激活有成本 $C_i$，并查集无法处理带权激活，必须建模为带权图跑最短路。
5. **虚拟节点编号为什么从 501 开始？** — 真实星系编号 $0 \dots 500$，虚拟节点必须避开这些 ID 以免冲突，从 501 起连续编号 $M$ 个，总节点 $501+M$。
