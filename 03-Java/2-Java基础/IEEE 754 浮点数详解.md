# IEEE 754 浮点数详解

> [!abstract] IEEE 754 浮点数 — Floating-Point Representation（浮点数的二进制表示标准）
> 一句话：一个浮点数由「**符号 + 阶码 + 尾数**」三段拼成，两个关键设计是 **尾数隐含前导 1**、**阶码用偏置值编码**。
> 单精度 32 位 = `1 + 8 + 23`，偏置 **127**；双精度 64 位 = `1 + 11 + 52`，偏置 **1023**。

---

## 一、三段结构

| 部分 | 单精度位数 | 双精度位数 | 含义 |
|------|:---:|:---:|------|
| 符号位 S | 1 | 1 | `0` 正、`1` 负 |
| 阶码 E | 8 | 11 | **偏置编码**的无符号整数 |
| 尾数 F | 23 | 52 | 规格化后**小数点右边**的位（隐含的前导 1 不存） |

规格化数的求值公式：

```
值 = (-1)^S × 1.F × 2^(E - 偏置)
```

注意阶码字段是 **`E - 偏置`**，不是 `E` 本身——这是最容易写错的一步。

## 二、两个关键设计（为什么要这样）

**① 尾数隐含前导 1（白赚一位精度）**

任何**规格化**的二进制浮点数都能写成 `1.xxxx × 2^k`——最高位永远是 1。既然人人都有的东西，干脆**不存**，只存小数点后面的部分。于是单精度实际有 **24 位有效数字**、双精度 **53 位**。

**② 偏置值（bias）：把负指数搬成非负数**

阶码字段存的是 `真实指数 + 偏置值`：

- **回避符号位**：阶码不用再单独表示正负；
- **让比较变简单**：**两个非负浮点数**，其位模式按无符号整数比较的结果与数值大小顺序一致，硬件可以直接拿整数比较器比浮点数。

单精度阶码字段的取值范围是 `1 ~ 254`（对应真实指数 `-126 ~ +127`）——两头的 `0` 和 `255` 被特殊值占用（见第四节）。

## 三、转换四步法（以 `-8.25` 为例）

| 步骤 | 操作 | 本例 |
|------|------|------|
| ① 定符号 | 负 → `1` | S = **1** |
| ② 转二进制 | 整数除 2 取余、小数乘 2 取整 | `8.25₁₀ = 1000.01₂`（`0.25 = 2⁻²`） |
| ③ 规格化 | 小数点移到第一个 1 之后，记下指数 | `1.00001₂ × 2³` → 真实指数 **3** |
| ④ 算阶码 + 填尾数 | 阶码 = 真实指数 + 127；尾数取小数点后补零到 23 位 | 阶码 `3+127=130=10000010₂`；尾数 `00001000000000000000000` |

拼接（按 4 位一组转十六进制）：

```
符号位 S   阶码 E       尾数 F (23位)
   1      10000010    00001000000000000000000
1100 0001 0000 0100 0000 0000 0000 0000
  C    1    0    4    0    0    0    0        →  0xC1040000
```

验算：`(-1)¹ × 1.00001₂ × 2³ = -1000.01₂ = -8.25` ✅

**反推（题目给编码让你求值）**：`C1040000H` 拆成 `1 | 10000010 | 00001000000000000000000` → 符号 1（负）、阶码 `130−127 = 3`、尾数隐含前导 1 得 `1.00001₂` → `−1.00001₂ × 2³ = −8.25`。

## 四、特殊值（看阶码 E 是不是全 0 / 全 1）

| 阶码 E | 尾数 F | 表示 | 说明 |
|--------|--------|------|------|
| 全 0 | 全 0 | **±0** | 有 +0 和 −0 **两个**（位模式不同） |
| 全 0 | 非 0 | **非规格化数**（denormal） | 值 = `0.F × 2^(1−127)`，用来表示比最小规格化数还小的数，**用精度换范围** |
| 全 1 | 全 0 | **±∞** | 溢出、除以 0 的结果 |
| 全 1 | 非 0 | **NaN** | Not a Number，**尾数非 0** 正是它与 ∞ 的区别 |

**Java 落点**：`Float.isNaN()/Double.isNaN()` 判的就是最后一行；`NaN != NaN` 恒成立，所以判 NaN 不能用 `==`；`0.0 == -0.0` 在 Java 里返回 `true`（虽然位模式不同）。

## 五、常见坑与面试点

1. **`0.1 + 0.2 != 0.3`**：十进制小数在二进制下大多是无限循环，存进去就被截断。→ 金额运算用 `BigDecimal`，而且**要用字符串构造**（`new BigDecimal("0.1")`），别用 `double` 构造（错上加错）。
2. **尾数的 1 是隐含的**：手写 23 位时千万别把前导 1 写进去。
3. **阶码 ≠ 指数**：答题时必须说"**存储阶码 = 真实指数 + 偏置**"，直接填 `3` 就错了。
4. **精度**：`float` 约 **7 位**十进制有效数字、`double` 约 **15~16 位**；`float` 有效位只有 24 个二进制位，所以 **`2²⁴` 以上的整数开始丢精度**（`(float)16777217 == 16777216.0f`）。
5. **浮点数别用 `==` 比较**：用误差范围 `Math.abs(a - b) < eps`，或 `BigDecimal.compareTo`。

## 六、快速自测

| 数值 | 编码 | 推导要点 |
|------|------|---------|
| `-8.25` | `C1040000H` | 见第三节 |
| `1.0` | `3F800000H` | S=0，真实指数 0 → E=127=`01111111`，F 全 0 |
| `0.5` | `3F000000H` | `0.5 = 1.0 × 2⁻¹` → E=126=`01111110` |
| `-0.0` | `80000000H` | S=1，其余全 0 |
