### **LeetCode 15「三数之和」= 排序 + 固定一个数 + 双指针找另外两个。难点不在双指针，在**去重**：外层跳过相同元素、内层两个指针移动后也要跳过相同元素，三处都做才不重不漏。**

### **一、问题本身**

从数组中找出所有和为 0 的三元组，**不能包含重复的三元组**（三元组内部顺序不重要）。

```
nums = [-1,0,1,2,-1,-4]
结果：[[-1,-1,2], [-1,0,1]]
```

---

### **二、整体思路**

1. **排序**（O(n log n)）：排序后数组有序，才能用双指针，也才能方便地去重
2. **固定第一个数 `nums[i]`**：问题转化为"在 `i+1 .. n-1` 里找两数之和等于 `-nums[i]`"
3. **双指针找另外两个**：`left = i+1`、`right = n-1`，和大了右指针左移、和小了左指针右移
4. **三处去重**（关键，见下）

---

### **三、三处去重（这题唯一有难度的地方）**

**第一处：外层固定数去重**

```java
if (i > 0 && nums[i] == nums[i - 1]) continue;
```

为什么是 `nums[i] == nums[i-1]` 而不是 `nums[i] == nums[i+1]`：如果和后面比，会把"第一个出现的值"也跳过，导致漏解。**必须是"和前一个比、且 i > 0"。**

**第二处：找到解之后，左右指针同时跳过重复**

```java
while (left < right && nums[left] == nums[left + 1]) left++;
while (left < right && nums[right] == nums[right - 1]) right--;
```

**第三处：移动指针时的自然跳过**

第二处做完后还要 `left++; right--;` 走到下一对新位置。如果只写移动不写跳过，相同元素会组合出重复的三元组。

---

### **四、代码**

```java
class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        Arrays.sort(nums);
        int n = nums.length;

        for (int i = 0; i < n - 2; i++) {
            // 剪枝：最小值已经大于 0，后面不可能凑出 0
            if (nums[i] > 0) break;
            // 第一处去重：跳过重复的固定数
            if (i > 0 && nums[i] == nums[i - 1]) continue;

            int left = i + 1, right = n - 1;
            int target = -nums[i];

            while (left < right) {
                int sum = nums[left] + nums[right];
                if (sum == target) {
                    res.add(Arrays.asList(nums[i], nums[left], nums[right]));
                    // 第二处去重：跳过重复的左右值
                    while (left < right && nums[left] == nums[left + 1]) left++;
                    while (left < right && nums[right] == nums[right - 1]) right--;
                    left++;
                    right--;
                } else if (sum < target) {
                    left++;
                } else {
                    right--;
                }
            }
        }
        return res;
    }
}
```

---

### **五、为什么可以"和小于 target 就左移"**

排序后 `nums[left]` 是从左往右递增的。`left` 往右移会让和变大，`right` 往左移会让和变小。所以：

- `sum < target`：需要更大的和 → `left++`
- `sum > target`：需要更小的和 → `right--`
- `sum == target`：记录，然后同时移动（因为再移动任何一个都会破坏和）

这是有序数组双指针的标准逻辑，正确性依赖"有序"这个前提。

---

### **六、复杂度**

| 项 | 复杂度 |
|---|---|
| 时间 | O(n²) —— 排序 O(n log n) + 外层 n × 双指针 O(n) |
| 空间 | O(log n) 排序栈（不算返回值） |

---

### **七、易错点（每题都是踩过的坑）**

1. **忘记剪枝 `nums[i] > 0 break`**：不会错，但会白跑很多轮
2. **外层去重写成 `nums[i] == nums[i+1]`**：漏解（把第一次出现的值跳过了）
3. **找到解后忘记跳过重复**：结果里出现重复三元组
4. **跳过重复时忘了 `left < right` 边界**：数组越界
5. **`res.add(Arrays.asList(...))` 后没复制**：`Arrays.asList` 返回的是定长视图，这里每次新建，没问题；但如果用同一个 `List` 反复 add 就会全变成最后一组
6. **先排序后忘记返回原顺序**：本题不要求原顺序，但如果题目要求"按原数组顺序输出三元组"，排序就会破坏顺序，要额外记录下标
7. **`i < n - 2` 写成 `i < n`**：会越界（`left = i+1` 时）

### **八、同族题**

| 题号 | 目标 | 差别 |
|---|---|---|
| 1 两数之和 | 和 = target，返回下标 | 用哈希，不能排序（要保下标） |
| 15 三数之和（本题） | 和 = 0，返回值 | 排序 + 双指针 + 去重 |
| 16 最接近的三数之和 | 和 ≈ target | 同样双指针，记录最小差 |
| 18 四数之和 | 和 = target，四元组 | 两层循环 + 双指针，去重更繁琐 |

**规律**：k 数之和的通用解法是"固定 k-2 个数 + 双指针"，复杂度 O(n^(k-1))。18 题就是在 15 题外面再套一层循环，去重逻辑也再多一处。
