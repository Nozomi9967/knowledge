# OS 名词解释速查（一句话定义 + 详细定义）

## 一、内存管理

### 页缓存（Page Cache）

**一句话定义**：内核拿空闲内存缓存磁盘文件内容的区域。

**详细定义**：所有对普通文件的读写（跳过页缓存的 `O_DIRECT` 除外）都必须经过它。读文件时，内核先把磁盘块加载进页缓存，再拷贝给用户缓冲区——所以第二次 `cat` 一个大文件会快得多，因为根本没碰磁盘。写文件也一样：先改页缓存并把页标记为"脏页"，由内核的 writeback 线程异步刷回磁盘。顺序写日志快的中间件（比如 Kafka 的日志盘）很大程度就是吃到了这个红利。它的关键属性是**可回收的软占用**：页缓存里的数据在磁盘上都有"原件"，干净页可以直接丢弃（下次访问重新读盘即可），脏页先回写再释放。这也是为什么"available 低"才说明内存真紧张、而不是 "free 低"——Linux 的哲学是空闲内存放着不用等于浪费。⚠ **容器坑**：页缓存计入 cgroup 内存用量——容器里疯狂写日志、大文件读写时，这部分"软占用"会把容器顶到限额上，这也是 OOM 排障里"页缓存也可能是元凶"的原因（详见 [[OOM Killer 与容器内存详解#二、第一步：页缓存与 slab 的回收]]）。

### Slab 分配器（Slab Allocator）

**一句话定义**：内核给 dentry、inode 等小对象专设的对象池分配器。

**详细定义**：用户态有 malloc，内核态同样要频繁分配几十到几百字节的小对象（`task_struct`、dentry、inode），每个都按整页 4KB 分配会非常浪费——slab 先把整页拿下来，再按对象类型切小块、分池复用，`kmalloc` 底层就是它。它分两类，对应"内存紧张时先回收页缓存、slab"那句话里的可回收边界：**可回收**的是 dentry（路径→inode 的缓存）、inode 这类纯缓存，丢了随时能从磁盘重建，计入 `/proc/meminfo` 的 **`SReclaimable`**，紧张时由 shrinker 机制收缩；**不可回收**的是活着的 `task_struct`、挂着的 socket 缓冲这类正在被使用的结构，对应 **`SUnreclaim`**——这部分涨上去（几十万线程、海量连接）是挤不掉的，只能等对象本身被释放。查看用 **`slabtop`** 或 **`cat /proc/slabinfo`**；⚠ `SUnreclaim` 持续增长往往是**内核或驱动内存泄漏**——这时即使页缓存全可回收，内存也可能被它顶到 OOM。

> 页缓存和 Slab 都是"软占用"——内存紧张时优先回收，代价最小。

### 匿名页 / 文件页（Anonymous Page / File-backed Page）

**一句话定义**：没有文件背底的内存页叫匿名页（堆、栈、JVM 堆、堆外内存都算），有磁盘原件的叫文件页（页缓存）。

**详细定义**：进程占的内存页按"磁盘上有没有原件"划分，这条分界线直接决定了它们被回收的方式：

| 维度 | 匿名页 | 文件页 |
|------|--------|--------|
| 磁盘上有原件吗 | 没有，数据只存在于内存 | 有，对应磁盘上的文件 |
| 典型来源 | malloc 堆、线程栈、JVM 堆、堆外内存 | 读文件、mmap 的文件内容（页缓存） |
| 内存紧张时 | 必须先写进 swap 才能释放页框 | 干净页直接丢，脏页回写文件后丢 |
| 再次访问时 | 缺页中断，从 swap 读回（毫秒级） | 重新读文件（代价小得多） |

JVM 堆、`DirectByteBuffer` 的堆外、每条线程约 1MB 的栈——全部是匿名页。这也解释了 OOM 排障时"元凶常在堆之外"的物理原因：**它们不像页缓存那样能零代价回收，只有换出（付延迟代价）或进程死掉（付生命代价）两条路**。`/proc/meminfo` 里对应 **`Anonymous`** 和 **`Cached`** 两行；swap 换出的页再被访问，必是**硬缺页**（见 [[缺页异常详解#五、判断总表]]）。

### 脏页与回写（Dirty Page / Writeback）

**一句话定义**：内容已改、还没刷回磁盘的页缓存页叫脏页；异步刷盘的过程叫回写。

**详细定义**：写文件先写页缓存就返回，脏页由内核 writeback 线程（`dirty_*` 一组 sysctl 控制时机，如 `dirty_ratio`/`dirty_background_ratio`）批量刷盘。这带来两个工程后果：断电会丢未回写的脏页（数据库因此要 WAL/fsync）；**刷盘风暴**会集中制造 IO 尖峰（`vmstat` 的 `bo` 跳变多半是它在干）。

### swap / 换入换出（Swap In / Swap Out）

**一句话定义**：磁盘上一块专门"收容"匿名页的区域；换出=把匿名页写进 swap 腾物理内存，换入=访问时再从磁盘读回。

**详细定义**：swap 通常是一块独立分区（`mkswap`/`swapon`）或 swap 文件，`free -h` 的 Swap 行看用量。它存在的意义是**用延迟换存活**：有了 swap，系统可用内存 ≈ RAM + swap，短暂尖峰能熬过去不必杀进程；反过来说，走到 OOM Killer 就意味着 swap 也写满、或干脆被 `swapoff` 关了。换出的执行者是 **kswapd**（后台守护）或分配路径上的直接回收，被挑中的通常是 LRU 链表上最久没人碰的"冷页"，页表里同时记一笔"该地址在 swap 哪个槽位"；之后访问触发缺页、从 swap 读回——**货真价实的磁盘随机读，major fault**。

> 通俗理解：RAM 是桌面，磁盘是书架。文件页是"书架上还有原件的复印件"，桌面挤了随手扔、要用再拿；**匿名页是"你手写的笔记"，全世界只有桌面这一份**——想腾地方只能先抄进抽屉（swap），回头要用还得去翻，而你不知道哪页笔记在抽屉里：写着写着突然得去翻抽屉，这就是抖动。

**为什么是"抖动"而不是"整体变慢"：关键在不确定性**。哪些页被换出、什么时候被访问到，谁也无法预测：平时一次内存访问不到 0.1ms，一旦恰好踩中躺在 swap 里的页，就插入一次毫秒级磁盘读（SSD 约 8~15ms，机械盘更久）。GC 扫堆、请求线程扫过成片页时随机踩中几个冷页，延迟曲线就从平直变成毛刺丛生。RT 敏感的中间件（Kafka、ES、Redis）宁可被 OOM 杀掉由守护进程快速拉起，也不接受这种不可预测的毛刺——所以主动 `swapoff`（ES 文档明确要求关 swap 否则告警）；调低 **`vm.swappiness`** 也能让内核更倾向先丢页缓存、少动匿名页。顺带两句：容器/K8s 环境通常压根不留 swap；部分系统用 **zram**（内存里的压缩盘）当 swap，拿 CPU 换 IO，知道有这回事即可。

观测看 `vmstat` 的 **`si/so`**（每秒换入换出块数），非零即真缺内存——"换出后 RT 抖动巨大"的完整因果见 [[OS八股#4.5 内存不够会怎样：swap 与 OOM Killer]]。

### O_DIRECT

**一句话定义**：绕过页缓存、用户缓冲区直达磁盘块设备的读写方式。

**详细定义**：数据库（MySQL InnoDB）常用——自己管缓存，避免"页缓存+内部 buffer 两份"的双重缓存和回写不可控。代价是对齐要求和失去页缓存红利；和 [[OS八股#7.3 零拷贝]] 的 `mmap`/`sendfile` 是两条相反的路线（一个干脆不要页缓存，一个贴着页缓存做零拷贝）。

### MMU（Memory Management Unit，内存管理单元）

**一句话定义**：CPU 里做地址翻译的硬件，虚拟→物理每一步都是它干的。

**详细定义**：每次访存，MMU 查 TLB（命中≈1 个周期）；miss 就由内置的 page walker 从 CR3 出发逐级走页表（最多 4 次访存）。除翻译外还管三件事：**权限检查**（读/写/执行、用户/内核位——段错误、COW 的只读拦截都是它报的）、**存在位=0 时抛缺页异常**、**顺手置访问位 A / 脏位 D**（喂给置换算法和回写）。虚拟内存能近乎零成本存在，全靠这坨硬件。

### TLB（Translation Lookaside Buffer，快表）

**一句话定义**：MMU 里的页表缓存，存最近用过的"页号→页框"映射。

**详细定义**：几十~上千条，按内容并行比对（所以叫"快表"）。局部性原理保证绝大多数访存命中；miss 才走多级页表 walk。它是**进程切换贵的直接受害者**——换 CR3 时若不靠 PCID 标签，条目全体作废。

### CR3（页表基址寄存器）

**一句话定义**：x86 里存**当前进程顶级页表物理基址**的寄存器。

**详细定义**：MMU 走页表的第一跳就从它出发。进程切换=写 CR3（顺带刷 TLB）；线程共用一张页表、CR3 不动——[[OS八股#二、进程 / 线程 / 协程]] 那句"切换时不用换 CR3"指的就是它。KPTI 之后陷入内核也要多切一次页表视图，syscall 因此更贵。

### PCID / ASID（Process Context IDentifier / Address Space ID）

**一句话定义**：打在 TLB 表项上的"地址空间编号"，让换页表不用全刷 TLB。

**详细定义**：TLB 每条都标记属于哪个地址空间，切换进程时旧条目原地保留、下次同名直接命中，把"全刷"降级成"按需淘汰"。有它的机器上，进程切换的翻译代价没有教科书说的那么夸张（x86 叫 PCID，ARM 叫 ASID）。

### VMA（Virtual Memory Area，虚拟内存区域）

**一句话定义**：内核记账"进程虚拟地址空间里哪一段是什么、什么权限、背后是谁"的一条区间记录。

**详细定义**：`mmap`/`brk`/加载 so 都是在建/改 VMA；`/proc/<pid>/maps` 看到的一行行就是它。VMA 只是**账本**——建好不代表物理页已分配，真访问才触发缺页补映射（匿名页首触，见 [[缺页异常详解#四、第三大软缺页来源：匿名页首触（⚠ 原稿未提，补上）]]）。这就是 VIRT 巨大、RES 很小的结构原因。

### mmap（Memory Map，内存映射）

**一句话定义**：把文件或一块匿名内存「映射」进进程虚拟地址空间，之后访问它就像访问内存，靠缺页按需加载。

**详细定义**：`mmap(addr, length, prot, flags, fd, offset)` 的关键是**只建立映射、不搬数据**——内核在地址空间里划一段 VMA 指向文件的页缓存，真正访问时缺页才把那一页读进来。所以它天然是**零拷贝**：你的"用户缓冲区"就是页缓存本身，省掉了 `read` 那次「页缓存 → 用户缓冲区」的 CPU 拷贝。它有三个身份：

| 用法 | 参数 | 用途 |
|------|------|------|
| 文件映射 | `fd` 给文件 | 读写这段地址 = 读写文件；`mmap + write` 做零拷贝发送 |
| 匿名映射 | `MAP_ANONYMOUS`（fd=-1） | 一整块内存，glibc `malloc` 大块（>128KB）走它，`munmap` 直接还内核 |
| 共享内存 | 文件/匿名 + `MAP_SHARED` | 多进程贴同一段物理页 → **IPC 里最快的共享内存** |

`MAP_SHARED` 改动会回写文件、且多进程可见；`MAP_PRIVATE` 则是写时复制（COW），改动不回写、不共享。两个典型坑：**随机访问会疯狂缺页**（比顺序 `read` 还慢）、**映射的文件被截断/删除会收 `SIGBUS`**。Java 落点是 `FileChannel.map()` → `MappedByteBuffer`（RocketMQ 的 CommitLog/ConsumeQueue、Kafka 索引、ES/Lucene 的 MMapDirectory）。

> 通俗理解：`read` 像"把书页**复印**一份给你"；`mmap` 像"把书架直接连到你桌上"——你翻到哪页，它才把哪页送来，全程只有一本书、没有副本。

**相关展开见 [[OS八股#七、I/O 模型与零拷贝]]；上面 VMA 词条说的「建 VMA」，建的就是它。**

### brk / sbrk（堆顶调整）

**一句话定义**：通过调整"堆顶指针"（program break）来增减堆区的系统调用，是 `malloc` 小块分配的底层。

**详细定义**：`brk` 把 program break 设到某个地址、`sbrk` 按增量移动它，效果是把堆区**整体连续地**拉长或缩短。glibc 的 `malloc` 对**小块**（默认 < 128 KB）优先走它、从堆里切；**大块**改用 `mmap` 匿名映射、`free` 时直接 `munmap` 还内核——这正是"`free` 之后内存不一定还给 OS"的原因（走 brk 的那部分只退回 glibc 的空闲链表）。观测点是 `/proc/<pid>/maps` 里 `[heap]` 段的伸缩。**相关展开见 [[进程内存指标与 glibc 分配详解]]**。

### 大页（HugePage / HugeTLB / THP）

**一句话定义**：把 4KB 页换成 2MB/1GB 的大号页，一级顶几百个普通页。

**详细定义**：两大收益——**页表条目数骤减**（同内存占用下 TLB 罩得住的地址多 512 倍）+ **walk 少走一级**（2MB 页跳过 L1）。代价是内部碎片和回收粒度变粗。数据库、DPDK 机器常开；JVM 有 `-XX:+UseLargePages`。THP（透明大页）由内核自动升降，行为不可控、延迟敏感服务常关（`/sys/kernel/mm/transparent_hugepage/enabled`）。

### 内存指标四件套（VIRT / RES / SHR / PSS）

**一句话定义**：VIRT=虚拟盘子，RES=真占物理，SHR=RES 里共享部分，PSS=共享按人数摊薄。

**详细定义**：看压力看 RES、看预留才看 VIRT；共享页会重复计入每个进程 RES，100 个进程加总超物理内存不是 bug——分摊看 PSS。读写命令（top/ps/`/proc`、`VmHWM` 峰值、`smaps_rollup`）见 [[进程内存指标与 glibc 分配详解#二、查看 VIRT / RES / SHR 的命令]]。

### cgroup（Control Group，控制组）

**一句话定义**：Linux 内核把一组进程归成组、统一设资源上限并统计用量的机制——容器"能用多少"靠它，namespace 管的则是"看得见什么"。

**详细定义**：Docker / containerd / Podman / K8s Pod 底层都是「namespace + cgroup」的组合，**容器不是虚拟机**（没有独立内核、共享宿主机内核）。cgroup 能控 CPU（配额/权重）、内存、IO、进程数（pids）；内存上限 cgroup v1 是 `/sys/fs/cgroup/memory/memory.limit_in_bytes`、v2 是 `/sys/fs/cgroup/memory.max`——`docker run -m 2g` 和 K8s 的 `resources.limits.memory` 最终都是写这两个文件。⚠ 触发范围有两种：整机内存耗尽是**全局 OOM**；而**容器用量超过自己的 cgroup 上限时，即使宿主机内存充足，内核也会在组内触发 OOM Killer**（退出码 137 的常见来源）。计入 cgroup 的不只是 Java 堆，还有元空间、线程栈、堆外内存和页缓存。完整机制、容器 Java 高频坑与排查命令组见 [[OOM Killer 与容器内存详解#五、容器与 cgroup：Java 进程为什么要特别小心]]。

## 二、进程

### PCB（Process Control Block，进程控制块）

**一句话定义**：内核描述和管理一个进程的数据结构，"PCB 是进程存在的唯一标志"。

**详细定义**：Linux 的实现是 `struct task_struct`；寄存器现场、状态位、优先级、页表基址、fd 表全在里面。僵尸=只剩 PCB、消亡=PCB 释放、进程切换=换 PCB。**完整展开见 [[OS八股#二、进程 / 线程 / 协程]] 末尾的 PCB 折叠标注**。

### fd（File Descriptor，文件描述符）

**一句话定义**：进程 fd 表的数组下标，指向内核"打开文件"对象的整数句柄。

**详细定义**：一切皆文件——文件、socket、管道、epoll 实例全是 fd；0/1/2 预留给标准三件套，新 fd 从 3 起，上限 `ulimit -n`（默认 1024 的由来）。fd 私有、`struct file` 共享，所以 fork 后父子共享文件偏移。**完整展开见 [[select 与 epoll 机制详解#二、先搞清 fd：后面全靠它]]**。

### BSS 段（Block Started by Symbol）

**一句话定义**：存放**未初始化**全局/静态变量的段，不占可执行文件体积。

**详细定义**：初值全为 0，加载时映射一页全零匿名页即可——"未初始化的全局变量默认是 0"的物理来源。和 `.data`（已初始化，值存在文件里）合成"全局区/静态区"。**相关展开见 [[OS八股#二、进程 / 线程 / 协程]] 地址空间布局**。

### IPC（Inter-Process Communication，进程间通信）

**一句话定义**：OS 提供的、让相互隔离的进程交换数据和协调行为的整套机制——存在的根本原因是每个进程有独立虚拟地址空间，谁也看不见谁的内存，必须靠内核做"中间人"或"公证处"。

**详细定义**：

**为什么必须有**：地址空间隔离是安全稳定性的基础（一个进程崩溃/越界不会改坏别人的数据），代价是进程间天然无法直接读写对方。IPC 要解决三件事：**数据传递**（字节/结构化消息从一端到另一端）、**同步与互斥**（谁先写谁后读、同时改不打架）、**通知与协调**（"我准备好了"/"该结束了"）。很多初学者以为 IPC 只是传数据——**同步问题往往才是真正棘手的另一半**。

**两条技术路线**（理解分野比背 API 有用）：

| 路线 | 机制 | 好处 | 代价 |
|------|------|------|------|
| **内核中转** | 管道、消息队列、套接字 | 天然隔离、安全、易用 | 数据复制两次（用户→内核→用户），带宽延迟受限 |
| **共享内存** | mmap 同批物理页进两家页表 | **最快**，之后零拷贝 | 安全抛回程序员——必须自己配信号量/锁，否则读到写一半的脏数据 |

所以实践常见组合是"**共享内存传数据 + 信号量做门铃**"。

```
进程 A（私有地址空间）                    进程 B（私有地址空间）
   代码/堆/栈                               代码/堆/栈
     │ write()/msgsnd()/send()                ▲ read()/msgrcv()/recv()
     ▼                                        │
 ┌───────────── 内核（受信任的中介） ─────────────┐
 │  管道/FIFO · 消息队列 · 套接字   ← 内核中转，拷贝两次 │
 │  共享内存页 ← mmap 映射同一物理页，零拷贝直接读写      │
 │  信号量/信号 ← 不传数据，只管次序与通知              │
 └───────────────────────────────────────────┘
```

**机制速查**（与 [[OS八股#六、IPC 进程间通信]] 的卷子口径对齐）：

| 机制 | 通信模型 | 关键特点 | 典型场景 |
|---|---|---|---|
| 管道 / 命名管道（pipe、FIFO） | 字节流，通常单向 | 内核缓冲，最简单 | `ps aux \| grep ssh`、父子进程 |
| 消息队列 | 有边界的结构化消息 | 按类型收取，支持异步 | 任务分发、解耦的生产者消费者 |
| 共享内存 | 直接共享物理页 | **最快**，需自行同步 | 视频帧、数据库缓冲池 |
| 信号量 | 计数 / 互斥 | 不传数据只管次序 | 配共享内存、限流、临界区 |
| 信号 | 异步事件通知 | 信息量极小，不可靠传递 | SIGTERM 优雅停机、超时提示 |
| Unix 域 / 网络套接字 | 双向流或数据报 | 通用、可跨机、跨语言 | 本地服务通信、微服务、DB 连接 |
| 内存映射文件 | 文件即共享内存 | 可持久化、可跨进程 | 大文件随机访问、LevelDB |

**几个容易被忽略的细节**：

- **管道有容量上限（Linux 默认 64KB），写满会阻塞**——读端不消费时 `write()` 挂起，这就是"背压"最朴素的形态；匿名管道只能亲缘进程用，跨任意进程要命名管道或套接字（`grep ssh` 那条管道的完整行为见 [[OS热门面试题#18. 往已关闭读端的管道写数据会发生什么？【低频·加分】]]）
- **消息队列与管道的区别在"边界"**：纯字节流可能读到半条消息（语义应用层自己切）；消息队列一次 `msgrcv()` 拿到完整一条，适合传结构化命令
- **套接字是最通用的选择**：统一了本机（AF_UNIX）和跨机（AF_INET）；本机 Unix 域比 TCP 回环快得多（绕开网络协议栈）。很多系统的实际架构是"本地也用套接字，将来拆分布式几乎不改代码"
- **现代系统把 IPC 包装成远程调用**：Android Binder、macOS Mach port、Windows COM——"像调本地函数一样调另一个进程"，底层仍是内核中转+内存映射；浏览器多进程（渲染/GPU/网络）也靠 IPC 拼——一个标签页卡死拖不垮整车的原理

**怎么选**：父子简单传数据→管道；跨任意进程可靠双向→Unix 域套接字；大数据量低延迟→共享内存+信号量（同步协议设计好）；异步解耦削峰→消息队列；只报个"出事了"→信号。归根结底，**IPC 是"隔离"与"协作"之间必须付出的代价，各机制只是在安全、性能、易用性三者间做了不同取舍**。

### 信号（Signal）与 SIGSEGV / SIGBUS

**一句话定义**：内核向进程投递的异步通知；SIGSEGV = 段错误（访问非法内存），SIGBUS = 总线错误（地址在映射内但物理上取不到）。

**详细定义**：非法内存访问时 MMU 触发硬件异常（本质是缺页异常），内核判定非法后向**出错的线程**投递 **SIGSEGV**；而"地址看着合法、实际取不到"的场景（如 mmap 的文件被截断后访问越界页）报 **SIGBUS**。进程**注册了处理函数**就转去执行它，否则按默认动作**终止并可能生成 core dump**。同类高频：SIGINT（Ctrl-C）、SIGKILL（**不可捕获**、必杀）、SIGTERM（可捕获，优雅退出）、SIGCHLD（子进程状态变化，见 [[wait 与僵尸进程回收详解]]）、SIGPIPE（写已关闭的管道/socket）。`kill -l` 可列出全部信号。

### core dump（核心转储）

**一句话定义**：进程异常终止时系统保存的一份"进程当时状态快照"，用于事后调试。

**详细定义**：含内存内容、寄存器、线程状态、调用栈等，用 `gdb ./prog core` 打开就能还原崩溃现场（哪一行、什么值）。**它不是"函数调用栈文件"**，而是进程多个内存区域的转储。是否生成、生成到哪（`/proc/sys/kernel/core_pattern`）、多大（`ulimit -c`）都受配置控制；线上通常关掉（体积大且含敏感数据），systemd 环境改用 `coredumpctl` 按需取。

### ulimit（资源上限）

**一句话定义**：查看/设置当前 shell 及其子进程能用的各种资源上限，`ulimit -a` 一次列全。

**详细定义**：高频几项——`-c` **core dump 大小**（`0` = 不生成）、`-s` **栈大小**、`-n` **最大 fd 数**（默认 1024 的由来，见 [[select 与 epoll 机制详解#二、先搞清 fd：后面全靠它]]，也是"连接数上不去"的头号排查项）、`-u` 最大进程/线程数。分**软限**（当前生效，`ulimit -S`）和**硬限**（软限的封顶，`ulimit -H`，只有 root 能抬高）。`ulimit -n 65535` 只影响**当前 shell**；要持久化得写 `/etc/security/limits.conf` 或 systemd 的 `LimitNOFILE=`。

## 三、错误码与内核计数

### errno 与 EAGAIN

**一句话定义**：errno 是内核给失败的 errno 编号；EAGAIN="现在没有，稍后再试"。

**详细定义**：非阻塞 fd 读空、写满返回 -1 且 errno=EAGAIN（也叫老名字 EWOULDBLOCK）——**epoll ET 模式"循环读到 EAGAIN"的判停条件就是它**（见 [[select 与 epoll 机制详解#六、LT 与 ET：机制层]]）。同类高频：EINTR（被信号打断）、EMFILE（fd 耗尽）、ENOMEM（内存不足）。

### minflt / majflt（软/硬缺页计数）

**一句话定义**：进程的软、硬缺页累计次数，`/proc/<pid>/stat` 第 10/12 字段。

**详细定义**：`ps -o min_flt,maj_flt -p <pid>` 直接可看。**majflt 持续增长 ≈ 在真读盘**（swap 抖动、mmap 大文件随机访问），和 `si/so`、`bi/bo` 互为印证；minflt 大量集中出现在进程启动期（堆页首触）属正常，JVM 可用 `AlwaysPreTouch` 把它挪到启动还债（见 [[缺页异常详解#四、第三大软缺页来源：匿名页首触（⚠ 原稿未提，补上）]]）。

## 四、网络

### 网卡（Network Interface，网络接口）

**一句话定义**：机器收发数据包的"网口"——**IP 其实是配在网卡上的**，不是"配在机器上"。

**详细定义**：物理的叫 `eth0`（有线）/ `wlan0`（无线），虚拟的叫 `lo` / `veth` / `docker0`；每张卡带自己的 IP、MAC、状态（up/down）、MTU。一台机器可以有多张卡、多个 IP，**路由表就是决定这个包走哪张卡**。**完整展开见 [[Linux 网络模式详解#① network namespace（网络命名空间）]] 的五样对照表**。

### veth pair（虚拟以太网对，"虚拟网线"）

**一句话定义**：**成对出现**的虚拟网卡——一根"虚拟网线"的两头，**从一头进去的帧，一定从另一头出来**。

**详细定义**：`ip link add veth0 type veth peer name veth1` 一条命令就创建**两张**网卡（`peer name` 的意思是**给"另一端"命名**——veth 天生成对，创建一端时顺带把另一端也造出来）。刚创建时两端都在当前网络命名空间，典型两步是：一端 `ip link set veth1 netns &lt;容器ns&gt;` **移进**容器的 netns（进去后常改名 `eth0`），另一端 `ip link set veth0 master docker0` **接到**宿主机的网桥上。它是「容器 / 虚拟机接入虚拟网络」的关键零件——本质是把一张网卡的两半分放在两个 netns 里，让它们像插了根真网线一样通信。**完整展开见 [[Linux 网络模式详解]] 第一节 ②**。

### lo（Loopback Interface，回环接口）

**一句话定义**：每个 network namespace 自带的一张虚拟网卡，专供本机进程「自己跟自己」通信，IP 固定 `127.0.0.1/8`。

**详细定义**：进程往 `127.0.0.1` 发包，内核直接把包**回环送回本机协议栈**——不走物理网卡、不经过任何路由器，所以 ping 它的 RTT 是微秒级、TTL 也不递减。整个 `127.0.0.0/8` 网段都保留给回环，`localhost` 默认解析到它（以及 IPv6 的 `::1`）。它没有真实链路层地址（MAC 报 `00:00:00:00:00:00`），MTU 是 65536，远大于以太网的 1500。**关键点在于它和 netns 绑定**：内核为每个 network namespace **自动创建** lo，但**默认是 down 状态**——lo down 时连 `127.0.0.1` 都 ping 不通，依赖 localhost 的程序会莫名失败，所以手动建完 netns 第一件事是 `ip link set lo up`。由此推出一个常考的坑：**容器（= 独立 netns）里的 `127.0.0.1` 是容器自己的 lo，不是宿主机的**，这就是「容器里 ping 不通宿主服务」的根源。**完整展开见 [[Linux 网络模式详解#① network namespace（网络命名空间）]]**。

### 路由表（Routing Table）

**一句话定义**：决定一个包"**从哪张网卡发、下一跳交给谁**"的查表。

**详细定义**：`ip route` 看。最关键的一条是默认路由 `default via <网关> dev <网卡>`——意思是"目的地不在我直连网段里的，统统丢给网关"。**没有匹配项包就发不出去**，报 `Network is unreachable`。容器靠宿主机转发时，这个"转发"开关是内核参数 `net.ipv4.ip_forward`。**见 [[Linux 网络模式详解#① network namespace（网络命名空间）]]**。

### ARP 表（ARP Cache，地址解析缓存）

**一句话定义**：同一局域网内 **IP → MAC** 的映射缓存。

**详细定义**：二层发帧认的是 **MAC 不认 IP**，所以发包前必须先知道"目标 IP 的 MAC 是啥"——ARP 协议广播问、对方单播答，结果缓存进表（`ip neigh` 看），表项会老化后重新问。**跨网段时只解析"网关"的 MAC**，剩下的交给网关去转发。这就是为什么 ARP 表总是和"同网段"绑定在一起。

### socket 端口空间（Port Space）

**一句话定义**：0~65535 端口号的占用范围——端口是**进程在网络里的"门牌号"**。

**详细定义**：TCP/UDP 用「IP + 端口」唯一标识一个通信端点，谁监听了 8080，发到 8080 的包就归谁（`ss -lntp` 看）。**每个 netns 各有一份端口空间**——所以**容器里能监听 80、宿主机也能监听 80，互不冲突**（在同一个 ns 里这是不可能的）。

### iptables 规则（包过滤 + 地址改写）

**一句话定义**：内核里的**包过滤 + 地址改写**规则表，不只是"防火墙"。

**详细定义**：分五个钩子（PRE/POSTROUTING、INPUT/OUTPUT/FORWARD）。容器网络里两大关键动作都在这里做：**DNAT**（改目的地址 = 端口映射，在 PREROUTING）、**SNAT / MASQUERADE**（改源地址 = 伪装成宿主机出网，在 POSTROUTING）。**完整展开见 [[Linux 网络模式详解]] 第五节 `-p` 数据流与第二节 iptables 基础**。

### MASQUERADE（地址伪装）

**一句话定义**：iptables 里 **SNAT 的一种特殊形式**——把出包的源地址自动改写成**出口网卡当前的 IP**，让内网"伪装成"网关出去。

**详细定义**：词源 `masquerade` = 化装舞会 / 伪装、冒充（好记）。与普通 SNAT 的区别是它**不带死一个源地址、而是动态取出口网卡的地址**，所以特别适合拨号 / 动态 IP 的出口——Docker 默认就用它（`-A POSTROUTING -s 172.17.0.0/16 ! -o docker0 -j MASQUERADE`）。它是**有状态**的：改写关系记在 `conntrack` 里，回包按表反向改回去，内网机器因此无需知道任何 NAT 细节。**展开见 [[Linux 网络模式详解]] 第一节 ④**。

## 五、文件系统

### mtime / ctime / atime（三个时间戳）

**一句话定义**：文件**内容**最后修改时间（mtime）、**inode 元信息**最后变化时间（ctime）、最后**访问**时间（atime）。

**详细定义**：

| 时间 | 何时更新 | 记忆 |
|------|---------|------|
| atime | 读到文件**内容**时 | **a**ccess |
| mtime | 文件**内容**被修改时 | **m**odify |
| ctime | **inode 元信息**变化时（权限、属主、链接数，也包括 mtime 自身变化） | **c**hange（注意不是 create） |

易错点：**改权限 `chmod` 只动 ctime、不动 mtime**；**`mv` 在同一文件系统内只改目录项、文件内容没变 → mtime 不变**（变的是**目录**的 mtime），所以"移动文件一定改变修改时间"是错的；`touch` 默认更新 mtime+atime，`touch -a` 只动 atime。atime 因写盘太频繁，现代 Linux 默认用 **`relatime`**（只有 atime 早于 mtime、或距上次更新超过 24h 才真正写）。
