# 968.监控二叉树（贪心 + 三态标记）

> [!abstract] 题目
> 给定一个二叉树，我们在树的节点上安装摄像头。节点上的每个摄像头都可以监视其**父对象、自身及其直接子对象**。计算监控树的所有节点所需的最小摄像头数量。

| 参数 | 范围 |
|-----|------|
| 节点数 | [1, 1000] |
| 每个节点的值 | 0 |

**示例 1：**
```
输入：[0,0,null,0,0]
输出：1
解释：一台摄像头足以监控所有节点。
```

**示例 2：**
```
输入：[0,0,null,0,null,0,null,null,0]
输出：2
解释：需要至少两个摄像头来监视树的所有节点。
```

---

## 核心思路：贪心 + 三态标记（自底向上）

从叶子往上贪心：**摄像头尽量放高处**（父节点），因为一个摄像头能覆盖三层（父、自身、子），放越高覆盖越广。

### 三态定义（节点的 val 标记）

| 状态 | 含义 |
|-----|------|
| 0 | 未被覆盖 |
| 1 | 已覆盖，且**本节点有摄像头** |
| 2 | 已覆盖，摄像头在**子节点**上 |

### 后序遍历递推

对节点 root，先递归处理左右子树，再根据子节点状态决定：

- **左右都空**（叶子）：不处理，返回（保持 val=0 未被覆盖——由父节点上方的摄像头来覆盖）。
- **任一子节点未覆盖（val==0）**：必须在当前节点装摄像头 `val=1, ans++`（此时它自身、父、子都被覆盖）。
- **任一子节点有摄像头（val==1）**：当前节点已被子摄像头覆盖，`val=2`（本节点不装）。
- **两个子节点都是 val==2**（都靠孙子覆盖，但当前节点没被覆盖到）：保持 val=0，交给父节点处理。

### 关键补漏：根节点

递归结束后，若根节点仍是 val==0（未被覆盖），必须在根节点补装一个摄像头，ans++。

## 完整 Java 代码（改后版，可过 LeetCode）

```java
class Solution {

    private int ans = 0; // 改为实例变量，避免多测试用例污染

    void fun(TreeNode root) {
        if (root == null) return;

        var l = root.left;
        var r = root.right;
        fun(l);
        fun(r);

        if (r == null && l == null) return;
        else if ((l != null && l.val == 0) || (r != null && r.val == 0)) {
            root.val = 1;
            ans++;
        } else if ((l != null && l.val == 1) || (r != null && r.val == 1)) {
            root.val = 2;
        }
    }

    public int minCameraCover(TreeNode root) {
        ans = 0; // 每次调用时清零
        fun(root);

        // 关键补漏：如果递归结束后根节点依然未被覆盖，必须在根节点补装摄像头
        if (root.val == 0) {
            ans++;
        }

        return ans;
    }
}
```

## ⚠️ 原来代码的 Bug 剖析（面试高频）

### Bug 1：static 变量污染（最重要的坑）

```java
// ❌ 原来：static int ans = 0;
public static int ans = 0;
```

**原因**：LeetCode 判题系统会复用同一个 Solution 实例跑**多个测试用例**，但 `static` 变量不随实例销毁，跨测试用例、跨提交都持久存在。上一个用例的 ans 没清零，会累积到下一个用例，导致答案偏大。

**修复**：
- 改成实例变量 `private int ans = 0`，并在 `minCameraCover` 入口处 `ans = 0` 清零。
- LeetCode 每次调用 `minCameraCover` 用的是同一个 Solution 实例，实例变量靠入口清零；static 则连清零的机会都没有。

### Bug 2：根节点未覆盖漏算

原代码递归完直接 `return ans`，没有检查根节点是否被覆盖。若根节点最终 val==0（两个子树都靠内部覆盖，根没被覆盖），需要补一个摄像头。修复：`if (root.val == 0) ans++;`

## 复杂度

- 时间：O(n)，后序遍历每个节点一次
- 空间：O(h)，h 为树高（递归栈）

## 面试话术

1. **为什么贪心是从下往上？** → 摄像头覆盖三层（父/自身/子），放得越高覆盖越广；从叶子往上，能不放就不放，必须放才放。
2. **三态为什么这么设计？** → 0 表示"欠覆盖"（等上面来管）、1 表示"自己是摄像头"、2 表示"被孩子覆盖"。只有三种真实情况，状态压缩到最小。
3. **叶子节点为什么不装摄像头？** → 叶子装了只覆盖自己+父，浪费；让父节点装能同时管三个，叶子保持 0 等父覆盖最省。
4. **static 变量的坑怎么避免？** → 判题系统复用实例跑多用例，任何跨用例的状态（static 或未清零的实例变量）都会污染。入口必须显式重置。
5. **根节点为什么单独补？** → 根没有父节点，如果它恰好是"未被覆盖"状态，没人再能覆盖它，只能自己装。
