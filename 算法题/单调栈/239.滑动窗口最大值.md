### **LeetCode 239「滑动窗口最大值」是单调队列的原型题：维护一个**下标递减、值递减**的双端队列，队首永远是当前窗口的最大值。每个元素最多进出队各一次，所以总复杂度 O(n)。**

### **一、问题本身**

给数组和窗口大小 `k`，窗口从左往右滑动，返回每个窗口内的最大值。

```
nums = [1,3,-1,-3,5,3,6,7], k = 3
窗口最大值：[3,3,5,5,6,7]
```

**暴力做法**：每个窗口扫一遍 O(k)，总 O(nk)。n=10^5、k=10^5 时是 10^10，必超时。

---

### **二、核心思路：为什么单调队列能加速**

观察窗口滑动时的变化：**右边界加入一个新元素，左边界移出一个旧元素**。

如果窗口里有个元素 `x`，它前面有个元素 `y < x`，那**只要 x 还在窗口里，y 永远不可能成为最大值**（x 比它大、还比它晚过期）。所以 y 可以直接扔掉——这就是单调队列的本质：**维护一个"候选最大值"的递减序列，淘汰掉永远没机会的元素**。

---

### **三、队列的三个动作**

队列存**下标**（不是值，因为要判断是否滑出窗口）。

**动作 1：入队前，弹出队尾所有小于等于当前值的元素**

```java
while (!q.isEmpty() && nums[q.peekLast()] <= nums[i]) q.pollLast();
q.offerLast(i);
```

这些被弹出的元素"永远当不了最大值了"，因为新来的更大、且过期更晚。

**动作 2：队首滑出窗口就弹出**

```java
if (q.peekFirst() < i - k + 1) q.pollFirst();
```

窗口是 `[i-k+1, i]`，队首下标小于 `i-k+1` 就过期了。

**动作 3：窗口满 k 个后，队首就是答案**

```java
if (i >= k - 1) res.add(nums[q.peekFirst()]);
```

---

### **四、代码**

```java
class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        int[] res = new int[n - k + 1];
        Deque<Integer> q = new ArrayDeque<>();   // 存下标，值单调递减

        for (int i = 0; i < n; i++) {
            // ① 队尾小于等于当前值的都弹出
            while (!q.isEmpty() && nums[q.peekLast()] <= nums[i]) {
                q.pollLast();
            }
            q.offerLast(i);

            // ② 队首过期就弹出
            if (q.peekFirst() < i - k + 1) {
                q.pollFirst();
            }

            // ③ 窗口成型后记录答案
            if (i >= k - 1) {
                res[i - k + 1] = nums[q.peekFirst()];
            }
        }
        return res;
    }
}
```

**①②③ 的顺序要注意**：先入队（并清理队尾），再清理队首过期，最后取答案。如果先清队首再入队，可能把"刚入队就过期"的情况漏掉（虽然本题不会，但顺序统一更安全）。

### **五、手动走一遍**

```
nums = [1,3,-1,-3,5,3,6,7], k = 3

i=0 (1): q=[0]                          窗口未成型
i=1 (3): 弹出 0（1<=3），q=[1]           窗口未成型

i=3 (-3): 不弹，q=[1,2,3]                窗口 [3,-1,-3]，队首 3 → 答案 3
i=4 (5): 弹出 3,2,1（都<=5），q=[4]      窗口 [-1,-3,5]，队首 5 → 答案 5
i=5 (3): 不弹，q=[4,5]                   窗口 [-3,5,3]，队首 5 → 答案 5
i=6 (6): 弹出 5,4，q=[6]                 窗口 [5,3,6]，队首 6 → 答案 6
i=7 (7): 弹出 6，q=[7]                   窗口 [3,6,7]，队首 7 → 答案 7

结果 [3,3,5,5,6,7]  ✅
```

### **六、复杂度**

| 项 | 复杂度 |
|---|---|
| 时间 | O(n) —— 每个下标入队一次、出队最多一次 |
| 空间 | O(k) —— 队列最多 k 个元素 |

**为什么是 O(n) 而不是 O(nk)**：虽然内层有 `while` 循环，但每个元素一生只被弹出一次，所以总的弹出次数 ≤ n。这是"均摊分析"的典型例子。

---

### **七、易错点**

1. **队列存值不存下标**：无法判断是否滑出窗口，会取到过期元素
2. **队尾比较用 `<` 而不是 `<=`**：用 `<` 时相等元素都保留，队列变长、性能变差（但结果仍对）
3. **忘记判断 `i >= k - 1`**：前 k-1 个窗口还没成型就记录答案，数组越界
4. **队首过期判断写成 `<= i - k`**：应该是 `< i - k + 1`，差一会多留一个过期元素
5. **用 `PriorityQueue`**：能过，但是 O(n log n)，还要处理"堆顶过期"的懒惰删除（存 `(值, 下标)` 对，取堆顶时检查下标是否过期），比单调队列麻烦
6. **以为要先清队首再入队**：顺序问题，建议固定成"清队尾 → 入队 → 清队首 → 取答案"

### **八、同族题：单调队列的三种用法**

| 题号 | 用途 | 关键 |
|---|---|---|
| 239（本题） | 定长窗口最大值 | 队列存下标、值递减 |
| 1696 跳跃游戏 VI | DP 转移取窗口内最大 dp 值 | 同上，比较对象换成 dp 值 |
| 862 和至少为 K 的最短子数组 | 前缀和 + 单调递增队列 | 队列存前缀和下标、值递增 |

**单调队列的判据**：题目里出现"滑动窗口内求最值"就用它。**注意和单调栈区分**——单调栈解决"找左边/右边第一个更大/更小的元素"（一次性求边界），单调队列解决"窗口滑动时的最值"（持续维护）。
