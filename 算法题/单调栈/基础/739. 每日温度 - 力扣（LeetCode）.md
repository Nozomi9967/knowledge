给定一个整数数组 `temperatures` ，表示每天的温度，返回一个数组 `answer` ，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

**示例 1:**

```
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]
```

**示例 2:**

```
输入: temperatures = [30,40,50,60]
输出: [1,1,1,0]
```

**示例 3:**

```
输入: temperatures = [30,60,90]
输出: [1,1,0]
```

这段代码是 **“单调栈”**（Monotonic Stack）算法的核心操作。这几行代码的具体作用是：**为了寻找当前天数之后“第一个比今天温度更高”的那一天，把栈里面所有“小于或等于今天温度”的元素全部剔除（弹出）。**

为了让你更容易理解，我们可以从以下几个角度来剖析这段代码的逻辑：

### 1. 栈（`st`）里面存的是什么？

在这个算法中，双端队列 `st` 被当作栈来使用，它里面存储的是**温度数组的下标（索引）**，而不是温度数值本身。 由于循环是从后往前（从右往左 `i = n - 1` 到 `0`）遍历的，栈顶的元素（`st.peek()`）永远代表着**当前位置右侧且最靠近当前位置的某些天的下标**。

### 2. 为什么要把小的元素 `pop()` 掉？

假设我们正在看第 `i` 天的温度 `t = temperatures[i]`。 如果栈顶那天的温度 `temperatures[st.peek()]` 比今天的温度 `t` 还要低（或者相等），那么对于第 `i` 天**左边**的那些天来说，栈顶的那一天就**永远不可能**成为它们的“下一个更高温度”了。

- **为什么？** 因为第 `i` 天的温度 `t` 更高，而且第 `i` 天在左边那些天的“更近的右边”。未来左边的天气寻找更高温度时，哪怕能跨过第 `i` 天，也一定会先遇到第 `i` 天，而不会去选择一个比第 `i` 天温度还低且更远的栈顶天数。
    
- **结论：** 栈顶的那个天数已经“没用了”（被第 `i` 天完美挡住了），所以我们可以放心地把它弹出（`st.pop()`）。
    

这个不断剔除的过程，保证了栈从栈顶到栈底对应的温度是**严格单调递增**的。


灵茶山老师这段话的意思是：**虽然代码里写了一个 `for` 循环嵌套一个 `while` 循环，看起来像是有两层循环（我们常直觉以为是 $O(n^2)$），但由于“单调栈”的特殊性质，它实际运行的速度非常快，时间复杂度只有 $O(n)$。**

为了让你彻底明白，我们可以用一个“电影院入场和离场”的生动比喻，来拆解为什么是 $O(n)$。

### 1. 核心逻辑：看“总次数”，而不是看“单次嵌套”

我们在算时间复杂度时，不能只看代码长什么样，得看数据被操作了多少次。

- **外层 `for` 循环：** 每一个温度元素，都**必须且只会**进栈（`st.push(i)`）一次。全班 $n$ 个同学，每个人都得进一次电影院。
    
- **内层 `while` 循环：** 里面的 `st.pop()` 是出栈操作。一个元素被弹出后，就彻底离开了栈，**再也不会被重新放回去**。
    

**关键点来了：** 如果一个东西只能进去一次，出来一次。那么所有人“进电影院”和“出电影院”的总动作次数是多少？

- 总入栈次数 = $n$ 次
    
- 总出栈次数 $\le n$ 次（最后可能还有人留在栈里没出来）
    

把这两个次数加起来：$n + n = 2n$ 次。 在计算机大 $O$ 表示法中，常数 $2$ 被忽略，所以总时间复杂度就是 **$O(n)$**。

```java
class Solution {

    public int[] dailyTemperatures(int[] temperatures) {

        int n=temperatures.length;

        int[] ans=new int[n];

        var dq=new ArrayDeque<Integer>();

        for(int i=n-1;i>=0;i--){

            int cur=temperatures[i];

            while(!dq.isEmpty()&&cur>=temperatures[dq.peek()]){

                dq.pop();

            }

            if(!dq.isEmpty()) ans[i]=dq.peek()-i;

            dq.push(i);

        }

        return ans;

    }

}
```


### 我的理解

从右往左遍历，边遍历边压栈，如果当前元素是遇到比自己小的就弹栈顶（也就是说维护一个递增单调栈），那么这个单调栈肯定是用来求第一个比当前元素大的那种题的，因为你是一直弹出栈顶，直到遇到一个元素比自己大，那么这个元素肯定就是第一个比自己大的

弹出的那些元素彻底没了不会有风险吗？
不会，因为当前元素比它们大，还比它们更靠左，要论第一个大的元素肯定是当前元素，而不是后面那些
