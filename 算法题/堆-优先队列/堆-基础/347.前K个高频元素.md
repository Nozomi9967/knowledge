# 347. 前 K 个高频元素

## 题目

https://leetcode.cn/problems/top-k-frequent-elements/

给整数数组 `nums` 和整数 `k`，返回出现频率前 k 高的元素，答案可任意顺序。要求优于 `O(n log n)`。

## 题解：计数 + 频率大根堆弹 k 次

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        PriorityQueue<int[]> pq = new PriorityQueue<>(
            (a, b) -> Integer.compare(b[0], a[0])   // 按频率的大根堆
        );
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int num : nums) {
            cnt.merge(num, 1, Integer::sum);         // 计数：没有则放 1，已有则旧值+1 求和
        }
        for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
            pq.offer(new int[]{e.getValue(), e.getKey()});  // {频率, 元素}：频率放 [0] 当排序键
        }
        int[] ans = new int[k];
        for (int i = 0; i < k; i++) {
            ans[i] = pq.poll()[1];                   // 弹 k 次，[1] 取回元素本身
        }
        return ans;
    }
}
```

## 逐点拆解

### 1. `cnt.merge(num, 1, Integer::sum)` 计数三件套

`merge(key, 初始值, 合并函数)`：key 不存在 → 直接放入初始值 1；key 已存在 → 用 `Integer::sum` 把**旧值和新值(1)求和**写回。等价的啰嗦写法：

```java
cnt.put(num, cnt.getOrDefault(num, 0) + 1);
```

⚠ merge 第三参是 **BiFunction（旧值, 新值）→ 结果**，参数顺序别记反；同理 `compute` / `computeIfAbsent` 也是高频替代，机试记 merge 一行最省。

### 2. `int[]{频率, 元素}`——元素放哪一位是设计题

堆元素塞 `int[]` 时，**排序键放 `[0]`、载荷放后面**，比较器就只需要 `b[0]` vs `a[0]` 一行。若反着写成 `{元素, 频率}`，比较器就得看 `[1]`， poll 时取 `[0]`——不错但容易绕晕。同一招在 [[算法题/堆-优先队列/215. 数组中的第K个最大元素]] 的 Dijkstra 距离堆里也用得上：`{距离, 节点}`，距离永远在 `[0]`。

### 3. 大根堆写法

`Integer.compare(b[0], a[0])` 交换参数 = 降序 = 大根堆，堆顶频率最高。三种等价写法与 `b - a` 溢出警告见 [[机试#大根堆（三种写法，全部防溢出）]]。频率量级 ≤ n 一般不溢出，但肌肉记忆统一 `Integer.compare`。

### 4. 弹出语义

大根堆 poll 依次给出频率第 1 高、第 2 高……的元素，弹 k 次即前 k 高。**频率相同的元素之间顺序不定**——题目只要求"前 k 个"这个集合，任意顺序合法，所以无需次级排序键。

## 复杂度

- 计数 `O(n)` + 入堆 `O(m log m)`（m = 不同元素数 ≤ n）+ 弹 k 次 `O(k log m)` → 时间 `O(n + m log m)`，优于题目要求的 n log n 红线（严格说是"平均快"；想要线性走下面的桶排序）
- 空间 `O(m)`

## 另外两解（面试官追问"能不能 O(n)"时答这个）

### 大小 k 的小根堆 — `O(n + m log k)`

只维护 k 个「当前频率最高」的候选：堆顶是这 k 个里频率**最小**的（第 k 高），新元素频率比堆顶高才替换。和 [[215.数组中的第K个最大元素（堆两解）]] 选型表里"k 很小"那一档同款思路。**k ≪ m 时才划算**，本题 k 通常不小，实际不如全量堆。

### 桶排序 — 严格 `O(n)`

频率的取值范围只有 `[1, n]`，天然适合计数排序思想：

```java
List<Integer>[] bucket = new List[n + 1];      // 下标 = 频率
for (var e : cnt.entrySet()) {
    int f = e.getValue();
    if (bucket[f] == null) bucket[f] = new ArrayList<>();
    bucket[f].add(e.getKey());
}
// 从高频率往低扫，凑够 k 个就停
int[] ans = new int[k];
for (int idx = 0, f = n; f >= 1 && idx < k; f--) {
    if (bucket[f] == null) continue;
    for (int x : bucket[f]) { if (idx == k) break; ans[idx++] = x; }
}
return ans;
```

- 核心洞察：**元素个数 n 封顶了频率上界**，桶数只有 n+1，装桶 + 倒扫都是 O(n)
- 这是"第 K 大/topK"家族拿到线性的标准答案之一；另一条是快速选择（平均 O(n)）
- 同思想：按频次分桶求 topK、按长度分桶——**值域小的排序键就配桶**

## 选型速查

| 方案 | 时间 | 空间 | 场景 |
|------|------|------|------|
| 全量频率大根堆（本文） | O(n + m log m) | O(m) | 默认写法，代码最短 |
| 大小 k 小根堆 | O(n + m log k) | O(k) | k ≪ m 的数据流场景 |
| 桶排序 | **O(n)** | O(n) | 被追问"能 O(n) 吗"必答 |
| 直接排序 entrySet | O(m log m) | O(m) | 最摆烂，`list.sort` 一行也能过 |
