## 一、每组最值对应的行（JOIN + MIN 子查询）

### 问题场景

找出每所学校 GPA 最低的学生（完整行信息：device_id、university、gpa）。

### ❌ 错误写法

```sql
SELECT device_id, university, gpa
FROM user_profile
GROUP BY university
HAVING gpa = MIN(gpa);
```

**为什么错？**

1. `device_id`、`gpa` 不是分组字段，在 `ONLY_FULL_GROUP_BY` 模式下直接报错
2. 即使关闭严格模式，MySQL 也不保证返回哪条记录（随机选取）
3. `HAVING gpa = MIN(gpa)` 语义不清——左边 `gpa` 是某条记录的值，右边 `MIN(gpa)` 是整组最小值，不在同一"维度"

### ✅ 通用解法：子查询 + JOIN

```sql
SELECT u.device_id, u.university, u.gpa
FROM user_profile AS u
JOIN (
    SELECT university, MIN(gpa) AS min_gpa
    FROM user_profile
    GROUP BY university
) AS m
    ON u.university = m.university
   AND u.gpa = m.min_gpa
ORDER BY u.university;
```

**思路拆解：**

1. 子查询先算出每个学校的最低 GPA
2. JOIN 回原表，用 `university` + `gpa` 双条件匹配
3. 匹配成功的行就是"该学校 GPA 最低的学生"

**注意：**

- 若多人并列最低，会全部返回（符合题意）
- 这是 SQL 处理"每组最值行"的标准模式

## 二、LEFT JOIN 聚合统计（重点题型）

### 问题场景

统计 2021 年 8 月复旦大学每个用户的答题数和正确数（包括 0 次答题的用户）。

### ✅ 标准写法

```sql
SELECT
    up.device_id,
    up.university,
    COUNT(qpd.id) AS question_cnt,
    SUM(CASE WHEN qpd.result = 'right' THEN 1 ELSE 0 END) AS right_question_cnt
FROM user_profile AS up
LEFT JOIN question_practice_detail AS qpd
    ON up.device_id = qpd.device_id
    AND qpd.date >= '2021-08-01'
    AND qpd.date < '2021-09-01'
WHERE up.university = '复旦大学'
GROUP BY up.device_id, up.university
ORDER BY up.device_id;
```

### 易错清单（⭐⭐⭐ 重点）

#### 1. 主表选择错误

```sql
-- ❌ 错误：从答题表出发
FROM question_practice_detail AS qpd
LEFT JOIN user_profile AS up ...
```

**后果：** 只保留有答题记录的用户，0 答题用户被排除。

**原则：** 想保留谁就把谁作为 LEFT JOIN 的**左表**（主表）。

---

#### 2. 日期条件位置错误

```sql
-- ❌ 错误：日期条件放 WHERE
FROM user_profile AS up
LEFT JOIN question_practice_detail AS qpd
    ON up.device_id = qpd.device_id
WHERE qpd.date >= '2021-08-01'
  AND qpd.date < '2021-09-01';
```

**后果：** `WHERE` 会把右表未匹配的行（`qpd.date = NULL`）整体过滤掉，LEFT JOIN 变成 INNER JOIN 效果。

**原则：** **限制右表匹配范围的条件** → 放 `ON`；**过滤主表的条件** → 放 `WHERE`。

---

#### 3. 学校条件位置错误

```sql
-- ❌ 错误：学校条件放 ON
LEFT JOIN question_practice_detail AS qpd
    ON up.device_id = qpd.device_id
   AND up.university = '复旦大学'
```

**后果：** `ON` 只影响匹配，不排除其他学校的行 → 非复旦用户仍被保留（只是右表字段为 NULL）。

**原则：** **主表（左表）的过滤条件** → 放 `WHERE`，才能真正排除不符合的行。

---

#### 4. 计数函数选择错误

| 写法                    | 无匹配用户计数 | 原因                             |
| ----------------------- | -------------- | -------------------------------- |
| `COUNT(*)` / `COUNT(1)` | **1**（错）    | 常量/整行非 NULL，照样计入       |
| `COUNT(qpd.id)`         | **0**（对）    | 只统计非 NULL 的 `qpd.id`        |

**原则：** LEFT JOIN + 统计右表记录数时，用 **`COUNT(右表列)`**。

---

#### 5. 缺少 GROUP BY

```sql
-- ❌ 错误：SELECT 里有非聚合列却不分组
SELECT
    up.device_id,  -- 非聚合列
    up.university, -- 非聚合列
    COUNT(qpd.id)  -- 聚合函数
FROM ...
```

**报错：** `In aggregated query without GROUP BY ... only_full_group_by`

**原则：** SELECT 里出现非聚合列，必须在 `GROUP BY` 中声明。

---

### ON 与 WHERE 的区别（实例对比）

**数据：** 练习表有 `2315(right)` 和 `2138(wrong)`；用户表 `2315=浙大`、`2138=北大`。

#### 条件放 ON（只影响匹配）

```sql
LEFT JOIN user_profile up
    ON qpd.device_id = up.device_id
   AND up.university = '浙江大学'
```

**结果：**

| device | result | university |
| ------ | ------ | ---------- |
| 2315   | right  | 浙江大学   |
| 2138   | wrong  | NULL       |

北大记录未被过滤，只是 `university` 变 NULL → 北大数据仍被计入统计 → **结果错误**。

#### 条件放 WHERE（真正过滤）

```sql
JOIN user_profile up
    ON qpd.device_id = up.device_id
WHERE up.university = '浙江大学'
```

**结果：** 只剩浙大记录 → **结果正确**。

**结论：** **ON 决定两表如何匹配；WHERE 决定匹配后哪些行保留。**

## 三、三表 JOIN + CASE WHEN 聚合

### 问题场景

统计浙江大学用户各难度题目的平均正确率。

### ✅ 标准写法

```sql
SELECT
    qd.difficult_level,
    ROUND(
        SUM(CASE WHEN qpd.result = 'right' THEN 1 ELSE 0 END) / COUNT(*),
        4
    ) AS correct_rate
FROM user_profile AS up
JOIN question_practice_detail AS qpd
    ON up.device_id = qpd.device_id
JOIN question_detail AS qd
    ON qpd.question_id = qd.question_id
WHERE up.university = '浙江大学'
GROUP BY qd.difficult_level
ORDER BY correct_rate ASC;
```

### 关键要点

#### 1. CASE WHEN 语法完整性

```sql
-- ✓ 正确
SUM(CASE WHEN qpd.result = 'right' THEN 1 ELSE 0 END)

-- ❌ 错误：漏了 END
SUM(CASE WHEN qpd.result = 'right' THEN 1 ELSE 0)
```

#### 2. FROM 表的选择

**原则：** 从"需要筛选的主体"出发。

- 只统计某学校用户 → 从 `user_profile` 开始，`WHERE` 筛学校
- 只统计实际答过题的记录 → 用 `JOIN`（不是 LEFT JOIN）

#### 3. LEFT JOIN 的坑

```sql
-- ❌ 错误：用 LEFT JOIN
FROM question_practice_detail AS qpd
LEFT JOIN question_detail AS qd ...
```

**后果：** 若用户表中存在**没答过题的人**，`GROUP BY difficult_level` 会多出一行 `difficult_level = NULL`（输出 `None | None`）。

**解决：** 改用 `JOIN`，自动排除无关联记录。

## 四、整体统计：COUNT 不需要 GROUP BY（⭐ 重点）

### 问题场景

统计 2021 年 8 月练习题目的**不同用户数**和**答题总次数**（整体汇总，不分用户）。

### ✅ 标准写法

```sql
SELECT
    COUNT(DISTINCT device_id) AS did_cnt,
    COUNT(*) AS question_cnt
FROM question_practice_detail
WHERE date >= '2021-08-01'
  AND date < '2021-09-01';
```

### 关键原理

- `COUNT()` 是聚合函数，**不分组时会把 WHERE 筛选后的所有行当作一个整体**，返回一行汇总结果。
- ❌ 加了 `GROUP BY device_id` 反而变成"每个用户一行"，不符合题意。

### COUNT 的三种用法

| 写法                      | 作用                     |
| ------------------------- | ------------------------ |
| `COUNT(*)`                | 统计行数（含 NULL）      |
| `COUNT(col)`              | 统计该列非 NULL 的行数   |
| `COUNT(DISTINCT col)`     | 统计该列去重后的值个数   |

### 月份范围写法

```sql
-- ✓ 推荐：起始日包含，下月起始日不包含
date >= '2021-08-01' AND date < '2021-09-01'

-- 也可以：但 BETWEEN 包含边界，容易混淆
date BETWEEN '2021-08-01' AND '2021-08-31'
```

## 五、正则校验（REGEXP）

### 问题场景

筛出合法手机号：
1. 连续 10 位数字（首位 1-9）
2. 3-3-4 格式，如 `123-456-7890`

### ✅ 标准写法

```sql
SELECT *
FROM contacts
WHERE phone_number REGEXP '^[1-9][0-9]{9}$|^[1-9][0-9]{2}-[0-9]{3}-[0-9]{4}$'
ORDER BY id;
```

### 正则语法速查

| 符号        | 含义                               |
| ----------- | ---------------------------------- |
| `^`         | 锚定开头                           |
| `$`         | 锚定结尾                           |
| `|`         | 或者                               |
| `[1-9]`     | 匹配一个 1-9 的数字                |
| `[0-9]`     | 匹配一个 0-9 的数字                |
| `{n}`       | 重复 n 次                          |
| `{m,n}`     | 重复 m 到 n 次                     |

### 关键要点

#### 1. 必须锚定开头和结尾

```sql
-- ❌ 错误：缺少 $
WHERE phone_number REGEXP '^[1-9][0-9]{9}'
```

**后果：** `1234567890abc` 也会被误匹配（前 10 位符合就通过）。

#### 2. 或关系要完整

```sql
-- ✓ 正确：两个完整模式用 | 连接
'^[1-9][0-9]{9}$|^[1-9][0-9]{2}-[0-9]{3}-[0-9]{4}$'
```

**拆解：**

- 左边：`^[1-9][0-9]{9}$` → 首位 1-9 + 后续 9 位 0-9
- 右边：`^[1-9][0-9]{2}-[0-9]{3}-[0-9]{4}$` → 3 位-3 位-4 位

#### 3. 注意边界

```sql
-- ❌ 错误：只检查"去掉 - 后有 10 位"
REGEXP '^[0-9-]{12}$'
```

**后果：** `9-0-1-234-5678` 这类连字符位置错误的号码也会通过。

## 六、子查询与 CTE 写法

> 子查询按**出现的位置**分三类：放 `FROM` 里（派生表）、放 `WHERE` 里（条件子查询）、放语句最前面用 `WITH` 命名（CTE）。考前这三种写法都要能默写。

### 1. 派生表子查询（FROM 子查询）

把一段 `SELECT` 的结果当成一张**临时表**，再 JOIN 回来——本笔记[[#一、每组最值对应的行（JOIN + MIN 子查询）|第一节]]就是这种。

```sql
SELECT u.device_id, u.university, u.gpa
FROM user_profile AS u
JOIN (
    SELECT university, MIN(gpa) AS min_gpa
    FROM user_profile
    GROUP BY university
) AS m                      -- 派生表必须起别名
    ON u.university = m.university
   AND u.gpa = m.min_gpa;
```

**要点：**

- 派生表**必须起别名**（`AS m`），否则报错
- 子查询先独立算出一个结果集，外层再当普通表用
- 典型用途：先聚合（算每组最值 / 计数），再 JOIN 回原表取完整行

### 2. WHERE 子查询（条件子查询）

子查询放在 `WHERE` 里当筛选条件，分几种：

```sql
-- 标量子查询：子查询只返回一个值
SELECT * FROM user_profile
WHERE gpa > (SELECT AVG(gpa) FROM user_profile);   -- 高于全站平均

-- IN：子查询返回一列多个值
SELECT * FROM user_profile
WHERE university IN (SELECT university FROM top_schools);

-- EXISTS：相关子查询，只问"有没有"
SELECT * FROM user_profile AS u
WHERE EXISTS (
    SELECT 1 FROM question_practice_detail AS q
    WHERE q.device_id = u.device_id         -- 引用外层表 → 相关子查询
);
```

**⚠ NOT IN 的 NULL 陷阱（高频坑）：**

子查询结果里只要有一个 `NULL`，`NOT IN` 就会返回**空集**（`x != NULL` 结果是 UNKNOWN，整条 AND 链必断）。排除逻辑一律用 `NOT EXISTS`，或保证子查询字段 `NOT NULL`。详见 [[IN和EXISTS#3. 唯一无法被优化器抹平的差异：NULL 值处理]]。

**标量子查询要点：** 必须保证只返回一行一列，返回多行会报 `Subquery returns more than 1 row`。

### 3. CTE（`WITH ... AS`，公用表表达式）

把一段查询**临时命名**，后面像查普通表一样引用它，执行完即失效。相当于"给派生表取个名字提到最前面"，可读性比层层嵌套的子查询好得多。

```sql
WITH school_min AS (            -- 命名一个临时结果表
    SELECT university, MIN(gpa) AS min_gpa
    FROM user_profile
    GROUP BY university
)
SELECT u.device_id, u.university, u.gpa
FROM user_profile AS u
JOIN school_min AS m
    ON u.university = m.university
   AND u.gpa = m.min_gpa;
```

**多层 CTE：** 用逗号隔开，后面的 CTE 可以引用前面的——常用来把"统计"和"排名 / 筛选"分成两层：

```sql
WITH song_cnt AS (              -- 第一层：统计
    SELECT month, song_id, COUNT(*) AS plays
    FROM listen_log
    GROUP BY month, song_id
),
ranked AS (                     -- 第二层：排名，引用第一层
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY month ORDER BY plays DESC) AS rk
    FROM song_cnt
)
SELECT * FROM ranked WHERE rk <= 3;     -- 外层才能筛窗口函数算出的别名
```

> [!tip] 为什么排名要分层
> `ROW_NUMBER()` 算出的别名**不能在同层 WHERE 筛**（WHERE 比窗口函数先执行），必须套一层 CTE / 子查询，到外层再筛 `rk`。详见 [[SQL学习复盘#15. ⭐⭐⭐ 为什么 ranking 不能在同一层 WHERE 里筛？]]。

### 派生表 vs CTE：怎么选

| 维度 | 派生表（FROM 子查询） | CTE（WITH AS） |
|------|----------------------|----------------|
| 可读性 | 嵌套深了难读 | 命名清晰，自上而下 |
| 复用 | 要用几次写几次 | 定义一次，后面多处引用 |
| 递归 | 不支持 | 支持（`WITH RECURSIVE`） |
| 版本 | 都支持 | **MySQL 8.0+** 才有 |

**一句话：** 简单一次性嵌套用派生表；多层逻辑、要复用、要递归，用 CTE 更清晰。注意 CTE 是 **MySQL 8.0** 才支持，低版本只能退回派生表写法。

## 附：通用易错清单（考前速记）

### LEFT JOIN 专项

1. **主表选择：** 想保留谁就把谁放左边
2. **日期条件：** 限制右表匹配范围 → 放 `ON`；过滤左表 → 放 `WHERE`
3. **计数函数：** 统计右表记录数用 `COUNT(右表列)`，不用 `COUNT(*)`
4. **学校等主表过滤：** 必须放 `WHERE`，放 `ON` 不起作用

### 聚合查询专项

1. SELECT 里的非聚合列必须在 `GROUP BY` 中
2. 整体汇总不分组时，不要加 `GROUP BY`
3. `CASE WHEN ... THEN ... ELSE ... END`，不能漏 `END`
4. 不能嵌套聚合函数（`AVG(COUNT(...))`）

### 其他

1. 日期区间：`>= 开始日 AND < 结束月 1 日`
2. 正则必须锚定：`^...$`
3. `HAVING` 用于过滤聚合结果，不是 `WHERE` 的替代品
4. 每组最值对应的行 → 子查询 + JOIN，不用 `GROUP BY + HAVING`
