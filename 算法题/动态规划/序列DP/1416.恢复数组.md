### **LeetCode 1416「恢复数组」动态规划解法**

核心思路是**一维序列 DP**：`dp[i]` 表示前缀 `s[0..i-1]` 的有效分割方案数，通过枚举最后一段数字的起点完成状态转移，时间复杂度 $O(n \cdot L)$（L 为最长合法数字的位数上限，本题中 $L \le 10$）。

---

### **一、问题本身**

给定一个仅包含数字的字符串 `s`（不含前导零），和一个整数 `k`。需要将 `s` 分割成若干个子串，每个子串解析为一个整数，要求：

- 每个整数在范围 $[1, k]$ 内
- 子串不能有前导零（即不能以 `'0'` 开头，除非子串就是 `"0"`，但 `0` 不在范围内，所以实际上任何包含 `'0'` 开头的子串都不合法）

求有多少种不同的分割方案。结果对 $10^9 + 7$ 取模。

> 例如 `s = "1317"`，`k = 2000`，共 8 种分割方案。

---

### **二、错误解法分析**

```java
class Solution {
    public int numberOfArrays(String s, int k) {
        int n = s.length();
        int[] d = new int[n + 1];
        var dic = new HashSet<String>(...);
        // ... 类似划分DP的写法
    }
}
```

**错误原因**：这道题不是简单的"划分 DP"模板。与 [[2707.字符串中的额外字符]] 不同，本题中：

1. 每个子串必须满足数值约束（$1 \le$ 子串值 $\le k$），不能只看是否在字典中
2. 子串有**前导零**限制——以 `'0'` 开头的子串不合法
3. 没有"保留额外字符"的概念——必须**完全分割**，每个字符都必须属于某一个子串

因此 DP 转移需要枚举所有可能的"最后一段"起点，并逐段验证数值合法性。

---

### **三、正确 DP 解法**

```java
class Solution {
    public int numberOfArrays(String s, int k) {
        int n = s.length();
        int mod = 1000000007;
        int[] dp = new int[n + 1];
        dp[0] = 1;
        for (int i = 0; i < n; i++) {
            for (int j = i; j >= 0 && i - j < 10; j--) {
                if (s.charAt(j) == '0') continue;
                long num = Long.parseLong(s.substring(j, i + 1));
                if (num > k) break;
                dp[i + 1] = (dp[i + 1] + dp[j]) % mod;
            }
        }
        return dp[n];
    }
}
```

#### **状态定义**

`dp[i]`：前缀 `s[0..i-1]` 的**有效分割方案数**。

`dp[0] = 1`（空串有 1 种分割方式——什么都不分）。

#### **状态转移**

对于每个位置 `i`（0 到 n-1），枚举最后一段数字 `s[j..i]` 的起点 `j`（从 `i` 往左扫）：

- `s[j] ≠ '0'`：子串不能有前导零
- `num = s[j..i]` 的整数值 $\le k$：子串值在合法范围内
- 满足条件时：`dp[i+1] += dp[j]`（前缀 `s[0..j-1]` 的方案数）

$$
dp[i+1] = \sum_{\substack{0 \le j \le i \\ s[j] \ne '0' \\ \text{val}(s[j..i]) \le k}} dp[j]
$$

#### **答案**

`dp[n]`，即整个字符串的分割方案总数。

---

### **四、关键优化点**

#### **1. 子串长度上限 `i - j < 10`**

`k ≤ 10^9`，最多 9 位数字。超过 10 位的子串一定大于 `k`，无需继续枚举。这个剪枝把内层循环从 $O(n)$ 降为 $O(10) = O(1)$，总复杂度从 $O(n^2)$ 降到 $O(n)$。

#### **2. `num > k` 时 `break` 而非 `continue`**

`j` 从 `i` 往左递减，子串 `s[j..i]` 越来越长，数值越来越大。一旦 `num > k`，更小的 `j` 产生的子串只会更大，直接 `break` 退出内层循环。

#### **3. `Long.parseLong` 而非 `Integer.valueOf`**

子串可能长达 10 位（`9999999999 > Integer.MAX_VALUE`），用 `int` 会溢出，必须用 `long`。

#### **4. 取模 `mod = 10^9 + 7`**

每次累加 `dp[j]` 后立即取模，防止中间值溢出 `int` 范围。

### **五、一个具体例子走一遍**

以 `s = "1317"`，`k = 2000`（`n = 4`）为例：

|---|--------|---------|-----|-------------|-------------|---------|
| 0 | j=0 | "1" | 1 | ✓ | dp[0]=1 | **1** |
| 1 | j=1 | "3" | 3 | ✓ | dp[1]=1 | |
|   | j=0 | "13" | 13 | ✓ | dp[0]=1 | **2** |
| 2 | j=2 | "1" | 1 | ✓ | dp[2]=2 | |
|   | j=1 | "31" | 31 | ✓ | dp[1]=1 | |
|   | j=0 | "131" | 131 | ✓ | dp[0]=1 | **4** |
| 3 | j=3 | "7" | 7 | ✓ | dp[3]=4 | |
|   | j=2 | "17" | 17 | ✓ | dp[2]=2 | |

### **六、与同类题的对比**

| 维度 | [[2707.字符串中的额外字符]] | 1416. 恢复数组 |
|------|--------------------------|--------------|
| 状态含义 | 前缀最少**额外字符数** | 前缀有效**分割方案数** |
| 分割要求 | 非完全分割（可跳过字符） | **完全分割**（每个字符必须属于某个子串） |
| 子串合法性 | 在字典 `HashSet` 中 | 数值 $\in [1, k]$ 且无前导零 |
| 转移 | `dp[i] = min(dp[i-1]+1, min(dp[j]))` | `dp[i+1] += dp[j]`（累加而非取最小） |
| 枚举方向 | `j` 从 0 到 i-1 | `j` 从 i 往左到 0 |
| 复杂度 | $O(n^2)$ | $O(n \cdot 10) = O(n)$（长度剪枝） |

### **七、面试话术**

1. **为什么是累加而不是取最小值？** — 本题求的是方案总数，每个合法分割点 `j` 都贡献 `dp[j]` 种方案，需要累加；而 [[2707.字符串中的额外字符]] 求的是最优值（最少额外字符），所以取 min。
2. **长度剪枝 `i-j < 10` 的依据** — $k \le 10^9$，最多 9 位，超过 10 位的子串一定大于 k。
3. **前导零为什么检查 `s[j]` 而不是 `s[i]`** — 子串 `s[j..i]` 的第一个字符是 `s[j]`，只要它以 `'0'` 开头就不合法（无论后面是什么）。
4. **`break` 的条件** — `j` 往左扫时子串变长、数值变大，一旦超过 `k` 就不可能再合法，直接退出。
