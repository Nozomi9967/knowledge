# 树

> [!abstract] 本篇定位 — 笔试常考的"树"
> 树这一章在笔试里几乎只考两类东西：**概念判定与计算**（性质公式、遍历序列还原、ASL、旋转后的形态）和**结构对比选型**（二叉树各种形态、BST / AVL / 红黑树 / B+ 树各自适合什么）。本文按「基本性质 → 特殊形态 → 遍历 → 线索二叉树 → 树/森林转换 → BST 家族（BST/AVL/红黑树）→ B 树 / B+ 树 → 哈夫曼树」的顺序铺开，每个考点都点明笔试怎么考、坑在哪，末尾附计算题速查表与易错点汇总。

## 一、树与二叉树的基本概念

### 1. 常用术语

| 术语 | 含义 |
|------|------|
| 结点的度 | 该结点拥有的子树（孩子）个数 |
| 树的度 | 树内各结点度的最大值 |
| 叶子结点（终端结点） | 度为 0 的结点，没有孩子 |
| 分支结点（非终端结点） | 度不为 0 的结点 |
| 孩子 / 双亲 / 兄弟 | 相邻两层的上下级、以及同父的结点 |
| 层次 | 根为第 1 层，向下逐层递增 |
| 树的深度（高度） | 树中结点的最大层次 |
| 路径长度 | 从结点 A 到 B 经过的**边数**（不是结点数） |
| 森林 | m（m ≥ 0）棵互不相交的树的集合 |

> [!tip] 一句话记忆
> 一棵 n 个结点的树**恰好有 n − 1 条边**（除根外每个结点都唯一对应一条从父结点指向它的边）。很多计算题都是从这一条起步的。

### 2. 二叉树的核心性质（必背）

| 编号 | 性质 | 公式 |
|------|------|------|
| 性质 1 | 第 i 层至多有 2^(i−1) 个结点（i ≥ 1） | 2^(i−1) |
| 性质 2 | 深度为 k 的二叉树至多有 2^k − 1 个结点（k ≥ 1） | 2^k − 1 |
| 性质 3 | 叶子数 = 度为 2 的结点数 + 1 | n0 = n2 + 1 |
| 性质 4 | n 个结点的完全二叉树深度 | ⌊log₂ n⌋ + 1 |
| 性质 5 | 完全二叉树编号关系（见下） | 2i / 2i+1 / ⌊i/2⌋ |

**性质 3 的推导（高频考"证明"）**：设结点总数为 n，度为 0、1、2 的结点数分别为 n0、n1、n2，则 n = n0 + n1 + n2。除根外每个结点都恰有一条从父结点指向它的边，所以边数 = n − 1；从"度"这一侧数，边数 = 0·n0 + 1·n1 + 2·n2 = n1 + 2n2。两式联立：n0 + n1 + n2 − 1 = n1 + 2n2，得 **n0 = n2 + 1**。

**推论**：完全二叉树有 n 个结点时，叶子结点数为 **⌈n/2⌉**（最后一个非叶结点的编号是 ⌊n/2⌋）。

### 3. 完全二叉树的编号性质

按层序从 1 开始编号，则对结点 i：

- 左孩子 = 2i，右孩子 = 2i + 1（仅当 2i 或 2i+1 不超过 n 时才存在）；
- 父结点 = ⌊i/2⌋（i 大于 1 时存在）；
- 编号 i 的结点所在层次 = ⌊log₂ i⌋ + 1。

### 4. 二叉树 ≠ 度为 2 的有序树

两者常被混淆，区别有两点：

- 度为 2 的树至少有 3 个结点（根 + 两个孩子），而**二叉树可以为空**；
- 度为 2 的有序树中，只有一个孩子的结点不必区分左右；而**二叉树中即使只有一个孩子，也严格区分它是左孩子还是右孩子**。

## 二、二叉树的特殊形态

### 1. 满二叉树

要求非常严格：

**每一层都必须填满。** 也就是说，每个节点要么有 0 个孩子，要么有 2 个孩子。

例如：

```
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
```

这是满二叉树。

如果高度为 h（根节点高度算第 1 层），节点数一定是：

$$2^h - 1$$

### 2. 完全二叉树

要求没那么严格：

**除了最后一层，前面的层必须全部填满；最后一层的节点必须从左往右连续排列。**

例如：

```
        1
      /   \
     2     3
    / \   /
   4   5 6
```

这是完全二叉树，但不是满二叉树。

因为最后一层没有填满，但 4、5、6 是从左往右连续的。

### 3. 形态辨析

| 形态 | 定义 | 与满二叉树的关系 |
|------|------|-----------------|
| 满二叉树 | 每层都填满，叶子全部在最底层 | — |
| 完全二叉树 | 除末层外填满，末层从左往右连续 | 满的一定是完全，反之不然 |
| 严格二叉树 / 真二叉树 | 每个结点的度是 0 或 2（没有单孩子结点） | 只满足这一条、但叶子不在同一层的，**不是**满二叉树 |
| 斜树 | 所有结点都只有左孩子（左斜）或只有右孩子（右斜） | 退化成单链表，高度 = n |

### 4. 面试要点补充

- **满二叉树一定是完全二叉树**，反之不成立（满是完全的特例，末层刚好也填满了）。
- **别把"每个节点 0 或 2 个孩子"单独当成满二叉树的判据**：只满足这一条、但叶子不在同一层的，叫**严格二叉树 / 真二叉树**，不是满二叉树。满二叉树还要求所有叶子都在最底层、每层填满。
- **完全二叉树最适合用数组存储**：按层序把节点放进数组（下标从 1 开始），节点 i 的左孩子是 `2i`、右孩子是 `2i+1`、父节点是 `i/2`，中间不会有空洞。**堆（大根堆/小根堆）就是用数组存储的完全二叉树**，这也是堆能做到 O(1) 定位父子节点的原因。
- **节点数与高度**：满二叉树 h 层恰好 $2^h - 1$ 个节点；完全二叉树有 n 个节点时，高度为 $\lfloor \log_2 n \rfloor + 1$。
- 完全二叉树有 nnn 个节点时，叶子节点数为 ⌈n2⌉\left\lceil \frac{n}{2} \right\rceil⌈2n​⌉

## 三、二叉树的遍历

### 1. 四种遍历

以"根"相对"左右子树"的访问先后命名：

| 遍历 | 顺序 | 助记 | 实现手段 |
|------|------|------|---------|
| 先序（前序） | 根 → 左 → 右 | NLR | 递归 / 栈 |
| 中序 | 左 → 根 → 右 | LNR | 递归 / 栈 |
| 后序 | 左 → 右 → 根 | LRN | 递归 / 栈 |
| 层序 | 自上而下、每层从左到右 | BFS | 队列 |

示例树：

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

| 遍历 | 结果 |
|------|------|
| 先序 | A B D E C F |
| 中序 | D B E A C F |
| 后序 | D E B F C A |
| 层序 | A B C D E F |

### 2. 由遍历序列还原二叉树（高频大题）

核心思路一句话：**先序 / 后序 / 层序负责"找到根"，中序负责"把序列切成左右子树"。**

| 已知组合 | 能否唯一确定 | 原因 |
|----------|:---:|------|
| 先序 + 中序 | ✅ 能 | 先序首元素 = 根，中序据根切分左右 |
| 后序 + 中序 | ✅ 能 | 后序末元素 = 根，同上 |
| 层序 + 中序 | ✅ 能 | 层序中第一个未使用的元素 = 根 |
| 先序 + 后序 | ❌ 不能 | 分不清左右子树边界；**仅当树是满二叉树时唯一** |

**手推步骤**（以先序 `A B D E C F`、中序 `D B E A C F` 为例）：

1. 先序首元素 `A` 是根 → 在中序里找到 `A`，左边 `{D B E}` 是左子树、右边 `{C F}` 是右子树；
2. 左子树先序为 `B D E` → 根是 `B`；其先序 `D E`、中序 `D E` → `D` 左、`E` 右；
3. 右子树先序为 `C F`、中序为 `C F` → 根是 `C`，`F` 是它的右孩子。

还原结果就是上面那棵树。

### 3. 遍历序列的笔试性质

- **先序遍历 = 从根出发的 DFS 入栈顺序**，非递归用栈实现；
- **对 BST 而言，中序遍历得到升序序列**——这是判定"是不是 BST"的最快方法；
- **先序的第一个 = 后序的最后一个 = 根**；
- 层序遍历用**队列**（BFS）。

## 四、线索二叉树

n 个结点的二叉链表共有 2n 个指针域，而真正用到的只有 n − 1 条边，所以有 **2n − (n − 1) = n + 1 个空指针域**。线索二叉树就是用这些空指针去指向前驱 / 后继，省掉遍历时的栈：

- 每个结点增加两个标志位 `ltag`、`rtag`；
- tag = 0：指针指向**孩子**；
- tag = 1：指针指向**遍历中的前驱（左指针）/ 后继（右指针）**。

| 线索类型 | 空的左指针指向 | 空的右指针指向 |
|----------|---------------|---------------|
| 先序线索 | 前驱 | 后继 |
| 中序线索（最常用） | 前驱 | 后继 |
| 后序线索 | 前驱 | 后继 |

**中序线索树找后继**：若 `rtag = 1`，右指针就是后继；若 `rtag = 0`，后继是右子树的**最左下结点**。

好处：找前驱 / 后继 O(1)，遍历不需要栈、也不需要递归。

## 五、树、森林与二叉树的转换

采用**孩子兄弟表示法（左孩子右兄弟）**：每个结点的左指针指向它的**第一个孩子**，右指针指向它的**下一个兄弟**。

| 转换 | 结果特征 |
|------|---------|
| 树 → 二叉树 | 根结点**没有右子树** |
| 森林 → 二叉树 | 各棵树的根通过右指针串成一条链 |

> 动图演示「森林 → 二叉树」的 5 步过程（3 棵树 / 12 个结点）：橙线 = 左指针（第一个孩子），蓝线 = 右指针（下一个兄弟），橙圈 = 森林中各棵树的根。

**遍历对应关系（高频易混）：**

| 树的遍历 | 森林的遍历 | 转换后的二叉树  |
| ---- | ----- | -------- |
| 先根遍历 | 先序遍历  | **先序**遍历 |
| 后根遍历 | 中序遍历  | **中序**遍历 |

> [!warning] 易错点
> 树**没有**"中根遍历"。树的先根 / 后根遍历，分别对应它转换后二叉树的先序 / 中序遍历——即"**后根对应中序**"，不是"后根对应后序"，这是最容易记错的一处。

### 转换的具体步骤

**森林 → 二叉树（3 步）**

1. **断多余父子线**：每个结点只保留与**第一个孩子**的连线，其余孩子的父子线剪掉。（A 有孩子 B、C、D → 只留 A–B，剪掉 A–C、A–D）
2. **兄弟串成右链**：同一父结点的孩子，从左到右用右指针依次相连。（B→C→D）
3. **树根也串成右链**：森林中各棵树的根，从左到右用右指针相连，第一棵树的根作二叉树的根。（A→H→L）

**二叉树 → 森林（3 步，反向）**

1. **拆根链**：从根沿右指针走，链上的结点就是森林里各棵树的根，断开它们之间的右连线。
2. **拆兄弟链、把兄弟挂回父结点**：对每个结点，沿它的**左孩子**往右走，那一串就是它的孩子（规则见下）。
3. **左孩子还原为父子边**：每个结点与左孩子的连线，直接还原成父子关系，再整理布局。

> 口诀：**左孩子管下一代，右孩子管同一代。** 往左走 = 进入孩子辈；往右走 = 同层找兄弟（或找下一棵树的根）。

### 怎么判断兄弟链 & 怎么挂回（二叉树 → 森林）

**兄弟链 = 二叉树里"沿右指针连续走"的一串结点。** 判断规则只有一条：**看这条右链的起点是谁的左孩子——是谁的左孩子，整条链上的结点就都是谁的孩子。**

| 右链 | 起点是谁的左孩子 | 父结点 | 需要补上的父子边 |
|------|----------------|:---:|:---:|
| B→C→D | B 是 A 的左孩子 | A | A–C、A–D |
| E→F | E 是 B 的左孩子 | B | B–F |
| I→J | I 是 H 的左孩子 | H | H–J |
| A→H→L（根链） | 起点是二叉树的根 | — | 分别是森林中各棵树的根 |

> ⚠️ 右链表示 B、C、D 是**同一层的兄弟**，不是父子——所以 D **不能**挂到 C 下面，C 也**不能**挂到 B 下面，它们**都挂到共同的父结点 A 上**，按顺序排成 A 的孩子。
> **检验**：某结点的**孩子个数 = 它的左孩子所在右链的长度**。如 A 的左孩子是 B，右链 B→C→D 长 3 → A 有 3 个孩子。

### 两个高频对应关系（选择题重点）

| 二叉树 T 中… | 对应森林 F 里… |
|--------------|---------------|
| **左孩子指针为空**的结点 | **叶结点** |
| 右孩子指针为空 的结点 | 某组兄弟中**最右边**的那个（或最后一棵树的根） |

**为什么"左孩子为空" = 森林的叶结点？** 左指针只表示"第一个孩子"；森林里是叶结点 = 没有孩子 = 没有第一个孩子 = **左指针为空**。反过来也成立（左指针为空 ⇒ 没有孩子 ⇒ 叶结点）。所以：

> **F 的叶结点个数 = T 中左孩子指针为空的结点个数。**

这正是那道选择题选 **C** 的原因，同时它排除了其余选项：

- **A 错**：二叉树的叶结点要求**左右孩子都为空**。森林里的叶结点若还有右兄弟（右指针不为空），在二叉树里就**不是**叶结点了。如前面的例子中 E 有右兄弟 F，E 在二叉树里就不是叶结点——所以 **T 的叶结点数通常少于 F 的**。
- **B 错**：度为 1 的结点数与森林叶结点数没有固定关系。
- **D 错**：右孩子为空 = 该结点没有下一个兄弟，即某组兄弟中最右边那个（或最后一棵树的根）。**右孩子为空的结点数 = 兄弟链的条数 = 森林里非叶结点数 + 1**（每个非叶结点对应一条孩子兄弟链，再加根链），与叶结点数无关。

## 六、二叉搜索树（BST，二叉排序树）

### 1. 定义

对任一结点，**左子树上的所有结点都小于它，右子树上的所有结点都大于它**。因此**中序遍历得到升序序列**。

### 2. 查找

从根开始比较：目标小于当前 → 往左；目标大于当前 → 往右；相等 → 命中；走到空 → 不存在。平均时间 O(log n)。

### 3. 插入

沿查找路径一直走到空位置，把新结点作为**叶子**挂上去——所以 BST 的插入一定发生在叶子。

### 4. 删除（分三种情况）

| 情况 | 处理 |
|------|------|
| 叶子结点 | 直接删除 |
| 只有一个孩子 | 用它的**唯一孩子**顶替它的位置 |
| 有两个孩子 | 用**中序前驱**（左子树最右结点）或**中序后继**（右子树最左结点）替换它的值，再删除那个前驱 / 后继结点 |

### 5. 平均查找长度 ASL

查找成功 ASL = 各结点**所在层数** × 查找概率之和。等概率查找 n 个结点时：

$$ASL = \frac{1}{n}\sum_{i=1}^{n} l_i$$

其中 $l_i$ 是第 i 个结点所在层数。查找失败的 ASL 则要看空指针落在的层。

### 6. 退化

若按有序序列依次插入，BST 会退化成**单链表**，查找退化到 O(n)。这正是平衡二叉树（AVL）要解决的问题。

## 七、平衡二叉树（AVL 树）

AVL 树是**任意结点左右子树高度差的绝对值不超过 1** 的 BST。

**平衡因子 BF**（Balance Factor）= 左子树高度 − 右子树高度，取值只能是 −1、0、1。

### 1. 四种失衡与旋转

插入新结点后，从**最小失衡子树**（离新结点最近的失衡祖先）开始调整。按"新结点落在失衡结点的哪个方向"分四种：

| 类型 | 插入位置 | 调整方法 |
|------|---------|---------|
| LL | 左子树的左子树上 | 对失衡结点**右旋**（顺时针） |
| RR | 右子树的右子树上 | 对失衡结点**左旋**（逆时针） |
| LR | 左子树的右子树上 | 先对左孩子**左旋**，再对失衡结点**右旋** |
| RL | 右子树的左子树上 | 先对右孩子**右旋**，再对失衡结点**左旋** |

记忆：**看新结点落在失衡结点的哪一侧，旋转就往回"拧"**；LR / RL 是"双旋"，先把它转成 LL / RR 再做单旋。

### 2. 手推示例

依次插入 1、2、3：

```
插入1:   1          插入2:   1            插入3:   1  ← RR 失衡，对 1 左旋
                             \                      \
                              2                      2
                                                    / \
                                                   1   3
```

- 依次插入 3、2、1 → LL，对 3 右旋；
- 依次插入 3、1、2 → LR（先左旋左孩子，再右旋根）；
- 依次插入 1、3、2 → RL。

题干常给一个"插入序列"，问"属于哪种旋转"或"调整后的先序 / 层序是什么"。

## 八、红黑树

BST 的一种**近似平衡**变体，每个结点带红 / 黑颜色，满足**五条性质**：

1. 每个结点是红色或黑色；
2. 根结点是黑色；
3. 每个叶子结点（NIL 空结点）是黑色；
4. 红结点的两个孩子都必须是黑色（**没有连续两个红结点**）；
5. 从任一结点到它所有后代叶子（NIL）的路径上，**黑结点数目相同**（黑高相等）。

由性质 4、5 可以推出：**最长路径长度 ≤ 2 × 最短路径长度**，所以树高不超过 2·log₂(n+1)——它是"近似平衡"，不是严格平衡。

### 与 AVL 对比（高频）

| 维度 | AVL 树 | 红黑树 |
|------|--------|--------|
| 平衡严格度 | 严格（左右高差 ≤ 1） | 近似（长路径 ≤ 2 × 短路径） |
| 树高 | 更低 | 略高 |
| 查找 | 更快 | 稍慢 |
| 插入 / 删除调整 | 旋转次数可能多达 O(log n) | **最多 3 次旋转**即可复原 |
| 适合场景 | 查找远多于增删 | **增删频繁** |

正因为"增删调整的代价低"，红黑树被广泛用作各种库的底层：Java 的 `TreeMap` / `TreeSet`、`HashMap` 的桶（链表过长时转红黑树）、C++ STL 的 `map`、Linux 内核等。

### 插入调整（了解即可）

新结点先染红。若父结点是黑 → 结束；若父结点是红，再看叔叔结点：

- **叔叔是红** → 父、叔、祖父一起变色，问题**上溯**到祖父继续处理；
- **叔叔是黑** → 通过旋转（LL / RR / LR / RL，与 AVL 同样的四种）+ 变色解决。

## 九、B 树与 B+ 树

### 1. m 阶 B 树（m 路平衡查找树）

- 每个结点最多有 **m 棵子树**（即 m − 1 个关键字）；
- 根结点若不是叶子，**至少有 2 棵子树**；
- 除根外的所有非叶结点至少有 **⌈m/2⌉ 棵子树**（即 ⌈m/2⌉ − 1 个关键字）；
- **所有叶子结点都在同一层**。

### 2. B+ 树（MySQL InnoDB 的索引结构）

- **非叶结点只作索引**，只存关键字、不存数据（数据全部在叶子）；
- **所有关键字都出现在叶子结点**，叶子结点按大小顺序**用链表相连**；
- 查找任何数据都要走到叶子，路径长度一致 → 查询时间稳定。

### 3. B 树 vs B+ 树

| 维度 | B 树 | B+ 树 |
|------|------|-------|
| 数据存放 | 所有结点都可能存数据 | **只有叶子结点存数据**，非叶只存索引 |
| 叶子链表 | 无 | **有**，叶子间顺序相连 |
| 关键字 | 每个关键字只出现一次 | 非叶的关键字在叶子中**重复出现** |
| 查找 | 可能在非叶就命中，路径不定 | **一定走到叶子**，路径长度一致 |
| 范围查询 | 需中序遍历 | **沿叶子链表顺序扫描**，效率极高 |

**为什么 MySQL 用 B+ 树而非 B 树 / 红黑树**：结点大小对齐磁盘页（InnoDB 为 16 KB）；非叶结点不存数据 → 一个结点能容纳更多索引项 → 树更**矮胖** → 磁盘 IO 次数更少；叶子链表天然支持范围查询与排序。（详见 [[MySQL索引]]）

## 十、哈夫曼树（最优二叉树）

### 什么是带权路径长度 WPL

带权路径长度（WPL, Weighted Path Length）= 树中**所有叶子节点**的「权值 × 该叶子到根的路径长度」之和：

$$WPL = \sum_{i=1}^{n} w_i \times l_i$$

- $w_i$：第 i 个叶子节点的**权值**
- $l_i$：该叶子到根经过的**边数**（根算第 0 层时，就等于叶子所在层数）

**哈夫曼树就是：当一组叶子权值固定时，WPL 最小的那棵二叉树**，所以又叫「最优二叉树」。直觉上就是让权值大的叶子离根近（路径短）、权值小的叶子离根远。

### 构造过程（贪心 + 小根堆）

每次从当前所有节点里挑**权值最小的两个**合并成一棵新子树（新根权值 = 两者之和），把新根放回集合，重复到只剩一个根。用小根堆维护即可做到 $O(n\log n)$：

1. 权值集合 `{7, 5, 2, 4}`
2. 取最小两个 `2, 4` → 合并成 `6`，集合变 `{7, 5, 6}`
3. 取最小两个 `5, 6` → 合并成 `11`，集合变 `{7, 11}`
4. 取最小两个 `7, 11` → 合并成 `18`，只剩一个根，结束

```
        18
       /   \
      7     11
           /   \
          5     6
               / \
              2   4
```

### 算这棵树的 WPL

叶子层数（根为第 0 层）：7 在第 1 层、5 在第 2 层、2 和 4 在第 3 层。

$$WPL = 7\times1 + 5\times2 + 2\times3 + 4\times3 = 7 + 10 + 6 + 12 = 35$$

**验算技巧**：WPL 也等于「构造过程中所有合并产生的新节点权值之和」——即 $6 + 11 + 18 = 35$。因为每个叶子每被向上并入一层，就多贡献一次自己的权值，正好被每次合并累加进去。考试手算时用这个对答案最快。

### 哈夫曼编码（常连带考）

给左分支标 0、右分支标 1，从根到叶子的路径就是该叶子的编码。因为字符全在**叶子**上，任何编码都不会是另一个的前缀，所以是**前缀编码**（解码无歧义）。上例编码：7→`0`、5→`10`、2→`110`、4→`111`。此时 WPL 恰好等于「编码后的总比特数」，所以哈夫曼编码是**最优前缀编码**，是数据压缩的基础。

### 面试要点

- **哈夫曼树不唯一**：合并时若有多个相同的最小权值，选谁都行，形态可能不同，但 **WPL 一定相同（都是那个最小值）**。
- **只有叶子存权值/字符**，内部节点是合并出来的，没有权值语义。
- **n 个叶子的哈夫曼树共有 2n−1 个节点**（合并 n−1 次、每次新增一个内部节点），且**不存在只有一个孩子的节点**（每个内部节点度数恒为 2）。
- 别把「路径长度」当成节点数——它是**边数**（等于层数差）。

## 十一、笔试计算题速查

| 计算对象 | 公式 |
|----------|------|
| 叶子数与度为 2 结点数 | n0 = n2 + 1 |
| 第 i 层最多结点数 | 2^(i−1) |
| 深度 k 的二叉树最多结点数 | 2^k − 1 |
| n 个结点完全二叉树的高度 | ⌊log₂ n⌋ + 1 |
| n 个结点完全二叉树的叶子数 | ⌈n/2⌉ |
| n 个结点二叉树的空指针域 | n + 1 |
| n 个结点的树 / 森林的边数 | n − 1（每棵子树各 n_i − 1 条） |
| n 个叶子的哈夫曼树结点总数 | 2n − 1 |
| n 个结点的不同二叉树形态数 | 卡特兰数 $\dfrac{1}{n+1}\dbinom{2n}{n}$ |
| 森林的叶结点数 | = 转换后二叉树中**左孩子指针为空**的结点个数 |
| 森林转换后二叉树中右孩子为空的结点数 | = 兄弟链条数 = 森林非叶结点数 + 1 |

卡特兰数前几项：n = 0、1、2、3、4、5 → **1、1、2、5、14、42**。

## 十二、笔试易错点汇总

1. **先序 + 后序不能唯一确定二叉树**——必须含中序（先序/后序/层序 与 中序 组合）。只有满二叉树时，先序 + 后序才唯一。
2. **满二叉树 ≠ 严格二叉树**——"每个结点度为 0 或 2"只是严格二叉树；满二叉树还要求叶子全在最底层、每层填满。
3. **先序的第一个 / 后序的最后一个 = 根**，中序用于切左右子树。
4. **完全二叉树高度 = ⌊log₂ n⌋ + 1**，别写成 ⌊log₂(n+1)⌋ 或 ⌈log₂(n+1)⌉。
5. **BST 删除双孩子结点**：用中序前驱 / 后继替换，不是随便接一个孩子。
6. **AVL 旋转方向别记反**：LL 右旋、RR 左旋；LR / RL 是双旋。
7. **红黑树是近似平衡**，树高不超过 2·log₂(n+1)，不是严格平衡。
8. **B 树 / B+ 树的区别在"数据是否只在叶子"**：B+ 树非叶只存索引，叶子有链表相连。
9. **树的先根遍历 ↔ 二叉树先序**、**树的后根遍历 ↔ 二叉树中序**（不是后序！）。
10. **路径长度是"边数"**，不是结点数；树高 / 深度是"层数"。
11. **森林的叶结点数 = 转换后二叉树中「左孩子指针为空」的结点数**（选择题常考）；而二叉树中「右孩子指针为空」的结点数 = 兄弟链条数 = 森林非叶结点数 + 1——两者别混。
