Java 中有四种访问权限修饰符，控制类、方法、字段的可见范围：

## 四种修饰符

|修饰符|同类|同包|子类（跨包）|其他包|
|---|---|---|---|---|
|`private`|✅|❌|❌|❌|
|（默认，package-private）|✅|✅|❌|❌|
|`protected`|✅|✅|✅|❌|
|`public`|✅|✅|✅|✅|

## 各自的使用场景

**`private`** 封装的核心。字段几乎都应该是 `private`，配合 getter/setter 暴露。内部实现细节不想被外部触碰时用。

```java
public class User {
    private String password; // 外部无法直接访问
    
    public String getPassword() { return password; }
}
```

**默认（package-private）** 不写修饰符时的默认状态。同包内可见，跨包不可见。适合包内协作的工具类或内部实现，不想对外暴露 API 时用。

```java
class InternalHelper { // 同包其他类可用，包外不可见
    void doSomething() {}
}
```

**`protected`** 专为继承设计。子类可以访问父类的 `protected` 成员，即使跨包。框架设计中常见，比如模板方法模式里暴露给子类重写的钩子方法。

```java
public abstract class BaseService {
    protected void beforeExecute() {} // 子类可重写，外部无法调用
}
```

**`public`** 完全公开。对外暴露的 API、接口方法、工具类的静态方法等用 `public`。

## 几个容易混淆的点

**`protected` 跨包的细节**：跨包子类只能通过 `this`（自身引用）访问 `protected` 成员，不能通过父类的对象引用访问。

```java
// 包 b 中的子类
public class Child extends Parent {
    void test(Parent p) {
        this.protectedMethod(); // ✅ 合法
        p.protectedMethod();    // ❌ 编译报错（跨包通过父类引用不行）
    }
}
```

**类本身的修饰符**：顶层类只能用 `public` 或默认，不能用 `private`/`protected`。内部类（inner class）则四种都可以用。

**接口成员**：接口中的方法默认是 `public abstract`，字段默认是 `public static final`，即使不写修饰符。

## 属性/方法修饰符的书写次序

访问权限修饰符之外，Java 还有 `static`、`final`、`transient`、`volatile` 等修饰符。它们组合出现时有约定俗成的书写次序。

**常见次序：访问修饰符在前，接着是 `static`、`final` 等，最后是类型和名称**，例如 `private static final int MAX = 10;`。

Java 语言规范（JLS）对修饰符顺序**并没有强制要求**，编译器接受任意顺序，例如 `final static private int X = 1;` 也能通过编译。但社区和主流代码规范（Google Java Style、阿里巴巴 Java 开发手册）都约定了统一写法，便于阅读和团队协作。

按 JLS 推荐顺序，修饰符依次为：

| 顺序 | 修饰符 | 可用于 |
|------|--------|--------|
| 1 | `public` / `protected` / `private` | 类、方法、字段 |
| 2 | `abstract` | 类、方法 |
| 3 | `static` | 方法、字段、内部类 |
| 4 | `final` | 类、方法、字段 |
| 5 | `transient` | 仅字段 |
| 6 | `volatile` | 仅字段 |
| 7 | `synchronized` | 仅方法 |
| 8 | `native` | 仅方法 |
| 9 | `strictfp` | 类、方法 |

字段常用的组合主要是访问修饰符、`static`、`final`、`transient` 和 `volatile` 这几类。

典型写法示例：

```java
public class Config {

    // 常量：访问修饰符 + static + final
    public static final String APP_NAME = "demo";

    // 静态共享变量，仅类内可见
    private static int counter = 0;

    // 实例字段，使用 final 表示不可重新赋值
    private final Long id;

    // 序列化时忽略的字段
    private transient String cache;

    // 多线程可见性保证
    private volatile boolean running = true;
}
```

需要注意：**访问修饰符只能有一个，且应放在最前面**；`final` 和 `static` 的先后实践中通常是 `static final`，这是最常见的约定；`transient` 和 `volatile` 只能用于字段，一般放在访问修饰符之后、类型之前。

> 修饰符的**含义**（`static` 类级别资源、`final` 不可变等）见 [[Java变量分类与默认值]] 与 [[Java基础面试题#Java 中 final 作用是什么？]]。
