CPU缓存（CPU Cache）是位于 CPU 和主内存（RAM）之间的一种**高速、小容量存储器**，用来弥补 CPU 运算速度和内存读写速度之间的巨大差距。

**为什么需要它**

CPU 的运算速度远远快于内存的访问速度（差几十到上百倍）。如果 CPU 每次读写数据都直接访问内存，CPU 大部分时间都会在"等数据"，性能浪费严重。所以在 CPU 和内存之间加了一层用更快的存储介质（SRAM）做的缓存，把"最近用过"或"可能要用"的数据先放在这里，CPU 读写时优先访问缓存，速度快很多。

**层级结构**

现代 CPU 一般是多级缓存：

- **L1**：每个核心独享，容量最小（几十 KB），速度最快
- **L2**：每个核心独享或少数核心共享，容量稍大（几百 KB ~ 几 MB）
- **L3**：所有核心共享，容量最大（几 MB ~ 几十 MB），速度相对慢一些

访问速度大致是：寄存器 > L1 > L2 > L3 > 主内存，容量则反过来，越往后越大。

**和这道题的关系**[[答案-Java并发-多线程#1. JMM 解决的三个问题]]

回到可见性问题：当线程操作一个变量时，CPU 会把这个变量从主内存加载到自己核心的缓存中进行读写操作（这就是题目里说的"工作内存"，可以理解成对应到 CPU 缓存）。如果线程 A 修改了缓存里的值，但还没把这次修改"刷"回主内存，此时线程 B（在另一个核心上运行）去读这个变量，由于它自己核心的缓存里还存的是旧值（或者它去读主内存也是旧值），就看不到线程 A 刚刚的修改——这就是可见性问题的根源。

`volatile` 的作用就是绕开/打通这层缓存机制：写 volatile 变量时强制把值刷回主内存，并让其他 CPU 核心缓存中该变量的副本失效（这背后涉及一个叫**缓存一致性协议（如 MESI）**的机制），从而保证所有线程看到的都是最新值。
