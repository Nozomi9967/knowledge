# 2944. 购买水果需要的最少金币数

## 一、题目

> 给你一个下标从 0 开始的整数数组 `prices`，其中 `prices[i]` 是购买第 `i+1` 个水果需要花费的金币数。
> 促销规则：如果你花费 `prices[i]` 买下了**下标为 i 的水果**，那么下标范围 `[i+1, 2i+1]` 的水果可以**免费拿走**（最多到数组末尾）。
> 注意：即使某个水果 j 可以免费拿走，你仍可以花 `prices[j]` 买下它——为了触发它的奖励。
> 返回拿到**所有**水果所需的最少金币数。

- 链接：https://leetcode.cn/problems/minimum-number-of-coins-for-fruits/description/
- 数据范围：`1 <= n <= 1000`，`1 <= prices[i] <= 10^5`
- **题解参考：** https://leetcode.cn/problems/minimum-number-of-coins-for-fruits/solutions/2542044/dpcong-on2-dao-onpythonjavacgo-by-endles-nux5/

> [!note] n 只有 1000
> 理论上 O(n²) 也能过，但「O(n²) → O(n)」靠的正是抓住 **j 与 i 的关系** 把内层循环换成滑动窗口最小值，这是本题真正想考的亮点。

## 二、核心：j 与 i 的关系

> [!abstract] 一句话总纲
> 买下**下标 i** 的水果，会免费送出 **[i+1, 2i+1]**；而**下一个要花钱买的水果 j** 必然落在 **[i+1, 2i+2]** 这个窗口里——这就是本题 DP 里  j 和 i 的唯一关系。

### 2.1 免费区间是怎么来的

- 买水果 `i`，花 `prices[i]`。
- 送的区间是 `[i+1, 2i+1]`（数组下标），超出 `n-1` 就截断。

验证（0 下标）：

| 买的水果 i | 免费区间 [i+1, 2i+1] | 示例 |
|:---:|:---|:---|
| 0 | [1, 1] | 买第 1 个送第 2 个 |
| 2 | [3, 5] | 买了第 3 个，送第 4、5、6 |
| 5 | [6, 11] → [6, 7] | 买了第 6 个，送第 7、8 |

> [!warning] 下标别混
> 题面写的是「免费获得下标范围在 `[i+1, i+i]` 的水果」，那是按 **1 下标**（第几个水果）写的。转成**数组 0 下标**后免费区间其实是 `[i+1, 2i+1]`。直接拿题面公式去编 0 下标代码就错了。

### 2.2 下一个要买的水果 j 在哪

- 买完 `i`，`[i+1, 2i+1]` 已经**免费到手**。
- 但免费区间里的水果你其实**可以再花钱买**——为了再触发它们的奖励（示例 3 里「买了第 3 个、又买了第 6 个」就是这个目的）。
- 所以下一个**花钱买**的水果 `j`，可以是免费区间内任意一个 `[i+1, 2i+1]`，**也可以跳过整个免费区间**，直接买免费区之后第一个水果 `2i+2`。

⟹ **`j` 的取值窗口 = `[i+1, 2i+2]`**

| 端点 | 含义 |
|:---:|:---|
| `i+1` | 免费区左端（也可作为下一次购买点） |
| `2i+1` | 免费区右端 |
| `2i+2` | 免费区**之外**第一个必须买的水果 |

### 2.3 为什么是滑动窗口 → 单调队列

- 每个 `i` 都要在窗口 `[i+1, min(2i+2, n)]` 里取 `dp` 的**最小值**。
- 窗口**左端点** `i+1` 随 i 减小而**左移 1**，**右端点** `2i+2` 随 i 减小而**左移 2**——一个「整体往左滑」的**滑动窗口**。
- 滑动窗口取最小值 → **单调队列** O(1) 摊还出最小，把整体从 O(n²) 降到 O(n)。

## 三、状态定义与转移

**状态：** `dp[i]` = 已经买了下标 `i` 的水果、并覆盖了 `[i..n-1]` 全部水果的最少金币数。

- `dp[n] = 0`：数组外的哨兵，表示「没有剩余水果要覆盖」。

**转移：**

```
dp[i] = prices[i] + min(dp[j])
        j ∈ [i+1, min(2i+2, n)]
```

- `prices[i]`：买 i 本身的花费。
- `min(dp[j])`：从下一个花钱买的水果 j 起的最优后续花费。

**答案：** `dp[0]`。第 0 个水果前面没有任何水果能免费送它，所以它**必然被买**，只能作为 DP 起点。

## 四、O(n²) 版本

```java
class Solution {
    public int minimumCoins(int[] prices) {
        int n = prices.length;
        int[] dp = new int[n + 1];       // dp[n] = 0
        for (int i = n - 1; i >= 0; i--) {
            int r = Math.min(2 * i + 2, n);  // 下一个要买的 j 的上界
            int best = Integer.MAX_VALUE;
            for (int j = i + 1; j <= r; j++) {
                best = Math.min(best, dp[j]);
            }
            dp[i] = prices[i] + best;
        }
        return dp[0];
    }
}
```

## 五、O(n) 单调队列版本

滑动窗口最小值：队头存**下标**，`dp` 值从队头到队尾**严格递增**，所以队头就是窗口内的 `min(dp)`。初始用一个哨兵下标 `n`（`dp[n] = 0`）当窗口元素。

```java
class Solution {
    public int minimumCoins(int[] prices) {
        int n = prices.length;
        int[] dp = new int[n + 1];
        Deque<Integer> dq = new ArrayDeque<>();
        dq.addLast(n);                       // 哨兵：dp[n] = 0
        for (int i = n - 1; i >= 0; i--) {
            int r = Math.min(2 * i + 2, n);  // 窗口右边界
            while (!dq.isEmpty() && dq.peekFirst() > r) {
                dq.pollFirst();              // 弹出滑出窗口的下标
            }
            int best = dp[dq.peekFirst()];   // 队头 = 窗口内 min(dp)
            dp[i] = prices[i] + best;
            while (!dq.isEmpty() && dp[dq.peekLast()] >= dp[i]) {
                dq.pollLast();               // 保持 dp 值严格递增
            }
            dq.addLast(i);                   // 当前下标作为未来窗口候选
        }
        return dp[0];
    }
}
```

**复杂度：** 时间 O(n)，空间 O(n)。

## 六、易错点

1. **窗口右端点是 `2i+2`，不是 `2i+1`**。免费区间是 `[i+1, 2i+1]`，但下一个能买的水果还包括免费区后第一个 `2i+2`。漏掉它会在「买 i 后直接跳买右边水果」的场景出错（示例 2 `[1,10,1,1]`：买第 1 个水果后**直接买第 3 个**，正是跳过免费区里的第 2 个）。
2. **免费区间端点按 0 下标算**，别把题面的 1 下标公式硬套。
3. **单调队列存下标、按 dp 值单调**，不是存 dp 值本身。

## 七、通俗理解

> 去水果店，老板说「你花 x 块买第 i 个水果，我免费送你**之后挨着的 i+1 个**水果」。你想拿全所有水果、又花最少钱。
> 说白了：你总在「下一个必须花钱的水果」处做决策——它要么落在刚被免费送的那批里（你再花钱买它，为了再薅一次奖励），要么就是免费区外第一个。所以每次决策的候选窗口就是 `[i+1, 2i+2]`，取后续花费最小的那个，从后往前一路推。
