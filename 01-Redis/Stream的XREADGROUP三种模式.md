## XREADGROUP 的三种读取模式

```
XREADGROUP GROUP <组名> <消费者名> [COUNT n] [BLOCK ms] STREAMS <stream> <模式>
```

最后一个参数决定了消费者读取哪些消息，行为完全不同：

### `>` — 读新消息（日常消费）

```bash
XREADGROUP GROUP mygroup consumer1 STREAMS mystream >
```

- **含义：** 只读取该消费者组中**从未被任何消费者处理过**的消息
- **使用场景：** 每个消费者启动后，不停地用 `>` 拉取新任务
- **通俗理解：** "给我分配新任务"

### `0` — 读 pending 消息（重启恢复）

```bash
XREADGROUP GROUP mygroup consumer1 STREAMS mystream 0
```

- **含义：** 只读取**已经投递给当前消费者、但还没回复 ACK**的消息（即 pending list）
- **使用场景：** 消费者挂了重启，把之前领了但没干完的任务重新拉回来
- **通俗理解：** "看看我还有哪些没干完的活"

### `$` — 读之后的消息（从最新开始）

```bash
XREADGROUP GROUP mygroup consumer1 STREAMS mystream $
```

- **含义：** 只读取执行这条命令**之后才到达**的新消息，历史消息一概不看
- **使用场景：** 新消费者加入，不想处理旧数据，只从当前开始消费
- **通俗理解：** "以前的活我不管，以后的新活给我"

---

### 核心区别速览

| 模式 | 读什么 | 什么时候用 |
|------|--------|-----------|
| **`>`** | 未被任何消费者处理过的消息 | 日常消费，拉新任务 |
| **`0`** | 已投递给自己但未 ACK 的消息 | 崩了重启，把未完成的任务捡回来 |
| **`$`** | 命令执行之后才来的消息 | 新消费者加入，不回溯历史 |

### 为什么面试官爱问这个？

这三个模式正好对应消息队列的三个核心问题：

1. **正常消费怎么读？** → `>`
2. **挂了重启怎么恢复？** → `0`（配合 pending list + ACK）
3. **新来的消费者要不要处理历史数据？** → `$`（不要）或从头 `>`（要）
