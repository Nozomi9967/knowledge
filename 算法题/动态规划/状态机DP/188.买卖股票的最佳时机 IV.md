### **LeetCode 188 是股票系列的「完全体」：在状态机上再加一维交易次数，`hold[j]` / `free[j]` 表示「已经用了 j 次交易额度」时的最大利润。有一个必做的优化——当 `k >= n/2` 时退化成无限次交易（122 题），否则 k 很大时 O(nk) 会超时。**

### **一、问题本身**

最多允许 `k` 次交易（一次交易 = 一次买入 + 一次卖出，先买后卖），求最大利润。

```
prices = [3,2,6,5,0,3], k = 2
买2卖6（+4）→ 买0卖3（+3）  →  7
```

---

### **二、状态定义**

```
hold[j]：当前持有股票，且已经用掉 j 次交易额度（第 j 次买入已完成）
free[j]：当前不持有，且已经完成 j 次完整交易
j ∈ [0, k]
```

**"用掉几次额度"的口径要统一**：本解法里**买入就算用掉一次**，卖出只把状态从 hold 转回 free 并把利润结算。这样 j 的含义明确、转移不重不漏。

初始状态：

```
hold[j] = -infinity   （j ≥ 0，一开始不可能持有）
free[j] = 0           （一次都没做，利润 0）
hold[0] 需要特殊处理：第 0 次买入就是第一次买入，所以 hold[1] = -prices[0]
```

更简单的做法是把 `hold[0]` 也设成 `-infinity`，买入时从 `free[j-1]` 转移，即"用掉第 j 次额度"。

---

### **三、转移方程**

对每一天的股价 `p`：

```java
for (int j = k; j >= 1; j--) {
    // 持有：继续持有，或从"已完成 j-1 次交易"的状态买入（用掉第 j 次额度）
    hold[j] = Math.max(hold[j], free[j - 1] - p);
    // 空仓：继续空仓，或从持有状态卖出（完成第 j 次交易）
    free[j] = Math.max(free[j], hold[j] + p);
}
```

**两个关键点**：

1. **`j` 必须倒序**。因为 `hold[j]` 依赖 `free[j-1]`，如果正序，`free[j-1]` 会被本轮（同一天）刚更新的值污染，等于在同一天既买又卖。
2. **先更新 `hold[j]` 再更新 `free[j]`**。`free[j]` 依赖当前的 `hold[j]`（今天买入后立刻卖出？不需要，因为同一天买卖利润为 0，无害但也没意义）。写成先 hold 后 free 是标准顺序。

---

### **四、必做优化：k 很大时退化**

一次完整交易至少要 2 天，所以**最多只能做 `n/2` 次交易**。当 `k >= n/2` 时，"最多 k 次"这个约束就失效了，等价于无限次交易：

```java
if (k >= n / 2) return maxProfitInfinity(prices);
```

不写这个优化的话，`k = 1000000000` 的用例会直接超时/超内存。**这是 188 最经典的坑，面试必问。**

无限次交易的实现（122 题）：

```java
private int maxProfitInfinity(int[] prices) {
    int hold = -prices[0], free = 0;
    for (int i = 1; i < prices.length; i++) {
        int nh = Math.max(hold, free - prices[i]);
        int nf = Math.max(free, hold + prices[i]);
        hold = nh; free = nf;
    }
    return free;
}
```

### **五、完整代码**

```java
class Solution {
    public int maxProfit(int k, int[] prices) {
        int n = prices.length;
        if (n < 2 || k == 0) return 0;

        // 优化：k 超过最大可能交易次数，退化为无限次
        if (k >= n / 2) return maxProfitInfinity(prices);

        final int NEG = Integer.MIN_VALUE / 2;   // 防加法下溢
        int[] hold = new int[k + 1];
        int[] free = new int[k + 1];
        Arrays.fill(hold, NEG);

        for (int p : prices) {
            for (int j = k; j >= 1; j--) {
                hold[j] = Math.max(hold[j], free[j - 1] - p);
                free[j] = Math.max(free[j], hold[j] + p);
            }
        }

        int ans = 0;
        for (int j = 0; j <= k; j++) ans = Math.max(ans, free[j]);
        return ans;
    }

    private int maxProfitInfinity(int[] prices) {
        int hold = -prices[0], free = 0;
        for (int i = 1; i < prices.length; i++) {
            int nh = Math.max(hold, free - prices[i]);
            int nf = Math.max(free, hold + prices[i]);
            hold = nh; free = nf;
        }
        return free;
    }
}
```

**为什么答案要遍历 `free[0..k]` 取 max**：因为"最多 k 次"不要求用满，可能用 3 次比用 5 次赚得多。如果题目是"恰好 k 次"才需要取 `free[k]`。

| 项 | 复杂度 |
|---|---|
| 时间 | O(n·k)，k ≥ n/2 时降到 O(n) |
| 空间 | O(k) |

---

### **七、易错点**

1. **不判断 `k >= n/2`**：k 很大时超时，这是本题最大的坑
2. **j 正序遍历**：同一天反复买卖，结果虚高
3. **`NEG` 用 `Integer.MIN_VALUE`**：`NEG - p` 下溢成正数
4. **返回 `free[k]`**：错，要取 `max(free[0..k])`
5. **初始状态设错**：`hold[j] = -prices[0]` 只对 `j=1` 成立，其余应该是负无穷
6. **k=0 或 n<2**：直接返回 0，不然数组下标会出问题
