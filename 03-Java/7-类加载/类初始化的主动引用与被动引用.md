# 类初始化的主动引用与被动引用

## 核心问题

Java 类加载过程的**初始化（Initialization）阶段**，JVM 只会初始化那些**真正需要被初始化**的类。哪些操作会触发初始化？哪些看似触发了、实际不会？这就是"主动引用 vs 被动引用"要回答的问题。

> JVM 规范规定：只有当类被**主动引用**时，才会触发其初始化阶段（执行 `<clinit>()` 方法）。

---

## 五种主动引用（触发初始化）

以下 5 种情况属于主动引用，JVM **必须**对类进行初始化：

### 1. `new` 关键字创建对象

```java
// 触发 B 的类初始化（执行 <clinit>）
B b = new B();
```

对应字节码指令：`new`。JVM 执行 `new` 指令时，如果类还没初始化，先触发初始化再分配对象。

> 同样：`newarray` 创建数组不会触发类初始化（数组由 JVM 特殊处理）。

### 2. 访问类的静态字段（非编译期常量）

```java
class Foo {
    static int x = 5;        // 非常量 → 触发初始化
    static final int Y = 10; // 编译期常量 → 不触发初始化！
}
```

重点区分：
- `Foo.x` → 非常量静态字段 → **触发** `Foo` 初始化
- `Foo.Y` → 编译期可确定的 `static final` → **不触发** `Foo` 初始化（因为值已在常量池中，无需加载类就能拿到）

### 3. 调用类的静态方法

```java
Foo.someStaticMethod(); // 触发 Foo 初始化
```

### 4. 反射调用

```java
Class.forName("com.example.Foo");      // 触发 Foo 初始化
Class.forName("com.example.Foo", true, classLoader); // 第二个参数 true 表示初始化
```

> `Class.forName("...", false, classLoader)` 第二个参数传 `false` **不会**触发初始化，只做加载和链接。

### 5. 子类初始化触发父类

当初始化一个子类时，如果父类还没初始化，必须先初始化父类。

```java
class Parent {
    static { System.out.println("Parent init"); }
}
class Child extends Parent {
    static { System.out.println("Child init"); }
}

// 访问 Child 的静态字段
Child.x = 1;
// 输出顺序：Parent init → Child init
```

> 这条**不反向生效**：访问父类的静态字段不会触发子类的初始化（见下面的被动引用示例）。

> 另外：`interface` 的初始化规则不同——子接口初始化**不要求**父接口初始化，除非子接口用到了父接口的字段。

## 被动引用（不触发初始化）

以下 6 种场景是面试高频坑，看起来像主动引用，但实际上是**被动引用**，不会触发初始化：

### 1. 通过子类引用父类的静态字段

```java
class Parent {
    static int x = 1;
    static { System.out.println("Parent init"); }
}
class Child extends Parent {
    static { System.out.println("Child init"); }
}

// 访问：
System.out.println(Child.x);
// 输出：Parent init（仅父类初始化，子类未初始化！）
```

**原因**：`x` 是父类的静态字段，JVM 只会初始化真正声明了这个字段的类，子类只是引用媒介。

### 2. 通过数组形式引用类

```java
Parent[] arr = new Parent[10];
// 不会触发 Parent 的初始化！输出：无
```

**原因**：`newarray` 指令触发的是 `[LParent;` 这个数组类的初始化，而不是 `Parent` 本身的初始化。

### 3. 访问编译期常量

```java
class Const {
    static final int VALUE = 123;
    static { System.out.println("Const init"); }
}

System.out.println(Const.VALUE);
// 输出 123，但不会输出 "Const init"
```

**原因**：编译期常量在编译时就被**常量传播优化**，直接内联到调用方的常量池中，不需要加载 `Const` 类。

### 4. 通过 `ClassLoader.loadClass()` 加载

```java
ClassLoader cl = ...;
Class<?> clazz = cl.loadClass("com.example.Foo");
// 不会触发初始化！只做了加载+链接
```

和反射 `Class.forName()` 的区别就在这——`loadClass()` 不做初始化。

### 5. `static final` 的包装类型常量

```java
static final Integer N = 100;
```

编译期常量仅限于**基本类型**和 `String` 字面量。包装类型（`Integer`、`Long` 等）的 `static final` 虽然值看似固定，但 JVM 不将其视为编译期常量，访问时**会**触发初始化。这点容易被忽略。

### 6. 接口初始化 ≠ 类初始化

```java
interface A {
    int x = 1;  // interface 的字段默认是 static final
    // Thread t = ...;  // 不会导致 A 被初始化
}
interface B extends A { }

// 访问 B.x → 不会初始化 B，但会初始化 A（如果 B 没有声明 x）
// 和类的"子类引用父类静态字段"行为类似，但接口的"先初始化父接口"规则不同
```

> 接口初始化细则是：一个接口初始化时，**不要求**其父接口也初始化，除非子接口用到了父接口的字段。

## 快速判断表

| 操作 | 是否触发类初始化 | 原因 |
|------|:---:|------|
| `new Foo()` | ✅ | 主动引用#1 |
| `Foo.staticField` | ✅（非编译期常量） | 主动引用#2 |
| `Foo.STATIC_FINAL = 123` | ❌ | 编译期常量，内联优化 |
| `Foo.staticMethod()` | ✅ | 主动引用#3 |
| `Class.forName("Foo")` | ✅ | 主动引用#4 |
| `cl.loadClass("Foo")` | ❌ | 只加载链接，不初始化 |
| `Child.staticFieldOfParent` | ❌ | 父类字段，子类不初始化 |
| `new Foo[10]` | ❌ | 数组类，非原始类 |
| `子类初始化` | ✅ 父类也会初始化 | 主动引用#5：父子连锁 |

## 面试话术

> **问：类初始化的主动引用有哪些触发时机？**
>
> 答：根据 JVM 规范，有 5 种主动引用会触发类初始化：第一，通过 `new` 创建对象；第二，访问类的静态字段（但编译期常量不算）；第三，调用静态方法；第四，通过反射 `Class.forName()`（注意 `loadClass()` 不算）；第五，初始化子类时如果父类未初始化会先触发父类初始化。
>
> 面试常考的被动引用坑点：通过子类引用父类的静态字段不会触发子类初始化；创建对象数组不会触发该类的初始化；访问 `static final` 的编译期常量也不会触发。

## 补充：常量折叠（constant folding）与"改常量不重编"的坑

编译期常量的"内联"在编译器术语里叫 **常量折叠（constant folding）**——编译器在**编译期**就把 `static final` 基本类型 / `String` 字面量的值算出来、直接嵌进调用方的常量池（字节码里直接是 `ldc` 那个字面量），运行时的字节码里**根本看不到对被引用类的读取指令**。

这带来一个真实的坑：

```java
// A.java
public class A {
    public static final int VERSION = 1;
}

// B.java（另一个类 / 模块）
System.out.println(A.VERSION);   // 编译成 ldc 1，而不是 getstatic A.VERSION
```

如果只把 `A.VERSION` 改成 `2`、**重新编译 A 但不重新编译 B**，B 的字节码里仍然是内联的旧值 `1`——A 改了，B 打印出来却还是 1。这就是"**改常量不重编 → 旧值残留**"，也是全量重编与增量编译行为不一致的常见来源。

> 这条只对**编译期常量**成立：`static final` 基本类型 / `String` 字面量会被常量折叠；`static final Integer`（包装类型）、以及值由方法调用 / 运行时计算得出的 `static final`，**都不是**编译期常量，不会折叠，改了就即时生效。实际意义：**版本号 / 配置不要用 `static final` 常量**，真正需要热更的值应走运行时加载（配置文件、配置中心），否则改了不重编调用方就会踩旧值。

## 面试问答

### Q1：什么是主动引用和被动引用？区分的意义是什么？

A：根据 JVM 规范，只有当类被**主动引用**时，才会触发初始化阶段（执行 `<clinit>()` 方法）。区分的意义在于——类的初始化是有成本的（执行 static 块、给静态变量赋值），JVM 通过区分主动和被动引用，做到"用到了才初始化"，避免不必要的开销。

### Q2：五种主动引用分别是什么？

A：五种情况：
1. `new` 关键字创建对象；
2. 访问类的静态字段，但**非编译期常量**；
3. 调用类的静态方法；
4. 通过反射 `Class.forName("xxx")`；
5. 初始化子类时，如果父类未初始化，先触发父类初始化。

### Q3：`Class.forName()` 和 `ClassLoader.loadClass()` 有什么区别？

A：`Class.forName("xxx", true, cl)` 第二个参数传 `true` 会触发初始化；`Class.forName("xxx")` 默认也会初始化。而 `ClassLoader.loadClass("xxx")` **只做加载和链接，不做初始化**。JDBC 驱动的经典用法就是利用 `Class.forName(driverClass)` 来触发驱动类的初始化，从而执行其 static 块注册 Driver。

### Q4：什么是编译期常量？为什么访问它不会触发类初始化？

A：编译期常量是指用 `static final` 修饰的**基本类型或 String 字面量**，且值在编译时就能确定。Java 编译器会在编译阶段做**常量传播优化**，直接把常量值内联到调用方的常量池中。运行时 JVM 直接从调用方的常量池中读取内联值，根本不需要加载这个类。，所以不会触发初始化。

### Q5：为什么创建数组不会触发类初始化？

A：`new Parent[10]` 执行的是 `newarray` 字节码指令，JVM 会为数组创建一个**数组类**（如 `[LParent;`），触发的是这个数组类的初始化，而不是 `Parent` 类本身的初始化。数组类由 JVM 特殊处理，与原始类的初始化流程不同。

### Q6：通过子类引用父类的静态字段，会触发子类初始化吗？

A：**不会。** 只会触发声明这个字段的类（父类）的初始化，子类不会初始化。原因在于 JVM 只初始化真正声明了被访问字段的类，子类只是引用的媒介。

### Q7：`static final Integer N = 100` 会触发类初始化吗？

A：**会。** 编译期常量仅限于基本类型和 String 字面量。包装类型（Integer、Long 等）的 `static final` 虽然值固定，但 JVM 不将其视为编译期常量，所以访问时**会**触发类初始化。

### Q8：接口的初始化和类有什么不同？

A：接口的初始化规则和类有两处关键不同：第一，子接口初始化**不要求**父接口初始化，除非子接口用到了父接口的字段；第二，接口没有 `<clinit>()` 方法，只有静态字段的初始化和静态代码块（如果有）。
