# 825. 按位与结果非零的最长上升子序列

[LeetCode 825](https://leetcode.cn/problems/longest-strictly-increasing-subsequence-with-non-zero-bitwise-and/) 1846

## 题目描述

给定一个整数数组 `nums`，找到最长的子序列（不要求连续），满足：

1. **严格递增**
2. **子序列中所有元素的按位与结果非零**

返回该子序列的最大长度。

> [!abstract] 核心约束
> - 子序列严格递增（保持原顺序，值严格增大）
> - `AND(nums[i1], nums[i2], ..., nums[ik]) ≠ 0`
> - 等价于：**至少存在一个比特位，子序列中所有数在该位都是 1**

## 错误思路分析：DP 状态信息丢失

### 第一反应：在 LIS DP 基础上加 AND 状态

```
dp[i][0] = 以 nums[i] 结尾的最长合法子序列长度
dp[i][1] = 该子序列的 AND 值
```

转移条件：`nums[i] > nums[j]` 且 `(nums[i] & dp[j][1]) != 0`

### 失败案例追踪

`nums = [6, 38, 24, 32, 27, 40]`，预期输出 3（子序列 `[24, 27, 40]`）

**index=4（值 27）处：**

| 子序列 | 长度 | AND 值 |
|--------|------|--------|
| `[6, 27]` | 2 | 6 & 27 = **2** |
| `[24, 27]` | 2 | 24 & 27 = **24** |

两条等长子序列的 AND 值不同，但 DP 只保留一个。更新条件是 `dp[j][0]+1 > dp[i][0]`（严格大于），当 `dp[2][0]+1 = 2` 不大于 `dp[4][0] = 2` 时**不更新**，`dp[4][1]` 保持为 **2**。

**index=5（值 40）处：**

- 用 `dp[4][1] = 2` 判断：`40 & 2 = 0` → 无法延伸 ❌
- 若 `dp[4][1] = 24`：`40 & 24 = 8 ≠ 0` → 可以延伸到 `[24, 27, 40]`，长度 3 ✅

### 根本原因

> AND 运算**只减不增**——每加入一个数，AND 值的位数只会减少不会增加。
>
> 长度相同的两条子序列，AND 值不同意味着它们"能继续延伸的潜力"不同。**只存一个 AND 值会丢失关键信息。**

即使把更新条件改成 `>=`（允许等长时也更新），也只会**任意保留一个** AND 值，没有保证留下的是"最优"的那个——而且"最优"本身就难以定义，因为不同位对后续延伸的影响不同。

## 正确解法：枚举比特位 + LIS

### 核心思路

AND 结果非零 **等价于** 至少存在一个比特位，子序列中所有数在该位都是 1。

因此可以把原问题拆解为：

1. 枚举每一个比特位 `b`（0 到 30）
2. 筛选出 `nums` 中第 `b` 位为 1 的元素（保持原顺序）
3. 对筛选后的序列求 **最长严格递增子序列**（LIS）
4. 所有比特位的结果取最大值

**关键：** 固定比特位后，子序列中所有数在该位都是 1，所以它们的 AND 在该位也为 1，AND 结果必然非零。递增性由 LIS 保证。两个条件**完全解耦**，不再需要在 DP 中维护 AND 值。

### 复杂度分析

- 枚举 31 个比特位：`O(31)`
- 每次筛选 + LIS（二分法）：`O(n log n)`
- 总时间复杂度：`O(31 · n log n) = O(n log n · log V)`，其中 `V = 10^9`
- 空间复杂度：`O(n)`（筛选出的序列 + LIS 的 d 数组）

### LIS 二分法详细推导

#### 核心是维护 `d[]`：长度为 `k` 的递增子序列的「最小末尾值」

这段代码用的是 LIS 的经典 $O(n \log n)$ 写法（patience sorting 思想）。关键在于数组 `d`：`d[k]` 记录的是「所有长度为 `k` 的递增子序列中，末尾元素的最小值」。末尾越小，后面就越容易接上新元素，所以我们只关心每个长度的「最小末尾」。

## 为什么 `d[]` 一定是有序的

这是能用二分的前提。`d` 在整个过程中始终**严格递增**：如果出现 `d[i] >= d[i+1]`，那么长度为 `i+1` 的那个子序列去掉最后一个元素后，就得到一个长度为 `i`、末尾值 `<= d[i]` 的子序列，这与「`d[i]` 是长度 `i` 的最小末尾」矛盾。所以 `d[1] < d[2] < ... < d[len]` 恒成立，二分查找合法。

## 逐句拆解

```java
int l = 1, r = len, pos = 0;
```

在有序的 `d[1..len]` 里找**最大的** `pos`，满足 `d[pos] < num`。`pos = 0` 是哨兵初值，表示「`num` 比所有现有末尾都小，接不上任何序列」，这种情况 `num` 将去刷新长度 1 的末尾。

```java
while (l <= r) {
    int mid = (l + r) >> 1;
    if (d[mid] < num) {   // num 能合法接在长度 mid 的序列后面
        pos = mid;        // 记录这个可接长度，继续往右找更长的
        l = mid + 1;
    } else {
        r = mid - 1;     // mid 太大，往左缩
    }
}
```

这是在 `d[mid] < num` 时尽量往右走，等价于「二分求上界」——找最长的、能被 `num` 接续的子序列长度。注意是严格 `<`，对应严格递增的 LIS；若题目允许相等，改成 `<=` 即可。

```java
d[pos + 1] = num;
len = Math.max(len, pos + 1);
```

这里有两层含义：

- **合法性**：因为 `d[pos] < num`，把 `num` 接在长度 `pos` 的序列后面，得到长度 `pos+1` 的合法递增序列。
- **最优性（也是赋值安全的关键）**：由 `pos` 的最大性，必有 `d[pos+1] >= num`（否则 `pos` 还能更大）。所以用 `num` 替换 `d[pos+1]` 既让末尾变小、又不破坏 `d` 的严格递增。这正是「最小末尾」维护的核心。

## 用一个例子走一遍

输入 `[10, 9, 2, 5, 3, 7, 101, 18]`，答案应为 4（如 `2,3,7,101` 或 `2,3,7,18`）。

| num | 查找范围 `d[1..len]` | 二分找到的 pos | 更新后 `d`（下标从 1 起） | len |
|---|---|---|---|---|
| 10 | 空 | 0 | [_, 10] | 1 |
| 9 | [10]；10<9? 否 | 0 | [_, 9] | 1 |
| 2 | [9]；9<2? 否 | 0 | [_, 2] | 1 |
| 5 | [2]；2<5? 是 | 1 | [_, 2, 5] | 2 |
| 3 | [2,5]；2<3 是→pos1，5<3 否 | 1 | [_, 2, **3**] | 2 |
| 7 | [2,3]；都<7 | 2 | [_, 2, 3, 7] | 3 |
| 101 | [2,3,7]；都<101 | 3 | [_, 2, 3, 7, 101] | 4 |
| 18 | [2,3,7,101]；2,3,7<18 是，101<18 否 | 3 | [_, 2, 3, 7, **18**] | 4 |

几个值得注意的点：

- `num=3` 那步，`5` 被 `3` 替换掉——长度 2 的末尾从 5 变成 3，后面更容易接（`7`、`18` 才接得上来）。这体现了「最小末尾」的价值。
- `num=18` 时 `101` 被替换成 `18`，长度不变但末尾更优，为将来留余地。
- 每次只会把某个位置的末尾「变得更小」，`d` 始终有序，二分始终合法。

## 一句话总结逻辑

对每个 `num`，二分定位「能接在其后的最长前缀长度 `pos`」，再用 `num` 去优化 `d[pos+1]` 这个最小末尾；最终 `len` 即 LIS 长度。注意 `d[]` 里存的只是末尾值，并不直接等于某条真实存在的递增子序列，它只是用来贪心地维护「每个长度最优末尾」的工具数组。

### 参考实现

```java
class Solution {
    public int longestSubsequence(int[] nums) {
        int ans = 0;
        // 枚举每一个比特位
        for (int b = 0; b <= 30; b++) {
            int mask = 1 << b;
            // 筛选出第 b 位为 1 的元素
            List<Integer> list = new ArrayList<>();
            for (int num : nums) {
                if ((num & mask) != 0) list.add(num);
            }
            // 对筛选后的序列求 LIS
            ans = Math.max(ans, lengthOfLIS(list));
        }
        return ans;
    }

    // 经典 LIS 二分实现
    private int lengthOfLIS(List<Integer> nums) {
        if (nums.isEmpty()) return 0;
        int[] d = new int[nums.size() + 1];  // d[len] = 长度为 len 的 LIS 的最小末尾值
        int len = 0;
        for (int num : nums) {
            int l = 1, r = len, pos = 0;
            // 二分查找：找到最长的可以接在 num 后面的序列长度
            while (l <= r) {
                int mid = (l + r) >> 1;
                if (d[mid] < num) {
                    pos = mid;
                    l = mid + 1;
                } else {
                    r = mid - 1;
                }
            }
            d[pos + 1] = num;
            len = Math.max(len, pos + 1);
        }
        return len;
    }
}
```

## 面试话术

1. **识别陷阱**：题目看起来是在 LIS 基础上加约束，很容易想到在 DP 状态中加 AND 值。但 AND 只减不增，状态信息在等长子序列间会丢失。

2. **转换视角**：从"维护 AND 值"转为"固定比特位"，利用"AND 非零 ⇔ 至少一位全为 1"的等价关系，把耦合条件拆开。

3. **复杂度证明**：枚举 31 位，每位的 LIS 是 `O(n log n)`，总复杂度可接受。

4. **扩展思考**：如果要求 AND 值等于某个特定值（非零），枚举比特位的思路仍然可行，只需额外记录满足 AND 值的子序列。
