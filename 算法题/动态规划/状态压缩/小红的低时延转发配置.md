# 小红的低时延转发配置 —— 状压 DP 完整笔记

> [!info] **标签**：动态规划 · 状态压缩 · 区间覆盖 · 贪心反例
> **难度**：中等偏难
> **时间限制**：C/C++ 1 秒，其他语言 2 秒
> **空间限制**：C/C++ 256 MB，其他语言 512 MB

---

## 一、题目原文

### 题意描述

小红正在优化一条由 $N$ 个交换节点组成的数据通路，节点编号为 $0$ 到 $N-1$。数据包会依次经过所有节点，节点 $i$ 默认产生 $\mathit{delay}_i$ 单位时延。

如果在节点 $i$ 启用**优先转发**，它会影响节点 $i$ 本身以及后续至多 $\mathit{win}_i$ 个节点。  
每个受影响节点的时延都会减少 $\mathit{opt}_i$，但时延最低只能降到 $0$。  
如果一个节点同时受到多个已启用配置的影响，所有减少量会**累加**。

小红最多可以选择 $K$ 个节点启用优先转发。请计算整条通路能够达到的**最小总时延**。

### 输入描述

```
第一行输入两个整数 N, K。
第二行输入 N 个整数 delay_0, delay_1, ..., delay_{N-1}。
第三行输入 N 个整数 win_0,  win_1,  ..., win_{N-1}。
第四行输入 N 个整数 opt_0,  opt_1,  ..., opt_{N-1}。
```

### 数据范围

$$3 \le N \le 50, \quad 0 \le K \le 10$$
$$0 \le \mathit{delay}_i,\ \mathit{opt}_i \le 10^7, \quad 0 \le \mathit{win}_i \le 3$$

### 输出描述

输出一个整数，表示配置后的最小总时延。

### 示例

**输入：**

```
4 1
10 20 30 40
1 0 2 0
15 25 12 100
```

**输出：**

```
60
```

**说明：**  
在节点 3 启用优先转发后，该节点时延从 40 降为 0，总时延 = 10 + 20 + 30 + 0 = 60。

## 二、原始代码的 Bug 分析

### 2.1 原始代码（有 Bug 的版本）

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n=in.nextInt(),k=in.nextInt();
        int[] d=new int[n];
        int[] w=new int[n];
        int[] o=new int[n];
        int ans=0;
        for(int i=0;i<n;i++){
            d[i]=in.nextInt();
            ans+=d[i];
        }
        for(int i=0;i<n;i++) w[i]=in.nextInt();
        for(int i=0;i<n;i++) o[i]=in.nextInt();

        PriorityQueue<int[]> p=new PriorityQueue<>(
            (a,b)->{
                if(b[3]!=a[3]) return Integer.compare(b[3],a[3]);
                return Integer.compare(a[0],b[0]);
            }
        );
        for(int i=0;i<n;i++){
            int sum=Math.min(o[i],d[i]);
            for(int j=1;j<=w[i]&&(i+j)<n;j++){
                sum+=Math.min(o[i],d[i+j]);
            }
            p.offer(new int[]{i,w[i],o[i],sum});
        }
        for(int i=0;i<k&&!p.isEmpty();i++){      // ← i 是第几轮
            int[] cur=p.poll();
            ans-=cur[3];
            int m=cur[0];                         // ← m 才是选中的节点编号
            d[m]-=Math.min(d[m],cur[2]);
            // ❌ Bug: 下面用了 w[i]、o[i]、(i+j)，应该用 w[m]、o[m]、(m+j)
            for(int j=1;j<=w[i]&&(i+j)<n;j++){
                d[m+j]-=Math.min(o[i],d[m+j]);
            }
            // ... 重建堆（略）
        }
        System.out.print(ans);
    }
}
```

### 2.2 Bug 一：变量 `i` 与 `m` 用混（直接导致 RE）

| 外层循环变量 | 含义                                       |
| ------------ | ------------------------------------------ |
| `i`          | 第几轮选择（0, 1, 2, ...），与节点编号无关 |
| `m = cur[0]` | **本轮选中的节点编号**                     |

问题出在"对后续节点施加削减"的循环里：

```java
for(int j=1;j<=w[i]&&(i+j)<n;j++){   // ❌ 用了轮次 i
    d[m+j]-=Math.min(o[i],d[m+j]);   // ❌ 用了 o[i]（轮次索引）
}
```

**用样例走一遍：**  
第一轮 `i=0`，堆顶是节点 3（m=3，收益 40）。  
循环变成 `j<=w[0]=1 && (0+1)<4`，执行 `d[m+j] = d[3+1] = d[4]`。  
数组长度 4，`d[4]` 越界 → **ArrayIndexOutOfBoundsException**。  

**修法：把 `w[i]`、`o[i]`、`(i+j)` 全部换成 `cur[1]`、`cur[2]`、`(m+j)`：**

```java
int m=cur[0], win=cur[1], opt=cur[2];
d[m] -= Math.min(d[m], opt);
for(int j=1; j<=win && (m+j)<n; j++){
    d[m+j] -= Math.min(opt, d[m+j]);
}
```

### 2.3 Bug 二：贪心算法本身是错的（修完还是 WA）

贪心策略："每轮选当前削减量最大的配置"，但它有以下根本缺陷：

**时延有 0 下界，多配置覆盖时存在收益浪费。**  
"面广量小"的配置把多个节点各削去一点，看似收益高，实则把这些位置上"精准"配置的收益空间挤掉。

**反例：**

```
输入：
3 2
1 9 9
2 0 0
5 9 9
```

| 策略 | 第1轮选               | 第2轮选            | 总时延                                                       |
| ---- | --------------------- | ------------------ | ------------------------------------------------------------ |
| 贪心 | 节点0（收益=1+4+4=9） | 节点1或2（收益=4） | 1+0+0=... 实际计算：d→[0,4,4]，再选节点1削掉4 → d=[0,0,4] → **ans=4** |
| 最优 | 节点1（收益=9）       | 节点2（收益=9）    | 1+0+0 = **1**                                                |

贪心第一步抢了节点 0 的配置（表面收益最高），把节点 1、2 各削掉 5，导致后续 `opt=9` 的精准配置浪费了大量削减量（削到 0 以下的部分全部白白浪费）。  

**结论：** 这道题必须用动态规划，穷举所有启用组合后取最优。

## 三、正确解法：状压 DP

### 3.1 关键观察（为什么只需要 3 个 bit）

> **$\mathit{win}_i \le 3$** 是整个算法的核心约束。

节点 $j$ 的配置最远影响到节点 $j + \mathit{win}_j \le j + 3$。  
反推：当决策节点 $i$ 时，**还能影响节点 $i$（及之后）的已启用配置**，只可能挂在节点 $i-1$、$i-2$、$i-3$ 上。  

$$j \le i-4 \Rightarrow j + \mathit{win}_j \le (i-4)+3 = i-1 < i$$

即任何 $j \le i-4$ 的配置已经"射程耗尽"，对节点 $i$ 及之后没有影响。

所以只需用 **3 个 bit** 的滑动窗口记录最近 3 个节点是否启用，状态数 $2^3 = 8$。

### 3.2 状态定义

$$dp[\mathit{rem}][\mathit{mask}]$$

- $\mathit{rem}$：剩余可用的启用次数（$0 \le \mathit{rem} \le K$）
- $\mathit{mask}$：3 位二进制，记录"最近 3 个节点是否启用"

| bit 位 | 对应节点（相对当前节点 $i$） | 含义               |
| :----: | :--------------------------: | ------------------ |
| bit 0  |            $i-1$             | 上一个节点是否启用 |
| bit 1  |            $i-2$             | 前两个节点是否启用 |
| bit 2  |            $i-3$             | 前三个节点是否启用 |

**语义：** 节点 $0 \sim i-1$ 已全部决策完毕，还剩 $\mathit{rem}$ 次启用机会，最近 3 个节点的启用情况是 $\mathit{mask}$，此时已累计付出的**最小总时延**。

### 3.3 初始状态

$$dp[K][0] = 0$$

含义：决策节点 0 之前，所有 $K$ 次机会未用，前面没有任何节点（窗口全空），代价为 0。其余所有状态初始化为 $+\infty$（不可达）。

### 3.4 转移过程（决策节点 $i$）

#### Step 1：计算节点 $i$ 已"被动"获得的削减量 $r$

遍历窗口内的 3 个位置，查看哪些已启用的配置的射程覆盖了节点 $i$：

$$r = \sum_{\substack{b=0,1,2 \\ \text{mask 第 } b \text{ 位为 } 1 \\ j = i-1-b \ge 0 \\ j + \mathit{win}_j \ge i}} \mathit{opt}_j$$

- `(mask >> b) & 1 == 1`：节点 $j$ 确实启用了
- `j + w[j] >= i`：配置 $j$ 的射程覆盖节点 $i$

#### Step 2a：节点 $i$ **不启用**

$$\text{代价} = \max(0,\ \mathit{delay}_i - r)$$

$$\text{新 mask} = (\mathit{mask} \ll 1)\ \&\ 7 \quad \text{（窗口右移，bit 0 补 0）}$$

$$\mathit{ndp}[\mathit{rem}][\text{新 mask}] = \min\bigl(\mathit{ndp}[\mathit{rem}][\text{新 mask}],\ \mathit{dp}[\mathit{rem}][\mathit{mask}] + \text{代价}\bigr)$$

#### Step 2b：节点 $i$ **启用**（需 $\mathit{rem} > 0$）

$$\text{代价} = \max(0,\ \mathit{delay}_i - r - \mathit{opt}_i) \quad \text{（自身也受自己配置影响）}$$

$$\text{新 mask} = ((\mathit{mask} \ll 1)\ |\ 1)\ \&\ 7 \quad \text{（bit 0 置 1）}$$

$$\mathit{ndp}[\mathit{rem}-1][\text{新 mask}] = \min\bigl(\mathit{ndp}[\mathit{rem}-1][\text{新 mask}],\ \mathit{dp}[\mathit{rem}][\mathit{mask}] + \text{代价}\bigr)$$

> **设计亮点：** $\mathit{opt}_i$ 对后续节点 $i+1 \sim i+\mathit{win}_i$ 的影响**此刻完全不算**，只是把"节点 $i$ 启用了"记入 bit 0。等 DP 走到节点 $i+1$、$i+2$、$i+3$ 时，Step 1 的射程检查会自动把 $\mathit{opt}_i$ 加入它们的 $r$。这种**延迟结算**的设计彻底避免了原始贪心那套"修改 `d` 数组再重建堆"的复杂维护。

#### Step 3：汇总答案

$N$ 个节点全部决策完后：

$$\mathit{ans} = \min_{\mathit{rem} \in [0,K],\ \mathit{mask} \in [0,7]} dp[\mathit{rem}][\mathit{mask}]$$

$K$ 是上限而非配额，不一定要用完，所以 $\mathit{rem}$ 取任意值均合法。

### 3.5 mask 滑动的直觉图示

```
决策节点 i=5，旧 mask = 011（bit0=1:节点4启用, bit1=1:节点3启用, bit2=0:节点2未启用）

  节点: ... 2  3  4  [5] 6  7 ...
  mask:      0  1  1   ?

  站在 i=5 视角      → 站在 i=6 视角（滑动后）
  bit0 = 节点4      → bit1 = 节点4
  bit1 = 节点3      → bit2 = 节点3
  bit2 = 节点2      → 丢弃（节点2的配置射程最远到2+3=5，已结算完毕）
  新 bit0           → 节点5 是否启用（由本轮决策决定）

  不启用节点5时：新 mask = (011 << 1) & 111 = 110 & 111 = 110 = 6
  启用  节点5时：新 mask = (011 << 1 | 1) & 111 = 111 & 111 = 111 = 7
```

### 3.6 无后效性证明

不同历史路径可能坍缩到同一 `(rem, mask)`，直接取较小值是否会丢最优解？

**不会。** 站在节点 $i$ 面前，未来的决策只依赖两件事：

1. 接下来在哪些节点启用（未来的选择，与历史无关）
2. **仍在射程内**的已启用配置是哪些 → 完整记录在 `mask` 里

已滑出窗口的配置对节点 $i$ 及之后影响恒为 0。"过去"对"未来"的全部影响都浓缩在 `(rem, mask)` 里，满足 DP 的**无后效性**。加上每步取 min 保证的**最优子结构**，归纳可得每个 `dp` 值都是真正的最小累计时延。

| 维度       | 值                                                           |
| ---------- | ------------------------------------------------------------ |
| 状态数     | $N \times (K+1) \times 8 \le 50 \times 11 \times 8 = 4{,}400$ |
| 每状态转移 | $O(3)$（计算 $r$ 需遍历 3 个 bit）                           |
| 总操作量   | $\approx 13{,}200$ 次                                        |
| 空间       | $O((K+1) \times 8)$（滚动数组，只保留当前轮）                |

**远低于题目 1 秒限制。**

## 五、完整正确代码

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        int n = in.nextInt(), k = in.nextInt();
        int[] d = new int[n], w = new int[n], o = new int[n];
        for (int i = 0; i < n; i++) d[i] = in.nextInt();
        for (int i = 0; i < n; i++) w[i] = in.nextInt();
        for (int i = 0; i < n; i++) o[i] = in.nextInt();

        final long INF = Long.MAX_VALUE / 4;

        // dp[rem][mask]
        // rem:  剩余启用次数
        // mask: 最近 3 个节点的启用情况（bit0=前1个, bit1=前2个, bit2=前3个）
        long[][] dp = new long[k + 1][8];
        for (long[] row : dp) Arrays.fill(row, INF);
        dp[k][0] = 0;   // 起点：K次未用，窗口全空，代价0

        for (int i = 0; i < n; i++) {
            long[][] ndp = new long[k + 1][8];
            for (long[] row : ndp) Arrays.fill(row, INF);  // 每轮必须重置！

            // rem 的下界剪枝：已决策 i 个节点，最多用掉 i 次机会 → rem ≥ k − i（i ≥ k 时下界为 0）
            // 注意是【下界】——rem 是“剩余”次数，随启用递减，可达区间是 [max(0, k−i), k]，上界恒为 k
            for (int rem = Math.max(0, k - i); rem <= k; rem++) {
                for (int mask = 0; mask < 8; mask++) {
                    long cur = dp[rem][mask];
                    if (cur == INF) continue;   // 不可达状态，跳过

                    // Step 1: 计算节点 i 已被动获得的削减量 r
                    long r = 0;
                    for (int b = 0; b < 3; b++) {
                        if ((mask & (1 << b)) == 0) continue;  // 该位未启用
                        int j = i - 1 - b;                     // 还原节点编号
                        if (j >= 0 && j + w[j] >= i) r += o[j]; // 射程检查
                    }

                    // Step 2a: 节点 i 不启用
                    int m0 = (mask << 1) & 7;                  // 窗口右移，bit0=0
                    long c0 = cur + Math.max(0, d[i] - r);
                    if (c0 < ndp[rem][m0]) ndp[rem][m0] = c0;

                    // Step 2b: 节点 i 启用（消耗 1 次机会）
                    if (rem > 0) {
                        int m1 = ((mask << 1) | 1) & 7;        // 窗口右移，bit0=1
                        long c1 = cur + Math.max(0, d[i] - r - o[i]);
                        if (c1 < ndp[rem - 1][m1]) ndp[rem - 1][m1] = c1;
                    }
                }
            }
            dp = ndp;   // 滚动到下一阶段
        }

        // Step 3: 汇总答案（rem 不要求用完）
        long ans = INF;
        for (int rem = 0; rem <= k; rem++)
            for (int mask = 0; mask < 8; mask++)
                ans = Math.min(ans, dp[rem][mask]);

        System.out.println(ans);
    }
}
```

## 六、手动验证（贪心反例）

**输入：**

```
3 2
1 9 9
2 0 0
5 9 9
```

### 6.1 贪心的错误过程

初始收益：

- 节点0：`min(5,1)+min(5,9)+min(5,9) = 1+5+5 = 11`（覆盖0,1,2）
- 节点1：`min(9,9) = 9`（只覆盖1）
- 节点2：`min(9,9) = 9`（只覆盖2）

**第1轮：** 选节点0（收益最大=11），`d → [0, 4, 4]`  
**第2轮：** 节点1收益=4，节点2收益=4（各取一个）→ `d → [0, 0, 4]`  
**贪心答案：** 0+0+4 = **4**（错误）

### 6.2 DP 的正确过程

初始 `dp[2][000] = 0`，逐节点转移（简化展示关键状态）：

| 阶段                              | 关键状态                                                     | 含义                    |
| --------------------------------- | ------------------------------------------------------------ | ----------------------- |
| 初始                              | `dp[2][000] = 0`                                             | 未决策任何节点          |
| 决策节点0，不启用                 | `dp[2][000] += 1` → 1                                        | 节点0代价=1             |
| 决策节点0，启用                   | `dp[1][001] += max(0,1-5)=0` → 0                             | 节点0代价=0（自身被削） |
| 决策节点1，由`dp[1][001]`，启用   | r=5（节点0射程覆盖），代价=max(0,9-5-9)=0 → `dp[0][011]=0`   | 节点1代价=0             |
| 决策节点2，由`dp[0][011]`，不启用 | r=5（节点0仍覆盖），代价=max(0,9-5)=4 → `dp[0][110]=4`       |                         |
| 决策节点1，由`dp[2][000]`，启用   | r=0，代价=max(0,9-9)=0 → `dp[1][001]=1`                      |                         |
| 决策节点2，由`dp[1][001]`，启用   | r=0（节点0 win=2但j=0，0+2>=2✓，但mask中bit1=1对应节点0，此时r=o[0]=5）... 注意此路中节点0**未启用**，故r=0，代价=max(0,9-0-9)=0 → `dp[0][011]=1` |                         |

**最终答案：** 所有 `dp` 中取最小 = **1**（节点1、节点2均启用，节点0不启用）✓

## 七、常见坑点总结

| 坑点             | 说明                               | 解决方案                     |
| ---------------- | ---------------------------------- | ---------------------------- |
| `i` 与 `m` 混用  | 外层轮次变量 `i` 不是节点编号      | 用 `cur[0]`（`m`）作节点索引 |
| 贪心失效         | 时延有 0 下界，覆盖重叠时产生浪费  | 状压 DP 枚举所有组合         |
| `ndp` 忘记重置   | 上一阶段残留值污染本阶段           | 每轮 `Arrays.fill(row, INF)` |
| `INF` 溢出       | `INF + delay` 变成负数被误选       | 取 `Long.MAX_VALUE / 4`      |
| 射程检查缺失     | 窗口内的启用节点不一定覆盖当前节点 | `j + w[j] >= i` 判断         |
| 边界检查缺失     | $i < 3$ 时窗口内有"不存在的节点"   | `j >= 0` 判断                |
| $K$ 是上限非配额 | 不一定非要用完 $K$ 次              | 答案取所有 `rem` 的最小值    |

## 八、算法思路对比

```
贪心（错误）                    状压DP（正确）
────────────────────            ──────────────────────────────
每轮计算各配置当前收益           枚举所有 (rem, mask) 状态
选收益最大的配置启用             对每个节点做"启用/不启用"两种决策
修改 d[] 数组                   延迟结算：启用事实存入 mask
重建整个优先队列                 按射程检查自动累加 r
                               无需修改原数组
时间复杂度：O(K·N·logN)         时间复杂度：O(N·K·8·3) ≈ 13200次
（修好Bug后）正确性：❌          正确性：✅
```
