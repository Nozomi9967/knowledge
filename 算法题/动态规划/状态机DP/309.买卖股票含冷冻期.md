### **LeetCode 309「买卖股票含冷冻期」是股票系列里唯一需要三个状态的：持有、不持有且可买、冷冻中。多出来的"冷冻"状态是因为卖出后必须隔一天才能再买，用两个状态没法表达"刚卖完"这个中间态。**

### **一、问题本身**

可以无限次交易，但**卖出股票后第二天不能买入**（冷冻一天），求最大利润。

```
prices = [1,2,3,0,2]
买1卖2（利润1）→ 冷冻 → 买0卖2（利润2）  →  3
```

---

### **二、股票系列的统一模型**

先把股票系列的通用状态机说清楚，后面几题都是它的变体：

```
状态：持有（hold） / 不持有（free）
转移：
  hold[i] = max(hold[i-1],  free[i-1] - price[i])   // 继续持有 或 今天买入
  free[i] = max(free[i-1],  hold[i-1] + price[i])   // 继续空仓 或 今天卖出
```

- 121（只能交易一次）：`hold` 的买入项要改成 `-price[i]`（不能累加前面利润）
- 122（无限次）：就是上面的标准式
- 714（含手续费）：卖出时多减一个 `fee`
- 188（限 k 次）：状态里加一维交易次数
- 309（含冷冻期）：**卖出后不能立刻买**，所以要多一个状态

---

### **三、三状态定义（本题核心）**

```
hold[i]  ：第 i 天结束时持有股票的最大利润
free[i]  ：第 i 天结束时不持有、且明天可以买的最大利润
cool[i]  ：第 i 天结束时处于冷冻期（今天刚卖）的最大利润
```

**为什么要单独拆出 cool**：因为"不持有"分两种情况——一种是早就卖了、现在能买；另一种是今天刚卖、明天不能买。如果合并成一个状态，转移时就没法区分"能不能立刻买"。

**转移**：

```
hold[i] = max(hold[i-1],  free[i-1] - prices[i],  cool[i-1] - prices[i])
          ↑继续持有        ↑从可买状态买入          ↑从冷冻状态买入？
```

注意第三项：**冷冻期能不能买入？** 严格按题意"卖出后第二天不能买"，如果 `cool[i-1]` 表示"第 i-1 天刚卖"，那么第 i 天就还在冷冻中，**不能买**。所以第三项不该有。

正确写法是把状态定义得更精确：

```
// 第 i 天结束时：
hold[i] = max(hold[i-1], free[i-1] - prices[i])
         // 买入只能从"非冷冻"的前一天来；这里 free[i-1] 定义成"可买"
free[i] = max(free[i-1], cool[i-1])   // 冷冻期过完自动变可买
cool[i] = hold[i-1] + prices[i]       // 今天卖出，进入冷冻
```

### **四、代码**

```java
class Solution {
    public int maxProfit(int[] prices) {
        int n = prices.length;
        if (n < 2) return 0;

        int hold = -prices[0];   // 第 0 天买入
        int free = 0;            // 什么都没做
        int cool = Integer.MIN_VALUE / 2;   // 第 0 天不可能处于冷冻期

        for (int i = 1; i < n; i++) {
            int newHold = Math.max(hold, free - prices[i]);
            int newFree = Math.max(free, cool);
            int newCool = hold + prices[i];
            hold = newHold;
            free = newFree;
            cool = newCool;
        }
        // 最后一天不持有（含冷冻）才是最大利润
        return Math.max(free, cool);
    }
}
```

**几个细节**：

- `cool` 初始化用 `Integer.MIN_VALUE / 2` 而不是 `MIN_VALUE`：后面要做 `+ prices[i]`，用 `MIN_VALUE` 会下溢变成正数，`/2` 是留出加法空间
- 返回 `max(free, cool)`：最后一天如果是刚卖出（cool），利润也算数，不能只看 free
- 三状态可以不用数组，三个变量滚动即可

### **五、另一种写法：用 i-2 表达冷冻**

还有一种更省状态的写法——只用两个状态，但买入时从 `i-2` 的 free 状态转移：

```java
int n = prices.length;
int[][] dp = new int[n][2];
dp[0][0] = -prices[0];   // 持有
dp[0][1] = 0;            // 不持有
for (int i = 1; i < n; i++) {
    dp[i][0] = Math.max(dp[i-1][0], (i >= 2 ? dp[i-2][1] : 0) - prices[i]);
    dp[i][1] = Math.max(dp[i-1][1], dp[i-1][0] + prices[i]);
}
return dp[n-1][1];
```

逻辑是"今天买入，必须从两天前的空仓状态来"（隔一天）。这种写法更短，但**语义不如三状态直观**，面试时容易被追问"为什么是 i-2"，所以建议先讲三状态、再提这个优化。

### **六、复杂度与易错点**

| 项 | 复杂度 |
|---|---|
| 时间 | O(n) |
| 空间 | O(1)（三变量滚动） |

**易错点**：

1. **少一个状态**：只写 hold/free 两态，冷冻期无法表达，答案偏大
2. **从 cool 状态买入**：题面是"卖出后第二天不能买"，所以买入只能来自 free
3. **`cool` 用 MIN_VALUE 初始化**：加法下溢，结果变成大正数
4. **返回值只取 free**：最后一天刚卖的情况漏掉
5. **n=1**：直接返回 0（不能买也不能卖）
