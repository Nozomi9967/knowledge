# Java 内部类

> 内部类（Inner Class）是定义在另一个类**内部**的类。笔试选择题最爱考的是**四种内部类的区别**，尤其是两个经典坑：① 内部类到底能不能访问外部类的**私有**成员；② 局部内部类能访问方法里的**哪些**局部变量。附带一个被题目表述坑到的点——匿名内部类"**只能使用一次**"到底错在哪。

---

## 一、四种内部类总览

| 类型 | 定义位置 | 是否持有外部类实例引用 | 能否 `static` | 典型特点 |
|------|---------|:---:|:---:|---------|
| **成员内部类**（非静态内部类） | 类中，方法外 | ✅ 持有（`this$0`） | ❌ | 必须先有外部类实例才能创建 |
| **静态内部类** | 类中，方法外，加了 `static` | ❌ 不持有 | ✅ | 可**不依赖外部类实例**直接创建 |
| **局部内部类** | 方法 / 代码块中 | ✅（若在实例方法中） | ❌ | 作用域仅限该代码块；能访问 **effectively final** 的局部变量 |
| **匿名内部类** | 使用处 `new 父类/接口(){...}` | 视上下文而定 | ❌ | **没有类名**，只能在声明处实例化 |

---

## 二、逐个说清楚

### 2.1 成员内部类（非静态内部类）

```java
public class Outer {
    private int x = 10;

    class Inner {              // 成员内部类
        void show() {
            System.out.println(x);   // 直接访问外部类的私有字段
        }
    }
}
```

**创建方式——必须先有外部类实例：**

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();   // 注意这个 outer.new 语法
```

**根因：** 编译器给非静态内部类偷偷加了一个 `this$0` 字段，指向外部类实例，所以它"绑"在一个外部对象上。详见 [[Java基础面试题#非静态内部类可以直接访问外部方法，编译器是怎么做到的？]]。

由于持有外部实例引用，**成员内部类不能声明静态成员**（JDK 16 起放宽，已允许——JEP 395）。

### 2.2 静态内部类

```java
public class Outer {
    private static int count = 0;

    static class Inner {       // 静态内部类
        void show() { System.out.println(count); }
    }
}

// 创建：不需要外部类实例
Outer.Inner inner = new Outer.Inner();
```

**只要一个根因**：静态内部类**不持有**外部类实例引用（没有 `this$0`），所以可以脱离外部类对象独立创建，也不会因为外部类实例存在而"意外"阻止外部类被回收。

### 2.3 局部内部类

定义在**方法体内**，作用域只在该方法内：

```java
public void method() {
    int a = 1;              // effectively final
    int b = 2;
    b = 3;                  // ❌ b 不再是 effectively final

    class Local {           // 局部内部类
        void show() {
            System.out.println(a);   // ✅ 可以访问 a
            // System.out.println(b); // ❌ 编译错误：b 不是 effectively final
        }
    }
    new Local().show();
}
```

> ⚠️ **经典坑：局部内部类只能访问所在方法中「`final` 或被事实最终（effectively final）」的局部变量，而不是"所有"局部变量。** Java 8 起放宽到 effectively final（赋值后不再修改即可），但不满足条件的变量会导致**编译错误**。原因：局部变量随方法栈帧消失，编译器只能把它的**值拷贝**进内部类当字段，拷贝一份就要求这个值之后不能再变。

### 2.4 匿名内部类

没有类名，**在使用处通过 `new 接口/父类(){...}` 一次性定义并实例化**：

```java
Runnable r = new Runnable() {
    @Override
    public void run() {
        System.out.println("running");
    }
};
```

它是局部内部类的一种"无名字"形式，同样只能访问 effectively final 的局部变量。

## 三、被坑过的那道题：「匿名内部类只能使用一次」到底错在哪

题目把"C. 匿名内部类没有类名，只能使用一次"判为**正确**，但严格说这个表述**不准确**——这也是很多人看它别扭的地方：

> **"只能使用一次"容易让人误解成「这个对象只能被使用一次」；准确的说法是「只能在声明处创建一次实例」。**

拆开看：

- ❌ **错的理解**：`r.run()` 只能调一次？——当然不是，`r` 可以任意多次调用。
  ```java
  Runnable r = new Runnable() { public void run() { ... } };
  r.run();   // ✅
  r.run();   // ✅ 想调几次调几次
  ```
- ✅ **准确的理解**：匿名内部类**没有类名**，所以**无法用类名再 `new` 出第二个实例**；它只在 `new ...(){...}` 那一处被**实例化一次**。想再要一个同类对象，只能把那段 `new ...(){...}` 再抄一遍。

所以更严谨的表述是：**"匿名内部类没有类名，只能在声明处实例化一次（无法用类名二次创建）"**，而不是"只能使用一次"。

> 📌 考试里遇到"只能使用一次"，选标准答案即可（它想表达的是"声明处只能 `new` 一次"）；但你保留这个精确性判断是对的。

## 四、内部类访问外部类成员：一个高频易错点

**内部类可以访问外部类的所有成员，包括 `private` 成员。**

```java
public class Outer {
    private int secret = 42;

    class Inner {
        void leak() {
            System.out.println(secret);   // ✅ 私有成员也能访问
        }
    }
}
```

**为什么能访问私有成员？** 因为编译后，外部类和内部类其实被编译成**两个独立的 `.class` 文件**（`Outer.class`、`Outer$Inner.class`），本质上已不是"同一个类"。编译器为了打通这个墙，会生成 `package-private` 的合成访问方法（`access$000` 之类），供内部类调用外部类的私有成员。所以"内部类能访问私有成员"是**编译器帮忙**的结果，不是 JVM 层真的共享了私有可见性。

> ⚠️ 因此**选项"内部类可以访问外部类除私有成员外的所有成员"是错的**——恰恰相反，私有成员**也能**访问，这反而是内部类常见的用途。

## 五、面试话术（口述版）

**问：Java 有哪几种内部类？区别是什么？**

> 主要有四种：成员内部类、静态内部类、局部内部类、匿名内部类。最关键的分界线是**静态内部类和非静态内部类**——记住一个根因就行：非静态内部类**持有外部类实例的引用**（编译器加了个 `this$0` 字段），静态内部类**不持有**。所以成员内部类必须先有外部类对象才能创建、不能声明静态成员；静态内部类可以直接 `new 外部类.内部类()` 独立创建。局部内部类定义在方法里，作用域只在该方法内，能访问方法里的局部变量但**只能是 effectively final 的**；匿名内部类是没有类名的局部内部类，在声明处用 `new 接口/父类(){...}` 一次性创建。另外要注意，**内部类能访问外部类的私有成员**，这是编译器生成合成访问方法实现的，不是 JVM 真的共享可见性。

**问：匿名内部类"只能使用一次"这种说法对吗？**

> 这个说法**不准确**。它想表达的是"匿名内部类没有类名，只能在声明处实例化一次、没法用类名再 new 第二个"，但说成"只能使用一次"容易被误解成"这个对象只能被调用一次"。实际上创建出来的对象可以反复使用——`Runnable r = new Runnable(){...}` 之后，`r.run()` 想调多少次都行。准确的说法是"**只能在声明处实例化一次**"。
