### **LeetCode 3259「两种能量饮料选其一的最大能量」动态规划解法**

核心思路是**双状态机 DP**：`dA[i]` / `dB[i]` 表示前 `i` 小时、最后一小时喝的是 A / B 饮料时的最大能量值。每一小时要么继续喝同一种饮料（累加当前饮料能量），要么从一个小时前切换过来（隔 1 小时冷却），取最大值。时间复杂度 $O(n)$，空间 $O(n)$（可滚动数组优化到 $O(1)$）。

---

### **一、问题本身**

有 `n` 小时，每小时可以从两种能量饮料 A、B 中选一种喝，分别获得 `energyDrinkA[i]` / `energyDrinkB[i]` 能量。约束：**从一种饮料切换到另一种，需要间隔 1 小时**（切换的那一小时喝的是新饮料，但前一小时不能再喝旧饮料——也就是切换前的那个小时必须"空过去"，等价于从对侧饮料的 `i-2` 状态跳过来）。求 `n` 小时能获得的最大总能量。

> 例如 `energyDrinkA = [4,1,1]`，`energyDrinkB = [3,2,1]`，可选 `A(4)→空→B(1)` 或全程 `A(4)→A(1)→A(1)` 等，求最大值。

---

### **二、DP 解法**

```java
class Solution {
    public long maxEnergyBoost(int[] energyDrinkA, int[] energyDrinkB) {
        int n = energyDrinkA.length;
        long[] dA = new long[n + 1];
        long[] dB = new long[n + 1];
        for (int i = 0; i < n; i++) {
            dA[i + 1] = dA[i] + energyDrinkA[i];
            dB[i + 1] = dB[i] + energyDrinkB[i];
            if (i - 1 >= 1) dA[i + 1] = Math.max(dA[i + 1], dB[i - 1] + energyDrinkA[i]);
            if (i - 1 >= 1) dB[i + 1] = Math.max(dB[i + 1], dA[i - 1] + energyDrinkB[i]);
        }
        return Math.max(dA[n], dB[n]);
    }
}
```

#### **状态定义**

- `dA[i]`：前 `i` 小时、**第 `i-1` 小时喝的是 A** 时的最大能量
- `dB[i]`：前 `i` 小时、**第 `i-1` 小时喝的是 B** 时的最大能量

下标整体偏移 1（`dA[i+1]` 对应前 `i+1` 小时），这是常见的"前缀"DP 写法，`dA[0]=0` 表示 0 小时 0 能量。

#### **状态转移**

对每个小时 `i`（0 到 n-1），先默认"继续喝同一种饮料"，再尝试"从对侧切换过来"：

1. **继续喝 A**：`dA[i+1] = dA[i] + energyDrinkA[i]`
   —— 第 `i-1` 小时喝 A，第 `i` 小时接着喝 A，能量累加。

2. **从 B 切换到 A**：`dA[i+1] = max(dA[i+1], dB[i-1] + energyDrinkA[i])`
   —— 切换需要 1 小时间隔。第 `i-2` 小时喝 B（状态 `dB[i-1]`），第 `i-1` 小时**不能喝**（冷却空档），第 `i` 小时改喝 A。所以要跳到 `i-1`（对应第 `i-2` 小时的状态），而不是 `i`。

同理：

3. **继续喝 B**：`dB[i+1] = dB[i] + energyDrinkB[i]`
4. **从 A 切换到 B**：`dB[i+1] = max(dB[i+1], dA[i-1] + energyDrinkB[i])`

综合：

$$
dA[i+1] = \max\Big(dA[i] + A[i],\ \ dB[i-1] + A[i]\Big)
$$

$$
dB[i+1] = \max\Big(dB[i] + B[i],\ \ dA[i-1] + B[i]\Big)
$$

#### **边界条件**

`dA[0] = dB[0] = 0`（0 小时无能量）。

`i - 1 >= 1`（即 `i >= 2`）时才允许切换，因为切换需要从 `i-1` 下标读取对侧状态，该状态至少要对应"第 0 小时（下标 `i=0`）喝饮料"才合法。前两小时（`i=0,1`）只能各自累计，不能跨侧切换。

#### **答案**

`max(dA[n], dB[n])`，即第 `n` 小时结束时两种"最后状态"中的较大者。

---

### **三、复杂度分析**

- **时间复杂度**：单层 `for` 循环 $O(n)$，每次转移 $O(1)$。
- **空间复杂度**：`dA / dB` 两数组各 $O(n)$，合计 $O(n)$。

**滚动优化**：`dA[i+1]` 只依赖 `dA[i]` 和 `dB[i-1]`，`dB[i+1]` 只依赖 `dB[i]` 和 `dA[i-1]`——每条 DP 只用到前一格和前两格。可将数组压缩为若干 `long` 变量，空间降到 $O(1)$。不过需要同时维护"前一刻"和"前前刻"两组值，写法略繁琐，原题 `n` 不大时不强制。

### **四、状态机视角**

这正是 [[123.买卖股票的最佳时机 III]] 同款**状态机 DP**模型，只是"持股/空仓"换成"喝 A / 喝 B / 冷却"：

```
喝A ──继续──► 喝A          喝B ──继续──► 喝B
  │                              │
  └──冷却1h──► 喝B              └──冷却1h──► 喝A
```

两个状态 `dA / dB` 互相转移，"冷却 1 小时"在状态转移里体现为**跳过一格下标**（读 `dB[i-1]` 而非 `dB[i]`），这是本题与普通双状态机（如股票题，直接读 `sell1`）唯一的区别——冷却使转移依赖跨了 2 步。

> [!abstract] 冷却的本质：转移依赖跨 2 步
> 没有冷却时，`喝A ← 喝B` 直接读对侧前一格 `dB[i]`；有 1 小时冷却时，中间那一格必须"空档"，所以读 `dB[i-1]`（再前一格）。**冷却 = 在状态机边上插入一个"不产出"的中间节点**，DP 里就表现为下标多退一格。

### **五、一个具体例子走一遍**

以 `energyDrinkA = [4,1,1]`，`energyDrinkB = [3,2,1]`（`n = 3`）为例：

| i | A[i]/B[i] | dA[i+1]（_TRY keep_） | 切换项 dB[i-1]+A[i] | dA[i+1]最终 | dB[i+1]（TRY keep_） | 切换项 dA[i-1]+B[i] | dB[i+1]最终 |
|---|-----------|----------------------|---------------------|-------------|----------------------|---------------------|-------------|
| 0 | 4 / 3     | dA[0]+4 = 4          | i<2 不切换       | **4**       | dB[0]+3 = 3          | i<2 不切换       | **3**       |
| 1 | 1 / 2     | dA[1]+1 = 5          | i<2 不切换       | **5**       | dB[2]+2 = 5          | i<2 不切换       | **5**       |
| 2 | 1 / 1     | dA[2]+1 = 6          | dB[1]+1 = 4         | **6**       | dB[2]+1 = 6          | dA[1]+1 = 5         | **6**       |

返回 `max(dA[3], dB[3]) = max(6, 6) = 6`。

路径解读：全程喝 A（`4+1+1=6`）或全程喝 B（先生 3、再 2、再 1 = 6）打平；任何切换都要损失 1 小时冷却，本题数字下切换无收益。

### **六、面试话术**

1. **两状态机而不是一维 DP？** — 决策有"这次喝 A 还是喝 B"的离散状态，且切换有 1 小时冷却，必须分别记录"最后喝的是哪种饮料"，一维 `dp[i]` 无法区分。
2. **为什么切换读 `dB[i-1]` 而非 `dB[i]`？** — 从 B 切到 A 时，中间那一小时不能喝（冷却），所以跳过下标 `i` 直接从 `i-1`（对应上一小时没喝 B 之前的状态）接续。
3. **为什么 `i-1>=1` 才允许切换？** — `dB[i-1]` 合法的最低下标是 0（对应第 0 小时），即 `i-1>=0`；但本题用 `i-1>=1` 锁定从 `i=2` 起才切换，等价于要求前两小时已稳定累计。具体边界视个人下标体系定，本题代码采用 `i>=2` 起切换。
4. **与 [[309.买卖股票含冷冻期]] 的同构** — 都是"双状态 + 切换需冷却 1 步"，转移依赖跨 2 格；只用状态对的语义不同（持有 vs 喝饮料）。
