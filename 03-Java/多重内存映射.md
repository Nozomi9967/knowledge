
你卡住的点其实是 **"颜色到底存在对象里，还是存在指针里？"**。

答案是：

> **颜色不在对象里，而是在"引用这个对象的指针"里。**  
> 所以同一块物理内存，可以同时被多个不同颜色的指针引用。

---

## 先看普通 JVM

假设有一个对象

```
对象A
地址：0x100000
```

内存里就是

```
0x100000
+----------------+
| name = "Tom"   |
| age = 18       |
+----------------+
```

变量

```java
Person p = new Person();
```

实际上

```
p -----> 0x100000
```

指针里面只有地址。

---

## ZGC 做了什么？

ZGC 发现：

> **64 位地址其实没全部用完。**

例如（不是实际位数，只是方便理解）

普通指针

```
000000000001000000
```

ZGC 把最高几位拿出来做标记。

例如

```
00 000000000001000000
^^
颜色位
```

于是：

```
00 + 地址
01 + 地址
10 + 地址
```

虽然二进制不同，

真正访问对象时，

```
00 000100000
01 000100000
10 000100000
```

都会把前面的颜色位去掉，

得到真正地址

```
000100000
```

因此：

> 三个指针最终都指向同一块物理内存。

---

## 举个例子

假设对象地址

```
0x12345678
```

三个引用可能是

```
Marked0

00|0x12345678

Marked1

01|0x12345678

Remapped

10|0x12345678
```

真正访问对象的时候：

CPU 并不会去访问

```
00|0x12345678
```

而是 ZGC 会把颜色位屏蔽掉：

```
mask

00|0x12345678
01|0x12345678
10|0x12345678
        ↓
0x12345678
```

所以最终访问的是

```
+----------------+
| Person对象      |
+----------------+
```

只有这一份。

---

## 所以为什么可以存在三个状态？

因为**状态不是对象的状态，而是"引用的状态"。**

比如：

```
对象：

0x100000
+----------+
| Person   |
+----------+
```

有三个地方引用它：

```
变量A

00|0x100000

变量B

01|0x100000

变量C

10|0x100000
```

它们实际上都指向：

```
        ┌──────────┐
00|addr │          │
01|addr ├─────────► Person
10|addr │          │
        └──────────┘
```

对象只有一个。

引用可以有不同颜色。

---

## 为什么要这样？

假设 GC 正在进行对象搬迁。

原来

```
对象A
0x100000
```

复制到

```
0x500000
```

如果没有颜色：

```
所有引用都必须马上改成

0x500000
```

这就需要 **Stop-The-World**，暂停所有线程。

---

ZGC 则允许：

```
线程1

Marked0 | 0x100000

线程2

Remapped | 0x100000

线程3

Marked1 | 0x100000
```

当线程真正访问对象时，会经过 **Load Barrier（加载屏障）**：

```
读取引用
     ↓
发现颜色不对
     ↓
GC 帮它修正
     ↓
改成新地址
     ↓
继续执行
```

这样不需要一次性更新所有引用，因此可以把停顿时间控制在非常低的水平。

---

### 一句话总结

你的疑问是 **"三个状态存在同一份物理内存"**。

关键就在于：

- **对象只有一份**，位于一个真实的内存地址。
    
- **颜色位存在于引用（指针）中，而不是对象中。**
    
- 多个引用可以带着不同的颜色位，但在去掉颜色位后，都指向同一个对象。
    
- ZGC 正是利用这种机制，让不同线程在垃圾回收过程中逐步修正引用，而不必一次性停止所有线程更新所有指针。
