### **基因序列相似度分析 — 莱文斯坦距离 + 模糊匹配排序**

核心思路是**精确匹配优先 + 编辑距离 DP 计算模糊匹配 + 剪枝优化**：先查精确匹配，无则对每条数据库序列计算莱文斯坦距离，长度差 > D 的剪枝跳过，距离 ≤ D 的按"距离升序 → 字典序升序"排序输出。时间复杂度 $O(N \cdot L^2)$，空间 $O(L^2)$。

---

### **一、题目核心分析**

- **本质**：将基因序列间的"突变距离"（莱文斯坦距离）用于数据库匹配。
- **匹配规则**：
  1. **精确匹配**：存在完全相同的序列 → 直接输出该序列并结束。
  2. **模糊匹配**：无精确匹配 → 输出所有距离 ≤ D 的序列。按距离升序排序，距离相同按字典序升序排序。
  3. **无匹配**：以上均不满足 → 输出 `None`。
- **数据范围**：$D \le 5$，$N \le 30000$，$L \le 25$。$N$ 大但 $L$ 小，$O(N \cdot L^2)$ 可过。

---

### **二、核心思路**

1. **精确查找**：遍历数据库，利用 `String.equals()` 查找是否存在完全一致的序列。若存在，直接输出并终止。
2. **距离计算**：若无精确匹配，计算待测序列与数据库中每个序列的莱文斯坦编辑距离。
3. **剪枝优化**：计算距离前先判断两个序列的长度差。若长度差 > D，编辑距离必然 > D，可直接跳过。
4. **筛选排序**：收集所有距离 ≤ D 的序列，按"距离升序 → 字典序升序"排序。
5. **格式化输出**：按要求输出结果。

---

### **三、算法详解：动态规划求编辑距离**

设 `dp[i][j]` 表示将字符串 A 的前 `i` 个字符转换为字符串 B 的前 `j` 个字符所需的最小操作数。

**状态转移方程：**

| 条件 | 转移 |
|------|------|
| `A[i] == B[j]` | `dp[i][j] = dp[i-1][j-1]`（无需操作） |
| `A[i] ≠ B[j]` | `dp[i][j] = 1 + min(dp[i-1][j-1], dp[i-1][j], dp[i][j-1])`（替换/删除/插入） |

**初始化：**

- `dp[i][0] = i`（需要 i 次删除）
- `dp[0][j] = j`（需要 j 次插入）

---

### **四、复杂度分析**

- **时间复杂度**：最坏情况计算 $N$ 次距离，单次 $O(L_1 \times L_2) \approx 625$，总计 $30000 \times 625 \approx 1.9 \times 10^7$，可过。
- **空间复杂度**：DP 表 $O(L^2)$（约 625 个 int），结果列表最坏 $O(N)$。

### **五、Java 代码实现**

```java
import java.util.*;
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));

        int D = Integer.parseInt(br.readLine().trim());
        int N = Integer.parseInt(br.readLine().trim());

        String[] database = new String[N];
        for (int i = 0; i < N; i++) {
            database[i] = br.readLine().trim();
        }
        String target = br.readLine().trim();

        // 1. 精确匹配优先
        for (String seq : database) {
            if (seq.equals(target)) {
                System.out.println(seq);
                return;
            }
        }

        // 2. 模糊匹配计算
        List<String[]> matches = new ArrayList<>();

        for (String seq : database) {
            // 剪枝：长度差 > D，距离一定 > D
            if (Math.abs(seq.length() - target.length()) > D) {
                continue;
            }

            int dist = calculateLevenshteinDistance(seq, target);

            if (dist <= D) {
                matches.add(new String[]{seq, String.valueOf(dist)});
            }
        }

        // 3. 输出结果
        if (matches.isEmpty()) {
            System.out.println("None");
        } else {
            // 排序：先按距离升序，再按字典序升序
            Collections.sort(matches, (a, b) -> {
                int d1 = Integer.parseInt(a[1]);
                int d2 = Integer.parseInt(b[1]);
                if (d1 != d2) return d1 - d2;
                return a[0].compareTo(b[0]);
            });

            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < matches.size(); i++) {
                if (i > 0) sb.append(" ");
                sb.append(matches.get(i)[0]);
            }
            System.out.println(sb.toString());
        }
    }

    // 动态规划计算莱文斯坦编辑距离
    private static int calculateLevenshteinDistance(String s1, String s2) {
        int m = s1.length();
        int n = s2.length();
        int[][] dp = new int[m + 1][n + 1];

        for (int i = 0; i <= m; i++) dp[i][0] = i;
        for (int j = 0; j <= n; j++) dp[0][j] = j;

        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (s1.charAt(i - 1) == s2.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],
                                    Math.min(dp[i - 1][j], dp[i][j - 1]));
                }
            }
        }
        return dp[m][n];
    }
}
```

### **六、踩坑点与反思总结**

#### **1. IO 性能（Scanner 慢于 BufferedReader）**

$N=30000$ 行输入，`Scanner` 读取速度慢，容易超时。应使用 `BufferedReader` + `readLine()`。

#### **2. 优先级逻辑（精确匹配先判）**

必须先判断精确匹配。如果存在精确匹配，不需要再进行模糊匹配计算，直接输出并 `return`。

#### **3. 排序稳定性**

排序规则必须严格遵循题目要求——距离为主键，字典序为次键。`Collections.sort` 的 comparator 必须准确实现二级排序。

#### **4. 剪枝技巧（长度差 > D 直接跳过）**

虽然本题 $L \le 25$ 数据量可以直接暴力通过，但加上 `Math.abs(len1 - len2) > D` 的判断可以显著提升效率，且是面试中展示优化意识的得分点。

### **七、面试话术**

1. **为什么不用 BFS 求编辑距离？** — 编辑距离的本质是序列对齐问题，DP 状态定义清晰、转移规则明确。BFS 的状态空间是 $(i, j)$ 对，等价于 DP 但实现更复杂。
2. **剪枝的原理是什么？** — 编辑距离的下界是 $|len(a) - len(b)|$（至少做这么多插入/删除才能对齐长度）。若下界 > D，距离必然 > D，无需计算。
3. **$D \le 5$ 这个约束有什么用？** — $D$ 很小意味着模糊匹配的结果集很小，排序成本 $O(|matches| \log |matches|)$ 可以忽略。
4. **如果 $N$ 更大（百万级）怎么办？** — 可以构建 Trie 或 BK-Tree 来加速模糊匹配，但本题 $N=30000$ 线性扫描足够。
5. **与 LC 583（两个字符串删除操作）的区别** — 583 只允许删除操作（求共同子序列），本题允许插入+删除+替换三种操作。
