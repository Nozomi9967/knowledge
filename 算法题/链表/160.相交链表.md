### **LeetCode 160「相交链表」的最优解是「双指针走完彼此的路」：指针 A 走完链表 A 后接着走 B，指针 B 走完 B 后接着走 A，两者必然在交点相遇（或同时到达 null）。因为两个指针走过的总路程相同，都是 `lenA + lenB`。**

### **一、问题本身**

给两个单链表，判断它们是否相交，若相交返回第一个交点节点。

```
A:       a1 → a2 ↘
                  c1 → c2 → c3
B:  b1 → b2 → b3 ↗
返回 c1
```

**关键前提**：链表相交后必然"合流"，不可能再分开（单链表每个节点只有一个 next）。所以形状一定是 "Y"，不是 "X"。

---

### **二、思路一：哈希表（直观但不是最优）**

遍历 A 把节点都存进 `HashSet`，再遍历 B 找第一个在集合里的节点。

- 时间 O(m+n)，空间 O(m)
- 缺点：需要额外空间，且面试官通常会追问"能不能 O(1) 空间"

---

### **三、思路二：双指针走彼此的路（最优解）**

**核心洞察**：如果两个指针以相同速度、走相同的总路程，它们必然同时到达终点。让指针在走完自己的链表后切换到对方的链表，总路程都是 `lenA + lenB`，所以：

- 如果有交点：两个指针会在交点处相遇（因为交点之前的路程差被"切换"抹平了）
- 如果没有交点：两个指针会同时走到 `null`，返回 null

```java
public class Solution {
    public ListNode getIntersectionNode(ListNode headA, ListNode headB) {
        if (headA == null || headB == null) return null;
        ListNode pA = headA, pB = headB;

        while (pA != pB) {
            // 走完自己的链表就跳到对方的头
            pA = (pA == null) ? headB : pA.next;
            pB = (pB == null) ? headA : pB.next;
        }
        return pA;   // 有交点返回交点，无交点返回 null
    }
}
```

**为什么这个循环一定会结束**：两个指针最多各走 `m+n` 步就会同时到达 null（无交点）或相遇（有交点），不会死循环。

### **四、手动推演一遍**

```
A: 4 → 1 → 8 → 4 → 5   （lenA = 5，交点在 8）
B: 5 → 0 → 1 → 8 → 4 → 5 （lenB = 6，交点在 8）

pA: 4,1,8,4,5,null→5,0,1,8   （第 9 步到 8）
pB: 5,0,1,8,4,5,null→4,1,8   （第 9 步到 8）
第 9 步相遇于 8  ✅
```

无交点时：

```
A: 1 → 2 → 3
B: 4 → 5
pA: 1,2,3,null,4,5,null
pB: 4,5,null,1,2,3,null
第 7 步同时为 null  ✅
```

### **五、思路三：长度差 + 快慢指针**

先各遍历一次求长度，让长的先走 `|lenA - lenB|` 步，然后同步走，相遇即交点。

- 时间 O(m+n)，空间 O(1)
- 逻辑更直白，但要遍历两次

**和思路二对比**：思路二只遍历一次，代码更短，是面试首选；思路三更容易解释"为什么能对齐"。**两个都值得会，被问"还有别的办法吗"时能立刻给出第二个。**

### **六、复杂度**

| 解法 | 时间 | 空间 |
|---|---|---|
| 哈希表 | O(m+n) | O(m) |
| 双指针切换 | O(m+n) | O(1) |
| 长度差对齐 | O(m+n) | O(1) |

### **七、易错点**

1. **切换条件写成 `pA.next == null`**：会跳过最后一个节点，应该是 `pA == null` 时切换
2. **在循环内判断 `pA == null` 后又取 `pA.next`**：注意顺序，先判断再移动
3. **把"值相同"当成"节点相同"**：相交判定必须比较**引用**（`==`），不是 `val`
4. **以为会死循环**：无交点时两指针同时到 null，循环条件 `pA != pB` 会变成 `null != null` 即 false，正常退出
5. **链表有环**：本题假设无环；有环的相交问题要先判环（141、142）

---

### **八、一个常见的追问**

**"如果链表可能有环，怎么判断相交？"**

先各自用快慢指针判环。三种情况：

- 都无环：用本题解法
- 一个有环一个无环：必然不相交
- 都有环：先找到各自的入环点，如果入环点相同则相交于环外；不同则要判断"从 A 的入环点绕一圈能否遇到 B 的入环点"，能则是同一个环（相交），不能则不相交

这是 160 + 141/142 的综合题，面试里能说出这三种分类就很加分。
